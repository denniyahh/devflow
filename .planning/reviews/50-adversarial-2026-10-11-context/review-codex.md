## CONFIRMED

- [severity: BLOCKER] The 2.x migration deadlocks any still-live 2.x run: `stop` must refuse, while upgrade must also refuse while either recorded PID is live. — evidence: [50-CONTEXT.md:120-126](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:120). There is no supported DevFlow action for the case that most needs migration. Worse, 2.x has no recorded start-time identity, so a recycled PID also blocks upgrade indefinitely. Define a safe, explicit recovery path for live and recycled 2.x PID records, with a negative test proving an unrelated live PID neither gets signalled nor permanently strands the worktree.

- [severity: BLOCKER] “Shutdown suppresses advance” has no required linearization and the spike implementation demonstrably races it. — evidence: [50-CONTEXT.md:62-64](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:62); the spike checks `stopping` before observing child completion, then advances without rechecking at [main.rs:108-124](.planning/spikes/socket-supervisor/main.rs:108), while shutdown sets the flag later at [main.rs:135-156](.planning/spikes/socket-supervisor/main.rs:135). A stop can therefore receive “stopped,” remove the socket, and still race into `advance`. Require one terminal-state owner/mutex or event loop, plus a deterministic interleaving test whose negative control proves natural completion still advances.

- [severity: BLOCKER] Corrupt-state protection requires root/phase attribution that the chosen socket scheme does not define. — evidence: D-09 requires sweep lookup by root and phase when state will not load at [50-CONTEXT.md:98-103](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:98), but socket naming remains discretionary at [50-CONTEXT.md:158-161](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:158). The spike’s recommended name is a root hash plus phase and explicitly relies on `state.json` to retain the handle [socket-supervisor-spike.md:118-130](.planning/audits/2026-07-24-socket-supervisor-spike.md:118). A hash is not invertible; a per-launch name also permits a second monitor unless there is a durable per-root/phase index. Make the index/sidecar, atomic publication order, permissions, cleanup, and collision rule binding before planning.

- [severity: MAJOR] The STALE pgid backstop’s validation rule cannot handle the failure it is intended to recover. — evidence: D-04 requires both a non-empty group and recorded start-time/boot-id validation [50-CONTEXT.md:67-69](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:67). The current process identity primitive validates one PID via `/proc/<pid>/stat` [agent.rs:214-230](crates/devflow-core/src/agent.rs:214), but a process-group leader may exit while descendants remain in its group. In that intended orphan case, the group is non-empty but the leader’s start time is no longer readable. Specify separate safe rules for leader-present and leader-gone groups, and test both; also test PGID reuse after the original group becomes empty.

- [severity: MAJOR] The fault proof omits SIGKILL during the in-process advance transition. — evidence: D-17 kills the monitor only “mid-stage” [50-CONTEXT.md:141-144](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:141), while the new supervisor invokes `advance_for_stage` after its child monitor returns [pipeline_launch.rs:979-993](crates/devflow-cli/src/pipeline_launch.rs:979). Killing between exit recording, state transition, socket replacement, and lock acquisition is a distinct lifecycle. Require fault fixtures at each publication boundary and prove no later `start`/`resume` can create a second monitor.

- [severity: MAJOR] The socket-length rule is off by one on the only measured platform. — evidence: D-01/criterion 3 permit a path unless it “would exceed” 108 Linux bytes [50-CONTEXT.md:44-48](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:44), but the spike measured longest Linux-bindable pathname as 107 bytes and first failure at 108 [socket-supervisor-spike.md:98-105](.planning/audits/2026-07-24-socket-supervisor-spike.md:98). Define accepted byte lengths precisely, including NUL handling, and require 107-success/108-failure controls on Linux; do not claim the unmeasured macOS boundary is equivalently proven.

- [severity: MAJOR] “Exactly GONE / STALE / ALIVE” is not a total probe contract. — evidence: D-01 defines only absent, refused, and connected paths [50-CONTEXT.md:44-47](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:44). The relied-on spike returns a fourth `UNKNOWN` for all other `connect()` errors [main.rs:163-174](.planning/spikes/socket-supervisor/main.rs:163). A socket removal between metadata check and connect is enough to hit an unlisted error path. Specify retry/classification rules or make probe failure an explicit error distinct from liveness, then test that negative control.

- [severity: MAJOR] Reboot is named in the backstop predicate but has no recovery outcome. — evidence: D-04 permits STALE teardown only when boot-id validation succeeds [50-CONTEXT.md:67-69](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:67). After reboot, the socket file can remain and the boot id must differ; killing is correctly forbidden, but the context never says who removes the stale path, updates state, or allows the preserved phase to resume. Define that fail-closed cleanup path and simulate a boot-id mismatch with a negative control proving no process is signalled.

- [severity: MINOR] The context says three backlog items are folded, then names five. — evidence: “three backlog items” at [50-CONTEXT.md:15-17](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:15) versus five items at [50-CONTEXT.md:21-23](.planning/phases/50-addressable-monitor-liveness/50-CONTEXT.md:21). Also, D-11 requires inserting Phase 999.130 between 50 and 51, but the current roadmap still places Phase 51 immediately after 50 [ROADMAP.md:334-365](.planning/ROADMAP.md:334). Correct the count and perform or explicitly gate the required roadmap insertion before calling this ready.
