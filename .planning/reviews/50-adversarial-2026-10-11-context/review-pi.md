## CONFIRMED

- **[severity: BLOCKER] Per-phase socket naming collides with the in-process advance that spawns the *next* stage's monitor.** `run_monitor` ends by calling `advance_for_stage` in the same process (`crates/devflow-cli/src/pipeline_launch.rs:918`, tail `... advance_for_stage(project_root, Some(phase), stage)`), and `monitor.rs:480-483` states the advance "for an agent stage **spawns the next monitor itself**". That next `__monitor` is a fresh process for the *same phase*, while the current monitor's listener is still bound (the old process has not exited; the spike only `remove_file(&sock)` at natural exit/shutdown, `spikes/socket-supervisor/main.rs:112,141,150`). The takeover logic then does `if Path::new(&c.sock).exists() { if UnixStream::connect(...).is_ok() { exit(3) } let _ = remove_file(&sock) }` (`main.rs:66-73`): the new monitor either refuses (stage transition dies) or unlinks the still-live old socket and binds its own name, producing **two live monitors for one phase**, with the old one now unaddressable by `stop`. The same unlink-then-bind is a TOCTOU race between any two concurrent launchers (`start` + `resume`, both of which `refuse_launch_over_a_live_run` gates only on a state read, `commands.rs:2432-2453`). CONTEXT defers only "**Per-phase versus per-launch naming**" to Claude's Discretion and never analyses the handoff. Correction: require an atomic publication (temp-bind + `rename`, or O_EXCL ownership file) and define the exact ordering by which stage N publishes stage N+1's path and stops answering.

- **[severity: BLOCKER] D-14 ∘ D-15 is a wedged catch-22 for any 2.x run with a live recorded pid.** D-14: "Every verb that writes state or launches (`start`, `resume`, `advance`, **`stop`**, `ship`, gate answers, …) refuses". D-15: the upgrade verb "**refuses while the 2.x state's recorded monitor or agent pid is alive**." So the only live escape run cannot be stopped (D-14) and the only writer that could stamp v3 refuses while it is alive (D-15). The refusal text is required to "name the way out (D-15)" — a verb that is guaranteed to refuse. The pid test is also recycle-prone: D-15 reads a bare pid, and the only primitive in reach is `agent_running` (`crates/devflow-core/src/agent.rs:36-47`), which is `kill(pid,0)` + `/proc` zombie check with **no start-time identity** — the exact 999.143/999.128 defect. A single recycled pid wedges the phase permanently. Correction: either exempt `stop` on incompatible states to a documented identity-checked manual kill, or give the upgrade verb a `--force` that signals the recorded pids after confirming identity with `process_start_time`.

- **[severity: MAJOR] The STALE backstop's pgid does not exist as an agent-dedicated group for `Legacy`, so `killpg` targets the operator's process group.** `.process_group(0)` exists **only** on the PipeOwning child (`crates/devflow-core/src/monitor.rs:1009`). The Legacy arm spawns `sh` with no group configuration (`monitor.rs:576-590`) and backgrounds the agent from the script (`monitor.rs:540-548`), so the agent's pgid is the `sh` monitor's pgid — inherited from the CLI that spawned it. D-04 says teardown "enumerates the recorded agent process group and `killpg`s it" (`state.json` gains `pgid`). For any Legacy-launched run (every non-Claude adapter), that recorded group is the operator's shell/`devflow start` group; `killpg` would signal the operator's terminal tree. The CONTEXT never states that the Legacy replacement must `process_group(0)`. Correction: make group creation an explicit, tested requirement of both arms and assert `pgid == agent_pid` before recording it.

- **[severity: MAJOR] The backstop's start-time validation fails precisely in the leader-dead/members-alive case it exists to fix.** The spike's design records `agent_pgid` + `agent_start_time` (`.planning/audits/2026-07-24-socket-supervisor-spike.md`, "Resulting design"), and D-04 gates the kill on "the group is non-empty **and** the recorded start time and boot id still validate". But `agent::process_start_time` reads `/proc/{pid}/stat` and returns `None` when it is unreadable (`agent.rs:214-221`). If the agent (group leader) is reaped while grandchildren survive, enumeration finds non-empty members but validation of the leader returns `None` → the backstop refuses and the orphans leak — the F1 "leader dead / members alive" row the socket design claims to solve (audit "Coverage against the known failure modes"). The spike's C5 only proves the case where the agent is still alive. Correction: validate the group by a surviving member (or a leader-independent group identity), and document the residual leak explicitly.

- **[severity: MAJOR] The liveness predicate is not total; a live-but-busy monitor can be misclassified as STALE and destroyed.** D-01 defines exactly three outcomes and ROADMAP criterion 1 requires each fixture to produce "**only** that state", but the spike's own probe has a fourth: `Err(e) if e.kind() == ConnectionRefused => "STALE", Err(e) => "UNKNOWN {e}"` (`spikes/socket-supervisor/main.rs:158-170`, same in `sweep`). `connect()` on a Unix socket can fail with `EACCES`, `ENOTSOCK` (path is a regular file left by a failed bind), `ENOENT` (unlink race), or `EAGAIN`/backlog saturation **while the monitor is alive**. A naive `_ => STALE` routes those into the destructive backstop. The CONTEXT maps neither UNKNOWN nor any errno. Correction: enumerate the errno → classification, make `ECONNREFUSED` the *only* STALE trigger, and give every other failure a distinct non-destructive state.

- **[severity: MAJOR] `sun_path` is off by one relative to the spike's own measurement.** The spike measured "**longest bindable socket path = 107 bytes (first failure at 108)**" (audit, C6). D-01 says a path that "would exceed `sun_path` (**108 bytes** Linux, 104 macOS) is refused at construction", and ROADMAP criterion 3 and REQUIREMENTS SUPV-01 repeat 108/104. A planner reading "exceed 108" writes `len > 108`, which accepts a 108-byte path that `bind()` rejects — the criterion-3 refusal is then false. (Linux `sun_path` is 108 bytes *including* the NUL.) Correction: state the usable maximum as **107 Linux / 103 macOS** and test the boundary pair 107-ok / 108-refused.

- **[severity: MAJOR] D-09 cannot be implemented as written: the corrupt state is the only place the backstop identity lives, and the socket name is a non-invertible hash.** D-09 requires `start`'s guard to refuse when it finds "an ALIVE (or **STALE with a live group**) socket", and says the socket→root+phase pairing must be "recoverable from the socket's name or a sidecar, **because the state that would record it is the thing that will not load**". But D-04 puts `pgid`, start time and boot id in `state.json` — so with an unloadable state the guard cannot determine "live group" at all. Separately, the socket key is a hash ("`…/devflow/ab12cd34-22.sock`", Discretion), and the registry's digest is a one-way FNV-1a of the root (`crates/devflow-core/src/registry.rs:75-88`): the *name alone* cannot recover the root. The only place the mapping exists is the separate `~/.cache/devflow/roots` registry, which D-09's "name or sidecar" wording excludes. Correction: either persist the full backstop identity in a socket-adjacent sidecar, or use the registry explicitly (and drop "name" as a mapping source).

- **[severity: MAJOR] The "major version" claim names no breaking public API, and whether `pub monitor_pid` is removed is left undefined.** ROADMAP:10 justifies the major bump because Phase 50 "adds a socket path to `state.json`"; D-13 calls the field "the published state-file contract". But `State` is `#[non_exhaustive]` (`crates/devflow-core/src/state.rs:17`) *specifically* so field additions are additive (doc at `state.rs:26-31`), and D-16 requires `MonitorLaunch::Legacy` to still exist (implementation replaced, variant kept). On that reading `cargo semver-checks check-release -p devflow-core` (CLAUDE.md) would find no required major bump. Conversely, D-12 says Phase 50 "removes its monitor-pid half by construction", and `pub monitor_pid` exists at `state.rs:288` — *removing* it is genuinely breaking. The CONTEXT never says which. Correction: name every `pub` item added/removed/changed, keep `monitor_pid` (untouched) or declare its removal, and re-run semver-checks.

- **[severity: MAJOR] Criterion 2's "answer identically" is near-vacuous after D-03 and the live rig cannot test the cohort it protects.** D-03 makes `Legacy` the same Rust supervisor as `PipeOwning`, so identical liveness follows from shared code — the assertion tests nothing. The real content of criterion 2 is the cohort: "`Legacy` … still carries every non-Claude agent and the checkpoint-resume relaunch" (ROADMAP criterion 2). But the live rig pins `--agent claude` (49-CONTEXT D-15) and only reaches `Legacy` via `relaunch_checkpoint_session` (`pipeline_launch.rs:1280`), a Claude stream-json resume. So the non-Claude path is never exercised by the live run, and D-16's "the run crosses both variants" is not a parity test (different moments, different conditions). Correction: require a table-driven parity test over the spike's R-A…R-M responsibilities under both arms with a non-Claude adapter, plus a negative control that the arms can be distinguished.

- **[severity: MAJOR] The supervisor/lock interaction is unspecified and breaks the Phase 48 one-writer rule and `stop`'s own sequencing.** `stop` never takes the per-phase lock until `persist_stopped_state` (`crates/devflow-cli/src/commands.rs:1882-1900`, `:2121-2127`), which calls `lock::acquire` and **errors** if the holder is still alive (`:2140-2145`, "phase state was not marked stopped"). With in-process advance holding that lock, a socket `shutdown` mid-advance kills the agent and exits without releasing the lock; the subsequent `persist_stopped_state` then hits `Contended`. D-04 says only "removes the socket, exits" and never mentions the lock; the spike's F5 asserts "The monitor releases it on clean shutdown" but that is a spike assumption, not a decision. Correction: define lock ownership for the in-process advance, have the supervisor release it on shutdown, and sequence `stop` as acquire-lock → send shutdown → persist.

- **[severity: MINOR] Folded backlog items lose their acceptance tests in the proof bar.** 999.128 requires "at a `Recycled` gate, the repair `stop`/`doctor` names succeeds" and 999.141 requires "a test that fails when a spawned `devflow` child writes outside its tempdir `HOME`" (ROADMAP 999.128/999.141). D-16/D-17/D-18 enumerate liveness fixtures and the live run, with no slot for these. Folding a defect without its named failing test is how the defect returns. Correction: add both to the plan's acceptance, each with a negative control.

- **[severity: MINOR] Only `state.json` is versioned; other 2.x artifacts are unexamined.** D-13/D-14 gate the entire 2.x→3.x break on one `schema_version` field in `State`. A 3.x binary also consumes gate request/response/ack files and `cron-instructions*.json` written by 2.x, and the events log carries its own independent `"v":1`. The upgrade verb "stamps `schema_version: 3`" and leaves those untouched. Correction: scope the incompatibility check to every persisted format the 3.x binary reads, or state explicitly that only `state.json` is covered.

## SUSPECTED

- **[severity: MAJOR] "Suppresses `advance`" (D-04) does not suppress any other advance.** The supervisor declining to call its own tail cannot stop (a) a foreground `devflow advance --phase N` running concurrently, or (b) a next-stage monitor that advance already launched before the shutdown landed (see finding 1). 999.138's own fix shape offered "`advance` honours `stopped=true` at the next stage boundary" as the alternative; D-04 chose signalling only. SPECULATION that this is unexploited today because `stop` precedes the socket path in the common case.

- **[severity: MAJOR] A boot-id mismatch leaves the STALE socket in place forever.** D-04's backstop "only" kills when the boot id validates; after a reboot (socket survives in `~/.cache/`), teardown cannot reap (correct) but nothing in D-04/D-06 says the socket file is removed, so `stop`/teardown can report "handled" while the phase stays STALE. D-17's fault arm asserts "giving GONE", which requires removal. Correction: separate "reap the group" from "remove the socket" and always attempt the latter.

- **[severity: MINOR] D-01/D-07 name `HOME`/`XDG_CACHE_HOME` but not the existing override.** `registry::cache_dir()` resolves `DEVFLOW_CACHE_DIR` first, then `XDG_CACHE_HOME`, then `HOME/.cache` (`crates/devflow-core/src/registry.rs:53-64`). If the socket resolver does not share that function, tests that isolate via the existing `DEVFLOW_CACHE_DIR` hook will still write sockets into the real cache — the exact 999.141 class D-07 is closing. Correction: require the socket dir to be `registry::cache_dir()` and add `DEVFLOW_CACHE_DIR` to D-07.

- **[severity: MINOR] The 2.x detection has no negative control.** Criterion 4 is "detected and reported as incompatible, never silently misread as GONE". A test that keys on socket-path absence rather than `schema_version` passes a 2.x fixture but misreports a genuine 3.x state whose socket field is `None`.
