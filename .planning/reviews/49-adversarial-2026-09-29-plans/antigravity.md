3. **Global Git Signing (`commit.gpgsign=true`) breaks headless unattended commits in `negctl.sh`**
   - **Evidence:** `.planning/phases/49-live-unattended-run-the-milestone-s-instrument/49-02-PLAN.md:159-160` (*"set repo-local `commit.gpgsign false` and `tag.gpgsign false` (RESEARCH Pitfall 7; this mode only)"*); `.planning/phases/49-live-unattended-run-the-milestone-s-instrument/49-07-PLAN.md:103-105` (*"scaffold `"$EV/negctl/repo"` with the default mode; assert `develop:.planning/config.json` exists (the control's precondition), `git rm` it and commit `chore: remove config.json for negative control` on `develop`; assert it is gone; write `negctl/develop.sha`."*).
   - **Impact:** `scripts/scratch-dogfood-repo.sh` only disables git signing in `--live-payload` mode, leaving default mode untouched. On machines with global SSH or GPG commit signing enabled (`commit.gpgsign=true`), `negctl.sh`'s `git commit` invokes the host signing agent. In headless, unattended, or subagent execution where ssh-agent or pinentry lacks a tty, `git commit` hangs or fails, aborting the negative control before launch. Furthermore, if it does succeed, it signs a throwaway probe commit with the operator's personal identity.
   - **Recommendation:** In `49-07-PLAN.md:105`, explicitly instruct `negctl.sh` to run `git -C "$EV/negctl/repo" config commit.gpgsign false` (and `tag.gpgsign false`) or execute the commit with `git -c commit.gpgsign=false commit ...`.
