## CONFIRMED

1. A stopped/cleanup attempt can leave DevFlow’s detached monitor alive after its project is deleted. `49-09-PLAN.md:84` specifies `KillMode=process`; `crates/devflow-cli/src/test_support.rs:532-548` confirms `devflow start` spawns a detached monitor designed to outlive the caller and must be explicitly reaped by its recorded PID. Yet cleanup only stops/resets the `start` and watcher units, then deletes the attempt directory (`49-12-PLAN.md:199-202`). Impact: a surviving monitor can advance against a removed project or contaminate a later attempt. Recommendation: record and verify the monitor PID/state; terminate it through DevFlow’s ownership-safe path before removing the project, and make “PID is dead” a gate.

2. Wave 3 autonomously spends real Claude quota before the operator checkpoint. `49-09-PLAN.md:8-9` marks the plan autonomous, while its action requires a real `claude -p` request through the user manager (`49-09-PLAN.md:185-201`, `:215-218`). Impact: a plan-validation run can consume the same credential/account quota and make an external model call without the live-attempt checkpoint. Recommendation: make the real probe a blocking human action, or require an explicit operator-provided opt-in flag immediately before it.

3. The autonomous negative-arm gate writes the real machine registry and knowingly leaves stale entries on a failure path. `49-07-PLAN.md:170-194` says the auto task registers under `~/.cache/devflow/roots/`, and that a failure leaves an entry naming a deleted temp path. Impact: later DevFlow commands can encounter residue from a plan self-test; the claimed test isolation is false for the registry. Recommendation: use an isolated registry root supported by the binary, or make the test abort/reap successfully before deleting its temp project and gate on zero matching registry entries.

4. `check-evidence --attempt-gate` authenticates consistency, not provenance, so planted or stale evidence can close the live checkpoint. The plan explicitly admits “Files an agent or operator could have edited decide whether the phase’s instrument passed” (`49-08-PLAN.md:217`); its gate accepts local `DONE`, `verdict.json`, a locally generated SHA-256 manifest, and passing local arm checks (`49-08-PLAN.md:187-195`). A copied good fixture plus a regenerated manifest and `current-attempt=1` meets this contract without a real launch. Impact: VERIFY-01 can be reported met from manufactured evidence. Recommendation: bind evidence to an unforgeable live-run nonce emitted by the pinned binary and attest launcher PID/unit identity, binary hash, project origin, and event sequence in the checker.

5. The DECN-03/SURV-01 gate passes fabricated prose instead of validating the required inputs. Task 2 requires six DECN inputs, captures, paths, quoted reasoning, and watcher fields (`49-12-PLAN.md:154-169`), but the gate only checks line counts, three words, event-count polarity, and three SURV strings (`49-12-PLAN.md:173-174`). For example, with one real `checkpoint_auto_decided` event, an eight-line section containing `CODE_STAGE_POLICY`, `checkpoint_auto_decide_prompt`, `session`, and `**DECN-03 outcome: Followed**` passes without either capture or comparison reasoning; similarly invented `interleaved_windows=`, `stop_marker=`, and `advance_failed` text passes without reading `analysis.txt`. Impact: criteria 4 and 5 can be falsely recorded. Recommendation: parse and compare every cited field directly from committed captures/events/analysis, require the quoted strings to occur in those files, and reject absent or mismatched values.

6. 49-12 is not retry-idempotent after its first evidence commit. Task 1 sanitizes into `$D/attempt-<N>` and commits it (`49-12-PLAN.md:115-129`), while the sanitizer is explicitly required to refuse an existing destination unchanged (`49-05-PLAN.md:129-143`). Any retry after a later Task 1 verification failure cannot recreate the committed evidence tree. Impact: a recoverable verifier failure becomes a wedged phase or pressures an unsafe manual deletion of committed evidence. Recommendation: make sanitization resumable only when the existing destination’s manifest and source identity match, otherwise fail with a distinct immutable-attempt error before committing.

7. The real auth-probe control is vacuous when the executor has no `CLAUDE*` variables. The action says `caller_claude_names` “must be above 0” to prove the session-leak check had something to catch (`49-09-PLAN.md:223-227`), but the gate merely prints `caller_claude_names=$cc` and never asserts it (`49-09-PLAN.md:230`). Impact: `session_names=0` passes even when there was no caller-session variable that could have leaked. Recommendation: add `[ "$cc" -ge 1 ] || rc=1` and a negative fixture where a non-credential `CLAUDE*` variable demonstrably reaches the unit and fails.
