### DECN-01 — partial (operator-accepted)

`CODE_STAGE_POLICY` (`crates/devflow-core/src/prompt.rs`) is well-written and correctly carved
out (forbids positional choice, treats "recommended" as evidence not verdict, demands the
comparison that produced the choice, excludes `blocking-human` / package-verification). It reaches
`code_stage_prompt` (first Code pass, claude-style) and `workflow_code_prompt`'s `FullExecute` arm
(Codex/Pi). It does **not** reach:

1. **`fix_prompt`** — the Claude/OpenCode loop-back rendered *after Validate fails*, which is
   exactly when decision checkpoints accumulate, and Claude is this project's primary driver. So
   the missed path is the common case. → deferred, **backlog 999.115**.
2. The standing policy is **contradicted by `checkpoint_auto_decide_prompt`**, which grants the
   agent authority over `blocking-human` gates that `CODE_STAGE_POLICY` explicitly withholds — in
   the same resumed conversation. → deferred, **backlog 999.116**.

Both deferrals are recorded operator decisions (`45-REVIEW.md` § Disposition, `45-VERIFICATION.md`
frontmatter `overrides:`, Dennis Kim, 2026-09-02). The deferral changes who owns the remaining
work; it does not make criterion 3 true. Counted here as `partial`, not as a defect.

### Integration Warning 1 — residual ambient trunk re-resolution (new, unfiled)

`crates/devflow-cli/src/pipeline_outcomes.rs:598-601` calls
`devflow_core::config::git_flow_for_project(project_root)` where every sibling site
(`pipeline_outcomes.rs:1066`, `pipeline_launch.rs:1480`, `monitor.rs:1277`, `ship_evidence.rs:166`)
was converted to `config::git_flow_for_run(project_root, state.base_branch.as_deref())`. `state` is
in scope. Reads as a missed conversion, not a deliberate exception (the CR-01 comment above it
governs *root* selection, not trunk config).

**Impact:** narrow — drift only when the base is set via `DEVFLOW_BASE_BRANCH` env (not
`devflow.toml`) *and* the detached `advance`/monitor process (no operator shell env) reaches this
line, yielding a wrong `develop..branch` count into the `consecutive_failures_made_progress`
heuristic. Saturating counters bound it. Not a broken flow. CONFIRMED by inspection; no test
exercises the env-var + detached-process combination for this site.

### Integration Warning 2 — uneven marker-less E2E coverage

CLI-level `devflow start` marker-less-never-advances regression tests exist for **pi, antigravity,
hermes** (`crates/devflow-cli/tests/phase7_cli.rs`). **codex, opencode, claude** are covered only
at the `agent_result.rs` parser layer. The guarantee is structurally shared (commit-gate + Layer 1
`None` → Layer 2), codex got a full Phase 44 dogfood, and claude is the reference driver — so this
is uneven coverage rather than a gap. **OpenCode is the weakest** (parser regression vs 3 vendored
captures, no `devflow start` E2E). Recommend one opencode CLI marker-less test.
