<objective>
Close review finding M1: re-measure the post-stdin-close exit timing across
several trials and archive it as evidence, and — for the first time — observe
what the CLI actually does when stdin is closed while background tasks are
still pending.

Purpose: the 0.38s exit figure that the ROADMAP and `30a-evidence/README.md`
both cite exists only in a harness's console output from a session that is gone.
It is unarchived and unreproducible, and it is a single sample. Separately,
review constraint 4 requires Phase 31's monitor to close stdin only on marker
AND drained task set, and states plainly that close-with-pending-tasks
"is untested and must be treated as undefined". Building a close rule around an
undefined behavior without ever observing it is the kind of assumption this
phase exists to remove.

Output: a re-measurement harness, archived per-trial evidence, and
`30d-MEASUREMENTS.md`.
</objective>

MEDIUM-HIGH — "the measurements may be internally reproducible yet externally

**MEDIUM — 30d does not reuse the production-replica launch path. ACCEPTED.**
Verified: `run_experiment_v3.py` builds a bare `["claude", "-p", …]` argv and
calls `subprocess.Popen(cmd, …, stderr=subprocess.STDOUT)` — direct exec, merged
stderr, unscrubbed environment, no detachment. That is the interactive shape
30c exists to move away from, so extending it would have measured exit timing in
an environment 30c had just finished proving is not production's. Task 1 now
imports 30-02's launcher; 30-02's Task 1 gained a matching requirement to expose
it as an importable function.

**MEDIUM — `mode_b_outcome` is not a mutually exclusive state. ACCEPTED.** A
trial can exit cleanly and still lose child work; it can hang while the child
completes. The four alternatives (`exits_cleanly`, `hangs`,
`exits_with_truncated_result`, `child_work_lost`) forced independent
observations through one slot, and the `nondeterministic` escape hatch made that
worse by hiding the disagreement's shape. Now recorded as independent fields
with a derived summary that is explicitly secondary to them.

**MEDIUM — the observation window is unspecified. ACCEPTED.** "Bounded" and "do
not block indefinitely" set no floor, and a floor is what matters: the slower
child has a 22-second deadline, so a window shorter than that manufactures
`child_work_lost` regardless of CLI behaviour. Floor and buffer now stated and
recorded per trial.

**MEDIUM — cleanup is not operationally specified. ACCEPTED.** The threat
register required `finally`-block cleanup while the action and acceptance
criteria required nothing checkable, and killing only the direct child leaves
delegated grandchildren behind. Process-group termination plus a verified
descendant sweep is now a first-class requirement with its own acceptance
criterion. Backlog 999.46 already tracks leaked fixture processes here; Mode B
deliberately closes stdin mid-work, which is precisely the shape that leaks.

    work is a legitimate finding — this mode has no expected outcome, which is
    the entire point of running it.

    for at least the slowest child's deadline measured from ITS dispatch (22
    seconds, per the reused v3 prompt) plus a delivery buffer, and make the
    total window a named constant with a default of 90 seconds. Record the
    actual window used in each trial's timings file. A window shorter than the
    child deadline manufactures "child work lost" out of an early stopwatch,
    which would be a measurement artifact presented as a CLI behaviour — and
    this measurement is the empirical input to Phase 31's close rule. Continue
    draining and recording stream events for the whole window even after the
    process exits, so a post-exit event (if the CLI emits one) is captured
    rather than missed.

    **Each trial runs in its own process group and that group is reaped before
    the next trial starts.** The launcher 30c provides already sets
    `start_new_session=True`, so the child is a process-group leader; record its
    pgid at launch. In a `finally` block covering every exit path — normal
    completion, timeout, and exception — signal the whole group
    (`os.killpg` with `SIGTERM`, then `SIGKILL` after a short grace period),
    then VERIFY the reap: poll for surviving members of that pgid and record
    the result in the trial log, including the case where survivors remain after
    the escalation. Killing only the direct child leaves the delegated
    grandchildren behind, and Mode B deliberately creates exactly that shape by
    closing stdin while children run. Backlog 999.46 already tracks leaked
    fixture processes in this repository; this plan must not add instances, and
    "we called kill on `proc`" is not evidence that it did not.

    Timestamp with a monotonic clock, not wall-clock time, for every interval
    measurement. Wall-clock is subject to NTP adjustment mid-measurement, and
    sub-second intervals are exactly where that shows up.

    Gate only on `local_agent`-typed entries in `background_tasks_changed.tasks`
    when deciding whether tasks are drained. RESEARCH.md's Pitfall 6 records an
    additional `local_bash`-typed `task_started`/`task_notification` pair per

    entries. Assumption A2 in RESEARCH.md's log is that the `local_bash` pair is

    evidence instead of another restatement.

    filename prefix per trial so trials are individually inspectable. Do not
    write a second redactor; do not copy staged files directly into the
