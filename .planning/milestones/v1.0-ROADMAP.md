## Overview

**This milestone was never declared at the time.** DevFlow did not use the "milestone" concept at
all until v2.0.0 was declared partway through Phase 20's era (2026-07-23) — phases 1-11 shipped
individually as versions 0.1.0 through ~1.2.0, tracked only in `ROADMAP.md`'s flat "Shipped" table,
with no grouping boundary. This archive retroactively applies the "v1.0" label the operator chose
on 2026-08-04 (declining to leave this history un-grouped indefinitely) so that phases 1-11 follow
the same archival convention as v2.0.0 and v2.3.0, rather than remaining permanently un-archived
simply because no milestone concept existed yet when they shipped.

**This is a convenience label, not a historical fact.** No `## v1.0 milestone` heading, closing
decision, or bounded scope was ever recorded in `ROADMAP.md` at the time. Unlike v2.0.0 and v2.3.0,
there is no "closing rationale" to preserve here beyond "these are the phases that shipped before
the milestone concept existed."

**Relationship to `v1.0-ASSESSMENT.md`:** a file by that name already exists in
`.planning/milestones/` (dated 2026-06-17) but is a different kind of artifact entirely — a
one-time feature-comparison snapshot ("ROADMAP aspirations vs. actual source code") generated at
the v0.1.0 release, not a milestone archive produced by any close-out process. It predates and is
unrelated to this retroactive v1.0 milestone label; both files are kept, uncombined.

**Source for this archive:** `ROADMAP.md` carries no `### Phase N:` detail headings for phases
1-11 at all (confirmed by direct search) — the only ROADMAP.md record of this era is the flat
"Shipped" table (reproduced below) and scattered prose in the "Reorganized (June 2026)" /
"Reorganized for MVP" sections, which also narrate later phases (12+) and were left in place
rather than picked apart by phase. The authoritative per-phase record is each phase's own
directory, now archived to `.planning/milestones/v1.0-phases/`.

## Milestone Summary

**Key Decisions:**

- **The GSD-native rewrite (Phase 11)** replaced the original `tmux`-based agent launcher entirely
  with direct process spawning and a monitor daemon (`monitor.rs`) that captures
  stdout/stderr/exit/pid to files and invokes `devflow advance` on completion. `tmux` stopped being
  a runtime dependency at this point. The CLI surface was substantially cut and rebuilt in this
  phase, then expanded through later phases.
- **Retroactive v1.0 declaration (2026-08-04):** the operator chose to backfill a milestone label
  for this era rather than leave it permanently un-archived, once the same question arose for the
  (already-existing, unlabeled) phases 12-29 during the v2.3.0 milestone's own close-out.

**Issues Resolved:** not individually reconstructed here — `CHANGELOG.md` has no curated entries
before 1.3.0 (Phase 15, the first phase of the *next* milestone), so the per-release detail for
this era lives only in each phase's own `SUMMARY.md`/`PLAN.md` in the archived phase directories.

**Technical Debt Incurred:** none recorded as carried forward specifically from this era beyond
what Phase 11's own remediation round (`11-remediation/`) already addressed.
