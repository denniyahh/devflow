# Phase 37.1: Pi Subagent-Extension Spike — Summary

**Pi subagent dispatch is VIABLE: `@bacnh85/pi-subagent` works as-shipped (synchronous, in-process, fails closed headless), so the full-dispatch arm is re-scoped to `MonitorLaunch::Legacy` with no `CloseRule`/drain gate.**

## Outcome

This is a **research spike**, not a build phase — its deliverable is the decision gate, not code.
The authoritative record is [`37.1-DECISION-GATE.md`](./37.1-DECISION-GATE.md); supporting evidence is
in [`37.1-RESEARCH.md`](./37.1-RESEARCH.md) and the primary-source reviewer logs at
`.planning/reviews/phase-37.1/research/`.

**Verdict: VIABLE (revised).** The original NOT VIABLE verdict rested on two claims that
primary-source research overturned:

1. *"No credible extension exists"* — false: the npm registry holds 20+ installable Pi-subagent
   extensions; the original pass catalogued 6 and dismissed all on metadata without reading source.
2. *"Full dispatch requires reusing `PipeOwning`/`CloseRule`"* — false framing: a synchronous
   extension whose `execute()` awaits its children keeps the parent `pi -p --no-approve` alive until
   subagents finish, so `MonitorLaunch::Legacy` process-exit supervision is sufficient.

## Consequences (consumed by Phase 39)

- Phase 39 ships **both** arms: Stage 1 baseline (`Legacy`/`-p` + provider fix) and Stage 2 dispatch
  (`@bacnh85` at user scope, no drain gate).
- The `CloseRule`/`PipeOwning` "full-dispatch arm" is dropped — it was the false premise.
- Trust boundary: `@bacnh85` is the only finalist that works as-shipped; process-spawning
  alternatives (`@dreki-gg`, `@smoose`) need a `--no-approve` child-argv patch, and `@mystilleef`
  must not be used (passes `--approve` to children, defaults `agentScope: "both"`).

## Open questions (carried to Phase 39)

1. Install user-scope vs vendor-and-pin `@bacnh85` (a standing decision, resolved at execution).
2. In-process sessions share the parent's context window — a capability difference from Claude's
   isolated-context `Task`, not a blocker for this milestone.
