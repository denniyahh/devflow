## Planner decision record

### P-01 — Codex parsing relocates, doesn't re-implement

`parse_codex_event_result` + `is_codex_event_stream` + `detect_codex_rate_limit` move into
`CodexDriver` (or a module it owns); the `agent_result.rs` call sites are rewired, not duplicated.
The relocation must be behavior-preserving — the existing result-evaluation tests are the proof.

### P-02 — Pi is print-mode only

`PiDriver::build_command` == `pi -p --no-approve <prompt>`; `health` == `pi auth check` (the Phase-36
predicate). The `render_prompt` for Pi is the same de-Claude-ified intent as Codex (no `/gsd-*`),
but Pi does NOT get a JSON unwrapper or `CloseRule` integration this phase.

### P-03 — Codex hardening lands only where it's cheap and safe

The non-interactive approval policy is VERIFIED against the installed CLI first: `--ask-for-approval`
is a global flag (must precede `exec`) and is rejected as an `exec` subcommand flag — the driver uses
the form the CLI actually accepts, proven by a real spawn negative control. `multi_agent_v2` is already
`stable true` (0.147.0) — the item is pinning its typed-subagent tool schema in tests, not enabling it.
`--add-dir` replacement of the `writable_roots` TOML override is a VERIFY-FIRST step with a falsifiable
equivalence test (a fixture proving both produce the same writable set for a linked worktree); if it
cannot be proven, keep the TOML override and the test records the divergence.
