## Planner decision record

### P-01 — `--no-approve`, not `--approve` (the review's reversal)

`--approve` trusts project-local `.pi/extensions`, `.agents/skills`, settings, and packages, which
execute **unsandboxed** (Pi has no sandbox). A fresh worktree establishes no trust, so unconditional
`--approve` is unsandboxed code execution from repo contents — a security boundary, not a
convenience. The default is `--no-approve`. The cost (project AGENTS.md/skills are not loaded) is
recorded; a config-gated trust decision is a Phase 37 / follow-up item, not a silent default.

### P-02 — Health check is `pi auth check`, not env sniffing

`DEVFLOW_PI_PROVIDER` is a provider *name*, not a credential — codex verified
`DEVFLOW_PI_PROVIDER=google` with no key still returns `credentials_not_configured`. `preflight`
runs `pi auth check` (Pi's own verb) and maps `ready` → headless-capable, anything else → the
credentialless `Err`. "Binary absent" is not preflight's job — `ensure_agent_binary` runs first on
the start path; preflight only runs once the binary exists.

### P-03 — No model/provider wiring in Phase 36

Model/provider selection is **Phase 37** (the `AgentDriver` contract has the config access
`AgentAdapter` lacks). Phase 36 passes no `--model`/`--provider` — Pi uses its own defaults. This
avoids the volatile-env trap the review flagged (a CLI/env value disappears across detached-monitor
stage launches).

### P-04 — `--` delimiter is mandatory

The positional prompt can begin with `-` or `- [ ]` (markdown lists). A bare `--` before `<prompt>`
prevents pi's arg parser from reading prompt text as flags.
