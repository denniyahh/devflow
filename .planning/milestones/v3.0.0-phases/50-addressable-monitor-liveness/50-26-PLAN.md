<objective>
Close the one gap in `50-VERIFICATION.md` (criterion 4 partial; review finding WR-03, reproduced with a negative
control). Making the follow-up live attempt judgeable on its own was this plan's Task 3; plan-checker round 2 split it
into 50-27, which runs beside this plan in wave 18.

Today a stream supervisor waits twice after its agent exits, and both waits depend on the agent's stdout closing. When
a process the agent started still holds that stdout, `drive_stream_io` first waits one idle timeout of silence (120 s
or more), because it returns only at EOF or after the idle timeout. Then `run_supervised_stage` joins the reader thread
with no bound, so the supervisor stays ALIVE with owner `advancing` forever. It answers `shutdown` with `accepted` and
never carries the stop out. After a `kill -9`, the STALE backstop refuses, because the leader is already reaped.

After this plan, `drive_stream_io` ends when the agent process exits, and the stream threads are waited for at most
`READER_DRAIN_WAIT` (3 s) after that. Then the capture is closed and the bound is recorded as an event. Nothing is
signalled. A completed run reaches its advance, and a `devflow stop` taken then is honoured at safe point 1 (D-04, R-2).
A stopped run also finishes its stop.

Purpose: a stalled unattended run stays "recoverable by design" (the phase goal) when an agent leaves a process holding
its stdout. Per D-18 and the operator's 2026-10-21 ruling, live attempt 2 (50-28) then runs on the fixed binary, and
50-27's `--attempt-gate --current-source` is what tells that attempt apart from attempt 1.

Output: the fix in `monitor.rs` with core tests A, B, C, D, F and G, e2e tests E1-E3, and a revert-check script and its
run.
</objective>

**Decision recorded (Claude remit, planner; the gap's design latitude; reversible):** end the stream loop at the
agent's exit, then bound the thread wait, for both outcomes. Signal nothing. Keep the pipe drained while the supervisor
lives. Rejected alternatives:
- (a) Bound only the join, as this plan's first version did. A completed or stopped run with a held stdout would still
  wait one idle timeout or more in `drive_stream_io` before the bound starts (agy-1). That outlasts `devflow stop`'s
  22 s final wait, and when the close rule has not fired it writes an idle-timeout verdict for a run that was stopped
  or completed.
- (b) End the group's leftover members in `observe_exit` for a `Completed` run. It cannot reach a holder outside the
  group, and killing leftovers on every normal completion is backlog 999.164 item 5's open decision.
- (c) A poll-based cancellable reader. It would rewrite the reader loop, whose lossy decoding two peer-review fixes
  pinned.
- (d) Drop the read end at the bound. A leftover that keeps writing would get SIGPIPE while the supervisor still runs
  (agy-2). Draining to nothing costs one blocked thread until the supervisor exits.

## What this plan does not establish

- **No live run exercises the fix yet.** Live attempt 1 predates it, as it predates CR-01's fix. 50-28 runs attempt
  2 on the fixed binary, with the fault arm on that binary. Until then `--fault-current` reads `dir=ABSENT`, on purpose.
- **A stream now ends at the agent leader's exit, not at stdout EOF** (plan-checker round 2, INFO 6). A launcher whose
  leader process exits before the children it started finish writing the agent's output would lose whatever they
  write more than 3 s later: the capture is closed at the bound, and the stage is judged on what arrived before. No
  current stream-shape agent is known to do this. Checked on this host while planning: `claude` resolves to a native
  ELF binary (no wrapper process); the `agy` wrapper is a bash script whose one command `exec`s
  `mise exec … -- antigravity-cli`, so the wrapper does not stay behind as a separate leader. Whether `mise exec` and
  `antigravity-cli` then exec or wait on a child was not checked; either way neither exits before the process it
  started, which is the case that would lose output. A future launcher that forks its writer and exits early would.
- **The 3 s bound is not a measured need.** When the bound starts, the agent has exited. Its own output is already in
  the pipe, and the reader drains it in milliseconds unless the machine is stalled. A holder's output after the bound
  is discarded. This rests on reading the code and on tests A-F, not on a measurement under heavy load.
- **After the supervisor exits, a leftover that writes to the agent's old stdout gets SIGPIPE or EPIPE** from the
  kernel. That is the pipe's semantics; DevFlow sends nothing. The alternative before this fix was a supervisor that
  never exited.
- **Detached threads live until the supervisor exits.** A silent holder leaves the reader blocked in `read(2)`. A
  holder of the agent's stdin can leave the writer blocked in `write(2)`, and that stdin then never sees EOF. That is at
  most two threads and two pipe ends per stage, released when the `__monitor` process exits after its advance. The
  advance can include a gate wait of days.
- **A stop honoured at a safe point is not criterion 4's full contract.** No group is killed, because the agent has
  already exited. The exit file keeps the agent's code while the `stopped` line reports 143 (999.166 item 6, IN-03
  class, widened by 50-29 to name it), and in-group leftovers keep running (999.164 item 5). WR-01 also stays open:
  long stretches with no safe point, such as the advance's lock wait of up to 600 s, still outlast `devflow stop`'s
  22 s wait.
- **The idle timeout can still fire in the same instant the agent exits.** This race predates the fix and was not
  measured.
- **E3 uses `devflow stop`'s no-record sweep arm**, because the fixture runs `__monitor` directly. The recorded-socket
  arm makes the same `request_shutdown` call and is covered by `stop_e2e`.
- **The revert check runs the debug test build,** not a release binary. A release binary has no test-support hold,
  so it cannot run E2 or E3.
- **macOS: compile only.**
