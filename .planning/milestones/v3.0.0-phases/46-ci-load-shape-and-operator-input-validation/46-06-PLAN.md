<objective>
Replace process-global `PATH` emptying with a child process, and prove the replacement hides `git`
before anything depends on it.

Purpose: C-01 found that `d525f9a` closed 47 of at least 78 exposures — tests reaching git through a
helper were never matched, so the commit message's "fixed as a class" is false. The operator's
disposition rejects widening the `env_lock` sweep and requires removing the hazard instead: run the
window in a child process, where an emptied `PATH` is invisible to every sibling test. This plan
builds the mechanism and migrates the two sites outside `pipeline_outcomes.rs`; 46-07 migrates the
remaining five and deletes `NoGitPath`; 46-08 reverts the 47 lines that are then unnecessary.

Output: a three-function helper in `test_support.rs`, its own both-directions proof, and the
`pipeline_launch.rs` site migrated.
</objective>

Add three items to `crates/devflow-cli/src/test_support.rs`, in the `#[cfg(test)]`-reachable
`pub(crate)` surface alongside `NoGitPath`:

1. A constant naming the child-mode environment variable, e.g. `DEVFLOW_CHILD_NO_GIT_ROOT`. One
   shared name is correct rather than a per-test constant: each child runs exactly one test, so
   there is nothing to disambiguate. Document that a hand-exported value puts a test into child

   `std::env::set_var`.

4. `assert_child_ran_exactly_one_passing_test(out: &std::process::Output, test_name: &str)` —
   asserts `out.status.success()`, that stdout contains `test {test_name} ... ok`, that it contains
   a `1 passed` summary, and that the `filtered out` count parsed from the summary is greater than
   zero. Print the child's full stdout and stderr in every failure message; a child failure is
