<objective>
Make `devflow stop` take its project root the way the rest of the CLI does, so that a wrong root
reads as "stop rejected my input" instead of "stop did not work".

Purpose: `stop` is a RECOVERY verb — it is reached for when something has already gone wrong. Today
`devflow stop --phase 7 .` dies in clap with a usage error that names no offending argument, which
is exactly how it read during the #200 reproduction. `start`, `resume`, `status`, `ship` and
`approve` all take a positional `[PROJECT]` with `default_value = "."`; `stop` is one of three
holdouts. The fix is three lines of source: two fields on the variant, one dispatch expression.

Output: a `Stop` variant whose shape is identical to `Resume`/`Status`, five new e2e cases plus one
extended one in `stop_e2e.rs`, and a corrected `OPERATIONS.md` signature row.

**Phase tracer note:** this phase's `type="tracer"` slice is Plan 01's Task 1 — the CPU-pin
definition site wired from the local gate through CI to an in-tree guard, the phase's only
architectural bet. Plans 02 and 03 are independent surfaces with proven in-file analogs and both
lead RED-first under TDD mode. Stated so the shape is a decision, not an oversight.

**Why `type: tdd` and not `type: execute`.** The clap edit itself is glue, which argues for
`execute`. D-13 is not glue: it is a defined-I/O behavioural contract (`argv` in, exit code and
stderr out) with a measurable before/after, and the failing-direction contract for this phase is
literally that the new cases must be shown to fail before `main.rs` changes and pass after.
Landmine 2 — a bare `!success()` passing in BOTH directions — is precisely the failure a
GREEN-first plan would ship without noticing. RED-first is what forces the stderr assertion to
exist. Task 3 (docs) carries `type="auto"`: there is nothing to red-green about a table cell.
</objective>
