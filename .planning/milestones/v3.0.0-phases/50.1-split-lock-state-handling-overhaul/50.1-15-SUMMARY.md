# Phase 50.1 Plan 15: Delete the Unkeyed Gate API Summary

**The single per-stage answer slot now exists only as something to set aside: nine `Gates` functions and the transition bridge are deleted, `GateFile.gate_id` is required, and `recover` quarantines an unconsumed answer instead of deleting it.**

## Accomplishments

- `Gates::{response_path, ack_path, respond, reap, poll_response, poll_response_cancellable, ack, cleanup, cleanup_with_partial_result}` are gone, with the bridge's unkeyed read, keyed sweep and `list_open`'s legacy-hiding clause.
- A gate file with no `gate_id` no longer parses. `list_open` logs a warning and skips it, because the listing would otherwise drop it silently.
- `write_gate` is `open_gate(..).map(|gate| gate.path)`.
- `recover`'s `remove_gate_files` closes each stage through `close_with_partial_result`. The "a failed gate removal keeps the state" order is unchanged.
- No CLI code named a deleted function. Only comments had to change there.

## Decisions Made

- `recover` treats a set-aside answer as removed from the live files, so `clean_phase_report` cannot say "nothing to clean" after moving one (48-REVIEW WR-03's concern). The orphan sweep's `orphan_gates_cleared` follows the same count.
- A gate file naming an empty or malformed id stays listed. It parses, and `a_gate_with_no_gate_id_is_reported_and_never_answered` pins the CLI's report-only handling. The must-have is about a file with no id, which is what the test covers. Its doc comment now says "an empty id".

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A close did not report removing a legacy ack**
- **Found during:** Task 1
- **Issue:** The old `cleanup` counted a lone legacy ack as removed, and `close` did not. Moving `recover` onto `close` would have made a clean remove the file and report nothing done.
- **Fix:** The private disposal now returns whether it removed a legacy ack, and `close` adds that to `report.removed`.
- **Verification:** `close_removes_a_lone_legacy_ack`, and the control above
- **Committed in:** `4bbbbd4`

**2. [Rule 2 - Missing critical] `list_open` would have dropped an id-less gate silently**
- **Found during:** Task 1
- **Issue:** Requiring the id makes a formerly listed file disappear from every listing.
- **Fix:** `list_open` logs a `warn!` naming the file and the parse error. No test asserts the log line.
- **Committed in:** `4bbbbd4`

**3. [Rule 2 - Missing critical] The quarantine count in `recover` had no test**
- **Found during:** self-review after Task 2
- **Fix:** Added `clean_phase_report_counts_a_lone_answer_it_set_aside`, and showed it fails without the count.
- **Committed in:** `e110dd6`

### Other departures

- **Task 1's commit holds the core test migration the plan lists under Task 2.** Task 1's own gate needs the core test modules to compile. Task 2 kept the integration fixtures and the workspace build.
- **`test_support.rs` (core) went into Task 1's commit** for the same reason.
- **Comments in files outside `files_modified`:** `crates/devflow-cli/src/config_parse.rs`, `crates/devflow-cli/src/test_support.rs` and `crates/devflow-cli/tests/stop_e2e.rs` named a deleted function, so those comments now name its replacement. No code changed there.
- **`gate_sweep_e2e`'s gate file needed no id added.** The plan read it at an older commit. `backdate_gate` now round-trips a `GateFile`, so the id survives, and that fixture is unchanged apart from a comment.
- **The test's keyed answer in `decimal_phase_paths`** uses a fixed id, `0123456789abcdef`, in place of the unkeyed name.

**Total deviations:** 3 auto-fixed (1 bug, 2 missing critical). **Impact:** all follow from moving `recover` to `close` or from making the id required. No scope added beyond that.
