<objective>
Move the state writes of the two pipeline files that own gate waits, transitions and launches onto `update_state`
through one CLI helper (D-08), closing the lost update across a gate wait.

Purpose: today `run_gate_with_timeout` saves the copy it loaded before a multi-day wait, merging back only
`gate_notify_cmd` (WR-10), so a `stop` or a `yes_ship` revoke written during the wait is overwritten. With every write a
re-read field delta, that cannot happen. The long per-phase lock is untouched here (50.1-16, -19, -20 remove it);
writes now take the short write lock as well, never while waiting for the long one. 50.1-11 migrates the remaining
three files and adds the scan. It runs after 50.1-08 because 08 rebuilds the poll loop this plan's gate-wait tests
wait on (backoff reads at 0 s, 1 s, 3 s …); written against the old loop, those tests' answer timing would be wrong after
the merge.
Output: `pipeline_launch::commit`; every save site in the two files migrated; V-12 and V-13 tests.
</objective>
