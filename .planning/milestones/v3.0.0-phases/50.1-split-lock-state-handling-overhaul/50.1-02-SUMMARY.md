# Phase 50.1 Plan 02: Accept Backoff and Zombie-Safe Probe Summary

**An EMFILE on the supervisor's control socket now costs 7 accept attempts a second instead of 654,532, and the last `kill(agent, 0)` liveness probe in the publish-failure test is replaced by `process_is_live`, with a subreaper control showing why.**

## Read this first

**The plan's premise for item 9 is wrong for the test it names.** The plan says a failed publish leaves an orphaned agent that becomes a zombie. On the path `a_supervisor_that_fails_to_publish_ends_its_agent_group` exercises, it does not: `AgentGroupGuard` reaps the agent itself. I ran that exact path under the subreaper, and `kill(agent, 0)` returned -1 (agent already gone), so the old probe was never fooled on that path. The swap is hardening, not a fix to a live false reading.

The zombie control therefore uses `kill_before_publishing`, a different way of failing to publish, where the supervisor is SIGKILLed first and the launcher ends the agent through its sidecar. That path does produce the zombie. See Deviations.

## Item 9 controls

The old probe is shown blind by the in-test `kill(agent, 0) == 0` assertion, which passes on the zombie after `process_is_live` has reported it gone. The other direction and the fixture were checked by temporary edits, all restored:

| Temporary edit | Test | Exit | Shows |
|----------------|------|------|-------|
| No `PR_SET_CHILD_SUBREAPER` call | zombie test | 100, `kill` returned -1 | The subreaper is what keeps the zombie: without it another process reaped the agent |
| Symlinked `sock/` publish error instead of `kill_before_publishing` | zombie test | 100, `kill` returned -1 | The guard reaps the agent on that path, so no zombie exists there |
| `AgentGroupGuard::drop` kills and reaps nothing | `a_supervisor_that_fails_to_publish_ends_its_agent_group` | 100, `no agent survives a publish error: 866095 is alive` | The swapped probe still catches a live survivor |

**Leftovers.** The zombie test ends by asserting `waitpid(-1, WNOHANG)` returns -1, so its child process has nothing left to reap. Using `waitpid` here replaces the plan's `pgrep -P` example, since the test pid is gone by the time an outside check could run. After the final runs, `ps -eo pid,args` showed no `sleep 300` process.

## What this does not establish

- **No real EMFILE was produced.** The test injects the error through the seam, on a real listener with a real pending client. Running a process out of descriptors was not tried.
- **CI's `--init` reaper is not exercised.** The subreaper stands in for a non-reaping PID 1. This shows the probes differ on a zombie, not how a CI job behaves.
- **The ping delay is reasoned, not measured.** The doc comment says pings, stop requests and the quit flag wait at most the 1 s cap during an EMFILE. It follows from the code (one thread, one sleep at a time); no test times it.
- **The 7-attempt figure is one run on this host.** The test's limit of 25 is what is enforced.

## Decisions Made

See `key-decisions` in the frontmatter.

The new zombie test does call `kill(agent, 0)`, once, as the negative control the plan specifies. Nothing in the repo uses that call to decide whether the agent is live in this test, so the plan's prohibition on new `kill(pid, 0)` liveness probes holds.
