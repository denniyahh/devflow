## Accomplishments

- **The fence.** `commit`, the pending record and the promotion are owned writes inside a supervisor's advance. `fenced` runs `open_registered`, the auto-answer, `set_aside_unbound`, `claim` and `close` inside `workflow::while_owner`. A hand-run `advance` and the foreground `devflow ship` stay unfenced.
- **The promotion watch.** It starts when the supervisor serves and runs beside the agent. Only pending means wait. A superseded or orphaned verdict while the agent runs ends the agent's whole group.
- **R-13.** `end_group_while_running` signals only while the owner phase is `AgentRunning` and `agent_exited` is false. `Control::stop` shares its SIGKILL step.
- **D-08.** `ADVANCE_LOCK_WAIT`, `LAUNCH_RECORD_WAIT`, `wait_for_launch_record` and `advance_with`'s `lock_wait` are gone, and `record_supervisor_stop` waits only for the write lock.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] A superseded supervisor still ran finalization hooks**
- **Found during:** review after Task 3
- **Issue:** the fence covers state and gates, and a hook batch runs before the next fenced step. RED: superseded at `before_finalization`, it merged and removed the feature branch before `clear_state_if_owned` refused it.
- **Fix:** `ensure_still_recorded` before the batch in `transition` and in each finalization loop pass. It is a check and not a fence, because D-08 forbids holding the write lock across a hook. A supersession landing after the check is not seen until the next fenced step.
- **Files:** `pipeline_gate.rs`, `pipeline_launch.rs`. **Commit:** `9019fc4`

**2. [Rule 1 - Bug] A stop would have sat out the promotion deadline**
- **Found during:** Task 1
- **Issue:** the plan joins the watch after `wait_agent`, "by its deadline at the latest". A stopped pending supervisor would then hold back its final `stopped` line for up to 15 s, the same as `SUPERVISOR_STOP_WAIT`, so safe point 3's shutdown could read as unconfirmed.
- **Fix:** a stop tells a watch with no verdict to quit, and the verdict is `None`. A completed agent with a stop flagged and no verdict ends as a stop. Test: `a_stop_ends_the_promotion_wait_of_a_supervisor_whose_agent_finished`.
- **Commit:** `ab05f8a`, `81c6771`

**3. [Rule 1 - Bug] `abort` and failure paths lost or outran the refusal**
- **Issue:** `abort` ignored errors, so a superseded supervisor would have deregistered the phase and emitted `workflow_aborted`. `spawn_agent_and_record` and `shut_down_unrecorded` wrapped `NotOwner` in a message, which `run_monitor` could not recognise.
- **Fix:** `is_not_owner` lets the refusal through as itself. A superseded launcher still ends its unpublished next supervisor through its socket. Tests: `a_superseded_launcher_promotes_nothing_and_ends_its_unpublished_next`, `a_superseded_launcher_spawns_nothing_and_gives_its_reservation_back`.
- **Commit:** `e78454b`, `f7c6434`

**4. [Rule 3 - Blocking] Fixtures that start a supervisor the state does not name**
- **Issue:** with the watch, such a supervisor reads superseded at once and ends its agent. `PublishFixture` and three e2e files outside the plan's list were affected. The first `check.sh all` caught the auto-chain pair.
- **Fix:** `PublishFixture` names its launch as pending, as a launcher does. `supervisor_e2e`'s `HeldStdoutRun`, `auto_chain_flag_e2e` and `auto_chain_leak_repair_e2e` seed a record naming the launch. The last clears that record after its SIGKILL, because `resume` would otherwise refuse over the STALE socket, which is not what that test is about.
- **Commit:** `b9f87ae`, `18a2954`

**5. [Rule 3 - Blocking] Smaller shape changes**
- `StageRun.agent_group_end`, not in the plan: the watch ends the group, so a later `end_agent_group` would report `already_exited` and V-27's `agent_group: "ended"` could not be told.
- `save_successor_stop` splits off `publish_record`'s second write, and `save_publish_fields` no longer writes `stopped`.
- `launch_parked_at_gate` was rewritten in Task 2, not Task 3, because V-23 and the R-09 test use it.
- `stop_waits_out_...` holds the write lock from a thread in the test process rather than a child process. `flock` is per open file description, so the supervisor still blocks on it, and the `stop` child's copy closes on exec.
- `commands.rs`: `shutdown_final_timeout`'s doc named the per-phase lock.
- `Gates` import moved into the test modules of `preflight.rs` and `pipeline_outcomes.rs`, because their production code no longer calls it.

## Not established

- **The 15 s release wait has no live test.** V-24, V-27 and their controls run the test build's 5 s. Only the margin arithmetic pins 15 s, and the e2e suites use the real binary only on paths that are promoted at once.
- **The tests do not show the watch under a slow machine.** 80 of 80 over 8 runs on an idle machine is a weak bound. A loaded CI runner that delays a promotion past 5 s would fail V-24 or the promoted control, by R2-09's design. Watch for it in CI.
