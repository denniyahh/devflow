## Why the credential scan decodes JSON (measured 2026-09-28, before this plan was revised)

30c's `credential_named_assignment` (`30c-monitor-env-harness.py:584-601`) applied to the raw text of the 12 real
DevFlow Code-stage captures under the main checkout's `.devflow/history/phase-43/` hits 30, 23, 4, 7, 9, 4 and 2 times
in 7 of them. Classified by character-class shape only (values were never printed), no hit has a credential shape:
usage counters such as `raw_tokens` or `tokens` followed by stream-json's escaped newline (which defeats 30c's
bare-number exemption), `********` placeholders, regex fragments and short words after names such as `key`,
`key_links`, `value_token` and `secrets` in echoed plan and source text. 30c only ever applied that pattern after its structural redactor; this tool scans the
raw source first and refuses, so 30c's pattern would refuse every real Code capture 49-12 must publish. The pattern set
Task 2 specifies — 30c's three prefix patterns unchanged, plus a named assignment or named field whose value is at least
20 characters of `[A-Za-z0-9_+/=.-]` holding a letter and a digit, all run on JSON-decoded strings — hit 0 times on those
12 files and on the 5 captures under `.devflow/history/phase-900/`, and caught all three credentials planted into the
largest capture (a `gh` token, an `API_KEY="…"` assignment inside a JSON-escaped string, and a structural
`"api_key": "…"` field). The same narrowed pattern run on the raw text missed the escaped assignment: decoding is what
gives both the precision and the recall.
