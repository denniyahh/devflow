## Warnings

### WR-01: Tests do not enforce the budget's documented constraints (pre-existing scaffold)

**File:** `tests/test_budget.py:5-11`
**Issue:**
- `OFFERED_BUDGETS = (30, 120, 300)` is accepted wholesale.
- The comment in `probe/budget.py:3-4` says 30 (below the 90 s failover) and 300 (above the 240 s pager) are wrong choices.
- Tests pass for all three values, so they cannot catch a regression to a wrong-but-offered value.
- `test_deadline_adds_the_budget_to_the_start` recomputes the same formula it checks (`10.0 + DEFAULT_RETRY_BUDGET_SECS`), so it passes for any constant.
- This file is scaffold the plan forbids editing, so treat it as a plan-level gap rather than an implementation defect.

**Fix:** Add a constraint test in a new file, since the existing one must not be edited:
```python
def test_budget_between_failover_and_pager(self) -> None:
    self.assertGreater(DEFAULT_RETRY_BUDGET_SECS, 90)
    self.assertLess(DEFAULT_RETRY_BUDGET_SECS, 240)
```

## Info

### IN-01: `deadline_after` accepts any float and does not name its clock

**File:** `probe/budget.py:8-10`
**Issue:**
- `deadline_after(float("nan"))` returns `nan`, `deadline_after(float("inf"))` returns `inf`, and negative starts are accepted.
- The docstring says "start time in seconds" but not which clock. Mixing `time.time()` and `time.monotonic()` would silently give wrong deadlines.
- BUDGET-01 specifies the plain sum, so this is not a bug against the requirement.

**Fix:** Name the clock in the docstring (for example, "must use the same clock the caller compares against, normally `time.monotonic()`"). Optionally reject non-finite input.

### IN-02: `tests/` has no `__init__.py`, so test discovery depends on the working directory

**File:** `tests/test_budget.py` (pre-existing scaffold)
**Issue:**
- `from probe.budget import ...` only resolves when the repo root is on `sys.path`.
- `python3 -m unittest discover -s tests` works from the repo root.
- Running it from another directory, or with `-I` plus `-t .`, fails.
- `devflow.toml` also has a bare `capture_retention = 64` with no explanation. This is scaffold and I did not verify what reads it.

**Fix:** Document the required invocation (run from the repo root) in the plan or README. Add `tests/__init__.py` only if more invocation styles are needed.
