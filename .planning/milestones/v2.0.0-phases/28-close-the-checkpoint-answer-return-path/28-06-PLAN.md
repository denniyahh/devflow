<objective>
Let `yes_ship` be set once in a project's config instead of retyped on every
invocation, while keeping every guarantee that made it a per-run flag in the
first place.

Purpose: D-12 is a deliberate, twice-confirmed reversal of Phase 23's own D-05
("`--yes-ship` is a per-run flag only — never config-persistable ... so a
standing unattended auto-merge can never become the silent default"). Phase 23
flagged this exact reversal as the costly direction and it was adopted anyway.
This plan implements the reversal AND the compensating control that keeps its
own stated risk addressable: a persisted authorization that announces itself on
every run it applies to is a standing default, but not a silent one.

D-13 is explicitly unaffected — the Ship gate still fires, is still answered
through the normal protocol, and is still attributed in the ledger. Only the
provenance of the value changes.

Output: a `yes_ship` config key with the project's standard env-over-file-over-
default precedence, an OR-combine at the single existing assignment site, and
tests at the library and CLI boundaries.
</objective>
