<objective>
Stop `devflow resume` from silently discarding a `--until` cap that never fired.

Purpose: `resume()` clears `stopped`, `stop_reason`, and `stop_until`
unconditionally (pipeline_launch.rs lines 226-228). That triple clear exists for
the case it was written for — a phase halted BY the cap, where leaving
`stop_until` set would immediately re-stop the phase the operator just asked to
resume. But `resume` is also the recovery verb for a rate-limited or
infra-paused phase, and in that case the cap has not fired yet: the operator
said "run to Plan and stop", the run paused at Code for an unrelated reason, and
resuming wipes the halt they asked for. The run then sails past the stage they
capped, with nothing in the record saying it was ever discarded. Gating the clear
on `state.stopped` is the whole fix.

Output: a conditional clear, plus a regression test proving the unfired case is
preserved alongside the existing test proving the fired case still clears.
</objective>
