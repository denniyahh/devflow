<objective>
Capture the two runtime facts D-01's confirmation step and D-04's relaunch need,
and give them somewhere durable to live: the Claude session id, and whether the
agent actually reported a human-blocking checkpoint.

Purpose: D-04's relaunch cannot address a session it cannot name, and D-01's
confirmation cannot distinguish "this failure IS the declared checkpoint" from
"an ordinary failure in a phase that happens to declare one somewhere" without
reading the field the executor emits. Both values are read from a capture file
`evaluate_layer1` already reads; neither requires new invocation plumbing.

Output: four pure-plus-thin-wrapper reader functions in `agent_result.rs`, and
two backward-compatible persisted fields on `State`.
</objective>
