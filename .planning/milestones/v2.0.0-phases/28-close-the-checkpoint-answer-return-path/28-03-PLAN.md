<objective>
Close the loop: recognize a confirmed human-blocking checkpoint and let DevFlow
resolve it unattended by resuming the session that raised it, recording what was
decided.

Purpose: this is the phase's reason to exist. A human-blocking checkpoint (a
task whose `gate` attribute carries the human-blocking value) is currently a
dead end for any DevFlow-driven run — the agent stops
and asks, no answer can reach it, and every retry spawns a fresh process that
asks the identical question. D-03 settles the policy (the agent decides, always,
no toggle — because no usable notification/response channel exists to degrade
gracefully onto, and a flag implying a working "off" state would be misleading).
D-04 settles the mechanism (resume the exact exited session). D-07 settles the
accountability (record it, unconditionally, because with no flag and no human
beforehand, that record is the only way anyone learns what the agent decided).

This plan deliberately overrides `checkpoints.md` rule 6, a GSD-core-wide
invariant, applied unconditionally rather than as an auto-mode exception. That
override was adopted after two rounds of explicit operator pushback — including
the Phase 26 near-miss, where a mistagged gate would have silently authorized a
crates.io publish — and reaffirmed both times. It is not re-litigated here.

Output: the resume primitive, the synthesized instruction, the bounded relaunch
path, the audit event, and the dispatch guard that makes all of it reachable
only under the conditions D-01 defines.
</objective>
