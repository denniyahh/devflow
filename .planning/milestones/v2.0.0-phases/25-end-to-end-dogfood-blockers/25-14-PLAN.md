<objective>
Make 25a's repair mechanism safe. `ensure_base_ref_current`'s `Behind` arm currently advances the
local base branch with an unconditional ref write, guarded by a precondition that can only see one
worktree. Both defects are in the same function and neither is visible from its call site.

Purpose: 25a exists because a human previously had to repair the base ref by hand before `devflow
start` would launch. A repair path that can itself move the base ref backwards, or move it out from
under a live linked worktree, does not close that requirement — it adds a second, silent way to
reach the same broken state. This plan makes the fast-forward conditional on the state that was
actually validated, and makes its "not checked out" precondition mean what it says.

Output: a compare-and-swap fast-forward, a repository-wide checked-out predicate, two new
regression tests (one per defect), and a doc comment that no longer argues the old design was safe.
No behavioural change to any other arm and no change to the call site.
</objective>

<resolved_decision>
## Compare-and-swap PLUS a repository-wide scan — not `git branch -f` alone

`25-VERIFICATION.md`'s `missing` list offers two alternatives for the checked-out defect: a
repository-wide `git worktree list --porcelain` scan, **or** attempting `git branch -f <base>
<remote_ref>` first, since that command already refuses on its own when the branch is checked out
in any worktree. `25-REVIEW.md`'s CR-02 makes the same offer.

**Ruling: the repository-wide scan, combined with a compare-and-swap `git update-ref`. Not `git
branch -f`.**

`git branch -f` solves exactly one of the two defects. It has **no `<oldvalue>` parameter** — there
is no form of `git branch -f` that refuses when the branch is not where the caller expected it to
be. Choosing it would close the checked-out defect and leave the lost-update defect open, and this
gap is one function with two defects, not two functions with one each. `git update-ref <ref> <new>
<old>` is the only ref-write in git's plumbing that is a compare-and-swap, and it is the only
mechanism that makes the write conditional on the state `base_ref_currency` actually validated.

Since the compare-and-swap is therefore mandatory, and `git update-ref` carries no
checked-out-branch protection at all, the repository-wide predicate must be built explicitly. It is
built from `git worktree list --porcelain`, whose output is a stanza per worktree in which an
attached worktree emits a line reading exactly `branch refs/heads/<name>` (a detached worktree emits
`detached`, a bare main repository emits `bare`). Confirmed against this repository at plan time.

**Deliberate conservatism:** a worktree stanza carrying `branch refs/heads/<base>` refuses, even if
that stanza is also marked `prunable` (its directory has been deleted but not yet pruned). That
matches git's own `branch -f` behaviour, which also refuses for a registered-but-prunable worktree,
and it errs toward refusal — which in this function costs one operator-visible refusal message
carrying an exact repair command, not a corrupted ref.

**Residual, stated not hidden:** there is a window between the scan and the compare-and-swap in
which a worktree could check out `<base>`. This is not eliminated. Two subprocess invocations bound
it, the compare-and-swap still prevents a lost update inside it, and the only alternative that
closes it (`branch -f`) reopens the larger defect. This residual is recorded in `must_haves.truths`
as a backstop and must appear in the function's doc comment.
</resolved_decision>
