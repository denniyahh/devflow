<objective>
Close GAP 1 of `25-VERIFICATION.md`: truth 4 — "a major version bump opens a gate and
never ships unattended, **in the default (worktree) execution path**" — is FAILED.

Two independently source-confirmed Critical defects (CR-01, CR-02 in `25-REVIEW.md`,
re-confirmed by the verifier from source) mean D-09's headline contract is not delivered
in `devflow start`'s DEFAULT mode (`worktree = true` unless `--no-worktree`):

- **CR-02 (scope):** `preflight_major_bump_check` always shells git against `project_root`.
  In the default worktree flow the phase's own commits live only on the worktree's feature
  branch and are unreachable from `project_root`'s HEAD until `hooks_after_ship`'s Merge
  step — which runs AFTER this preflight. A `feat!:` commit made during Code is therefore
  invisible to this gate and is first classified inside `VersionBump`, after Merge has
  already committed, with no rollback.
- **CR-01 (composition):** `generic_preflight_checks` `?`-chains its three checks. If
  gh-auth fails first, the major-bump check never executes at all; approving that gh-auth
  gate via `GateAction::Advance` calls `launch_stage_inner` directly and never re-runs
  `generic_preflight_checks` — so a check that never ran once is never run at all for that
  stage launch.

Both existing integration tests use the no-worktree `major_bump_fixture`, the one fixture
shape where neither defect can manifest.

Purpose: make D-09's gate actually fire in the mode this project actually runs in.
Output: a worktree-scoped major-bump check, a non-short-circuiting check chain, and two
regression tests over real-git fixtures that structurally could not have passed before.
</objective>
