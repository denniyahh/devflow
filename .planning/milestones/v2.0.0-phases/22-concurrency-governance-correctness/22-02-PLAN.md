  <behavior>
    - A phase summary retains its latest event and its newest valid ts from any stage_launched event.
    - A later non-stage_launched event does not clear the earlier launch timestamp.
    - Multiple stage_launched events select the newest matching timestamp.
    - Corrupt lines, missing files, missing timestamps, and phases without launches are ignored without changing existing fail-soft behavior.

    Keep the single read_to_string and single line parse pass. For every valid
    event, continue overwriting the latest-event field by append order; when
    event is stage_launched and ts is a valid u64, update only that phase's
    timestamp when it is newer. Do not derive the timestamp from the latest
    event, change invalid-line handling, add a second helper that rereads the
    file, or change the public behavior of last_event_for_phase beyond any
    necessary compatible adaptation. Update the existing core one-pass test
    to assert both latest-event and timestamp facts, including a later
    non-launch event and corrupt-line coverage.
  </action>
