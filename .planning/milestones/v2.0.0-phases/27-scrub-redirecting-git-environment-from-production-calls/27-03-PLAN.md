<objective>
Migrate `devflow-core`'s remaining two git-calling modules: the ten sites in
`version.rs` and the three in `agent_result.rs`.

Purpose: these two modules answer questions whose wrong answers are consequential
in different ways. `version.rs` derives the next release version from the
repository's tags and commit history — a `GIT_DIR`-retargeted read produces a
version number computed from a stranger's tags, which then gets written to
`Cargo.toml`, tagged, and published. `agent_result.rs` decides whether an agent
actually did the work, by checking that a branch exists and counting commits — a
retargeted read can manufacture a passing verdict out of an unrelated
repository's branches.

Output: zero unscrubbed production git invocations in either file.
</objective>

## Shared recipe: the hostile-`GIT_DIR` harness

```
HOSTILE=$(mktemp -d) && git init -q "$HOSTILE"
GIT_DIR="$HOSTILE/.git" cargo test <scope>
```

A `test result:` line must actually print. A timeout, or a `0 passed` line
(meaning the filter matched nothing), is a FAILURE, not a pass. Never use a bare
`cargo test --workspace` under a hostile `GIT_DIR` — it does not terminate
(`27-RESEARCH.md` Pitfall 2).
