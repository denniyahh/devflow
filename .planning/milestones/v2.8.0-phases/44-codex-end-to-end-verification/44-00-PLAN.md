      and legacy compatibility tests.
    - `crates/devflow-core/src/recover.rs` — its direct `delete_cron_instructions` call sites. They
      are intentionally out of scope: cleanup remains a reset path (D-19).
    - `44-CONTEXT.md` D-15 through D-19 — especially the requirement to report legacy path kind only
      when it is knowable.
  </read_first>

  <behavior>
    - `consume_cron_instructions_deletes_per_phase_record`: a per-phase record only is deleted and returns `Ok(Some(PerPhase))`.
    - `consume_cron_instructions_deletes_matching_legacy_record`: a valid legacy record naming this phase only is deleted and returns `Ok(Some(Legacy))`.
    - `consume_cron_instructions_reports_both_deleted_records`: matching per-phase and legacy records are both deleted and return `Ok(Some(Both))`.
    - `consume_cron_instructions_preserves_foreign_legacy_record`: a valid legacy record naming another phase returns `Ok(None)` and remains on disk.
    - `consume_cron_instructions_preserves_unreadable_legacy_record`: an unreadable legacy record returns `Ok(None)` and remains on disk; its ownership is unknown,
      so a consumption path must not delete it or claim that it consumed it.
  </behavior>

  <action>
    Write the five unit tests above first and observe that the new symbol is absent before adding it.
    Then add a public `CronInstructionPathKind` result type and a public
    `consume_cron_instructions(project_root, phase) -> Result<Option<CronInstructionPathKind>, ShipError>`
    helper.

    The helper owns the record-inspection policy. It must identify per-phase and legacy records,
    delete only records that are demonstrably for `phase`, and return `Some(kind)` only after every
    matched record was deleted. If no phase-owned record exists, return `Ok(None)`. If a filesystem
    deletion fails, return `Err`; callers must not emit an audit event on that result. Do not expose
    `legacy_cron_instructions_path` outside `devflow-core`, and do not change
    `delete_cron_instructions` or either `recover::clean` call site.

    The `Both` variant is required: collapsing two deletions into `PerPhase` would make D-18's audit
    record false. An unreadable legacy file is deliberately not consumed in this new path; existing
    recovery cleanup behavior remains unchanged and is covered by 44-02.
  </action>
