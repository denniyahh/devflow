### Carried research assumptions relevant to this plan

- **A1 — THE load-bearing one.** The exact stdout shape of `opencode providers list` on a machine with
  ZERO configured credentials was never observed. Does it omit a section entirely, print `0 credentials`,
  print nothing, or something else? No destructive test against a credential-less machine was performed
  (D-08 states this explicitly). Every live verification ran on a machine WITH credentials, so the
  negative case is unobservable without breaking real credentials. **If the real shape differs from the
  constructed fixture, `health` either false-greens — never refusing, defeating OPCD-03 entirely — or
  false-reds, refusing a correctly-configured machine.** Task 1 mitigates by summing count lines rather
  than pattern-matching a section header (a shape that returns 0 for an absent section, an empty section,
  and an explicit `0 credentials` line alike), but the mitigation is reasoned, not witnessed. Confirming
  this needs a genuinely credential-less environment: a scratch container, a CI runner, or a throwaway
  `HOME`/`XDG_DATA_HOME` override with no `auth.json` and no provider env vars. P-05 forbids reporting
  the negative path as live-verified until that happens.
- **A2** — `opencode auth list` is assumed byte-identical to `opencode providers list`. Low risk: this
  plan uses `providers list` directly, the form the live evidence is based on.
- **A4** — A dispatchable subagent's `opencode agent list` header line is assumed to take the form
  `<name> (<mode>)` with mode in `{primary, subagent, all}`. Derived from `opencode agent create --help`'s
  documented `--mode` choices plus one live baseline (`build (primary)`); no live capture of an actual
  configured subagent exists, because this machine has none. A substring match is somewhat resilient to
  spacing drift but is not proven against real subagent output. Fail-closed, so a miss costs a false
  `subagent_dispatch: false`, never a false `true` and never a refused launch.
