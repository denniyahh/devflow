# Phase 35.1 Plan 03: Unattended-Launch Preflight Summary

**An unattended launch is now refused, before any agent is spawned, when the GSD config cannot hold the chain flag, the Code stage would not launch on the pipe-owning arm, or a plan declares a checkpoint no mode auto-approves — with each of the three watched refusing a fixture built to make it refuse, and each paired with a passing counterpart one change away.**

## Needs your awareness — two capability removals this plan makes

Both follow directly from the plan's C2 ("the Code stage would launch on the pipe-owning arm — Claude, no legacy opt-out", must_haves truth #4), and both are subject to D-09's no-override rule. Neither is stated in those words anywhere in the plan, and both are user-visible:

1. **`--mode auto` is now Claude-only.** The chain-flag guard binds inside the pipe-owning monitor, which only the Claude stream path starts. A `--mode auto` run on `codex` or `opencode` is therefore refused at Define. Observed live: `parallel --phases 7,8 --agents claude,codex` had phase 7 pass all three conditions and phase 8 refused with *"the agent is `codex`, not claude"*.
2. **`--mode auto` combined with the legacy launch opt-out (D-11's escape hatch) is now refused.** This is Pitfall 4's gap becoming a refusal, which is the intent — but it means the two flags are now mutually exclusive.

A third, smaller one: **`--mode auto` now requires `.planning/config.json` to exist**, so an auto run in a project that is not GSD-configured is refused.

There is no override for any of these (D-09), and both external review lanes objected to that on record. This is the concrete instance count they were worried about: **nine in-repo test fixtures had to change** because they described auto-mode launches that are now refused. That is not a defect — every one of them was a genuinely NOT-viable unattended launch — but it is the best available evidence of how often the combination occurs in practice, and it is higher than "rare". 35.1-04's guide must state limitations 1 and 2 plainly.

### 4. The modified `generic_preflight_checks`, with the placement justification

```rust
fn generic_preflight_checks(project_root: &Path, state: &State) -> Result<(), String> {
    let mut reasons = Vec::new();
    if let Err(reason) = preflight_major_bump_check(project_root, state) {
        reasons.push(reason);
    }
    // D-07 (35.1-03) sits SECOND, and the position was chosen rather than
    // defaulted to. It can never co-occur with the major-bump or gh-auth
    // reasons — those apply only at `Stage::Ship`, and
    // `unattended_launch_check_applies` covers only Define and Code — so
    // second is effectively FIRST on every launch where this reason exists at
    // all, and `truncate_reason`'s 300-character cap cannot elide it.
    //
    // The one check it CAN co-occur with is interactivity (Codex, Auto,
    // Define), and it outranks that deliberately: interactivity reports a
    // symptom this check's C2 also reports, with more actionable detail and a
    // per-condition breakdown. Losing the shorter, more-redundant reason to
    // truncation costs less than losing this one.
    //
    // Aggregated with `if let Err`, never `?` — see this function's CR-01 doc
    // comment above. A `?` here would mean a human approving the major-bump
    // gate at some future Ship-and-Code-composing stage never sees why the
    // unattended launch was refused.
    if let Err(reason) = preflight_unattended_launch_check(project_root, state) {
        reasons.push(reason);
    }
    if let Err(reason) = preflight_interactivity_check(project_root, state) {
        reasons.push(reason);
    }
    if let Err(reason) = preflight_gh_auth_check(state) {
        reasons.push(reason);
    }
    if reasons.is_empty() {
        Ok(())
    } else {
        Err(reasons.join("; "))
    }
}
```

An `if let Err(...)` push, not a `?`.

## Decisions Made

Three inside the executor's own remit, beyond the key-decisions above:

- **`claude_stream_launch_enabled` widened to `pub(crate)`.** The plan's `key_links` require C2 to ask the launch path's own predicate rather than re-derive it, and the function was private. One keyword; no behaviour change. This is the one edit in `pipeline_launch.rs`'s non-test code and is the only merge-conflict surface with 35.1-02.
- **The report goes through a `&mut dyn Write` sink on an inner function**, so a test asserts on emitted bytes. `libc` is not a dependency, so in-process fd redirection was unavailable, and the alternative — asserting on a re-derivation of what the report ought to say — would have measured the test's own format string. The public check keeps the fixed `(&Path, &State)` signature D-09 demands.
- **The state label is carried into the refusal string.** `[DOES NOT HOLD]` and `[COULD NOT BE DETERMINED]` call for different operator actions, and a distinction observable only inside the module is indistinguishable from not having one.

### What this does NOT establish
