**A real `SIGKILL` is shown to leave GSD's `workflow._auto_chain_active` set — and the next real `devflow resume` is shown to clear it in the working tree, clear it at the branch tip with a scoped commit, refuse that commit when the file carries an operator's edit, and announce every repair on stdout and in `events.jsonl`.**

## Accomplishments

- **The leak is demonstrated, not assumed.** The plan's whole repair rests on the premise that `Drop` cannot cover a kill. That premise is now a measured assertion on a real killed process, marked in the source as the negative control for the entire plan.

## Decisions Made

Beyond the frontmatter's `key-decisions`, three were made inside the executor's remit:

- **The branch-tip probe reads `git diff --quiet`'s exit CODE, not just success/failure.** `Some(0)` agrees, `Some(1)` differs, anything else (128 for "not a repository" / "unknown revision", or a spawn error) is `Unknown` and sets `commit_refused`. A two-valued read would have folded every git failure into "agrees" and silently skipped the repair.
- **A `git show HEAD:<path>` that fails is a refusal, not a licence to commit.** It covers the case where the file is staged but not in `HEAD` — there is nothing to compare the remainder against, so the sweep guard cannot run and the commit is deferred.
- **The helper's unit-test fixture uses a minimal config shape, not the full `REAL_SHAPE`.** Byte-preservation across a write is already pinned by `gsd_config`'s own tests; repeating that fixture here would test the writer a second time rather than the helper.

## Deviations from Plan

**1. [Rule 3 — Blocking] Task 3's resume step runs against a git-only `PATH`, not a `FakeBin claude` with a rewritten stage**

- **Found during:** Task 3, designing step 5.
- **Issue:** The plan prescribed launching the real `devflow resume` with a `FakeBin` `claude` on `PATH`, having first rewritten the persisted stage to one `auto_chain_flag_eligible` does not cover. Two problems with that shape, both of which this repository has already paid for:
  1. A successful `resume` spawns a **detached** monitor. Its lifetime is not bounded by the test process, so the plan's own acceptance criterion ("no process outlives the test binary") would need a poll-and-kill loop around a process whose exit time depends on stage evaluation.
  2. Rewriting the stage to `Define`/`Validate` puts the relaunched stage's outcome through `handle_stage_failure` → `run_gate`, which BLOCKS. That is the exact wedge `CLAUDE.md` records from 35-02, and that 35.1-01 hit and had to design around.
- **Fix:** `resume` is run with `PATH` set (for the child process only, via `Command::env` — never a process-global `set_var`) to a temp dir containing a symlink to `git` and nothing else. `launch_stage` calls `ensure_agent_binary` first, so `resume` performs the repair, prints, emits, and then aborts the launch. **Nothing is spawned that could re-set the flag**, which makes the "cannot mask the repair" property structural rather than contingent on an eligibility predicate.
- **Files modified:** `crates/devflow-cli/tests/auto_chain_leak_repair_e2e.rs`
- **Verification:** both tests pass in 0.16s and fail loudly (not hang) with the call site removed; `pgrep` against this worktree finds nothing after the run.
- **What it costs:** no test here drives a repair followed by a *successful* stage launch — recorded as coverage row D8 and in the section below.
- **Committed in:** `d67a926`

**2. [Rule 2 — Missing critical] `committed_tree_repaired` is re-probed, not inferred**

- **Found during:** Task 1, reading `commit_path`'s doc comment.
- **Issue:** The plan's step 4 set the flag from `commit_path` returning `Ok`. But `commit_path` deliberately converts git's "nothing to commit" into `Ok(())` (19b/D-16), so `Ok` is not evidence that the tip moved — the flag would have claimed a repair that may not have happened.
- **Fix:** after the commit, `probe_head` runs again. `Agrees` sets `committed_tree_repaired`; `Differs` sets `commit_refused` with a message saying the commit reported success but the tip still disagrees.
- **Files modified:** `crates/devflow-core/src/gsd_config.rs`

## What this does NOT establish

- **A repair that reaches the branch tip still depends on Ship merging that branch.** The commit lands on `feature/phase-NN`; nothing here forces it onto `develop`. A leak that reached `develop` by some other route is repaired only when the next `devflow start` forks a worktree from it — which is exactly why the repair sits at **both** entry points and not only at `resume`. `start`'s call site is proven by placement and by the shared helper's unit tests, **not** by an end-to-end test of its own.
- **No test drives a repair followed by a successful stage launch.** By deviation 1, the resume step aborts at `ensure_agent_binary`. The composition of "repair, then launch normally" is covered only by code ordering plus 35.1-01's separate launch e2e.
- **The e2e tests are n=1 each**, and the SIGKILL timing is one point in a race. They establish that the mechanism works on the path taken, not that it works under load, concurrency, or a real 40-minute stage.
- **The sweep guard is proven against one shape of "other change"** — an edited sibling key in the same object. Deeper structural divergences (a reordered array, a re-typed value) are covered by the same `Value` equality but are not separately exercised.
- **`scripts/check.sh all` ran on this host, not in the pinned CI container.** The pre-push container gate has not been exercised for this diff.
