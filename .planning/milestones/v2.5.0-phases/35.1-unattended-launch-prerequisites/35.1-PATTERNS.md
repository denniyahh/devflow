### `crates/devflow-core/src/gsd_config.rs` (NEW — utility/config-writer, file-I/O)

**Analog:** `crates/devflow-core/src/workflow.rs`

**Imports pattern** (`workflow.rs:1-13`):
```rust
use crate::phase_id::PhaseId;
use crate::state::State;
use std::io::Write;
use std::path::{Path, PathBuf};
use tracing::{debug, warn};
```
`gsd_config.rs` will instead need `serde_json::Value` (not a typed struct — the file has keys this
crate does not own: `commit_docs`, `git`, `intel`, `review`, `model_overrides`, `mempalace`) plus the
same `std::path`/`std::fs` primitives. Do not import `serde::{Serialize, Deserialize}` for a typed
`Workflow`/`Config` struct — a typed round-trip would drop unknown keys on write, which is exactly
the "leave every other key untouched" contract this file must honor (RESEARCH.md "Don't Hand-Roll").

**Error type pattern** (`workflow.rs:15-27`):
```rust
#[derive(Debug, thiserror::Error)]
pub enum WorkflowError {
    #[error("state I/O failed: {0}")]
    Io(#[from] std::io::Error),
    #[error("state JSON failed: {0}")]
    Json(#[from] serde_json::Error),
    #[error("no active DevFlow state at {0}")]
    MissingState(PathBuf),
}
```
Follow this exact shape for a new `GsdConfigError` (or reuse `WorkflowError` if the planner decides
the two files' failure modes are close enough) — `Io`/`Json` `#[from]` variants let every call site
use `?` with zero conversion boilerplate, matching every other error enum in this crate
(`GateError`, `MonitorError`, `ResultError`, `ShipError`, `LockError` all share this shape per
`workflow.rs:91-96`'s own doc comment).

**Core pattern — atomic write** (`workflow.rs:174-193`, copy the *shape*, not the body — this file's
`save_state` serializes a `State` it fully owns; `gsd_config.rs` must parse-mutate-reserialize a file
it only partially owns):
```rust
pub fn save_state(state: &State) -> Result<(), WorkflowError> {
    debug!("saving state: phase={} stage={}", state.phase, state.stage);
    let path = state_path(&state.project_root, state.phase);
    let contents = serde_json::to_string_pretty(state)?;
    write_state_atomic(&path, &contents)?;
    Ok(())
}

fn write_state_atomic(path: &Path, contents: &str) -> Result<(), WorkflowError> {
    if let Some(parent) = path.parent() {
        ensure_devflow_dir(parent)?;
    }
    let tmp = path.with_extension("tmp");
    std::fs::write(&tmp, contents)?;
    std::fs::rename(&tmp, path)?;
    Ok(())
}
```
The new `set_auto_chain_active(path, bool) -> io::Result<()>` (RESEARCH.md's own recommended
signature) should: (1) `serde_json::from_str::<Value>` the existing file (defensive — treat a
missing/malformed file as a `could-not-determine` case per V5, never panic), (2) `value["workflow"]["_auto_chain_active"] = json!(bool)`, inserting the `workflow` object if absent, (3)
`serde_json::to_string_pretty(&value)` then the identical `tmp` + `rename` two-liner above. **Do not
create a new `ensure_devflow_dir`-style parent-creation step** — `.planning/` already exists by the
time this runs; only the atomic-write tail applies.

**Don't-hand-roll note (V5 / defensive parsing):** mirror GSD's own defensive-default idiom rather
than assuming the key exists —
```javascript
// Source: ~/.claude/gsd-core/bin/lib/check-command-router.cjs:95-111 (verified this session)
const autoAdvance = Boolean(workflow.auto_advance ?? false);
const autoChainActive = Boolean(workflow._auto_chain_active ?? false);
```
The Rust equivalent when *reading* the flag back (e.g. for the force-clear's "was it even set"
check) is `value.get("workflow").and_then(|w| w.get("_auto_chain_active")).and_then(Value::as_bool).unwrap_or(false)` — never `value["workflow"]["_auto_chain_active"]` on a read path, since indexing panics on a missing key.

**Required Cargo change:** `Cargo.toml:22` currently reads `serde_json = "1"` with no features —
confirmed no `indexmap` in `Cargo.lock:431-437`. Change to `serde_json = { version = "1", features = ["preserve_order"] }` (or the workspace-dependency equivalent) BEFORE writing `gsd_config.rs`, or every write silently re-sorts `.planning/config.json`'s top-level keys alphabetically.

### `crates/devflow-cli/src/pipeline_launch.rs` `run_monitor` (MODIFIED — service, event-driven)

**Analog — RAII guard shape:** `LegacyEnvOverride` (`pipeline_launch.rs:2679-2700`, test-only today
but exactly D-01's asked-for shape):
```rust
struct LegacyEnvOverride(Option<std::ffi::OsString>);

impl LegacyEnvOverride {
    fn set(value: &str) -> Self {
        let prior = std::env::var_os("DEVFLOW_CLAUDE_LEGACY_LAUNCH");
        unsafe { std::env::set_var("DEVFLOW_CLAUDE_LEGACY_LAUNCH", value) };
        Self(prior)
    }
}

impl Drop for LegacyEnvOverride {
    fn drop(&mut self) {
        unsafe {
            match self.0.take() {
                Some(prior) => std::env::set_var("DEVFLOW_CLAUDE_LEGACY_LAUNCH", prior),
                None => std::env::remove_var("DEVFLOW_CLAUDE_LEGACY_LAUNCH"),
            }
        }
    }
}
```
The new guard mutates `.planning/config.json` via `gsd_config::set_auto_chain_active`, not an env
var, and its `Drop` sets the flag back to `false` unconditionally (D-06: this is a boolean the
guard owns for its scope's duration, not a prior-value restore — unlike `LegacyEnvOverride`, which
restores a caller-supplied prior value because the env var may have had a meaningful pre-existing
state; `_auto_chain_active` does not: `false` is always correct on exit).

**Exact insertion point** — current `run_monitor` body (`pipeline_launch.rs:594-627`):
```rust
pub(crate) fn run_monitor(
    project_root: &Path,
    phase: PhaseId,
    workdir: &Path,
    prompt_file: &Path,
    idle_timeout_secs: u64,
    argv: &[String],
) -> Result<(), CliError> {
    let prompt = std::fs::read_to_string(prompt_file).map_err(|err| { ... })?;
    let Some((program, args)) = argv.split_first() else { ... };

    monitor::run_pipe_owning_monitor(
        project_root,
        phase,
        workdir,
        &prompt,
        std::time::Duration::from_secs(idle_timeout_secs),
        program,
        args,
        &[],
    )
    .map_err(|err| CliError::Message(format!("pipe-owning monitor failed: {err}")))?;

    advance(project_root, Some(phase))
}
```
The guard's `set()` (writing `true` to `workdir/.planning/config.json`) belongs immediately before
the `run_pipe_owning_monitor` call; the guard variable must be bound (`let _guard = ...`) so `Drop`
fires when this function returns via the `?` on `run_pipe_owning_monitor`'s `Err` OR falls through
to `advance(...)` — covering both D-02 cases (in-stage error, normal exit) in one guard scope. **Do
not gate this on `Stage::Code` inside `run_monitor` itself** — `run_monitor` is generic over every
stage that uses the pipe-owning arm; the caller (`launch_stage`/`spawn_agent_and_record`) must only
route through this guarded path when `state.stage` is in the D-05 constant, so `run_monitor` stays
stage-agnostic and the policy lives in one place (D-05's own "one greppable place" rationale).
`workdir` here is `state.worktree_path` (or `project_root`) — the SAME path
`.planning/config.json` under it is a *tracked, committed* file, so the write must target
`workdir.join(".planning/config.json")`, not `project_root`.

### `crates/devflow-cli/src/preflight.rs` (MODIFIED — middleware/guard, request-response)

**Analog:** `preflight_gh_auth_check` / `gh_auth_check_applies` (`preflight.rs:625-661`):
```rust
fn gh_auth_check_applies(stage: Stage) -> bool {
    stage == Stage::Ship
}

fn preflight_gh_auth_check(state: &State) -> Result<(), String> {
    if !gh_auth_check_applies(state.stage) {
        return Ok(());
    }
    match std::process::Command::new("gh").args(["auth", "status"]).output() {
        Ok(output) if output.status.success() => Ok(()),
        Ok(_) => Err("gh auth status reports not authenticated".to_string()),
        Err(_) => {

            Ok(())
        }
    }
}
```
This is the "fails soft on absent tool, fails hard on a definite negative" split — but D-07 needs a
**third** state (`could not determine`), which this analog does not have (its "binary absent" case
is deliberately fail-soft, the opposite of D-07's fail-closed mandate). Use
`preflight_major_bump_check` (`preflight.rs:733-788`) as the second analog specifically for the
fail-closed shape:
```rust
// D-10: refuse rather than proceed when the true highest tag exists but
// is not reachable from HEAD — mirrors `compute_version`'s own refusal
// exactly, since this check must never disagree with it.
if let Some(highest) = &highest {
    let unreachable = match &baseline {
        Some(reachable) => highest > reachable,
        None => true,
    };

}
```
i.e. an ambiguous/unreachable/unknown condition returns `Err`, not `Ok`. D-07's new check should

```rust
let tmp = path.with_extension("tmp");
std::fs::write(&tmp, contents)?;
std::fs::rename(&tmp, path)?;
```
Every write to a file a concurrently-running process (here: the live Claude/GSD session) may also

### RAII guard, restore-on-drop
**Source:** `crates/devflow-cli/src/pipeline_launch.rs:2679-2700` (`LegacyEnvOverride`)
**Apply to:** the D-01 chain-flag guard in `run_monitor`.
```rust
impl Drop for LegacyEnvOverride {
    fn drop(&mut self) {
        unsafe {
            match self.0.take() {
                Some(prior) => std::env::set_var("DEVFLOW_CLAUDE_LEGACY_LAUNCH", prior),
                None => std::env::remove_var("DEVFLOW_CLAUDE_LEGACY_LAUNCH"),
            }
        }
    }
}
```
Restore-on-`Drop` covers normal return, early `?`, and panic-unwind (this workspace sets no
`panic = "abort"`) — it does not and cannot cover SIGKILL, which is why D-01 also mandates the
independent force-clear at `start`/`resume`.

### Real-binary integration test (`FakeBin` idiom)
**Source:** `crates/devflow-cli/tests/start_reachability_e2e.rs:38-60`
**Apply to:** D-02's SIGKILL/in-stage-error regression tests (the automatable halves).
```rust
struct FakeBin {
    _dir: tempfile::TempDir,
    path: PathBuf,
}

fn fake_bin_dir() -> FakeBin {
    let dir = tempfile::tempdir().unwrap();
    let claude = dir.path().join("claude");
    fs::write(&claude, "#!/bin/sh\nprintf 'DEVFLOW_RESULT: {\"status\":\"success\"}\\n'\n").unwrap();
    let mut perms = fs::metadata(&claude).unwrap().permissions();
    perms.set_mode(0o755);
    fs::set_permissions(&claude, perms).unwrap();
    FakeBin { _dir: dir, path: dir.path().to_path_buf() }
}
```
For D-02's SIGKILL case, the fake `claude` script needs to `sleep` long enough for the test to
`kill -9` the monitor pid mid-stage, then assert the NEXT `devflow resume`/`start` clears the
flag — this is genuinely new fixture shape (no existing sleeping/killable `FakeBin` script found in
this session's search), not a verbatim copy.
