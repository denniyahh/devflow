# Phase 35 — end-to-end evidence

Run at the operator's request, before phase verification. Every prior claim in this phase rested on
unit/integration tests plus reverted-fix negative controls; nothing had been observed on a live
binary. This is that observation.

## 1. CR-01 — the blocker, demonstrated live with a before/after

The review found CR-01 by tracing code, and the fix was verified by unit tests. Neither had watched
it fail. This did.

**Method.** A throwaway git repo (`develop`, `main`, `feature/phase-01` one commit ahead), a
hand-written `.devflow/state-01.json` at `stage: code`, a chosen `.devflow/phase-01-exit`, and
`devflow advance --phase 1` driven directly — no agent, no tokens. `git` was made unresolvable by
running with `PATH=/nonexistent`, which is the live equivalent of the `NoGitPath` harness. The
classification is read from `.devflow/events.jsonl`, which `advance` writes before it blocks on the
gate.

| case | pre-fix `73311d0` | post-fix `d9c4349` |
|---|---|---|
| **exit 137 + `git` unresolvable** | `status: unknown`, `decided_by_layer: 3` ❌ | `status: resource_killed`, `decided_by_layer: 2` ✓ |
| exit 0, `stage: code`, `git` unresolvable | `status: unknown`, `decided_by_layer: 3` | `status: unknown`, `decided_by_layer: 3` — **unchanged** |

Both properties hold: the fix changes the case it must change, and leaves untouched the case it must
not. Had both rows moved, the measurement would have been broken rather than the code.

Pre-fix, an OOM-killed agent whose `git` also failed — one root cause, two observations — was
classified `unknown` and routed through `handle_validate_outcome`, burning `consecutive_failures`
and the new per-phase budget, in direct violation of `pipeline_launch.rs`'s stated prohibition. That
is now observed rather than inferred.

**Baseline sanity (git available, exit 137):** `resource_killed` / layer 2, gate fired with
`unexpected: true`. Confirms the harness drives the real path.

## 2. 35-03 — the rewritten signing probe, with a working control

`devflow release --check` against the real repository:

- **real repo:** `tag-signing viability ✓ signing viable (SHA256:9BPyx2…)`, exit 0, 0.05 s
- **control repo** (scratch repo, `gpg.format=ssh`, `user.signingkey` pointing at a non-key):
  `tag-signing viability ✗ the configured signing key could not sign a test payload`, exit 1

Same binary, same command, different key, different verdict — and the failure message names the
signing operation specifically. The ✗ text matches what 35-03's own pty measurement produced,
corroborating that work from a second direction.

**A first control attempt failed and is recorded rather than discarded.** Overriding the key via
`GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0` reported the *same* fingerprint and still said viable —
because `hermetic_command` calls `env_remove` by design (there is a `git_env_hermeticity` test
pinning it). The control had not taken. A control that agrees with the positive case because it
never applied is worse than no control, since it reads as confirmation.

## What this does NOT establish

- **Only two of the phase's five areas were exercised live.** CR-01/35-01's classification path and
  35-03's probe. **35-04's ceiling and carry-forward, and 35-05's freshness rule, were NOT run
  end-to-end** — they remain covered by unit tests plus reverted-fix controls only.
- **No agent ever ran.** `advance` was driven directly. Nothing here exercises the monitor, the
  stream-json transport, or a real Code↔Validate cycle.
- **n=1 per cell.** One host, one run per case. This shows the mechanism, not its reliability.
- **The gate was never answered.** Every `advance` blocked on its gate and was killed by a timeout,
  so nothing downstream of the gate — loop-back dispatch, `GateInfra` vs `GateReview` *handling* —
  was observed. Only the classification that precedes it.

## Incidental finding: the monitor leak reproduces trivially

Roughly six `devflow advance` invocations left **13** orphaned processes, each killed cleanly by
`SIGTERM` afterwards. They are orphaned, not signal-resistant. This is the known immortality/leak
class, reproduced here as a side effect rather than as the subject — worth noting that it takes only
a handful of gate-firing runs to accumulate.
