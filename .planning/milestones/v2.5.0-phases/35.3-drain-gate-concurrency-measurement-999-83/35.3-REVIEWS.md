## 3. Concerns

### HIGH — The drill does not generate the required provenance artifacts

The plan requires each capture to get a `run.log`, and the second task requires the script to append counts to `COUNTS.md`. The implementation only prints counts to stdout and creates raw/stderr files:

- Capture paths are created at [scripts/drain-drill.sh:142-150](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:142).
- `count_events` prints to stdout but never writes a log or markdown record: [scripts/drain-drill.sh:154-160](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:154).
- No `run.log` or `COUNTS.md` write occurs anywhere in the script.

The committed logs and `COUNTS.md` therefore appear to have been produced manually or by an uncommitted process. Re-running the documented drill will not reproduce the committed evidence.

**Impact:** The measurement is not an executable, self-contained evidence workflow as claimed.

### MEDIUM — The claimed child reaper is inert

The script installs a trap, but `CHILD_PIDS` is never populated:

- It is initialized empty at [scripts/drain-drill.sh:166](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:166).
- The cleanup loop only iterates that empty variable: [scripts/drain-drill.sh:167-173](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:167).
- Claude is launched synchronously in the foreground at [scripts/drain-drill.sh:150](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:150).

Thus the T-35.1-18 guarantee is not implemented. An interrupted shell may or may not terminate the child through process-group behavior, but this script does not explicitly ensure it.

### MEDIUM — Failed Claude runs are not recorded honestly

Because `set -e` is active, a non-zero Claude exit at [scripts/drain-drill.sh:150](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:150) aborts the script before any outcome record is written. The plan explicitly requires recording the outcome and achieved sample size, including failures or reductions.

This also means a partial run can leave raw files without a corresponding provenance record.

### LOW — Invalid prompt variants silently select Variant B

The parser accepts any value after `--prompt`:

- [scripts/drain-drill.sh:58-60](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:58)

The selector then treats every non-`A` value as B:

- [scripts/drain-drill.sh:140-141](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:140)

`--prompt C` should fail rather than silently measuring the wrong workload.

### LOW — `--runs` is not validated

`RUNS` is accepted without checking that it is a positive integer: [scripts/drain-drill.sh:61-63](/var/home/denniyahh/Github/devflow/.worktrees/phase-35.3/scripts/drain-drill.sh:61). Values such as `--runs foo` produce an arithmetic error; zero or negative values silently produce no captures. This undermines the claimed achieved-`n` accounting.

## 4. Suggestions

- Make `launch_and_capture` explicitly manage the child PID (prefer a temporary stdin file plus background launch), record the PID in `CHILD_PIDS`, and remove it after `wait`.
- Wrap `wait`/exit handling so every run writes a `run.log` with exit status, counts, and whether the run was valid.
- Have the script append the exact per-run rows to `COUNTS.md`, or clearly separate a capture-only mode from a report-generation mode.
- Validate `PROMPT_VARIANT` against `A|B` and `RUNS` against `^[1-9][0-9]*$`.
- Add a negative test that interrupts a running backgrounded child and verifies no Claude process remains.

## 5. Risk Assessment

**MEDIUM.** The committed evidence supports the stated measurement narrative, and the gate logic itself is consistent with the reported event families. But the drill is not reproducible from the committed script, and its advertised cleanup guarantee is ineffective. Those gaps weaken confidence in future reruns and in the integrity of any later evidence generated from this tooling.
