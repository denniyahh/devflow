## Planner decision record

### P-01 — The analysis lives in `35.3-evidence/README.md` (resolves "where the record goes")

The phase's evidence directory is `35.3-evidence/`. The analysis is its `README.md`, mirroring
34-evidence's `README.md` (layout + conventions) and `DRAIN-ANALYSIS.md` (the per-stage/per-path
answer) in one file. It is the phase's criterion-2 and criterion-4 deliverable, and it is what
`/gsd-verify-work` and any future reader consult.

### P-02 — The label correction is a version pin, never a provenance retraction (resolves criterion 3's shape)

RESEARCH established the fixture's provenance is **true**: Phase 30's capture really emitted
`background_tasks_changed`. The correction therefore cannot be "this event is invented." It is a
CLI-version pin: name the capture and era the shape came from, state that the current pinned CLI
does not emit it, and point at the per-task arm as the current-vocabulary tracker. If the drill's
own capture contradicted that (unexpected `background_tasks_changed` on 2.1.228), the correction
inverts — the record, not this expectation, drives the text.

### P-03 — The backlog item is conditional and specific

D-03 is explicit: file a `999.x` backlog entry only for a residual gap the measurement found
(notably the backgrounded-shell path emitting neither vocabulary), never a widening item for the
sub-agent path unless `open_tasks` is itself shown wrong. Task 2 makes this conditional on the
evidence; a green "no gap found" run files nothing and states why.
