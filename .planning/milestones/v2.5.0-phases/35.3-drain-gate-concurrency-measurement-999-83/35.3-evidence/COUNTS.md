## What the current CLI actually emits

**Sub-agent dispatch (Variant A)** — the per-task vocabulary only, never
`background_tasks_changed`:

```
task_started (task_type: "local_agent", description: "Compute sum of 12 and 34")
  → task_updated  (patch.status: "completed")
  → task_notification (status: "completed")
```

`background_tasks_changed` ×0 across both runs. This confirms, at n=2, the Phase 34
refutation and commit `47ea511`'s n=1 capture: the widened `open_tasks` arm is what
observes this path, because the legacy `background_tasks_changed` arm never fires.

**Backgrounded shell (Variant B)** — BOTH the legacy drain event AND the per-task
vocabulary, for the SAME task id:

```
background_tasks_changed (tasks: [{ task_type: "local_bash", … }])   ← announce
task_started (task_type: "local_bash")
  → task_updated   (patch.status: "completed")
  → task_notification (status: "completed")
background_tasks_changed (tasks: [])                                  ← drained
```

This is the first capture anywhere in this repository of the backgrounded-shell path:
Phase 34 recorded 8 `Bash` calls with zero `run_in_background: true`. It shows the
backgrounded-shell path emits **`background_tasks_changed`** — the legacy drain arm is
NOT dead for this path — **and** the per-task vocabulary, so the widened gate's two arms
are both satisfied.

## Key observation for the fixture label (criterion 3)

The synthetic fixture (`monitor.rs` `bg_tasks_line`) manufactures
`background_tasks_changed` with `task_type: "local_agent"`. Production, on 2.1.228,
emits `background_tasks_changed` with `task_type: "local_bash"` (backgrounded shells)
and emits `local_agent` only in the per-task `task_started` vocabulary (sub-agents).
The fixture's `local_agent` is faithful to the Phase 30 capture it cites — but the
current CLI puts `local_bash` inside `background_tasks_changed`, so the fixture models
a combination the current CLI never produces.
