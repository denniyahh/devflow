### `crates/devflow-cli/src/pipeline_outcomes.rs` — augment `verification_authored_this_run` + `select_loop_back_fix`

**Analog:** the function and its call site, unmodified today (lines 317–470).

**Current signature to extend** (lines 446–450) — doc comment (lines 397–445) explicitly states the
function "must touch neither the filesystem nor `[State]`" so the nonce values must be **pre-resolved
by the caller**, not looked up inside:
```rust
fn verification_authored_this_run(
    current: (Option<u64>, Option<u64>),
    run_start_baseline: (Option<u64>, Option<u64>),
    baseline_captured: bool,
) -> bool {
    let (current_hash, current_mtime) = current;
    let (baseline_hash, baseline_mtime) = run_start_baseline;
    let written_since_baseline = match (current_mtime, baseline_mtime) {
        (Some(now), Some(baseline)) => now != baseline,
        _ => false,
    };
    match (current_hash, baseline_hash) {
        (None, _) => false,
        (Some(_), None) => baseline_captured,
        (Some(now), Some(baseline)) => now != baseline || written_since_baseline,
    }
}
```
The nonce comparison must be a fourth argument (per CONTEXT.md's Established Patterns note and the
tuple-argument shape this function already uses), combined with `&&` against the existing
hash/mtime logic per D-02 ("both signals must agree" — nonce alone is not sufficient, see
Anti-Patterns in RESEARCH.md).

**Call-site pattern to extend** (`select_loop_back_fix`, lines 336–364):
```rust
let current = agent_result::phase_verification_fingerprint(evidence_root, phase);
let current_mtime = agent_result::phase_verification_mtime_nanos(evidence_root, phase);
if current.is_some() && !state.verification_baseline_captured {
    events::emit(&state.project_root.clone(), phase, "verification_baseline_absent", ...);
}
if verification_authored_this_run(
    (current, current_mtime),
    (state.last_verification_fingerprint, state.last_verification_mtime_nanos),
    state.verification_baseline_captured,
) {
    state.last_verification_fingerprint = current;
    state.last_verification_mtime_nanos = current_mtime;
    FixType::GapsOnly
} else {
    FixType::FullExecute
}
```
The nonce read (`state.verification_run_nonce`) is resolved here, exactly where the fingerprint and
mtime already are, and passed as the fourth argument into the augmented predicate.

**Truth-table test pattern to extend** (lines 3925–3995,
`verification_freshness_truth_table_is_exhaustive`):
```rust
#[test]
fn verification_freshness_truth_table_is_exhaustive() {
    assert!(!verification_authored_this_run((None, None), (None, None), true), "row 1: ...");
    assert!(verification_authored_this_run((Some(7), Some(100)), (None, None), true), "row 2: ...");
    assert!(!verification_authored_this_run((Some(7), Some(100)), (None, None), false), "row 2b: ...");
    assert!(!verification_authored_this_run((Some(7), Some(100)), (Some(7), Some(100)), true), "row 3: ...");
    assert!(verification_authored_this_run((Some(7), Some(200)), (Some(7), Some(100)), true), "row 3b: ...");
    assert!(!verification_authored_this_run((Some(7), None), (Some(7), Some(100)), true), "row 3c: ...");
    assert!(verification_authored_this_run((Some(7), Some(200)), (Some(8), Some(100)), true), "row 4: ...");
}
```
Every row is `verification_authored_this_run(current_tuple, baseline_tuple, captured_bool) ==
expected_bool` with an inline `"row N: reason"` message naming which over-correction it catches. The
augmented function's rows (now including the nonce dimension) should extend this same table —
copy the row/comment/assert shape, not a separate test file. The doc comment above the test
(lines 3900–3924) is itself a markdown truth table (`| current | baseline | captured | fresh? |
fails under |`) — RESEARCH.md's Open Question 2 explicitly recommends writing this table out first,
the same way, before implementing.

**D-04 "both directions in one test" pattern:** no exact existing analog (this is a new test), but
its shape should mirror `verification_freshness_truth_table_is_exhaustive`'s structure: one `#[test]`
fn, two `assert!`/`assert_eq!` calls back-to-back (scenario A: nonce matches + fingerprint unchanged

### Conditional GSD verification (D-03 half 2) — availability-probe pattern

**Analog:** `agent_binary_available` in `crates/devflow-cli/src/preflight.rs:63–77` — no existing
test shells out to `gsd-tools`, but this is the codebase's established "is an external program on
PATH" probe to copy the shape of:
```rust
fn agent_binary_available(program: &str) -> bool {
    use std::os::unix::fs::PermissionsExt;
    let executable = |path: &Path| {
        path.is_file()
            && std::fs::metadata(path)
                .map(|m| m.permissions().mode() & 0o111 != 0)
                .unwrap_or(false)
    };
    if program.contains('/') {
        return executable(Path::new(program));
    }
    std::env::var_os("PATH")
        .map(|paths| std::env::split_paths(&paths).any(|dir| executable(&dir.join(program))))
        .unwrap_or(false)
}
```
D-03's conditional half should: probe for `gsd-tools` (or `node` + the known `gsd-tools.cjs` path)
using this same PATH-probe shape (or a `Command::new(...).output()` existence check), and skip with
a `println!`/`eprintln!` notice — not fail the test — when absent, matching D-03's own wording
("invoked via `gsd-tools` when available, skipped with a notice when not"). RESEARCH.md's live
session already confirmed the live invocation and output shape to assert against:
```
$ node .../gsd-tools.cjs query init.execute-phase 7    | grep branch_name
"branch_name": "feature/phase-07"
$ node .../gsd-tools.cjs query init.execute-phase 35.2 | grep branch_name
"branch_name": "feature/phase-35.2"
```
No committed Rust code currently shells out to `gsd-tools` — this is a genuinely new integration
point, not a refactor of an existing one, so treat the probe-and-skip wrapper as the only "pattern,"
not the invocation itself.

**Source:** every field/function touched in this phase (`state.rs:170–196`,
`pipeline_outcomes.rs:280–316, 397–445`) carries a doc comment stating: what it protects against in

capture site — each needs the same two-directions-plus-incident-reference doc comment, not a bare
one-liner. This is the file's own established bar for changes in this exact area, not a general

("must touch neither the filesystem nor `[State]`")
