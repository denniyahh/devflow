# Phase 52.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust `#[test]` under cargo test / cargo nextest; insta snapshots |
| **Config file** | `Cargo.toml`; `scripts/check.sh` |
| **Quick run command** | `cargo nextest run -p devflow --bin devflow --no-tests=fail -E 'test(=<module::path::name>)'` (or `-p devflow-core --lib`) |
| **Full suite command** | `scripts/check.sh all` and `scripts/check-in-container.sh all`; host-only `scripts/check.sh service` |
| **Estimated runtime** | named-gate sweep (130 nextest commands, one test or suite each) about 7.5 min on the host, 2026-11-17; `scripts/check.sh service` 12 s |

---

## Sampling Rate

- **After every task commit:** the task's named nextest gates, chained with `&&`
- **After every plan wave:** `scripts/check.sh all`, plus `scripts/check.sh service` on the host. Exception: the wave-4 head (52.2-06) is red by design until wave 5 (52.2-07/08/22) ports the suites; see the `red_window` field in 52.2-06 and 52.2-07
- **Before `/gsd-verify-work`:** container gate, service target and CI green, then the proof run
- **Max feedback latency:** longest single named gate about 14 s (`failover_e2e` suite); service target 12 s (measured 2026-11-17)
