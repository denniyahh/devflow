# Phase 52.2: Foreground Runner - Research

**Researched:** 2026-11-16
**Domain:** Rust process supervision under a systemd user manager; liveness by `flock`; CLI verb rework in `devflow-cli`
**Confidence:** HIGH for the systemd behaviour (measured on this host, systemd 262) and the code inventory (read this
session); LOW for the GitHub-hosted user-manager job (not measured).

## Summary

Every systemd question CONTEXT.md handed to research was answered by bounded probes on this host. Every probe unit (34
recorded names) was started under a recorded name, and all read `LoadState=not-found` afterwards, with no probe
processes left.
1. **Environment.** `systemd-run --user --setenv NAME` (no value) copies the caller's value into the unit, and the
   value never appears on any command line.
2. **Readiness.** `Type=notify` with `NotifyAccess=main` makes `systemd-run` (without `--no-block`) block until the
   main process sends `READY=1`, and exit 1 if the process dies first, a child sends the READY, or the start times
   out.
3. **`Type=exec` is not enough.** It returned 0 over a process that exited 1 straight after exec.
4. **Deactivating window.** A unit whose main process has exited but whose SIGTERM-ignoring descendant still runs
   reads `ActiveState=deactivating` until `TimeoutStopSec`, then `inactive` / `not-found` under `--collect`.
5. **Stop blocks.** `systemctl --user stop` blocks for that same window.
6. **Signal order.** In 20 of 20 stops, the main process had already caught its own SIGTERM when its wait on the
   killed child returned. The negative control (SIGTERM to the child alone) left the flag unset.

The code side splits cleanly.
- **What stays.** The stage logic (`monitor::run_supervised_stage`) and the stop primitives (`StopToken`, the signal
  pipe, `wait_for_exit_without_reaping`, `end_group_while_running`) are reusable once the socket, sidecar,
  `PromotionWatch` and liveness adoption are taken out. The lock primitives in `liveness.rs` (`claim_phase_holder`,
  `probe`) already have exactly the semantics D-07 needs, and std opens every file close-on-exec.
- **What goes.** The stage chain is recursive across processes today: `run_monitor` → `advance_for_stage` →
  `advance_with` → … → `spawn_agent_and_record` → `spawn_next_supervisor` → `spawn_monitor` (a new detached
  `__monitor`). The spike replaced only the last hop with an in-process call, which made it recursive in one process.
  The planner should invert it: `advance_with` returns what to run next, and one loop in the runner runs it.

**Primary recommendation:**
- **Launch.** `start`/`resume` run their guards under the phase holder, then call `systemd-run --user
  --unit=<derived> --collect -p Type=notify -p NotifyAccess=main -p KillMode=control-group -p TimeoutStopSec=10s -p
  TimeoutStartSec=30s --expand-environment=no --working-directory=<root>`, plus one `--setenv NAME` per valid caller
  variable. The command is `<current_exe> <hidden runner verb> …`.
- **Runner.** It takes `.devflow/.runner-NN`, sends `READY=1` by a hand-written datagram, and runs one in-process
  stage loop. No new crates.

## Architectural Responsibility Map

| Capability | Primary Tier | Secondary Tier | Rationale |
|------------|-------------|----------------|-----------|
| Launch a run as a unit, report a failed start | CLI caller (`start`/`resume`) | systemd user manager | Only the caller can print to the operator's terminal; systemd reports readiness or failure synchronously |
| Liveness ("is a run live?") | Runner lock file (`.devflow/.runner-NN`, kernel `flock`) | systemd `ActiveState` (D-07a wait only) | The kernel releases the lock at process death; the unit state covers the window after the lock frees |
| Exclusion between mutating verbs | Phase holder (`.devflow/.holder-NN`) | — | Separate file from liveness so the launcher→runner hand-off cannot deadlock (D-07) |
| Stage execution, output capture, verdict | Runner process (unit main) | devflow-core `monitor` stage logic | One process owns agent, capture, gates and state writes |
| Hard-kill coverage | systemd (`KillMode=control-group`) | — | The cgroup is killed whatever the runner does (spike + D-08) |
| Stop | `devflow stop` → `systemctl --user stop` | Runner SIGTERM handler | systemd delivers the signal; the runner records `stopped` |
| Gate answers | Any shell (`devflow gate approve/reject`) | Runner gate wait | Unchanged file-gate protocol |
| Status / logs | CLI read-only | `.devflow/` files | Read the one liveness function and the state |

### Locked Decisions

Provenance is per item: **(operator)** = the operator chose it in this discussion; **(agent)** = decided inside the

#### Run shape
- **D-01 (operator):** Every run is a user service. `start` and `resume` always launch the runner with
  `systemd-run --user`, a fixed unit name derived from project and phase, `-p KillMode=control-group` and `--collect`;
  they print the unit name and the `devflow status` / `devflow logs` lines and return. There is **no user-facing
  terminal-held run and no `--foreground` flag.** Operator's reasoning: a held terminal accepts no DevFlow commands and
  only shows progress lines (agent output goes to `.devflow/` files), so it is a log tail, not a run type.
  — **Reversibility:** reversible — the CLI is `4.0.0-alpha.1` and unpublished.
- **D-02 (agent, follows D-01):** The runner's foreground entry point is an internal hidden subcommand: the unit's
  command, and what tests call directly (`scripts/check-in-container.sh` runs plain `docker run` with no user
  manager: all three review lanes, round 1). It replaces the hidden supervisor subcommand, hidden `__monitor` and
  hidden `advance` (see Reusable Assets).
- **D-03 (agent):** On a host where `systemd-run --user` is unavailable, `start` and `resume` refuse and say what is
  missing (never fail closed silently). No fallback launch.
- **D-04 (agent; measured 2026-11-16, one run on this host, systemd 262):** A `systemd-run --user` unit does **not**
  get the caller's environment: a variable set only in the caller read `absent` inside the unit, and the unit's cwd was
  `$HOME`. So the launch passes, explicitly: `--working-directory` = the project root, the runner as an absolute path
  (`std::env::current_exe`), and the environment the runner and agent need. How credentials are passed without putting
  secret values on a command line (`--setenv NAME=value` is visible in `/proc/*/cmdline`; `--setenv NAME` copies the
  caller's value by name) is for research. Control: the agent on the caller's PATH only, and a required
  `DEVFLOW_*` variable set only in the caller, must both reach the agent.
  — An external lane (DeepSeek, review round 1) measured the opposite; the control above refutes it on this host.
- **D-04a (agent, review round 1):** The launch reports a failure to start instead of returning success over a dead
  unit: the runner only counts as launched once it holds D-07's lock (e.g. `Type=notify` with readiness sent after the
  lock is taken, or `Type=exec` plus a wait for the lock; research picks and verifies that `systemd-run` blocks until
  then). Negative control: a nonexistent runner path makes `start` exit non-zero naming the unit and the error.
- **D-04b (agent, review rounds 1–2):** Keep `KillMode=control-group` (D-01; the spike's hard-kill result was
  measured with it). Round 1 found that under it `systemctl stop` also SIGTERMs the agent directly, which can end it
  before the runner's control thread records the stop, so the stage reads as failed (exit 143) instead of `stopped`
  (DeepSeek lane, measured; not re-run by the agent). Round 1's answer, `KillMode=mixed`, was withdrawn in round 2:
  after an abnormal runner exit, `mixed` may leave the agent running until `TimeoutStopSec` (agy lane, from
  systemd.kill(5); unmeasured). The fix is in the runner instead: it classifies an agent exit only after draining its
  own pending stop signal, so an agent killed by the unit's SIGTERM during a stop reads `stopped`. Test: a stop whose
  SIGTERM reaches the agent first still records `stopped`; control: an agent that exits 143 with no stop requested
  records a stage failure. `TimeoutStopSec` is set explicitly on the unit, and D-07a's wait is bounded above it.
- **D-04c (agent):** If user lingering is off, `start` warns that the run ends at logout. It does not refuse.

#### Stopping a run
- **D-05 (operator):** `devflow stop --phase N [PROJECT]` stays and stops whichever run the operator names. It stops
  that phase's unit; the runner traps SIGTERM (and SIGINT), ends the agent's process group, records `stopped` (event
  and state), and exits non-zero. Operator: having to stop a unit with `systemctl` by hand is unacceptable UX.
  Stopping the runner always ends its agent first: an agent without its runner has nothing capturing output or verdict.
  - (agent) `stop` stays idempotent on a phase with no live run. `--launch` goes with the sockets it addressed.
  - The spike's stop path recorded nothing without a supervisor record (`record_supervisor_stop`), so the
    stopped-recording code is new, with a test that a stopped run reads `stopped` and `resume` continues it.
  - **(agent, review round 1) Existing stop semantics carry unchanged:** a permitted finish wins over a late stop
    (`finish_run`, `pipeline_gate.rs`, operator 2026-11-11); a stop at a pending gate closes the gate and keeps the
    state resumable, never `Abort` (`open_and_await`); the stop token spans the whole run, not one stage, and exactly
    one SIGTERM/SIGINT handler is installed (today `install_holder_stop_handler` and `install_signal_pipe` replace each
    other). Tests: stop before a gate answer, after approval, during the next stage's launch, after finish permission.
  - **(agent) A runner that does not honour SIGTERM** is SIGKILLed by systemd after `TimeoutStopSec`; that leaves
    the run reading `crashed` (lock free, stage recorded running), and `stop` says so instead of claiming `stopped`.
- **D-06 (operator; corrected in review round 1):** `devflow recover` the verb is removed. Its listing duplicates
  `status`; its state deletion duplicates `discard`. Corrections: `recover.rs` helpers still used elsewhere
  (`format_age`, `inspect_all` for `doctor`) move, not vanish; the gate waiter's lifetime lock (`Gates::register_waiter`)
  survives, so gate files and `Hold::take`'s `*.hold-tmp` temps can still be left by a kill. `discard` removes a phase's
  orphan gate files and hold temps, including a gate-only phase with no state, worktree or branch (today it refuses
  that), with a test for each.

#### One liveness signal (999.237)
- **D-07 (operator):** One per-phase lifetime lock is the only liveness signal. The runner holds it for its whole life,
  opened close-on-exec so the agent never inherits it. Held = live, free = not live. Every verb that asks (`start`,
  `resume`, `discard`, `stop`, `cleanup`, `status`) asks through one function. This is 999.237's fix.
  - Evidence required: the spike saw a lock read "held" while a child with an inherited descriptor lived. A test shows
    the agent child does not hold the lock, with the negative control (a child given the inherited descriptor keeps it
    held).
  - Table test, per 999.237's fix shape: every verb × lock (held, free) × state (none, reservation-only, running,
    stopped, finished, unloadable), one test walking the table. Held-lock/no-state and held-lock/unloadable are
    required rows. "One liveness signal" means liveness; the state still says which verb applies.
  - **(agent, review rounds 1–2) Two files, two jobs.** Liveness and exclusion are different locks, so the hand-off
    cannot deadlock (round 2: one file cannot be held by both launcher and runner):
    - the **runner lock** (`.devflow/.runner-NN`): taken by the runner at its start and held for its whole life. It
      is the one liveness signal. Readiness (D-04a) is sent only after it is taken.
    - the **phase holder** (`.devflow/.holder-NN`, today's `claim_phase_holder` file): exclusion only. A verb that
      mutates (`start`, `resume`, `discard`, `cleanup` per phase in turn) takes it before its checks and keeps it
      across its mutation; `start`/`resume` keep it until the launch reports ready, then release it. The runner
      never takes it.
    - Both files follow `claim_phase_holder`'s invariant: never removed, replaced or `unlock()`ed, excluded from every
      cleanup, so no two processes lock different inodes.
    - Tests: two concurrent `start`s (one launches, one refuses); `start` racing `discard`; `status` reads live for a
      service run after `start` has returned.
  - **(agent)** A lock that cannot be probed (I/O error) reads as an error, never as free.
  - **D-07a (operator, 2026-11-16, review round 1):** The lock frees a moment before systemd finishes killing the
    unit's remaining processes. Verbs that delete or relaunch (`start`, `resume`, `discard`, `cleanup`) therefore also
    wait, bounded, until the phase's unit reads inactive before acting; the lock stays the liveness signal. Test: a
    descendant that ignores SIGTERM keeps the unit deactivating, and `discard` must not act until it is gone.
- **D-07b (operator, 2026-11-16, review round 1):** The service path is tested by a small set of host-only named
  tests that start real user services (launch, stop records `stopped`, hard kill leaves no agent, launch failure
  reported, D-07a's wait). The pinned container runs everything else through the hidden runner entry point.
  **Mechanism (operator, 2026-11-16, review round 2):** a separate named target, `scripts/check.sh service`, not an
  environment switch, so `all` stays identical everywhere (`check.sh`'s header, `ci_parity_guards.rs`). `all` does not
  include it. The pre-push hook runs it on the host beside the container gate. It fails, never skips, when no user
  manager exists. **Plus a CI job** on a GitHub-hosted VM runner that enables lingering and runs the same target, as a
  required check. Unverified: that a hosted runner can run a user systemd manager. The plan proves this first, with a
  negative control (the job fails when the manager is absent), before making the check required. The
  `.planning/user/DEV-SETUP-CHECKLIST.md` is updated in the same change. The new job also needs the job list in
  `ci_parity_guards.rs` (`job_splitter_finds_exactly_the_live_ci_jobs`) updated (review round 3, pi).
- **D-08 (agent, follows D-01):** No orphan-agent check. With every run a unit under `KillMode=control-group`, a hard
  kill of the runner takes the whole unit down: the spike (real program, one run) found no member of the agent's
  group left and the unit inactive. The orphan case (a killed terminal runner leaving its agent working the tree while
  `resume` starts a second agent there) existed only for terminal runs, which D-01 drops. Outside reach, as today: a
  process the agent itself places in another unit or container (its own `systemd-run`, podman) survives the unit.

## Architecture Patterns

### System Architecture Diagram

```
operator shell
  │ devflow start|resume --phase N
  ▼
```

### Pattern 1: Launch, and the readiness contract (D-04a, measured)
**What:** `systemd-run` without `--no-block` "will wait until the unit's start-up is completed" [CITED: systemd-run(1)
--no-block]. With `Type=notify` that means until `READY=1` from the main pid.

Measured on this host (one run each):

| Case | `systemd-run` rc | Elapsed | stderr |
|---|---|---|---|
| B1 notify, READY from main after 2 s | 0 | 2.0 s | `Running as unit: …-1.service; invocation ID: …` |
| B2 notify, exit 1 before READY | 1 | 2.1 s | `Job for …-2.service failed because the control process exited with error code.` |
| B3 notify, nonexistent binary | 1 | 0.0 s | `Failed to find executable /nonexistent/devflow: No such file or directory` (client-side, no unit created) |
| B4 notify, READY sent by a **child** under `NotifyAccess=main`, `TimeoutStartSec=4` | 1 | 4.2 s | `Job for …-4.service failed because a timeout was exceeded.` |
| B5 exec, nonexistent binary | 1 | 0.0 s | `Failed to find executable …` |
| B6 exec, `sh -c 'exit 1'` | **0** | 0.0 s | `Running as unit: …` (success over a dead unit) |
| B7b same unit name while the first is active | 1 | 0.0 s | `Failed to start transient service unit: Unit …-7.service was already loaded or has a fragment file.` |

After B1 returned, `is-active` read `active`. The `NOTIFY_SOCKET` seen by the main process was
`/run/user/1000/systemd/notify`, a filesystem path rather than an abstract `@` name (journal of B1).

**Example (hand-written notify; written for this research, not compiled):**
```rust
/// Tell systemd this unit is ready, once the runner lock is held. A no-op when
/// NOTIFY_SOCKET is unset (the runner verb called directly, as in container tests).
fn notify_ready() -> std::io::Result<()> {
    use std::os::linux::net::SocketAddrExt;
    use std::os::unix::net::{SocketAddr, UnixDatagram};
    let Some(target) = std::env::var_os("NOTIFY_SOCKET") else { return Ok(()) };
    let socket = UnixDatagram::unbound()?;
    let bytes = std::os::unix::ffi::OsStrExt::as_bytes(target.as_os_str());
    let addr = match bytes.strip_prefix(b"@") {
        Some(name) => SocketAddr::from_abstract_name(name)?,
        None => SocketAddr::from_pathname(std::path::Path::new(&target))?,
    };
    socket.send_to_addr(b"READY=1", &addr).map(|_| ())
}
```
Notes:
- `NotifyAccess=main` holds as long as the runner is the exec'd main process: it is, since the unit's command is
  `current_exe`.
- Remove `NOTIFY_SOCKET` from the agent's `Command` (`env_remove`). Under `NotifyAccess=main` the agent's messages are
  ignored anyway (B4), so this only keeps the agent's environment lean.
- Do not use `remove_var`: it is `unsafe` in edition 2024, and the rules forbid process-global env mutation.

### Pattern 2: Environment by name (D-04, measured)
Measured (probe A, one run):
- With `PROBE_SECRET_X` set only in the caller, `--setenv PROBE_SECRET_X` gave `inside: secret=s3cr3t-value-123`.
- The `systemd-run` command line, read from `/proc/<pid>/cmdline`, held only `--setenv PROBE_SECRET_X`.
- **The value is exposed on the user bus:** `systemctl --user show -p Environment <unit>` printed
  `Environment=PROBE_SECRET_X=s3cr3t-value-123`.
- Control without `--setenv`: `secret=absent pwd=/home/denniyahh`.
- `/proc` is mounted without `hidepid` (`rw,nosuid,nodev,noexec,relatime`), so command lines are readable by every
  user. The user bus socket (`/run/user/1000/systemd/private`, `srwx------`) and `/proc/<pid>/environ` are readable
  only by the owner, so by-name passing narrows exposure from every user to the same uid.
- Values with a newline or ESC passed through intact.
- **An invalid name fails the whole launch:** `Cannot assign environment variable BAD%NAME: Invalid argument`, rc=1.
  Bash exports functions as `BASH_FUNC_x%%`, so a caller with an exported function would fail every start unless the
  name is filtered.
- systemd.exec(5) says Environment= "is not suitable for passing secrets … exposed to unprivileged clients via D-Bus
  IPC" [CITED: systemd.exec(5) Environment=].

**Recommendation (agent remit, D-04):**
- **What to pass.** Pass every caller variable whose name matches `^[A-Za-z_][A-Za-z0-9_]*$`, by name, except the
  manager-owned names: `NOTIFY_SOCKET`, `LISTEN_FDS`, `LISTEN_PID`, `LISTEN_FDNAMES`, `INVOCATION_ID`,
  `JOURNAL_STREAM`, `MANAGERPID`, `SYSTEMD_EXEC_PID`, `WATCHDOG_PID`, `WATCHDOG_USEC`.
- **Why everything.** It reproduces today's behaviour. The detached `__monitor` inherits the caller's environment
  minus the git redirect variables: `hermetic_command` strips them, and adapter values travel "on the `__monitor`
  process's environment and only their names on its argv (`--keep-env NAME`), so a value is never visible in the
  process table" [VERIFIED: crates/devflow-core/src/monitor.rs:534-536].
- **Why not an allowlist.** It would have to guess what each agent needs: credentials, `SSH_AUTH_SOCK` for signing,
  proxies, `DEVFLOW_GATE_NOTIFY_CMD`.
- **Keep the existing scrubs.** The runner still applies `hermetic_command`'s git scrub and `strip_notify_env` to the
  agent.
- **PATH.** The unit's PATH defaults to the manager's, and user units inherit the manager's whole block [CITED:
  systemd.exec(5) "Environment variables in spawned processes"]. That PATH is not the caller's: on this host the shell
  adds mise shims. So PATH must be passed by name; it is, under the pass-everything rule.

### Pattern 3: Liveness read (D-07, D-07a)
Lock semantics [VERIFIED: crates/devflow-core/src/liveness.rs:200-228, 342-363], quoted verbatim:
- `pub enum Held { Live, Abandoned, Missing }`.
- `probe`: `File::open` NotFound → `Held::Missing`; `try_lock_shared()` `Ok` → `Held::Abandoned`, `WouldBlock` →
  `Held::Live`, `Error(error)` → `Err(error)`.
- `claim_phase_holder`: `.create(true).truncate(false).mode(0o600)`, then `try_lock_past_probes` (waits out a probe's
  shared lock for `PROBE_RACE_WAIT: Duration = Duration::from_millis(50)`, liveness.rs:46), then
  `write_identity_record` (`"{pid} {start}\n"`).
- Path form: `.join(".devflow").join(format!(".holder-{}", phase.padded()))` (liveness.rs:288-292), where `padded()`
  is `format!("{:02}.{minor}", self.major)` or `format!("{:02}", self.major)` [VERIFIED: phase_id.rs:98-103].

**Close-on-exec:** `claim_phase_holder` opens through `OpenOptions` and never clears `FD_CLOEXEC`. Rust std opens every
file with `O_CLOEXEC` [ASSUMED from std docs, not re-read this session]. The existing test
`a_phase_holder_is_not_inherited_by_a_spawned_child` (liveness.rs:743), with its `clear_close_on_exec` control
(liveness.rs:726-733), is the model for D-07's "agent does not hold the lock" test and its negative control.

**Recommendation:**
- Generalise `claim_phase_holder`'s body into a private `claim_lock_file(path)`.
- Add `claim_runner_lock(root, phase)` on `.devflow/.runner-{padded}`. That keeps the never-removed invariant and the
  identity record, which names the pid for `status`.
- Keep `HolderError::Held`'s Display text out of runner-lock messages: it says "held by a foreground process".

Unit-state reads (measured, probe C: main exits at 1 s while a child traps TERM, `TimeoutStopSec=4`):

| t | `show -p ActiveState -p SubState -p LoadState` | `is-active` rc |
|---|---|---|
| 0.5–1.0 s | `active` / `running` / `loaded` | 0 |
| 1.5–5.0 s | `deactivating` / `stop-sigterm` / `loaded` | 3 |
| 5.5 s | `deactivating` / `stop-watchdog` | 3 |
| ≥6.0 s | `inactive` / `dead` / `not-found` | 4 |

**Use `systemctl --user show -p ActiveState --value <unit>`** (rc 0, prints `inactive` for a collected or never-loaded
unit; measured). Do not use `is-active` rc: 3 means both deactivating and inactive.
- `--collect` = `CollectMode=inactive-or-failed`: the unit is unloaded "even if it failed" [CITED: systemd-run(1)
  --collect]. So `failed` is rarely observable, and "inactive" alone does not say how the run ended (D-13).
- A `systemctl` error (no bus) must read as an error, never as inactive.
- D-07a bound: poll every 100–200 ms for up to `TimeoutStopSec + 5 s`, then refuse naming the unit.

`systemctl --user stop` blocks until the unit is down: 4.2 s with a TERM-ignoring child and `TimeoutStopSec=4`,
0.0 s without one (probe D1/D2). With `KillMode=control-group`, SIGKILL follows after `TimeoutStopSec` [CITED:
systemd.kill(5) KillMode=].

### Pattern 4: One stop handler, classify after draining (D-04b, D-05)
Today two handlers replace each other: `install_signal_pipe` (supervisor/runtime.rs:492-521: a close-on-exec,
non-blocking pipe; the handler writes one byte only when `getpid()` equals the installer) and
`install_holder_stop_handler` (liveness.rs:389-414: an atomic store). The exit decision is `Supervisor::wait_agent` →
`wait_for_exit_without_reaping` → `token.observe_exit(|stop_requested| …)` (runtime.rs:641-651). `stop_requested` is
set by the socket control thread after it reads the pipe, so a stop that lands while the agent dies can be read too
late.

Measured: 20 of 20 `systemctl --user stop` runs on a unit whose Python main process blocked in `wait()` on a child in
its own session printed `child_rc=-15 flag_at_reap=15`. The main process had caught its own SIGTERM by the time its
wait returned. Control (SIGTERM to the child only): `flag_at_reap=None flag_after_200ms=None`. That is consistent with
systemd signalling the main pid before the cgroup [ASSUMED: systemd `unit_kill_context` order, source not read], but
it was measured with Python, which retries an interrupted wait after running the handler, not with Rust.

**Recommendation:**
1. One handler for the whole runner process: keep the signal pipe, and also store the signal number in an atomic.
   Remove `install_holder_stop_handler`'s second `sigaction`, or route both through one function.
2. Wait for the agent on the main thread (the kernel delivers a process-directed signal to the main thread first when
   it can take it [ASSUMED]).
3. Before `observe_exit`, the waiting thread reads the atomic and drains the pipe itself (non-blocking), requesting the
   stop under the token lock.
4. If the agent died by a signal and no stop is recorded, poll the flag for a bounded grace (about 500 ms) before
   classifying the stage as failed. Point 4 makes the D-04b test deterministic whichever order the signals arrive in.
5. Keep `StopToken`/`OwnerPhase` (runtime.rs:49-59: `AgentRunning, Advancing, GateWait, HandedOff, Finished`).
   `HandedOff` becomes dead with no successor process, so remove it or leave it unused.
   `STOPPED_EXIT_CODE: i32 = 128 + libc::SIGTERM` (runtime.rs:43).

**TimeoutStopSec value:** `10s`. The runner's stop path is SIGTERM to the agent group, up to `TERMINATE_VERIFY_WAIT`
(`std::time::Duration::from_secs(3)`, agent.rs:109), then SIGKILL and a state write. 10 s leaves about 2x margin; the
manager default here is `DefaultTimeoutStopUSec=45s` (measured). Then D-07a's wait bound is 15 s, and the one host test
that waits out a TERM-ignoring descendant takes about 10 s. [ASSUMED adequacy: agents' real shutdown time not
measured.]

### Pattern 5: In-process stage loop (replaces `run_monitor`/`advance_with`/`spawn_next_supervisor`)
Today [VERIFIED: pipeline_launch.rs:1494-1645, 2152-2200, 2545, 3658-3700]:
- `run_monitor` runs `run_supervised_stage`, then on `AgentOutcome::Completed` with `Promotion::Recorded` calls
  `advance_for_stage` → `advance_with`.
- `advance_with` applies safe points, the verdict and gates, then reaches `launch_stage` → `spawn_agent_and_record` →
  `spawn_next_supervisor` → `monitor::spawn_monitor`, which starts a detached `__monitor` and waits for it to publish.
- The spike intercepted at `spawn_agent_and_record` (`spike_run_in_foreground`): it ran `run_supervised_stage` in
  process, then called `advance_for_stage` again, which is recursion per stage.

**Recommendation:**
- Change the tail of the launch path so that, where it calls `spawn_next_supervisor`, it returns a
  `NextStage { spec: StageSpec, … }` value (or `Finished`/`Stopped`/`GatePending`), and `advance_with` returns it.
- The runner verb is `loop { let next = advance_with(...)?; match next { Launch(spec) => { let run =
  run_stage(spec)?; record(run) }, Finished => break, Stopped => break, … } }`.
- Everything that exists only because each stage is a new process goes: `Reservation`'s publish wait,
  `PromotionWatch`, `Promotion::{Recorded,Superseded,OrphanedPending}`, `take_successor`, `forward_stop_to_successor`,
  `end_superseded`, `pending_supervisor`, the sidecar and socket.
- MemPalace rule (50.1-04): `update_state` never spawns a process or waits on a gate inside its closure, so the loop
  must wait for gates and agents outside state-lock closures.
- MemPalace surprise T-50.1-97: a second launch path re-opened a gate and launched a stage twice. The runner loop is
  the only code that launches a stage, so add a source-scan test asserting one call site of the stage spawn.

### Anti-Patterns to Avoid
- **`Type=exec` as the readiness contract.** It reports success over a process that exits right after exec (B6).
- **`is-active` exit codes for D-07a.** 3 covers both deactivating and inactive. Read `ActiveState`.
- **`--setenv NAME=value` for anything secret.** It is world-readable in `/proc/*/cmdline`.
- **Unit-name hash with `DefaultHasher`.** Its algorithm is not guaranteed stable across Rust releases, so a reinstall
  could change the name and `stop` would miss a running unit [ASSUMED from std docs]. Use a fixed algorithm (FNV-1a
  64, a few lines) over the canonical project root's bytes.
- **Relying on systemd's default expansion of `${VAR}` in argv.** Measured: `brace=${HOME}` became
  `brace=/home/denniyahh` unless `--expand-environment=no` was given. `%h` was escaped by systemd-run itself (printed
  literally either way).
- **Recursing per stage** (the spike's shape). Use one loop.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Killing the agent tree on a runner crash | `PR_SET_PDEATHSIG`, an orphan reaper, pid files | `KillMode=control-group` | The spike found PDEATHSIG kills the agent but not its children; the cgroup kills all |
| "Did the launch start?" | Polling the lock from `start` with its own timeout | `Type=notify` + `TimeoutStartSec` | systemd already reports exit, timeout and name collisions synchronously (B2/B4/B7b) |
| Liveness | A pid file, socket ping, start-time match | `flock` probe on `.runner-NN` | The kernel releases it at death; read once through `probe` |
| Run exclusion against a second `start` | Checking "unit exists" by hand | Phase holder; systemd's own name collision is a second line (B7b) | — |
| Env passing | A serialised env file with its own cleanup | `--setenv NAME` per name | No file to leak or remove |

**Key insight:** the five liveness signals existed because the runner was a free-floating process. Under a unit,
systemd owns "is it running", the cgroup owns "kill everything", and one lock owns "is DevFlow's runner alive". Each
extra signal kept would reintroduce combinations to test.

## Common Pitfalls

### Pitfall 1: Invalid environment names fail every launch
**What goes wrong:** `start` fails with `Cannot assign environment variable BAD%NAME: Invalid argument` (measured).
**Why:** bash exports functions as `BASH_FUNC_name%%`, and systemd rejects any name outside `[A-Za-z0-9_]` that
starts with a digit [CITED: systemd.exec(5) Environment=].
**How to avoid:** filter names before building `--setenv` arguments; unit-test the filter with a planted bad name.

### Pitfall 2: A stop that reads as a stage failure (D-04b)
**What goes wrong:** the agent dies of the unit's SIGTERM, and the runner classifies exit 143 before its own stop is
recorded.
**How to avoid:** Pattern 4. Drain synchronously on the waiting thread, and give a signal-death a bounded grace.
**Warning signs:** a `stopped` test that passes only some of the time; a `stage_failed` event after `devflow stop`.

### Pitfall 3: The lock frees before the cgroup is empty (D-07a)
Measured window: 4.5 s of `deactivating` with `TimeoutStopSec=4`. A `discard` that trusts the lock alone deletes the
worktree under a still-running descendant. Gate every delete and relaunch on `ActiveState == inactive`.

### Pitfall 4: `is-system-running` as the availability probe
It returned `degraded` with rc 1 on this healthy host. Use `systemctl --user show -p Version --value`. Measured: rc 0
printing `262.1-1.fc45`. Negative control: with `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` unset, rc 1 and
`Failed to connect to user scope bus via local transport: $DBUS_SESSION_BUS_ADDRESS and $XDG_RUNTIME_DIR not defined …`.

### Pitfall 5: Probe-and-fork races in in-process tests
**What goes wrong:** a probe's own shared lock, duplicated into a child another test thread forks, reads held
(999.221, 999.236).
**How to avoid:** run lock tests under nextest, which gives each test its own process. Keep `try_lock_past_probes`'s
50 ms wait.

### Pitfall 6: Host service tests that scrub too much
Fixtures point `HOME`/`XDG_*` at scratch, but `systemctl --user` and `systemd-run --user` need the real
`XDG_RUNTIME_DIR` (and `DBUS_SESSION_BUS_ADDRESS`). Without them: `Failed to connect …` (measured). Pass those two to
the `systemd-run`/`systemctl` `Command`, and pass the test's scratch `HOME`/`XDG_CONFIG_HOME`/`DEVFLOW_CACHE_DIR` to the
unit by name or value, as the spike did with `--setenv=NAME=value`. Test values are not secret.

### Pitfall 7: Units leaked by a failed test
Give every test unit a name with the test's pid and phase, as the spike did (`devflow-spike-{pid}-{phase}`). Stop it
in a `Drop` guard by recorded name (`systemctl --user stop`, then `reset-failed`). Assert `LoadState=not-found`
afterwards. Never stop units by pattern.

### Pitfall 8: Zero-test false green in the `service` target
The service tests must not run under `all`. With `#[ignore]` plus `cargo test -- --ignored`, a mistyped filter runs 0
tests and exits 0. Use `cargo nextest run -p devflow --test <service file> --run-ignored only --no-tests=fail`, and make
the first assertion of each test that the user manager answers, so "no manager" fails instead of skipping. Note that
`check.sh`'s header says it is "Deliberately NOT parameterised by environment"; the `service` case keeps that.

### Pitfall 9: `start` printing success before the runner is real
Release the phase holder only after `systemd-run` returned 0. On a non-zero return, clear the reservation exactly as
today's failed launch does (`abandon_reservation`, pipeline_launch.rs:2110) and print the unit name with systemd-run's
stderr (D-04a). `systemd-run` returns at READY, so a runner that dies after READY is a `crashed` run that `status`
reports, not a launch failure.

### Pitfall 10: doc_check both directions
Removing a `DEVFLOW_*` read leaves its documentation behind, and `doc_referenced_identifiers_exist_in_source` fails.
Removing `Recover` while the docs still say `devflow recover` fails the same test. The same holds for the
`.devflow/phase-NN-agent-pid` path rows.

## Code Examples

### Bounded wait for the unit to read inactive (D-07a; shape, not compiled)
```rust
/// Wait until `unit` reads inactive, at most `bound`. A systemctl failure is an
/// error, never "inactive".
fn wait_unit_inactive(unit: &str, bound: Duration) -> Result<(), CliError> {
    let deadline = Instant::now() + bound;
    loop {
        let out = Command::new("systemctl")
            .args(["--user", "show", "-p", "ActiveState", "--value", unit])
            .output()?;
        if !out.status.success() {
            return Err(CliError::Message(format!(
                "could not read unit {unit}: {}", String::from_utf8_lossy(&out.stderr).trim())));
        }
        match String::from_utf8_lossy(&out.stdout).trim() {
            "inactive" | "failed" => return Ok(()),
            state if Instant::now() >= deadline => return Err(CliError::Message(format!(
                "unit {unit} is still {state} after {}s; run `devflow stop` or wait", bound.as_secs()))),
            _ => std::thread::sleep(Duration::from_millis(200)),
        }
    }
}
```

|---------------|---------|-----------------|
| V2 Authentication | no | — |
| V3 Session Management | no | — |

|---------|--------|---------------------|
