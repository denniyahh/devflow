# Phase 52.2 Plan 09: status and logs on the one liveness answer Summary

**`devflow status` now lists every phase its state, runner-lock and gate files name, one row each (`phase N: live — … devflow stop --phase N`, `crashed — … resume … discard`, `debris`, `unloadable`, `idle`, …) built on `runner_liveness` then the state; the banner offers approve/reject only to a gate with a live waiter; and `logs -f` ends with the run's state line, including after a hard kill that left no exit file.**

## Accomplishments

- `RunStatus` (Live, Stopping, Finished, Stopped, Crashed, Idle, Debris, Unloadable, Error) with `word()` and `line(phase)`, and `run_status(project_root, phase, &Existing) -> Option<RunStatus>`; `None` is a phase with nothing on disk but a free lock.
- `status_phases` reads `.devflow/` (for `.runner-NN`) and `Gates::dir` by name, NotFound as empty and any other read error as an Err that `status` prints; the state half is `workflow::state_file_phases`. `stage: idle` prints only when no phase has a row.
- `status` prints the row first, then the loaded state's detail lines (stage, agent, started, run, fallback, write lock, progress, last action); the agent-pid line, the supervisor probe line and the hint lines are gone.
- The banner keeps each gate's context and, per `Gates::waiter_status`: Live gives approve/reject, Absent a debris line naming `devflow discard --phase N`, Err an error line with no answer.
- `logs -f`: on the exit file, `post_exit_line` (60 s bound, 500 ms poll) waits until the run leaves the followed stage, then prints the row; a quiescent poll with the runner NotLive prints the row and ends; a liveness error ends non-zero naming it.
- Deleted: `status_supervisor_lines`, `status_hint_lines`, `status_hints`, `recovery_hints`. Kept: `orphaned_agent_line`, `live_phase_agent`, `no_supervisor_live` and `probe_phase`, which `doctor` and `phase_run_liveness` still call (52.2-11 and 52.2-23 remove them). No file under `crates/devflow-core/` changed (`git diff --stat 6548d85..HEAD -- crates/devflow-core` is empty), so no semver check applies.
