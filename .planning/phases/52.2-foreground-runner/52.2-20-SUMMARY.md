## Accomplishments
- `HermeticHome::new` writes three POSIX sh fakes into `service-bin/`. `systemctl` handles `--user show -p Version --value`, `--user show -p ActiveState --value U` (marker files `U.fail` and `U.deactivating`) and `--user reset-failed U`. `systemd-run` and `loginctl` handle nothing yet; plan 52.2-06 extends them. Any unhandled call exits 1 with `fake <tool>: unhandled: <args>`.
- `hermetic_devflow` sets PATH to `service_bin:<parent PATH>`. `HermeticPath::hermetic_path(X)` sets `service_bin:X` and panics with `hermetic_path needs a command built by common::hermetic_devflow` when the command's PATH does not start with the fake dir.
- `host_service_devflow` gives the same HOME/XDG/GIT isolation with the caller's PATH and user-bus variables; its doc restricts it to `service_e2e.rs`.
- The R-13 plain-Command control in test_home_isolation gets the fakes through `with_fake_service_manager` and keeps its real HOME and cache variables.
- 27 PATH sites converted: test_home_isolation 1, phase7_cli 19, doctor_antigravity 2, fallback_agent_config 1, start_reachability_e2e 2, gate_notify_persist_e2e 2. None of the six files keeps a `.env("PATH"` call (checked by `rg` exit status 1 on each).
