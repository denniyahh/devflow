### WR-02: `manager_available` treats any exit-0 `systemctl` as a live manager

**Files modified:** `crates/devflow-cli/src/service.rs`
**Commit:** 5a75347
**Applied fix:** the Version probe counts as an answer only when its stdout starts with an ASCII digit, which is `check.sh`'s rule. An exit-0 probe without a version goes to `classify_unanswered` with "exited 0 but printed no version: <stdout>". `unit_active_state` passes its stdout through `active_state_reading`, which accepts only systemd's eight `ActiveState` values and reports any other text as a read error that names the unit.
**Tests:**
- `service::tests::a_version_probe_answers_only_with_a_version`. RED: `an exit-0 notice with no version was read as a manager's answer`. GREEN: 1 passed (control row: `257.9-1.fc45` is an answer). WR-04 renamed the function under test to `manager_major_version`; the test now asserts `None`/`Some(257)` and passed after that change.
- `service::tests::an_active_state_outside_systemds_set_is_a_read_error`. RED: `a shim notice was read as ActiveState: Ok("systemd is not running")`. GREEN: 1 passed (controls: `inactive`, `deactivating`).

### WR-03: `devflow logs -f` right after `resume` reads the previous stage's exit file

**Files modified:** `crates/devflow-cli/src/pipeline_launch.rs`
**Commit:** 794924e
**Status:** fixed: requires human verification (launch ordering)
**Applied fix:** the finding offered two fixes; this applies the first. `resume_with_fallback` calls `archive_prior_capture(&state, None)` under its phase holder, after the agent-binary check and before `launch_runner_unit`. This is the same archive the runner's `begin_runner_stage` makes, and it emits `capture_archived`. The runner's own archive then finds nothing and does nothing. An archive error fails the resume the way a launch error does: the run is marked stopped again, naming the error. The second fix (ignore an exit file older than the capture) was not used, because the stale exit file is written after its capture, so comparing their ages cannot tell the old stage from the new one.
**Test:** `pipeline_launch::tests::resume_archives_the_stopped_stages_capture_before_launch`
- RED: `resume left the stopped stage's exit file, which logs -f reads as the resumed stage's exit`
- GREEN: 1 passed. It also asserts exactly one `capture_archived` event. `resume_clears_stop_marker_and_advances_past_stop_point` still passes.
