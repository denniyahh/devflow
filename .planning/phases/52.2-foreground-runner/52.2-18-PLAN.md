  <action>
    Write scripts/repeat-named-test.sh (`set -eu`, POSIX sh). Its arguments are: a mode (`nextest` or `inprocess`), the cargo target arguments as one string, split on purpose, the test name, and a count; it refuses any other mode with a usage line. `nextest` mode runs `cargo nextest run <target> --no-tests=fail --retries 0 --status-level pass --final-status-level none --color never -E "test(=NAME)"` (all five flags are in `cargo nextest run --help` for the installed 0.9.152; `--retries 0` keeps a retried flake from reading as a pass, and `--final-status-level none` keeps the final summary from printing the PASS line a second time; explicit flags override any NEXTEST_* status variable). `inprocess` mode runs the whole target unfiltered, `cargo test <target>`, as 52.1 D-08 requires for 999.221/222/232: their races need sibling tests in one process, so a single `--exact` test would never reproduce them. It writes each run's stdout and stderr together (`2>&1`) to a file under `mktemp -d` and removes the dir on exit. A run passes only if cargo exits 0 and its output has exactly one matching line, per mode (addresses review concern codex-8: nextest prints no libtest lines). In `nextest` mode the matching line is one whose first whitespace-separated field is `PASS` and whose last field is NAME, nextest's reporter line `PASS [time] <binary-id> NAME`, which it writes to stderr. In `inprocess` mode it is a line equal to `test NAME ... ok`. NAME is the full path as each runner prints it. Otherwise the script prints `run I: named test NAME matched M times` or `run I: cargo exited E`, followed by the run's last 20 output lines on stderr. Each mode runs count times, prints `passed K of N`, and exits 1 on any failure. Set its exec bit with `git add` then `git update-index --chmod=+x`. Run it for each carried flake test under the runner that failed. That is `inprocess` for 999.221, 999.222 and 999.232; take the module-qualified names and their targets from the 52.1 SUMMARYs, for example `-p devflow --bin devflow` for the 999.221 test and `-p devflow-core --lib` for opencode's health_fails_closed_on_a_hung_probe. Confirm each full path with `--list` output first. Record per test: the reproduction result from its 52.1 SUMMARY, N, K, and that N passes bound nothing about a rate. The harness's own in-process checks use the smallest deterministic target, `-p devflow --test check_service_target`, which holds the single test check_sh_service_fails_naming_the_missing_user_manager from 52.2-03 (addresses review concern agy-8). A sibling test that fails or flakes in a larger target would print `cargo exited E` instead of `matched 0 times`, and the zero-match control would then fail for the wrong reason. The `nextest` mode's own missing-test control runs the same single-test target with a name that does not exist: nextest's `--no-tests=fail` refuses it, so the script must print `run 1: cargo exited` and the echoed `no tests to run` line and exit 1. Its positive run is the runner_e2e one below, which proves the PASS-line match on real nextest output.
  </action>
