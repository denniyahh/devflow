# Phase 52.2 Plan 06: Every run is a systemd user unit Summary

**`start` and `resume` now launch `devflow __runner` with `systemd-run --user` under the phase's unit name and return once it holds its lock, refusing per kind when no user manager answers; `devflow stop` stops that unit and reports from the state (stopped, finished, stopped during launch, unloadable, crashed), refuses while another verb holds the phase, and has no `--launch`.**

## Accomplishments
- `start`: manager check first (Absent adds the lingering hint, Unreachable names the bus variables, Failed says the manager did not answer, all with systemctl's stderr), then the phase holder, the D-07a wait for a stopping unit, the guards and the reservation, the prepared state, then `launch_runner_unit` while the holder is held. A failed launch clears the state and names the unit and systemd-run's stderr.
- `resume`: same order; every refusal and state write stays under the holder in `resume_loaded`, then an agent-binary check and the unit launch; a failed launch re-marks the run stopped.
- `stop`: no holder taken. Runner lock first; with it free, a held phase holder refuses with its pid; no live run is a no-op; otherwise `systemctl --user stop`, then `stop_outcome` (finished read before stopped).
- The runner's first step is `runner_first_step`, after `RunnerLoop` is engaged.
- About 1,500 lines of supervisor-era stop code deleted (`stop_launch`'s tree and every arm the plan listed, plus `stop_no_waiter_repair`); clippy reported nothing else unused.

## Deviations from Plan

**1. [Rule 3 - Blocking] In-crate unit tests that called `start`/`resume` were ported or deleted in this plan**
- **Found during:** Tasks 1 and 2.
- **Issue:** about 40 unit tests in commands.rs and pipeline_launch.rs asserted a detached supervisor record after `start` or `resume`. No later plan owns them, and `cargo test -p devflow --bin devflow` is a green gate here.
- **Fix:** tests whose subject carries assert the unit launch on the service double and bind `service::double::LaunchedRunners`; supervisor-mechanics tests are deleted with ledger rows.

**2. [Rule 2 - Missing critical] The cfg(test) runner harness has an idle mode and a full mode**
- **Issue:** running the whole runner in every unit test that resumes made tests race the runner's state writes (a Code gate opened under a test that asserted the gate closed).
- **Fix:** the harness child holds the runner lock and runs nothing by default; `double::set_full_runner(true)` runs `run_runner` (used by the argv-replay and rate-limit resume tests). The child gets PR_SET_PDEATHSIG SIGTERM.

**3. [Rule 2] `resume` checks the agent binary before launching the unit**
- **Issue:** without `launch_stage` in `resume`, a missing agent was found only inside the unit.
- **Fix:** `ensure_agent_binary` runs right before `launch_runner_unit`; a failure re-marks the run stopped (`resume_re_marks_stopped_when_launch_stage_fails_outright` keeps its name and passes).

**4. [Plan wording] `runner_first_step` refuses a pending gate instead of waiting on it**
- **Issue:** the plan says "gate pending: wait on it". No launcher hands the runner such a state (`start` writes a fresh state; `resume` clears `gate_pending` and closes the gates first), and re-attaching to a dead waiter's gate would need its question and handler, which the state does not hold.
- **Fix:** an error naming `devflow resume`, which the runner routes through `recover_failed_advance` like any other failed first step.

**5. [Rule 1 - Bug] Suites on the argv-scan reaper leaked fake-launched runners**
- **Found during:** the workspace run. 13 `devflow __runner` processes from failover_e2e outlived their tests with their roots deleted.
- **Fix:** `HermeticHome::drop` ends every runner the fake recorded (`a8b1e6d`). Re-running failover_e2e left no runner. The 13 leaked runners were SIGTERMed by their recorded pids, and the 13 `/tmp/.tmpXXXX/.devflow` dirs their stop records recreated were removed by exact path.

**6. Naming:** discard's existing helper was renamed `discard_waits_out_a_stopping_unit`, so `wait_out_a_stopping_unit` is the start/resume helper the plan names. `launch_stage` is `#[cfg(test)]` (only tests call it now; 52.2-11 folds it).
