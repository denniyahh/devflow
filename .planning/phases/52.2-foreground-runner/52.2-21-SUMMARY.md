## Deviations from Plan

### Operator-approved scope addition (2026-11-17)

**Hermetic children can no longer resolve a real agent CLI.**
- **Problem:** `hermetic_devflow`'s PATH was the fake service dir followed by the parent PATH, so a broken or missing agent stub fell through to the developer's real CLI (52.2-02: `~/.local/bin/codex` ran for about 16 s).
- **Change:** an `agent-guard/` dir per HermeticHome and `guarded_path` placement, described above. Names are read from the registry (`driver_for(kind).build_command` for every `AgentKind`), not copied from the operator's list. The registry launches `agy`, not `gemini`; `gemini` and `antigravity` (installed on this host under linuxbrew) are guarded as well.
- **Why not entries in service-bin:** service-bin is first on PATH, so an agent fake there would shadow every test's own stub.
- **Files:** crates/devflow-cli/tests/common/mod.rs, crates/devflow-cli/tests/test_home_isolation.rs
- **Commit:** 9ffbfdb
- deferred-items.md's entry is marked `status: resolved (52.2-21, commit 9ffbfdb)`.

### Other

- **Scan reports all offenders at once.** The first version stopped at the alphabetically first suite (auto_chain_leak_repair_e2e.rs), so it never named failover_e2e.rs, which the acceptance criterion expects the RED run to name. It now collects every offender and panics once with the list.
- **One PATH override allowed in test_home_isolation.rs.** The guard test must run a planted program on a synthetic PATH, so `run_on_path` keeps exactly one `.env("PATH", ...)`. The scan allows exactly that one there, the same way the raw-spawn scan allows the R-13 control.
