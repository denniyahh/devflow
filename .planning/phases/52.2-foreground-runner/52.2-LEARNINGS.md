# Phase 52.2 Learnings: Foreground Runner

## Decisions

### A run is a systemd user unit running a hidden `devflow __runner`
`start` and `resume` launch `devflow __runner` with `systemd-run --user` (Type=notify) under the phase's unit name and return once it holds `.devflow/.runner-NN`; the runner runs Plan, Code and Validate as its own children in one loop.

**Rationale:** Replaces the detached supervisor and its liveness machinery with one foreground process and a service manager that can hard-kill it.
**Source:** 52.2-01-SUMMARY.md, 52.2-02-SUMMARY.md, 52.2-06-SUMMARY.md

### Liveness is the runner lock, then the unit, nothing else
`cleanup`, `discard`, the start/resume launch guard and `doctor` ask `runner_liveness` alone; the agent pid file, supervisor sockets and the stateless liveness-lock sweep are removed.

**Rationale:** D-07: one source of truth for whether a run is live; the old readers could not see a runner unit at all.
**Source:** 52.2-26-SUMMARY.md, 52.2-04-SUMMARY.md

### devflow-core semver: accept-break, with a planned-removal gate
The operator chose accept-break (2026-11-16). A fixed-string removal list and `scripts/semver-planned-removals.sh` fail on any devflow-core removal no plan names; moved items keep their old path through `pub use`, and items no plan names stay even with no caller.

**Rationale:** Allows deleting the supervisor and recover modules while making every removal deliberate and reviewable.
**Source:** 52.2-12-SUMMARY.md, 52.2-24-SUMMARY.md

### A user manager that does not answer reads Absent only under the user's own runtime dir
An unanswered Version probe is Absent only under this user's `/run/user/<uid>` with no `systemd/private`; a timed-out probe is Failed, and every other unanswered case refuses with systemctl's stderr.

**Rationale:** Absent and Failed lead to different refusals; guessing Absent would hide a real manager fault.
**Source:** 52.2-04-SUMMARY.md

### start takes every refusal from one pure function in a fixed order
`launch_guards` orders the refusals: live runner lock, finished, incomplete, unloadable, orphan gate files, leftover worktree or branch; `--dry-run` runs the same guards over facts gathered without locks, so it prints the same first refusal.

**Rationale:** One ordering for start and its dry run; no refusal can be bypassed by a code path that checks a different subset.
**Source:** 52.2-14-SUMMARY.md, 52.2-15-SUMMARY.md

### No --force on start or cleanup; recover is removed
`start --force` and `cleanup --force` are gone (clap's own unknown-argument error), `recover` and devflow-core's `inspect_all`/`RecoveryStatus` are deleted, and `discard` takes over gate files and orphan hold temps.

**Rationale:** 52.1 D-09.1/D-11 and D-06: one verb per job, and `recover --clean` was found deleting a live runner's state.
**Source:** 52.2-10-SUMMARY.md, 52.2-13-SUMMARY.md, 52.2-16-SUMMARY.md

### A launch takes no reservation and the state records no launch
`State` lost `supervisor`/`pending_supervisor`; the phase holder keeps a second launcher out and the runner writes state through plain `update_state`/`clear_state`. Old state files with those keys still load (unknown fields ignored).

**Rationale:** With one runner lock per phase there is no second run to fence against.
**Source:** 52.2-25-SUMMARY.md

### A runner stop records stopped and exits 143
SIGTERM or SIGINT to the runner ends the agent's group, writes stop_reason `stopped by SIGTERM to the runner` and a `runner_stopped` event; a stop that reaches the agent first reads stopped, not a failed stage; the runner exits 1 for any other unfinished run.

**Rationale:** Carries the 52.1 stop orderings (gate, approval, hand-back, finish over a late stop) onto the runner.
**Source:** 52.2-05-SUMMARY.md, 52.2-08-SUMMARY.md

### Host-only service tests fail, never skip, and are a required check
`scripts/check.sh service` runs the `#[ignore]` user-unit tests or fails naming the missing manager; pre-push runs it on the host, and after it ran green on CI the operator made `Service tests (host user manager)` a required check on develop.

**Rationale:** A missing prerequisite must not read as a pass.
**Source:** 52.2-03-SUMMARY.md, 52.2-18-SUMMARY.md

### Push route for CI evidence: the filtered replay branch
The pre-push hook refuses `.planning/` on every `feature/*` branch, so the operator chose `feature/phase-52.2-pr` cut by `scripts/cut-pr-branch.sh`; the green CI commit is that replay (d3be8c7), with no crate source difference from 9de8b28.

**Rationale:** The plan's push target could never pass the hook.
**Source:** 52.2-18-SUMMARY.md

## Lessons

### A probe's exit code is not an answer
The pinned devcontainer image's `/usr/local/bin/systemctl` shim prints "systemd is not running" and exits 0, so an exit-code-only manager probe passed in the container. The probe now also requires output starting with a digit.

**Context:** Found by `scripts/check-in-container.sh all`, not on the host.
**Source:** 52.2-03-SUMMARY.md

### A missing or broken test stub falls through to the developer's real agent CLI
A failed exec of a bad-shebang stub let PATH search reach `~/.local/bin/codex`, which ran for about 16 s with the Plan prompt in a test repo. Hermetic children now get an agent-guard dir that stops any unresolved agent name.

**Context:** 52.2-02 found it; 52.2-21 added the guard as an operator-approved scope addition.
**Source:** 52.2-02-SUMMARY.md, 52.2-21-SUMMARY.md

### Old live checks are blind to a runner unit
Ported onto a live runner, `recover --clean` exited 0 and deleted the run's state, because its live check read the supervisor socket and agent-pid file, which a runner has neither of.

**Context:** Until the verb was removed in 52.2-10, a live run's state could be deleted.
**Source:** 52.2-07-SUMMARY.md

### A plan's premise needs a measured control
For Codex in auto mode the unattended-launch check refuses at Plan regardless of CONTEXT.md, so the planned control (commit a CONTEXT.md) still opened the gate; supervise mode was the real negation. In 52.2-19 the planned dirty-tree control's premise (52.1 D-15) did not hold either, and the operator used attempt 1 as the control.

**Context:** Both were found only by running the planned control.
**Source:** 52.2-11-SUMMARY.md, 52.2-19-SUMMARY.md

### Plan text left files and items out of files_modified
Many plans needed edits outside their list (main.rs for the exit code, libc moved from dev-dependencies, OPERATIONS.md made false by a change, test files no plan owned) or found a planned "move" with nothing to move.

**Context:** Recorded as Rule 2/3 deviations in most summaries; no plan was blocked by it.
**Source:** 52.2-02-SUMMARY.md, 52.2-04-SUMMARY.md, 52.2-15-SUMMARY.md, 52.2-23-SUMMARY.md, 52.2-25-SUMMARY.md

### The exhaustive verb x lock x state table finds what targeted tests miss
Walking all 78 cells of D-07's table found that `cleanup` passed over a held runner lock with no state and exited 0; it now keeps the phase and exits non-zero.

**Context:** No targeted test covered the held/none cell.
**Source:** 52.2-17-SUMMARY.md

### A deterministic failure can hide as a flake while two readers race
`phase7_cli::cleanup_worktree_cli_flow` failed 1 in 2113 in the workspace run and passed alone; once the supervisor reads were gone it failed alone every time, exposing the real race (cleanup refusing while the runner still held its lock).

**Context:** Fixed by waiting (bounded 10 s) for the lock to be free.
**Source:** 52.2-22-SUMMARY.md, 52.2-26-SUMMARY.md

### The proof run predates the review fixes
The live proof run used binary 1adab3a; the code-review fixes then changed start, resume and stop (6 crates files). Those paths were re-run against real user units with a fake agent, but no live proof run exists on the fixed code.

**Context:** Verification's own "evidence against the verdict"; reinstall before the next dogfood run.
**Source:** 52.2-VERIFICATION.md

## Patterns

### Fail-closed dead-code expectation for staged wiring
Items not yet called carry `#[cfg_attr(not(test), expect(dead_code, reason = "...52.2-06"))]`, which becomes a compile error once the named plan calls them.

**When to use:** Landing an API one plan before its caller, so the marker cannot outlive its reason.
**Source:** 52.2-01-SUMMARY.md

### Chain functions hand back the next launch
Launch-chain functions return `Result<Option<StageLaunch>, CliError>` (arms that end, wait or refuse return `Ok(None)`), and the runner loop decides with one type, `Settled { Next(Box<StageLaunch>), Exit(i32) }`.

**When to use:** Replacing spawn-from-inside with one owning loop that runs every stage.
**Source:** 52.2-02-SUMMARY.md, 52.2-05-SUMMARY.md

### Fake service manager first on every hermetic PATH
Fake `systemctl`/`systemd-run`/`loginctl` live in each HermeticHome's `service-bin/`; PATH overrides go only through `HermeticPath::hermetic_path`, enforced by a whitespace-insensitive source scan that reports every offending suite at once.

**When to use:** Any integration suite that spawns devflow and could touch the real user manager or a real agent.
**Source:** 52.2-20-SUMMARY.md, 52.2-21-SUMMARY.md

### Test ledger for removed tests
Every deleted test gets a ledger row (`subject removed` or `successor`), and `scripts/test-ledger-check.sh` proves the ledger by test name; the operator signed off all 342 `subject removed` rows.

**When to use:** A deletion-heavy phase where tests go with the code they covered.
**Source:** 52.2-07-SUMMARY.md, 52.2-19-SUMMARY.md

### Source scans move with the code they guard
When the stop primitives moved to `devflow_core::stop`, the forbidden signal/exit scan's helpers moved to `stop::tests` and a new scan with a planted control covers stop.rs; walk sentinels were repointed when their target file was deleted.

**When to use:** Moving code that a source-scan test guards by file path.
**Source:** 52.2-12-SUMMARY.md, 52.2-24-SUMMARY.md

### Named-test repeat harness for flake evidence
`scripts/repeat-named-test.sh` requires exactly one matching test per run (nextest PASS line or libtest ok line), runs in chunks under 8 minutes in parallel lanes, and reports N runs as N runs on one host.

**When to use:** Closing a flake backlog item with evidence rather than one green run.
**Source:** 52.2-18-SUMMARY.md

## Surprises

### The post-commit hook dirties the tree build.rs reads
`scripts/hooks/post-commit` leaves `.planning/user/errors/state-stale.json` modified, which build.rs counts as dirty (999.240), so the proof binary was built from a clean detached checkout of HEAD.

**Impact:** Every in-tree release build after a commit reads dirty.
**Source:** 52.2-19-SUMMARY.md

### The scratch dogfood repo was not clean after a run
999.238: the fixture repo left `.planning/state.json` and `.planning/milestone.lock` untracked; the operator chose fix (a), committing `.gitignore` lines for them.

**Impact:** The proof run's first attempt could not serve as the clean-tree case.
**Source:** 52.2-19-SUMMARY.md

### discard's orphan-temp sweep is directory-wide
`remove_orphan_hold_temps` sweeps every orphan temp in `.devflow/` and `.devflow/gates/`, so discarding one phase removes another phase's orphan hold temps (each named on its own line).

**Impact:** A phase-scoped sweep would need a new devflow-core item, outside the phase's semver list.
**Source:** 52.2-10-SUMMARY.md

### The removal gate only sees items the baseline has
Items this phase added and later removed (`spawn_signal_dispatcher`, `StopToken::begin_agent`, `liveness::boot_id` at its new path) never print in the planned-removal gate.

**Impact:** Their removal is checked only by each plan's own acceptance.
**Source:** 52.2-12-SUMMARY.md

### Roughly 40 in-crate unit tests asserted the detached supervisor
Unit tests in commands.rs and pipeline_launch.rs asserted a supervisor record after `start`/`resume`, no later plan owned them, and running the full runner in each made tests race its state writes, so the cfg(test) harness gained an idle mode.

**Impact:** 52.2-06 ported or deleted them with ledger rows and added `double::set_full_runner`.
**Source:** 52.2-06-SUMMARY.md

### Status still lists a crashed run as active, and text still says "supervisor"
`status` prints the state record's `run: active` under a row that says crashed (deferred), and user-facing text still says "supervisor" (999.239).

**Impact:** Wording and display only; left for follow-up.
**Source:** 52.2-09-SUMMARY.md, 52.2-VERIFICATION.md
