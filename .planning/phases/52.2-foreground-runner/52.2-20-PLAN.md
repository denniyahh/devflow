<objective>
Make the test fakes for the user manager impossible to bypass before any verb calls the manager. Plan 52.2-04 is the first to call `systemctl` from `start`, `discard` and `cleanup`, and plan 52.2-06 the first to call `systemd-run`. Today 40 `.env("PATH", ...)` calls in 13 suites replace the child's PATH (counted at 2ac5d56: phase7_cli 19, supervisor_e2e 4, start_lock_e2e 3, gate_notify_persist_e2e 2, failover_e2e 2, start_reachability_e2e 2, doctor_antigravity 2, and 1 each in test_home_isolation, stop_e2e, pending_supervisor_e2e, gate_wedge_e2e, fallback_agent_config and auto_chain_leak_repair_e2e). Any of them would drop a fake put on PATH, so the child would reach the real manager on the host and fail in the container. This plan adds the fakes, the PATH helper and the first six conversions. Plan 52.2-21 converts the other seven suites and adds the source scan that keeps the count at zero.

Purpose: required property of review round 1: no test outside `scripts/check.sh service` reaches the real user manager (D-07b: the container runs everything else without one).
Output: the fakes and helpers in common/mod.rs, a tracer test, and six converted suites.
Spec-less phase: truths derive from CONTEXT.md decisions.
</objective>

  </behavior>
  <action>
    In common/mod.rs: HermeticHome::new creates a `service-bin` dir inside its tempdir, reached through `HermeticHome::service_bin()`. Write three POSIX sh fakes there. `systemctl` handles `--user show -p Version --value` (prints a version), `--user show -p ActiveState --value U` (reads marker files in its own dir: `U.deactivating` prints deactivating; `U.fail` exits 1 printing a bus-error text; otherwise prints inactive), and `--user reset-failed U` (exit 0). `systemd-run` and `loginctl` handle nothing yet. Every unhandled call exits 1 printing `fake <tool>: unhandled: <args>` to stderr; plan 52.2-06 extends the fakes. hermetic_devflow sets PATH to `service_bin` followed by the parent's PATH. Add `pub trait HermeticPath` implemented for Command, with `fn hermetic_path(&mut self, path: impl AsRef<OsStr>) -> &mut Command`. It reads the command's own PATH (through get_envs), checks that its first entry is a dir holding the fake `systemctl`, and sets PATH to that entry followed by `path`. When the command has no such entry it panics: `hermetic_path needs a command built by common::hermetic_devflow`. Add `host_service_devflow(home)`: the same HOME, XDG and GIT scrubbing as hermetic_devflow, but PATH, XDG_RUNTIME_DIR and DBUS_SESSION_BUS_ADDRESS stay the caller's, with no fake dir. Its `///` doc says that only service_e2e.rs may use it, because that suite runs under `scripts/check.sh service` against the real manager. In test_home_isolation.rs, add_start_args calls `.hermetic_path(...)` instead of `.env("PATH", ...)`. The R-13 plain-Command control gets the fake dir through a `common::with_fake_service_manager(&mut command, &home)` helper, which puts service_bin first and touches nothing else, so its HOME and cache variables stay real. Then write the tracer test.
