# Phase 52.2 Plan 10: remove `recover`, extend `discard` Summary

**`devflow discard --phase N` now lists and removes the gate files and orphan hold temps a killed run leaves (a gate-only phase included) and refuses a gate whose waiter is live; the `recover` verb and devflow-core's `inspect_all`/`RecoveryStatus` are gone, and a source scan keeps every production string, doc and help line from naming it.**

## Accomplishments

- `discard_debris` reads the phase's gate files (`Gates::dir` names starting `NN-`, or `.NN-` for write temps, with a stage that parses; set-aside answers skipped) and its hold temps, probing each `*.waiter` with `liveness::probe`: held or unprobeable refuses with `its {stage} gate has a live waiter (…) … nothing was removed`. `remove_discarded_debris` closes each stage with `Gates::close`, prints `removed gate file` per path gone and a warning per path left, then sweeps `.devflow/` and `.devflow/gates/` with `remove_orphan_hold_temps` and prints each removed temp. The listing names both before any removal. `.holder-NN` and `.runner-NN` are never listed.
- `Command::Recover`, its dispatch, `recover_cmd` and its only helper `refuse_a_live_supervisor` (with the test helper `plant_previous_boot_launch` it orphaned) are deleted. In core, `inspect_all`, `inspect_state` and `RecoveryStatus` with their three unit tests; `format_age` and every other item stay. `CliError::Recover` stays: its `From` still converts core errors.
- `log_format_env` drives `devflow discard --phase 1` on a fixture that is now a git repository (discard lists worktrees); both tests keep their names and the DEBUG `loading state from` line still proves the load. The two `gate_wedge_e2e` recovery runs run `discard`, after `git switch develop` (discard refuses a branch the primary checkout holds; the advance arm also names its unmerged branch).
- Repair text: `no_waiter_repair` names `resume` or `discard`; the write-lock hold note drops its recover case (its unit test drops `13 s while`); doctor's write-lock line names `devflow discard` only; the agent-pid guidance names the pid file and discard (deviation 2). README's command table swaps `recover` for `discard`; OPERATIONS.md loses the recover row and bullet and describes discard's debris removal; ARCHITECTURE.md's hold note and repair-verb line follow.
