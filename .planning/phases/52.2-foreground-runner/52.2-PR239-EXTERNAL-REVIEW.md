## Disputed / dismissed (with reason)

- agy: `discard` removes state under a stopping runner — false: `RunnerStopping` is waited out (`wait_unit_inactive`) and re-read before anything is removed (commands.rs ~2113-2128).
- agy: `logs -f` exits after the first stage — documented design (D-10: it ends when the agent's exit lands and prints the run's state line).
- agy: `discard` drops uncommitted work — documented: discard lists what it removes; pi checked this as fine.
- agy: failed resume loses the `--until` cap — only when the cap had fired and the operator is overriding it, which is the intended clear.
- pi: verbs refuse when `XDG_RUNTIME_DIR` is unset — deliberate (D-03): only positive evidence of no manager (Absent) lets the lock answer alone; an unreachable manager refuses.
- pi: a `__runner` started outside a unit cannot be stopped by `stop` — internal verb, not an operator path.
- codex/agy: `run_bounded` reads output after exit (background child holding the pipe, > 64 KB output) — speculation; the callers are systemctl/systemd-run with one-line output and no `--pipe`.
- agy: `start --dry-run` waits up to 15 s on a stopping unit — true by code, but harmless and consistent with start's guard facts.

The base-branch half needs no separate change: a phase with a state keeps its branch whatever trunk it is judged against. RED 339f70c (`cleanup_keeps_the_merged_branch_of_a_kept_state_only_run` failed: branch swept), GREEN cca1b17; control `cleanup_sweeps_the_same_merged_branch_when_no_state_names_it` passes at both.

Shared by `start` and `resume` through `launch_runner_unit`; documented in OPERATIONS.md, Run shape.
