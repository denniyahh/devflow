# Phase 52.2 Plan 04: Runner liveness and the D-07a unit wait Summary

## Accomplishments
- `runner_liveness`: runner lock first (probe error refuses), then `manager_available` (Absent prints the runner-lock-only note and reads no unit; Unreachable and Failed refuse), then the unit's `ActiveState` (`inactive`/`failed` NotLive, anything else Stopping).

- Every `systemctl` call runs through `run_bounded`; in unit tests `service::tool` panics and the readers use the thread-local double.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] libc was a dev-dependency only**
- **Found during:** Task 2
- **Issue:** The plan says libc is already a CLI dependency, but `crates/devflow-cli/Cargo.toml` listed it only under `[dev-dependencies]`, so production `libc::getuid()` would not compile.
- **Fix:** Moved `libc = "0.2"` to `[dependencies]`, which still covers the test reapers. No new crate: devflow-core already depends on libc 0.2, and `Cargo.lock` is unchanged.
- **Committed in:** 35b95c3

**2. [Ordering] manager_available landed in Task 2, not Task 1**
- **Issue:** Task 1's action lists manager_available among the service.rs additions, but nothing calls it until Task 2's runner_liveness. Adding it in Task 1 would have left dead code.
- **Fix:** Added with its only caller in 35b95c3. Behavior is the same as planned.

**3. [Test shape] start test uses codex in supervise mode**
- **Issue:** In auto mode, codex stops at the unattended-prerequisites gate and claude runs the delivery canary. Either way start never reaches the launch guard, so the RED failed for the wrong reason.
- **Fix:** `--agent codex --mode supervise`. The test also gets `LaunchedRunReaper` and `DEVFLOW_GATE_TIMEOUT_SECS=1`, so a run that launches by mistake is reaped.

**4. [Test shape] the bounded-call kill test runs `sh -c 'echo $$ > pidfile; exec sleep 30'`**
- **Issue:** `run_bounded` takes a Command and does not expose the child's pid, which the ESRCH check needs.
- **Fix:** sh writes its own pid and then execs sleep, so the pid is the same process.

**5. [Test shape] the Absent child test sets `RUST_TEST_NOCAPTURE=1` on the child**
- **Issue:** libtest captures a passing test's stderr, so the parent would never see the note.
- **Fix:** The child runs with that variable set, and the parent reads its stderr. The variable is not `DEVFLOW_*`, so doc_check is not involved.

**Total deviations:** 1 blocking fix and 4 changes to ordering or test shape. **Impact:** no scope change.
