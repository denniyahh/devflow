# Phase 52.2 Plan 16: cleanup removes only what is provably safe Summary

**`devflow cleanup` has no `--force`: it walks each phase under its holder, waits out a stopping unit as `discard` does, and removes a finished run, a dead start's reservation or a stateless worktree only when its branch is merged into its base, its worktree is clean and no run is live; everything else it keeps with a line naming `devflow discard` (and `devflow resume` for an incomplete run), and a phase whose liveness cannot be read is kept and makes the exit non-zero.**

## What changed

- `Command::Cleanup` lost its `force` field; `cleanup --force` now gets clap's `unexpected argument '--force'` (pinned in `phase7_cli::removed_flags_are_unknown`).
- `cleanup` (commands.rs) drives the pass by `worktree::list` as before, resolving each `.worktrees/` entry's phase by `state_for_worktree` else `phase_from_worktree_path`, then visits every phase `workflow::state_file_phases` names that no worktree resolved to. Per phase: `claim_foreground_holder`, the state re-read under the write lock, then `cleanup_liveness`. The interim refusal 52.2-04 left (refuse a deactivating unit, abort the pass) is gone.
- Rule for a phase worktree with no live run: an incomplete run (stopped, or prepared and not finished) is kept naming `devflow resume --phase N` and `devflow discard --phase N`; anything else is removed with its state only when `commits_not_in_develop` against the run's base is 0 and `uncommitted_changes` (unchanged: it counts untracked files) is 0, else kept with each reason and `devflow discard --phase N`. The removed worktree's merged `feature/` branch is deleted.
- Rule for a state-only phase: a dead start's reservation has only its state removed; every other state, and an unloadable one, is kept naming `devflow discard` (and `devflow resume` when incomplete). The branch is never touched.
- `.holder-NN` and `.runner-NN` are never removed (asserted in four tests).
- Removed as orphans of the change: `kept_unmerged_branch`, `kept_stopped_worktree_line`, `stop_e2e`'s `LiveRun::start_in_a_worktree`.
