## What changed

- **Table test** (`commands::tests::every_verb_follows_the_lock_and_state_table`). Runs in a hermetic child of its own; each cell gets a scratch git repo, plants its state (Codex, Supervise), and holds the runner lock or the phase holder in a further child of the same test (`hold_in_a_child`, released by a marker file). Each verb runs through its library function: `start`, `pipeline_launch::resume`, `discard`, `stop_report`, `cleanup`, and `status` plus `run_status`'s word. A cell checks the result text, the launch count, the `stop_unit` count and the state file's bytes, and every mismatch is collected and printed as `Verb x Lock x State: expected ..., got ...`.
- **Service double additions** (service.rs, cfg(test)): `double::register_stop_target(unit, child)` records a lock-holding child for the cfg(test) `stop_unit` to end without counting a launch (`launched_units` unchanged), the function the plan asks to name; `double::stop_calls()` counts `stop_unit` calls, needed for the "no stop_unit call" assertions. `end_runners` ends registered children too.
- **`stop_report`** (commands.rs): `stop`'s body now returns the line it prints; `stop` prints it. No behaviour change.
- **cleanup** (commands.rs, GREEN): `runner_lock_phases_not_free` lists phases whose `.runner-NN` is held (or does not probe); cleanup visits those no worktree or state file named, and `cleanup_phase` reads liveness before calling a stateless phase untouched. The keep line names the runner lock file. OPERATIONS.md's cleanup row says a held runner lock keeps a phase with no run state or worktree too.
- **Concurrency tests**: `run_liveness_e2e::two_concurrent_starts_launch_one_run_and_refuse_the_other` and `run_liveness_e2e::start_racing_discard_never_leaves_a_run_without_its_worktree` take the phase holder in the test process with `claim_phase_holder` and run `devflow` as a child (review r3 codex-5). The racing test adds a fourth step, the holder held again over a launched run, so "worktree and state remain" is checked over a real worktree. `service_e2e::status_reads_live_for_a_service_run_after_start_returned` (host) adds a control: after `systemctl --user stop` status no longer reads live.
- **UnitGuard flake** (service_e2e.rs, deferred-items): the drop polls `LoadState` for `not-found` for up to 10 s instead of reading once.
- **Scans** (`removed_surface_scan.rs`): shared counting helpers (`cli_lines_offering_force`, `doc_lines_offering_force`) run on planted text and on the real files. RED found `ARCHITECTURE.md:373` and `docs/guides/configuration.md:27`, the `--force` start flag rows. Both rows are gone; each table is followed by a sentence that `start` removes nothing and its refusal names `devflow discard --phase N` (and `devflow resume --phase N` over an incomplete run). Comments in pipeline_outcomes.rs (two) and state.rs (one) no longer describe `start --force` as current; agent_result.rs:3690's dated incident note is history and stays.
