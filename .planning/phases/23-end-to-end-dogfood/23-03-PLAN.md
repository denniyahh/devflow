and `find` archaeology. This is the enumeration half of re-aimed unit **23b**
(bound gate lifetime); plan 23-04 adds the reaper that acts on what this plan

`find` because there is no cross-root state anywhere in this codebase —
confirmed this session by `rg` for `cache/devflow|roots.json|dirs::|home_dir`
across `crates/`, which returns **zero** production hits. 27 orphaned monitor

(`gate_show`, `gate_respond`, `doctor`) inherits that scope.

existing launch path, and `devflow gate list --all-roots`.

The module owns a machine-global list of currently-active DevFlow project roots. Public surface:

Registration is best-effort observability, never a reason to fail a launch. Do not move, reorder, or otherwise alter any existing statement in that function.

  <action>
Replace `register_in`'s direct `std::fs::write` with an atomic write: serialize to a temp path adjacent to the roots file, then `std::fs::rename` over the target. This is the same shape `gates.rs::write_atomic` already uses, and it matters here because `devflow parallel` can launch several phases within milliseconds of each other, each calling `register_in`.

Before the first write, create the cache directory if absent and set its mode to `0o700` using `std::fs::set_permissions` with `std::os::unix::fs::PermissionsExt`. The registry names every project this user is currently running; on a shared host that is information disclosure (threat T-23-33 below). Reuse the same rationale D-09 recorded for the socket directory.

Add `pub fn prune_missing_in(cache_dir: &Path) -> usize` and a thin `pub fn prune_missing() -> usize` wrapper. It loads the current list, drops every entry whose `project_root` does not exist as a directory, writes the survivors back atomically, and returns the number dropped. The forensics record is explicit that dead roots are the normal case, not the exception: the orphan population included monitors whose build trees and worktrees had already been deleted.

Call `prune_missing_in` from `load_roots_in`? No — keep them separate. `load_roots_in` must stay side-effect-free so a read-only command cannot mutate machine state; pruning is invoked explicitly by its callers (the sweep in plan 23-04, and `gate list --all-roots` which may call it before rendering).
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → devflow-core | `~/.cache/devflow/roots.json` is read by every `--all-roots` invocation; its contents are attacker-influenceable by any process running as this user |
| registry entry → `Gates::list_open` | a registered `project_root` becomes a path DevFlow will `read_dir` on behalf of the operator |
| local multi-user host → cache dir | the registry names every project this user is currently running |
