<objective>
Build the supervisor process itself: the run loop that owns the agent, and the
`devflow` subcommand that *is* the supervisor.

This is where D-10 — the phase's single most load-bearing property — lands.
Today `monitor.rs:138-147` builds a shell string ending
`; {binary} advance {project_root} --phase {phase}`, a **separate forked
process**. That process is exactly what Phase 17's incident orphaned: the shell
trap only ever tracked the agent pid, so a signal arriving during the tail had
nothing to kill. Because the supervisor becomes `devflow` itself, it calls the
advance logic directly and then exits. **There is no tail process left to
orphan.** The original failure mode is removed by construction, not by better
signal handling.

**R-M is enforced by the type system here, not by a flag.** `serve` returns
`SupervisorExit`, whose `Stopped` variant carries no exit code and therefore
gives the caller nothing to advance with. A stopped phase cannot advance its own
state machine because the shape of the return value makes it unexpressible —
which the spike audit calls out as "a genuine behavioural improvement, not just
parity."

**Note on D-08's big-bang.** This plan *adds* the new path while the `sh -c`
path still exists; plan 23-07 deletes the old one and swaps the call site. That
is a two-commit landing sequence, **not** a dual-path period: there is no
feature flag, no config toggle, and no run in which an operator could choose
between the two. Nothing calls `serve` until 23-07 rewires
`pipeline_launch.rs:126`. D-08 forbids running both process models behind a
toggle; it does not require the addition and the deletion to be one commit.

Purpose: make the supervisor a real, tested Rust process before anything
depends on it.
Output: `monitor::serve`, the hidden `devflow supervise` subcommand, in-process
advance, signal handling, and fake-agent integration coverage of every
R-A..R-M parity item that does not require a real agent.

## Recorded decision — Claude's Discretion item #1: supervisor signal handling

**DECIDED: land it in 23b (this plan), not deferred.**

CONTEXT.md left this to the planner and required an explicit, recorded call.
The spike installs no handler, so a SIGTERM to the supervisor kills it without
cleanup and leaves a stale socket. That degrades *correctly* — the sweep finds
it and the pgid backstop reaps the group — but "degrades correctly" here means
the operator's agent keeps running unsupervised until someone notices, which is
a milder version of the exact Phase 17 incident this phase exists to close.

It is landed now because it is cheap in this design and expensive later: the
run loop built in Task 1 is a non-blocking poll, so a handler that does nothing
but set an `AtomicBool` the loop already checks each iteration costs a dozen
lines and reuses the teardown path verbatim. Deferring it would mean revisiting
the loop's structure in a later phase to make it interruptible.

Add the supervisor run loop to `monitor.rs`. This code runs **inside** the
supervisor process; it does not spawn one (plan 23-07 adds `spawn_supervisor`).

**`SupervisorConfig`** — a plain public struct carrying everything the loop
needs, so `serve` reads no globals: `socket_path: PathBuf`, `workdir: PathBuf`,
`stdout_path: PathBuf`, `stderr_path: PathBuf`, `pid_path: PathBuf`,
`exit_path: PathBuf`, `program: String`, `args: Vec<String>`,
`envs: Vec<(String, String)>`, `shutdown_grace: Duration`.

**`SupervisorExit`** — public enum, `NaturalExit(i32)` and
`Stopped(StopSource)`; **`StopSource`** — public enum, `Socket` and `Signal`.
This shape is the R-M enforcement: `Stopped` carries no exit code, so a caller
holding it has nothing to advance with. Do not add a `bool` alongside — the
point is that the suppression is not a flag someone can forget to check.

**`serve(cfg: SupervisorConfig) -> Result<SupervisorExit, MonitorError>`**:

1. **Takeover safety.** Probe `socket_state(&cfg.socket_path)` first. `Alive`
   → return `MonitorError::LiveSupervisorOwnsSocket`; never steal a socket a
   live supervisor owns. `Stale` → remove the file and continue. `Gone` →
   continue.
2. Ensure the socket's parent directory exists (plan 23-05's
   `supervisor_socket_dir` already creates it at 0700), `UnixListener::bind`,
   then set the socket file to **0600**, then `set_nonblocking(true)` on the
   listener so the loop can poll it alongside the child.
3. Create the stdout and stderr files (separate files — R-B: stderr must never
   corrupt the JSON stdout capture DevFlow parses for its result marker).
4. Spawn the agent: `Command::new(&cfg.program)` with `cfg.args`,
   `.current_dir(&cfg.workdir)` (R-A: the worktree, not the project root),
   `.stdin(Stdio::null())`, stdout and stderr from the two files,
   `.process_group(0)` (whole agent subtree in one killable group, and — because
   the agent becomes its own group leader — its pid *is* its pgid, which is what
   plan 23-07's `spawn_supervisor` records), and every pair in `cfg.envs`
   applied with `.env(k, v)` (R-F: adapter-scoped env must reach the agent and
   its grandchildren).
5. Write the agent pid to `cfg.pid_path` (R-C).
6. **Install the signal handlers** — a module-level `static AtomicBool`, and an
   `extern "C"` handler registered for `SIGTERM` and `SIGINT` that does exactly
   one thing: store `true`. A plain atomic store is async-signal-safe;
   allocating, locking, formatting or logging inside a signal handler is not, so
   the handler must contain nothing else.
7. **Poll loop**, ~25-50 ms per iteration, checking three things each pass, in
   this order:
   - `child.try_wait()` returned `Some(status)` → natural exit. Compute the code
     as `status.code()`, falling back to `128 + signal` for a signal death
     (shell convention, R-D). Write it to `cfg.exit_path`. Remove the socket
     file. Return `SupervisorExit::NaturalExit(code)`.
   - the signal flag is set → teardown via the shared path below, returning
     `SupervisorExit::Stopped(StopSource::Signal)`.
   - a connection is pending on the non-blocking listener → accept it, read one
     line with a read timeout, and dispatch: `ping` answers a single line
     naming the supervisor pid and the agent pid; `shutdown` runs the shared
     teardown and returns `SupervisorExit::Stopped(StopSource::Socket)` after
     replying `stopped`; **anything else answers `unknown <input>` and is
     otherwise ignored** — never parsed further, never executed (ASVS V5). A
     `WouldBlock` from `accept` is the normal no-connection case, not an error.
8. **Shared teardown path**, used identically by the socket command and by a
   signal: `libc::killpg` the agent's group with `SIGTERM`, poll for the child
   for `cfg.shutdown_grace`, escalate to `SIGKILL` and reap if the grace
   expires, write `143` to `cfg.exit_path` (R-K: teardown still records a
   definite outcome, never silence), remove the socket file. Do **not** run any
   advance-shaped work here.

Every fallible call propagates with `?` against `MonitorError`. No
`.unwrap()`/`.expect()` outside `#[cfg(test)]`. `serve` must not call
`std::process::exit` — the spike does, because it is throwaway proof code;
production returns so the caller can decide what happens next, which is exactly
what R-M depends on.

Add unit tests in `monitor.rs`'s own test module for the pieces that need no
child process: the `unknown` dispatch answering without acting, and the
takeover refusal when the socket is `Alive`. Everything requiring a real agent
belongs in Task 2.
