## Assumption-Delta Architecture Checkpoint (advisory, non-blocking)

The detector fired on a `pluralization` signal (`"prerequisite for onboarding
any second agent"`). The transition in this phase is the **inverse** of the
usual trigger: this plan *removes* the second-agent path rather than adding
one. That is still the same identity-model question.

- **Noun that is now primary:** **one agent per phase.** After this plan, a
  DevFlow phase has exactly one agent identity for its whole lifetime. There is
  no "slot A / slot B", no in-process handoff, and no token-exhaustion failover
  to a second agent. `devflow parallel` remains, but it is N *phases*
  concurrently — each still single-agent — not N agents per phase.
- **Decision: `promote`.** Single-agent is promoted from "the common case" to
  "the only case" in the CLI surface, with the multi-agent shape deleted rather
  than kept alongside. Rationale, citing **D-13**: the capability *intent* is
  preserved, not discarded — DEN-67 (999.42) remains open and carries it, and
  when a second agent is supported the failover is to be reimplemented **on the
  supervisor**, not by restoring the old in-process chaining. Keeping a
  vestigial two-agent code path alongside would preserve the wrong shape.
- **Accepted debt, and what forces a later promote back:** re-introducing a
  multi-agent identity model requires **both** prerequisites recorded in
  DEN-67 — **DEN-58** (the socket supervisor, this phase's 23b) *and*
  **DEN-56** (999.31, the Modular Agent Driver, explicitly deferred out of this
  phase because it is a Codex blocker, not a Claude one). Until both land, a
  second agent has neither an addressable process to fail over to nor a driver
  abstraction to be driven by.
</assumption_delta_decision>
