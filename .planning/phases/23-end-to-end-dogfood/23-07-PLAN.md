**Add `spawn_supervisor(state, program, args, envs) -> Result<SupervisorHandle, MonitorError>`**
to `monitor.rs`. It replaces `spawn_monitor` at the same conceptual position:
called by `launch_stage_inner`, returns a handle the caller persists.

Its body:
1. Resolve the socket path with `supervisor_socket_path(&state.project_root, state.phase)`.
2. Resolve the four capture paths through `agent_result::{stdout_path,
   stderr_path, exit_code_path, agent_pid_path}` and call
   `workflow::ensure_devflow_dir` on the capture parent, **exactly as the
   current implementation does at :91-104**. The socket redesign changes how the
   agent is supervised, not where captures land — R-C/R-D parity depends on
   these four accessors being called unchanged.
3. Resolve the workdir as `state.worktree_path.as_deref().unwrap_or(&state.project_root)`,
   unchanged from today.
4. Spawn `std::env::current_exe()` with the `supervise` subcommand, building the
   argv to plan 23-06's **pinned contract** (review finding — Codex, HIGH). Emit
   the supervisor's own inputs as named options, then a literal `--` separator,
   and only after it the agent program followed by each of its arguments:

   `supervise --phase <N> --project <root> --socket <path> --workdir <dir> -- <program> <args…>`

   The `--` is load-bearing, not decorative. Adapter argv is heavily hyphenated —
   `claude.rs:20-30` emits
   `-p <prompt> --output-format json --dangerously-skip-permissions`, and the
   Codex adapter adds `exec --sandbox --json -c <key=value>` — and today none of
   it meets a parser, because `monitor.rs:162-170` hands it straight to
   `Command` through a shell wrapper. Routing it through a `devflow` subcommand
   is a **new** parsing surface; without the separator Clap consumes the agent's
   flags as DevFlow's own.

   Push `--` as its own argv element, exactly once, then `program`, then each
   element of `args` verbatim. No quoting, no joining into a single string, no
   shell escaping: there is no shell left in this path, so escaping would
   corrupt the arguments rather than protect them — which is precisely why
   `shell_escape` is deleted below rather than reused here.

   Attach `envs` with `.envs(...)` so adapter-scoped variables are **inherited**
   by the supervisor and thence by the agent and its grandchildren (R-F), rather
   than passed on argv where `ps` would expose them. `stdin`/`stdout`/`stderr`
   all `Stdio::null()`, as today — the supervisor's own output goes nowhere; the
   agent's goes to the capture files.
5. Poll `wait_for_agent_pid(&state.project_root, state.phase)` for the agent
   pid. Because plan 23-06's `serve` spawns the agent with `process_group(0)`,
   that pid **is** the agent's pgid.
6. Build and return a `SupervisorHandle` with the socket path, that pgid,
   `process_start_time(agent_pid)`, and `boot_id()`. If either identity fact is
   unavailable, still return the handle with the socket path populated — the
   socket is the primary mechanism and must work regardless; the backstop
   simply refuses to fire without them, which plan 23-05 already enforces.

(review finding — Codex, HIGH — and a must-have of this plan).** `launch_stage_inner`

`workflow::save_state(state)?`, under a WR-04 comment explaining exactly why:

`ensure_agent_binary` at :86, `enforce_build_staleness` at :93, the capture

**previous** stage's dead handle, and `liveness()` then misreports
`Stuck → devflow resume` when the real remedy is something else entirely.

That reasoning transfers verbatim to `supervisor`, and the consequences are
worse: a `SupervisorHandle` is not just a diagnostic pid, it is a **capability**
naming a socket to command and a process group to signal. Left stale across an
early failure, `status`, `doctor`, `cleanup` and the new `devflow stop` would
each act on the *previous* stage's handle — and `stop` in particular would
issue `shutdown` on, or `reap_stale_group` against, a group that is not the one
the operator asked about.

same position — **before** the first `?`, with the same immediately-following
`workflow::save_state(state)?` — and carry the WR-04 comment forward, updated to
name `supervisor`, to say the field is a capability rather than a pid, and to
name the three fallible steps below that can still return early. Do not move the
clear later, do not fold it into the spawn site, and do not make it conditional
on the handle looking stale: the point is that it is unconditional and comes
first.
