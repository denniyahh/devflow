**Add `spawn_supervisor(state, program, args, envs) -> Result<SupervisorHandle, MonitorError>`**
to `monitor.rs`. It replaces `spawn_monitor` at the same conceptual position:
called by `launch_stage_inner`, returns a handle the caller persists.

Its body:
1. Resolve the socket path with `supervisor_socket_path(&state.project_root, state.phase)`.
2. Resolve the four capture paths through `agent_result::{stdout_path,
   stderr_path, exit_code_path, agent_pid_path}` and call
   `workflow::ensure_devflow_dir` on the capture parent, **exactly as the
   current implementation does at :91-104**. The socket redesign changes how the
   agent is supervised, not where captures land — R-C/R-D parity depends on
   these four accessors being called unchanged.
3. Resolve the workdir as `state.worktree_path.as_deref().unwrap_or(&state.project_root)`,
   unchanged from today.
4. Spawn `std::env::current_exe()` with the `supervise` subcommand and the
   arguments plan 23-06's `Command::Supervise` variant declares — phase,
   project root, socket path, workdir, then the agent program and its args.
   Attach `envs` with `.envs(...)` so adapter-scoped variables are **inherited**
   by the supervisor and thence by the agent and its grandchildren (R-F), rather
   than passed on argv where `ps` would expose them. `stdin`/`stdout`/`stderr`
   all `Stdio::null()`, as today — the supervisor's own output goes nowhere; the
   agent's goes to the capture files.
5. Poll `wait_for_agent_pid(&state.project_root, state.phase)` for the agent
   pid. Because plan 23-06's `serve` spawns the agent with `process_group(0)`,
   that pid **is** the agent's pgid.
6. Build and return a `SupervisorHandle` with the socket path, that pgid,
   `process_start_time(agent_pid)`, and `boot_id()`. If either identity fact is
   unavailable, still return the handle with the socket path populated — the
   socket is the primary mechanism and must work regardless; the backstop
   simply refuses to fire without them, which plan 23-05 already enforces.
