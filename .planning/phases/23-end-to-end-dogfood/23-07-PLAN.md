<assumption_delta_decision>
## Assumption delta — the "second agent" pluralization signal

The assumption-delta detector fired on `kind: pluralization`, term `second`,
from `23-CONTEXT.md`'s deferred-ideas entry: *"Returns as the prerequisite for
onboarding any second agent."* That pulls against this plan, which deletes the
only construct in the codebase that expressed two agents on one phase.

**Noun now primary:** the **phase**. Identity remains `(project_root, phase)`.
Every runtime artifact is keyed by phase alone and by nothing else — verified
this session: `state-{phase:02}.json` (`workflow::load_state`),
`.devflow/lock-{phase:02}` (`lock::lock_path`),
`.devflow/phase-{phase:02}-stdout` / `-stderr.log` / `-exit` / `-agent-pid`
(`agent_result::stdout_path` and siblings), `.devflow/gates/{phase:02}-{stage}.json`
(`Gates::gate_path`), and this phase's own new
`registry::RegisteredRoot { project_root, phase }`. The agent is a scalar
attribute of that key, `State.agent: AgentKind`, not part of it.

**Decision: `no-change`.**

**Rationale:** the deleted construct was never a second identity. Its slot type
(`SequentagentSlotKind::A` / `::B`) named a *position in a sequential handoff*,
not a concurrent participant — both slots wrote the same `state-NN.json`, the
same capture files, and the same lock, one after the other. Removing it removes
a degenerate expression of "two agents", not a working one. Restoring a slot
letter would not be a step toward the real thing.

**What would force a later `promote`:** a second agent running **concurrently**
on one phase — the shape DEN-56's modular agent driver would enable and DEN-67
would consume. At that moment `phase` alone stops being a sufficient key: two
concurrent agents would clobber one `phase-NN-stdout`, contend on one
`lock-NN`, and race one `state-NN.json`. The key must then become
`(phase, agent_slot)` across all five artifact families listed above, and the
per-phase lock's own contention semantics must be revisited. That is a strictly
larger change than restoring the deleted verb, which is precisely why D-13
records the intent on DEN-67 rather than in code.

**Suggested (not required) invariant test:** a single test asserting that
`lock::lock_path`, `agent_result::stdout_path`, `agent_result::exit_code_path`,
`agent_result::agent_pid_path`, and `Gates::gate_path` are all derivable from
`phase` alone — that is, that no agent identity appears in any of those paths.
The day someone adds a concurrent second agent, that test fails loudly and
names the exact five call sites that need re-keying, instead of two agents
silently overwriting one capture file. Offered as a suggestion for the executor
to land if it is cheap; not an acceptance criterion.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| published binary → operator scripts | removing a subcommand breaks any script or scheduled job that invokes it |
| cron manifest → future scheduled execution | a resume manifest is written now and executed later, potentially after the upgrade that removes its target |
| shared file → surviving command | the deleted function shares a source file with `parallel`, which must keep working |
