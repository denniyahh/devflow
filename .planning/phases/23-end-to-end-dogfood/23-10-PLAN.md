<objective>
Give the operator an explicit, clean phase abort — the verb that was missing
when Phase 17 needed one.

`devflow cleanup --force` deliberately refuses to touch a live agent or monitor.
That refusal is correct, and it left a hole: there has been **no** command that
actually stops a running phase. The operator's only recourse was `ps` and
`kill`, which is exactly the manual intervention this phase's goal forbids.

23c falls out cheaply now that the socket handle exists (999.34 / DEN-59): the
happy path is a `shutdown` line on the socket the supervisor is already
listening on, and the STALE path is the identity-validated process-group
backstop plan 23-05 already built and tested.

**R-M is the behavioural property that matters most here.** The spike audit
calls it out as "a genuine behavioural improvement, not just parity": *a stopped
phase must not advance its own state machine.* That was never expressible in the
shell script. It is expressible now — plan 23-06 made `SupervisorExit::Stopped`
carry no exit code, so the supervisor cannot advance after a stop. This plan
adds the operator-facing verb that triggers it, and the regression test that
keeps it true.

This plan also lands **Claude's Discretion item #4** — the `hooks_after_ship`
worktree removal and the per-phase capture sweep.

Purpose: make aborting a run a first-class, auditable operation.
Output: `devflow stop`, an R-M regression test, and the two ship/stop cleanup
paths.
</objective>

## Recorded decision — Claude's Discretion item #4: `hooks_after_ship` worktree removal and the capture sweep

**DECIDED: land both, each by reusing an existing primitive. No new mechanism.**

CONTEXT.md left open whether `hooks_after_ship` should gain a worktree-removal
step and whether per-phase capture files should be swept, noting DEN-59's
operator note and that both are untested-on-success paths this phase is the
first to exercise. RESEARCH verified both are answerable from primitives that
already exist and are already trusted:

- **`Hook::WorktreeRemove`** — `worktree::remove(project_root, &path, force)`
  already exists and is already called this way from `commands.rs`'s `cleanup`.
  Landing it now matters because plan 23-11's acceptance run is the first run
  ever to *complete* Ship: without it, that run leaves its worktree behind and
  the phase's own success path is the thing that proves it broken.
- **Capture sweep on stop** — `agent_result::archive_phase_files` already
  exists and is already called on relaunch rollover. Reusing it means the stop
  path inherits the project's existing retention semantics rather than
  inventing a second deletion path with different ones. Archival, not deletion:
  a stopped run's captures are exactly the evidence an operator wants after
  aborting.

The alternative — deferring both — would leave the phase's own acceptance run
exercising an untested success path for the first time with nothing watching.

Add the `Stop` CLI variant and its handler.

**`main.rs`** — `Stop { phase: u32 (required, `#[arg(long)]`), project: PathBuf
(positional, default `.`) }`. **No `--force` flag**: a stop is always explicit
by construction — the operator typed the verb and named the phase — so there is
nothing for a force flag to override. Dispatch arm:
`Command::Stop { phase, project } => stop(&project_root(project)?, phase)`.

**`commands::stop(project_root, phase)`** — the handler:

1. Load the phase's state. If there is none, print that there is nothing to stop
   and return `Ok(())`. Not an error: stopping a phase that does not exist is
   the same outcome the operator wanted.
2. Branch on `monitor::socket_state(&handle.socket_path)` when
   `state.supervisor` is present:
   - `Alive` → `monitor::request_shutdown(...)`. The supervisor holds the real
     handle: it kills its own agent group, records exit code `143`, removes the
     socket and exits, and its `Stopped` return provably suppresses advance.
   - `Stale` → `monitor::reap_stale_group(&handle, grace)`. That function
     already refuses unless the recorded boot id and process start time both
     validate, and refuses rather than signalling blind when either is
     unavailable. Report how many group members it reaped.
   - `Gone` → nothing to tear down; fall through to the bookkeeping.
   - `Unknown` → report it plainly and do not signal anything.
3. When `state.supervisor` is absent but `state.monitor_pid` is populated, this
   is the pre-supervisor phase plan 23-08's `doctor` finding names. **Say so and
   refuse to signal.** Print the same guidance the finding gives — the monitor
   was started by an older binary and cannot be reached by this one; locate and
   signal it by hand, or let it complete. Silently doing nothing here would be
   the loss-of-control failure the finding exists to prevent.
4. Bookkeeping, on every branch: set `state.stopped = true`; set
   `state.stop_reason` **only if it is currently `None`** — a phase parked by
   `--until` (20c) already carries a reason, and the explicit stop that follows
   must not overwrite the record of why it stopped in the first place. Persist
   with `workflow::save_state`.
5. Resolve any gate the phase left open, so a stopped phase does not sit
   holding a gate no one will answer. Use `Gates::list_open` and `Gates::respond`
   with a non-approving response whose `responded_by` names the stop.
6. Emit `workflow_stopped` **before returning**, carrying the phase, the socket
   state observed, and which branch was taken. Events are append-only and never
   silent — an unattended abort must be reconstructable from `events.jsonl`
   alone. Emit the event even on the "nothing to stop" branches, so the record
   distinguishes "operator stopped a live phase" from "operator stopped a phase
   that was already gone".
7. Print an operator-facing summary. **Never print the absolute socket path** —
   the file name is enough (999.10 / WR-02).

**Documentation** — add `devflow stop` to `README.md` and `OPERATIONS.md`
alongside `cleanup` and `doctor`. This is required, not cosmetic: every
`Command` enum variant must appear as `devflow <variant>` in a scoped document
or `doc_check::source_devflow_env_vars_and_subcommands_are_documented` fails.
Do not add a `doc-check-allowlist.toml` exception instead. Say explicitly in the
docs that `stop` is the verb for a live phase and `cleanup` is the verb for a
finished one, since the pair is the thing an operator has to choose between.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `devflow stop` → a running process tree | The verb's whole purpose is to signal processes; a mistargeted signal kills the wrong thing |
| `devflow stop` → the phase's state machine | A stop that leaves advance reachable would let a phase the operator aborted go on to merge |
| `Hook::WorktreeRemove` → the filesystem | A worktree removal with a wrong or empty path could delete the project root |
| stop-time archival → captured agent output | Captures contain raw agent stdout, which has previously carried absolute paths and usernames |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-50 | Elevation of Privilege | a stopped phase advancing to Ship and merging after the operator aborted it | high | mitigate | R-M, enforced structurally by plan 23-06's `SupervisorExit::Stopped` carrying no exit code, and guarded here by `stop_suppresses_advance`, which asserts on the **absence** of an `advance_evaluated` event rather than on the presence of the stop |
| T-23-51 | Spoofing | the process-group backstop signalling a recycled PID's group | high | mitigate | The `Stale` branch delegates to `monitor::reap_stale_group`, which plan 23-05 built to refuse unless the recorded boot id and start time both validate, and to refuse rather than signal blind when either is unavailable. `stop` adds no second signalling path |
