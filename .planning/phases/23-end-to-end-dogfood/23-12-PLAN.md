## Two design decisions this plan makes explicitly, so the executor does not re-litigate them

**1. The guard fails open when the base branch has no `.planning/ROADMAP.md` at
all.** This is not laziness — it is what keeps the guard from being a breaking
change. `crates/devflow-cli/tests/phase7_cli.rs`'s `init_repo` commits
`.planning/phases/{07,08,09}-test/` fixtures but **never** a `ROADMAP.md`, and
that suite launches `devflow start` for phases 11, 13, 42, 44, 45 and 46 —
none of which have a phase directory either. A guard that refused on a missing
ROADMAP entry would turn that entire suite red. More importantly the fail-open
is *correct*: a repository whose base branch carries no roadmap has given
DevFlow no basis on which to judge whether a phase exists, and the existing
`commands::phase_artifact_on_develop` predicate already establishes this
project's fail-open-where-blind convention in exactly this situation. The real
2026-07-26 failure is still caught, because `develop` **did** carry a
`ROADMAP.md` — it simply lacked the Phase 24 heading.

**2. The guard emits no event and writes no `.devflow/` file.** It runs before
`workflow::save_state`, in a repository where nothing has started; emitting
would create `.devflow/` in a project that never ran. It matches the existing
pre-state Codex leg in `commands::start` exactly: a `CliError::Message` return,
which the CLI surfaces on stderr with a non-zero exit. `devflow start` is always
operator-typed (or reached through `devflow parallel`, which calls `start`
directly) and is never the forked `advance` tail, so stderr plus a non-zero exit
*is* the never-silent property here.
</objective>

**Step 3 — add the probe to `crates/devflow-cli/src/preflight.rs`**, as a
sibling of `ensure_agent_binary`, with `///` doc comments on every item (house
convention; the crate is binary-only so these are `pub(crate)`):

- A `#[derive(Debug, Clone, PartialEq, Eq)]` enum named `PhaseReachability`
  with exactly three variants: `Reachable`; `Undeterminable`; and
  `Unreachable { roadmap_entry_found: bool, phase_dir_found: bool }` whose two
  fields record whether each half was **found**, so a message can name what is
  missing. Document the invariant that at least one field is `false` in the
  `Unreachable` variant.

- `fn phase_reachability_on_base(project_root: &Path, phase: u32, base: &str) -> PhaseReachability`,
  implemented as four ordered steps, each shelling out with
  `std::process::Command::new("git")` and `.current_dir(project_root)`, argv
  arrays only, never a shell string:

  1. `git rev-parse --verify --quiet <base>`. A spawn error or a non-success
     status means the base branch does not exist here (or this is not a
     repository) → return `Undeterminable`.
  2. `git show <base>:.planning/ROADMAP.md`. A spawn error → `Undeterminable`.
     A non-success status means the base branch carries no roadmap at all →
     return `Undeterminable`, per this plan's fail-open-where-blind decision.
     Document that reasoning inline in one sentence.
  3. Scan the roadmap stdout for the phase heading: a line whose
     `trim_start()` starts with the string built by `format!("### Phase {phase}:")`.
     The trailing colon is load-bearing — it is what stops a probe for phase 2
     from matching `### Phase 24:`. Every heading in this project's ROADMAP
     already uses that exact form.
  4. `git ls-tree -r --name-only <base> -- .planning/phases/`. A spawn error or
     non-success status → `Undeterminable`. Otherwise the directory is found
     when some output line, after `strip_prefix` of
     `format!(".planning/phases/{phase:02}-")`, yields a remainder containing a
     `/` — the same idiom `commands::phase_artifact_on_develop` uses, and the
     reason a directory holding only a `.gitkeep` counts as present. Note the
     zero-padding: phase 7 is `07-`, phase 24 is `24-`.

  Both halves found → `Reachable`; otherwise
  `Unreachable { roadmap_entry_found, phase_dir_found }`.

- `fn unreachable_message(phase: u32, base: &str, roadmap_entry_found: bool, phase_dir_found: bool) -> String`,
  a pure builder so the message is unit-testable without git. It must produce,
  in order: a first line stating that phase `{phase}` is not reachable from
  `{base}` and that this is the branch `devflow start` forks its worktree from,
  using the literal phrase `is not reachable from`; then one indented `missing:`
  line per absent half — for the roadmap half naming the heading
  `### Phase {phase}:` and the file `ROADMAP.md` on `{base}`, for the directory
  half naming `.planning/phases/{phase:02}-*/` on `{base}`; then a closing line
  telling the operator that a phase promoted only on another branch is invisible
  to the run and to merge that branch into `{base}` first, then re-run. The
  message must contain no absolute filesystem path, no `project_root`, and no
  username — every path it names is repository-relative. This repository has
  leaked absolute paths into operator-facing strings three times (999.10, and
  again in 18-07's `self_dogfood_stale_blocked` reason); do not make it four.

- `fn ensure_phase_reachable_on_base(project_root: &Path, phase: u32, base: &str) -> Result<(), CliError>`
  returning `Ok(())` for `Reachable` and `Undeterminable`, and
  `Err(CliError::Message(unreachable_message(…)))` for `Unreachable`. Propagate
  with `?` at the call site; no `.unwrap()` or `.expect()` outside tests.
