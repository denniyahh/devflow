with Claude, on this repository — the phase's actual acceptance criterion, which

(recorded artifact, not a verbal report), **D-07** (accepted risk, mitigations
encoded in plan 23-10).

Purpose: no phase in this project's recorded history has completed a full
five-stage DevFlow-driven run. The ROADMAP's own run record is unambiguous —
Phase 17 reached Ship and died to two monitor deaths; Phase 21 stopped after
Define; Phase 22 stopped dead at a Plan relaunch with no evaluation at all. This
phase's own probe got further than any of them, producing eleven correct stage
launches and reaching Ship, and was turned away there by a content gate. This
run is the first attempt with that content gate class addressed, with a
pre-authorized Ship gate, and with a way to end the run cleanly if it parks.

Output: `23-ACCEPTANCE-RUN.md`, and a human judgment on it.

**Why self-hosted and not scratch, restated because it is the whole point of
D-02.** `staleness_outcome` (`crates/devflow-cli/src/staleness.rs:276-284`)
returns a hard block only for the self-dogfood-and-stale combination and merely
warns otherwise. The staleness guard blocked two of the three prior recorded
runs. It is **structurally unreachable in a scratch repository**. A scratch-only
acceptance would ship this phase without ever exercising the case that broke
every prior run.

**Visible skip, recorded per protocol:** spec-less probe fallback skipped —
phase has no requirement IDs to probe (visible skip). `must_haves.truths` are
derived from the ROADMAP phase goal and the probe/forensics evidence.

**Precondition, inherited and non-negotiable:** plan 23-10's checkpoint returned
`proceed`, its setup artifact is committed, `git status --porcelain` is empty,
and the recovery ref exists on `origin` with a rehearsed restore path. If any of
those is not true, this plan does not start.
