**New `MonitorError` variants**, added to the existing `thiserror` enum rather
than a parallel error type: `SocketBind` (wrapping the io error with the path),
`LiveSupervisorOwnsSocket` (takeover refusal), `NoCacheDir` (no resolvable

**`supervisor_socket_dir() -> Result<PathBuf, MonitorError>`** — resolve
`$XDG_CACHE_HOME`, falling back to `$HOME/.cache`; join `devflow`. Create it if
absent and set its mode to **0700**. Deliberately **not** `$XDG_RUNTIME_DIR`:
systemd removes `/run/user/$UID` when the user's last session ends, which would
destroy the socket mid-run for an operator who logs out — fatal for the long
unattended runs this whole phase exists to enable (D-09, already decided).
Return `NoCacheDir` if neither variable resolves. The 0700 directory is a
security control, not tidiness: it closes the window between `UnixListener::bind`
and the socket file's own `chmod`, during which the socket is briefly
world-connectable.

**`supervisor_socket_path(project_root: &Path, phase: u32) -> Result<PathBuf, MonitorError>`**
— `<dir>/<hash>-<phase>.sock`, where `<hash>` is 12 lowercase hex characters of
a **64-bit FNV-1a** hash of the project root's byte representation, implemented
inline (a dozen lines: offset basis `0xcbf29ce484222325`, prime
`0x100000001b3`). Do **not** use `std::collections::hash_map::DefaultHasher` —
its output is explicitly not guaranteed stable across Rust releases, and a
toolchain upgrade mid-run would change the derived path. The hash keys concurrent
projects apart; the phase suffix keys concurrent phases apart. Return
`SocketPathTooLong` if the resulting path is **104 bytes or longer** — the
macOS `sun_path` bound, applied on every platform so a path that works here
cannot silently be one that fails there.

**`SocketState`** — a public enum with exactly four variants: `Alive`, `Stale`,
`Gone`, `Unknown`. Derive `Debug, Clone, Copy, PartialEq, Eq`. Give it a
`describe()` (or equivalent) returning operator-facing text, matching the shape
`commands::Liveness` already uses for its own rendering. `Stale` must have its
own distinct wording — the single most important observability property in this
phase is that a stale socket does not read like a phase that was never started.

**`socket_state(socket_path: &Path) -> SocketState`** — reproduce the spike's
probe contract verbatim in behaviour: file does not exist → `Gone`; connect
succeeds → write `ping`, read one line back, → `Alive`; connect fails with
`ErrorKind::ConnectionRefused` → `Stale`; any other error → `Unknown`.

**Timeout, concrete (review finding — OpenCode, divergent view, adopted).** Do
not write "a couple of seconds". Declare a module-level
`pub const SOCKET_PROBE_TIMEOUT: Duration = Duration::from_millis(1000)` and
apply it to **both** `UnixStream::set_read_timeout` and
`set_write_timeout`. One second is the chosen bound because `devflow status` is
polled every 30–60 s by the observation protocol in plans 23-02 and 23-12, so a
one-second worst case is invisible in that loop, while a two-second one would
be a visible tax on every single invocation against a wedged supervisor.
Reference the constant from both call sites rather than repeating a literal, so
the bound is changeable in one place and greppable in acceptance.

A timeout on the ping exchange after a successful connect resolves `Unknown`,
**not** `Alive` — a supervisor that accepts a connection but never answers is
not proven healthy. This case gets its own test (below); it is the one the
reviewer specifically named as untested, and it is the difference between "we
reached something" and "something is working".

Every fallible call uses `?` against `MonitorError`. No `.unwrap()` and no
`.expect()` outside `#[cfg(test)]` — the spike uses them freely because it is
throwaway proof code, and every one of them must become `?` here.

**Leader-exited semantics — the case the backstop exists for (review finding —
Codex, divergent view, resolved here rather than left to the implementer).**
Validating only the leader's pid and start time refuses to reap precisely the
orphan group the backstop was built for: when the supervisor dies, nothing reaps
the agent, init adopts and reaps it, and the leader pid disappears while its
descendants keep running in the group. `process_start_time(pgid)` then returns
`None`, and a naive "refuse on `None`" rule turns the backstop into a no-op in
its own primary scenario. The resolution keeps the F3 guard fully intact by
observing that a **process-group id can only be claimed by a process whose pid
equals it** — so if pid `pgid` does not exist, that group id cannot have been
re-claimed by an unrelated leader, and any remaining members inherited it from
the original agent.

`group_reap_verdict`'s arms, in order:
1. `socket != SocketState::Stale` → `Refuse("supervisor socket is not stale")`.
   A live supervisor owns its own teardown; a `Gone` socket has nothing to reap.
2. `live_boot_id` is `None`, or differs from `handle.boot_id` →
   `Refuse("boot id unavailable or changed since the handle was recorded")`.
   After a reboot the recorded pgid means nothing.
3. `leader_start == Some(t)` where `t != handle.agent_start_time` →
   `Refuse("recorded pgid is now a different process")`. This is the F3 PID-reuse
   guard, unchanged.
4. `leader_start == Some(t)` where `t == handle.agent_start_time` → `Reap`.
   The original leader is still alive; this is the ordinary case.
5. `leader_start == None` — the leader has exited. Then:
   - `member_start_times` is empty → `NothingToReap`. The whole group is gone;
     this is success, not a refusal, and callers must not treat it as an error.
   - any member's start time is **strictly earlier** than
     `handle.agent_start_time` → `Refuse("group contains a process older than the recorded agent")`.
     A descendant cannot have started before its ancestor, so an older member
     means this group id is not the one that was recorded.
   - otherwise → `Reap`. This is the orphan case, and reaping it is the entire
     purpose of the backstop.

**`reap_stale_group(handle: &SupervisorHandle, grace: Duration) -> Result<usize, MonitorError>`**
— the STALE-path backstop, and the only code in this phase that signals a
process group. It is now a thin I/O shell around the pure predicate: gather
`socket_state(&handle.socket_path)`, `boot_id()`,
`process_start_time(handle.agent_pgid as u32)`, and
`process_group_members(handle.agent_pgid)` mapped through `process_start_time`;
call `group_reap_verdict`; then branch:
- `Refuse(reason)` → return `MonitorError::HandleIdentityMismatch` carrying the
  reason. Never signal. Do **not** downgrade an unavailable identity fact to
  "assume it matches" — on a platform where start time is unavailable, refusing
  is correct.
- `NothingToReap` → remove the stale socket file and return `Ok(0)`.
- `Reap` → `libc::killpg(pgid, SIGTERM)`, poll for the group to empty for
  `grace`, escalate to `SIGKILL`, remove the stale socket file, and return the
  number of group members observed before the first signal.
