<objective>
The STALE backstop D-04 chose, built to R-4's discrimination rule as RESEARCH Finding 1 settled it: signal only a group
whose leader is present and identity-validated, treat a recycled leader pid as proof the group is gone, and refuse —
reporting, never signalling — a group whose leader is gone. D-04 records this as the riskiest code in the design (it
kills by a value read from disk); it is therefore a pure classifier over gathered facts plus a thin acting shell, and
the classifier gets a mutation run.

Purpose: `devflow stop` on a STALE socket (50-14) can reap an orphaned agent group without ever signalling a group it
cannot prove is the original.
Output: `supervisor/backstop.rs`, its `pub mod` line, and a `/proc/<pid>/stat` fields parser in `agent.rs`.
</objective>

The rule to implement, from RESEARCH Finding 1 (Linux, `/proc` over own-uid processes), in order:
1. sidecar and state record (when state loads) agree on launch_id, pgid, agent start time and boot id — else refuse
   (`RefuseMismatch`); 2. sidecar boot id ≠ current boot id → `PreviousBoot` (remove files, signal nothing);
3. enumerate `/proc/*/stat` with uid == euid, pgrp == pgid, state ≠ `Z` → none → `EmptyGroup` (remove files);
4. `/proc/<pgid>` exists, its start time == recorded and its pgrp == pgid → `LeaderPresentSignal`;
5. `/proc/<pgid>` exists with a different start time → `LeaderRecycled` (signal nothing, remove files);
6. no process with pid == pgid but members exist → `RefuseLeaderGone { members }` (report, never signal, keep files).
Unsafe targets (pgid that does not fit `pid_t`, ≤ 1, or equal to `getpgrp()`) → `RefuseUnsafeTarget` before any I/O.
Step 4 sends via `pidfd_open(P)`, re-reads P's start time after opening, then `pidfd_send_signal(fd, SIGTERM, NULL,
PIDFD_SIGNAL_PROCESS_GROUP)`, waits `agent::TERMINATE_VERIFY_WAIT`, then the same with SIGKILL; on `EINVAL` (kernel
lacks the flag, `[ASSUMED]` Linux ≥ 6.9) fall back to validate-then-`killpg` and record `SignalPath::ValidatedKillpg`;
`ESRCH` mid-grace means the leader died, so re-assess the remaining members (leader gone → refuse and report). The
assumptions A1 (a pid is not reused while it names a pgid) and A3 (kernel flag) are recorded in RESEARCH; the residual
F1 limit (leader gone, members live) is documented in the refusal text and in OPERATIONS (50-17). `libc 0.2.186`
exports `PIDFD_SIGNAL_PROCESS_GROUP`, `SYS_pidfd_open` and `SYS_pidfd_send_signal` (RESEARCH, verified by compile);
no new dependency.

Off Linux (MAC-2, operator decision 2026-10-16: DevFlow 3.0.0 must keep compiling on macOS). Compile probes against
`libc 0.2.186` on the pinned 1.97.1 (2026-10-16): `SYS_pidfd_open`, `SYS_pidfd_send_signal` and
`PIDFD_SIGNAL_PROCESS_GROUP` are each `error[E0425]` on `aarch64-apple-darwin`, and compile once the items that use
them carry `#[cfg(target_os = "linux")]`, with Linux unchanged; `killpg`, `getpgid`, `setsid` and `setpgid` compile on
both. Every fact the rule above proves identity with comes from Linux `/proc`: the leader's start time and pgrp, the
group census and the boot id. macOS has none of them (backlog 999.158, 999.159), and this phase adds no macOS identity
mechanism. Gathered naively off Linux, the census is empty and step 3 would answer `EmptyGroup` and remove the files of
a group that may still be running. So off Linux the backstop refuses before step 1: it signals nothing, removes
nothing, and prints a repair line. That branch is compile-checked only, by `cargo check --target
aarch64-apple-darwin` for both packages with `--all-targets`, which links and runs nothing for macOS. Without the
rustup target that check fails with `error[E0463]: can't find crate for core`, an environment failure fixed by `rustup
target add aarch64-apple-darwin` (per toolchain: add it again after a `rust-toolchain.toml` bump).
