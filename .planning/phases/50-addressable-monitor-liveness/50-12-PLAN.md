<objective>
Move every liveness consumer onto the probe (CONTEXT "Liveness presentation", Claude's discretion): `status`, `cleanup`
and `doctor` (including `doctor --json`) stop reading `monitor_pid` and answer GONE / STALE / ALIVE from the recorded
socket, each non-ALIVE answer naming its repair verb, and `doctor` gains the read-only sweep finding D-06 asks for.

Decisions recorded (Claude remit, planner): `BetweenStages` folds into ALIVE (advance runs inside the supervisor);
GONE while a stage is recorded as running and the phase is not stopped is a finding, not a normal state; doctor stays
path-free (T-18-01, `commands.rs:3724-3726`) by identifying a socket by phase and launch id, while `status` — which
speaks only about the operator's own project — prints the socket path; doctor's sweep finding is scoped to the
doctor's project root, like every other doctor finding, except the deleted-root class, which is machine-wide like the
stray finding whose role it takes over; an orphan is repaired with `devflow stop --phase N --launch <id>`, because the
bare `devflow stop --phase N` addresses only the state's own record.

Purpose: the operator sees the three states and the repair for each, without any pid on the answering path.
Output: the replaced `Liveness` presentation, `check_supervisor`, the orphan finding, and status e2e coverage.
</objective>
