<objective>
Make the launch path testable and hermetic before it switches to sockets. Today the `PipeOwning` arm re-execs
`current_exe()` as `__monitor`; inside a unit-test binary that is libtest, which rejects the arguments, so in-crate
tests never actually supervise a stream launch, and once 50-11 routes BOTH shapes through `__monitor` every in-crate
launch test would break. This plan introduces one `LaunchContext` (cache dir + monitor executable), a test-only
harness entry that runs the real `run_monitor` code inside the test binary, and in-crate cache isolation (RESEARCH
Finding 7c: `spawn_agent_and_record` registers with the test process's real HOME today).

Decision recorded (Claude remit, planner, 2026-10-14): the seam is an explicit `LaunchContext` argument to
`spawn_monitor` resolved by one CLI function with a `#[cfg(test)]` branch — not a process-global override and not an
env var read in production code — because it keeps the released binary's behaviour fixed at compile time and needs no
`set_var`.

Purpose: 50-11 can switch both shapes to `__monitor` with every in-crate test still exercising real supervision.
Output: `LaunchContext`/`MonitorExec` in core, `launch_context()` and two harness entries in the CLI, child-wrapped
launching tests.
</objective>
