<objective>
Replace `release --check`'s tag-signing predictor with the operation it was predicting.

Purpose: the predictor infers viability from `ssh-add -l` and has false-negatived live on two
separate release cuts with signing genuinely working. The mechanism is unreliable by construction,
not by circumstance: `ssh-add -l` cannot see on-disk private key material, so agent membership is
not a necessary condition for `git tag -s` to succeed. A probe cannot drift out of sync with git's
real behaviour because it has no independent behaviour — it does the actual operation on disposable
input.

Output: a rewritten `check_ssh_signing_viability`, the deletion of the predictor and its now-orphaned
types and helper, probe fixtures with their negative controls, and the rewritten `release --check`
surface tests.
</objective>

**F-8 — the probe workspace name must be unique per CALL, not per process. Added after the second
cross-AI review pass (A-M1).** The original wording specified a workspace "unique to this process",
created with the non-recursive constructor so a pre-planted path fails the creation. That guard
shape is right and stays. The uniqueness scope was wrong: `cargo test` runs tests as parallel
**threads inside one process**, so a process identifier is shared by every concurrent probe test.
Two probe tests running at once collide, the loser's creation fails with an already-exists error,
and it fails soft to `Unknown` — a flaky test whose failure points at the probe rather than at the
harness.

**Decision: compose the name from three parts — the process id, a monotonically incremented
process-wide counter, and a sub-millisecond time component** — using only `std` (a
`std::sync::atomic` counter and `std::time`), because this crate must add no dependency. Put the
composition in one small private helper so a test can assert its property directly rather than
inferring it from a probe result. The security property is unchanged and still carries: the
non-recursive creation is what makes a pre-planted directory or symlink fail rather than redirect,
and per-call uniqueness only removes the self-collision.

**C6 is superseded by F-8 and must not be actioned separately.** The second review pass recorded the
same area twice — once as cross-*process* identifier reuse (LOW) and once as the intra-process
thread collision above (MEDIUM). They are the same code and the same fix; the thread case is the
likelier one and the one the fix is written for. Do not add a second mitigation for the process-reuse
framing.

**Do not widen the scope.** The GPG/openpgp branch is untouched — the backlog scopes this to the SSH

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DevFlow → `ssh-keygen` child | An external binary handling private key material; its stdout, stderr and exit code cross back into operator-visible output |
| DevFlow → the shared system temporary directory | The probe creates a directory and writes a payload and a signature there; the directory is world-reachable before creation |
| `release --check` → operator terminal | Every reason string is printed; the configured signing key value must never appear in it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-35-11 | Information Disclosure | `NotViable` / `Unknown` reason strings | high | mitigate | Exit code is the sole verdict; the child's stderr is read by nobody and reproduced nowhere; the four reasons are fixed strings keyed by failure class and contain no path and no key material. Enforced by the leak assertions in Task 2 and the surviving leak-check tests in Task 3 (D-02, D-08) |
| T-35-12 | Tampering | probe workspace under the system temp dir | medium | mitigate | Create the directory with the non-recursive constructor that fails when the path already exists, under a name unique to each individual call — process id plus an atomic counter plus a sub-millisecond component (F-8) — so a pre-planted directory or symlink cannot redirect the payload write and two concurrent probe threads cannot collide with each other; fail soft to `Unknown` when creation fails (Task 1) |
| T-35-13 | Elevation of Privilege | `ssh-keygen` sign invocation | medium | mitigate | Sign only bytes the probe generated itself inside its own private directory; never sign repository content; remove the directory and its contents on every exit path including the timeout path. Recorded as this plan's `must_haves.prohibitions` entry (Task 1) |
| T-35-14 | Denial of Service | `release --check` preflight | high | mitigate | `SSH_ASKPASS_REQUIRE` set to never closes the passphrase-prompt route, and a wall-clock ceiling with kill and reap closes the rest, so no blocking mode can hang an unattended preflight.
