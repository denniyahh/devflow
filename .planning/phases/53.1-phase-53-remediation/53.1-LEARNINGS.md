# Phase 53.1 Learnings: Phase 53 remediation

## Decisions

### Far rate-limit reset leads with the route to another agent
A reset more than `RATE_LIMIT_FAR_RESET_SECS` (6 h) away puts `devflow stop --phase N`, then `devflow resume --phase N --agent <other>`, before the reset time. The constant has no env var.

**Rationale:** The route comes before any variable-length text so it survives the 450-character display cut (also at Validate with the longest phase id). `<other>` is the run's fallback only when it was spent, because `resume --agent` onto an unused fallback is refused.
**Source:** 53.1-02-SUMMARY.md

---

### Resume past a fired --until cap advances through the shared enter_stage
`devflow resume` after an `--until plan` halt launches Code through `pipeline_gate::enter_stage`, shared with `transition`. Fallback, canary and handoff checks are judged on a never-written clone at Code before any write, and `transition` is recorded before `agent_handoff`.

**Rationale:** Review finding agy C2 showed the handoff was preflighted against the saved Plan stage. One `resume_advance` helper is read by both the archive-stage and advance paths so they cannot disagree.
**Source:** 53.1-03-SUMMARY.md, 53.1-REVIEWS.md

---

### Gate guidance names `devflow gate reject N --note`, never a bare `--note`
The decisions sentence on stage-failure gates and the post-run sign-off route on human_needed gates both name `devflow gate reject N --note`.

**Rationale:** `gate approve` also takes `--note`, so a bare `--note` is ambiguous. The C2 test allows exactly that one rendered sentence after the way-on.
**Source:** 53.1-06-SUMMARY.md, 53.1-REVIEWS.md

---

### Post-commit stale-state marker moves into the per-worktree git dir
The hook writes `$(git rev-parse --git-path devflow-stale-state.json)`, not a tracked-tree path. The old path stays ignored via `.planning/user/errors/.gitignore` while the main checkout runs the old hook.

**Rationale:** The old marker left the tree dirty after every summary commit (999.240, 999.253), which tripped the validate clean-tree rule and the build.rs dirty flag.
**Source:** 53.1-05-SUMMARY.md

---

### Finish has GSD complete the phase and commit only what GSD reported writing
`finish_run` runs GSD's `query phase.complete N --json-errors`, then commits the files its four write flags name through GSD's own `query commit`. A scoped planning dir (GSD_PROJECT or workstream) is refused before any write. A refusal is recorded in a `gsd_phase_complete` event with a path-free message and never undoes the finish.

**Rationale:** The review found the finish route staged fixed `.planning/` paths while GSD writes under its resolved planning dir (codex 6). A reply with all four flags false records ok true, committed false.
**Source:** 53.1-07-SUMMARY.md, 53.1-REVIEWS.md

---

### Planning-root check compares canonical paths
The scoped-planning-dir check canonicalizes both paths, falling back to the given path when it cannot.

**Rationale:** A symlinked evidence root must not read as a scoped planning directory.
**Source:** 53.1-07-SUMMARY.md, STATE.md

---

### Cancel is recorded only for an in-flight or queued id
`CallFlags::in_flight` is cleared right after `worker.call` returns, under the queue lock, before the cancelled-set remove.

**Rationale:** A late cancel for a finished id must not silence a later call that reuses the id (999.258).
**Source:** 53.1-03-SUMMARY.md

---

### Residual Plan->Validate resume gap filed as 999.260, not fixed
The fix covers Plan->Code only. 999.260 is filed and the OPERATIONS.md resume row names it.

**Rationale:** Keeps the phase to the entries in scope. The 999.251 closure says the fix covers Plan->Code only.
**Source:** 53.1-08-SUMMARY.md

---

### Cleanup prints "removed nothing; kept N" after keeping a run
"no worktrees to clean up" is printed only when no Kept or Unsettled outcome exists.

**Rationale:** The old output contradicted itself right after keeping a stopped run (999.213).
**Source:** 53.1-04-SUMMARY.md

## Lessons

### Review against the source caught two critical plan defects
Tier B round 1 (codex and agy) found 2 critical and 11 major findings. The driving agent confirmed agy C1 (far-route test used an auto-mode rig where `resume --agent codex` is refused) and agy C2 against the source. Both led to replan changes in 53.1-02 and 53.1-03.

**Context:** The replan ran by hand because DevFlow's Plan stage has no reviews mode.
**Source:** 53.1-REVIEWS.md, 53.1-CONTEXT.md

---

### A planned gate can fail on pre-existing debt
`shellcheck scripts/hooks/post-commit` reported three SC2086 findings on the current file. A decisions-note test would have failed after its own fix because the reason contained `retry`.

**Context:** Plan 05 fixed the hook with `mapfile` arrays. Plan 06 used a neutral reason and tested the guidance separately.
**Source:** 53.1-REVIEWS.md, 53.1-05-SUMMARY.md, 53.1-06-SUMMARY.md

---

### A negative control must catch the partial fix
Plan 01 added an allowed `rate_limit_event` row. A partial fix that falls through only when no `rate_limit_event` exists failed with `stream routine allowed event then error_rate_limit: want RateLimited`.

**Context:** Every plan ran a revert-once control (D-13) that reverse-applied the GREEN change and asserted the same failure text as RED.
**Source:** 53.1-01-SUMMARY.md, 53.1-REVIEWS.md

---

### Plan text can name the wrong CLI shape or stale line numbers
The plan wrote `devflow stop --phase N <root>`, but the CLI takes `--root`. The 53.1-08 plan cited pipeline_outcomes.rs 1766-1773, and the arm was at 2048-2056. A ROADMAP entry cited :2603 where the advance lives at :2627 in `resume_advance`.

**Context:** The executors fixed each as Rule 3 or Rule 1 deviations. Line numbers were re-read on the tree before being written down.
**Source:** 53.1-02-SUMMARY.md, 53.1-08-SUMMARY.md

---

### An existing test can pin the call order of a new GSD read
`a_validate_pass_is_recorded_with_the_head_it_ran_on` scripts GSD stub replies in order. The new planning-root read consumed the next verification reply, so a verdict row failed.

**Context:** Fix: one `NO_PLANNING_ROOT` reply after each reply that leads to a finish. Any test scripting stub replies for a run that finishes needs one `planning.inspect` reply per finish.
**Source:** 53.1-07-SUMMARY.md

---

### Moving a write site breaks a source-scan test
`state_stage_is_written_only_by_transition_and_the_code_loop_back` failed when extracting `enter_stage` moved the write out of `transition`.

**Context:** The expected list now names `enter_stage`. `enter_stage` clears `relaunch_note`, which is what the scan guards.
**Source:** 53.1-03-SUMMARY.md

---

### Editing through scripts bypasses the formatter hook
Plan 06's Task 2 lines were committed unformatted and needed a separate rustfmt commit (1762a7e).

**Context:** Run `cargo fmt --all -- --check` before the commit when editing programmatically.
**Source:** 53.1-06-SUMMARY.md

---

### The plan's mandated commit subjects exceed 72 characters
Several plan-dictated subjects were 73 to 85 characters. The commit-msg hook only warned.

**Context:** Plans 01 and 05 kept the wording. Plans 04 and 06 shortened it.
**Source:** 53.1-01-SUMMARY.md, 53.1-04-SUMMARY.md, 53.1-05-SUMMARY.md, 53.1-06-SUMMARY.md

## Patterns

### Revert-once negative control before accepting a GREEN
Reverse-apply only the GREEN production change, confirm the target test fails with the RED assertion text, restore from the committed bytes, re-run green.

**When to use:** Every TDD task.
**Source:** 53.1-01-SUMMARY.md, 53.1-02-SUMMARY.md, 53.1-03-SUMMARY.md

---

### Gate text as a pure function with the clock passed in
The clock is read once in `handle_rate_limited_outcome` and passed as `now`.

**When to use:** Any gate or context text whose output depends on time, so tests can pin it.
**Source:** 53.1-02-SUMMARY.md

---

### Judge pre-write checks on a never-written clone
Apply the advance to a clone, run the checks, then commit the real writes in order.

**When to use:** Resume or handoff paths where checks must see the post-advance state but must not mutate before refusing.
**Source:** 53.1-03-SUMMARY.md

---

### Option-chain detectors that return None from every exit
The stream detector reads are Option chains combined with `or_else`, so each early exit falls through to the next read.

**When to use:** Parsing streams where a routine event must not end the search.
**Source:** 53.1-01-SUMMARY.md

---

### In-process tracing capture
`tracing_subscriber::fmt()` with a test-local `Arc<Mutex<Vec<u8>>>` writer under `tracing::subscriber::with_default`.

**When to use:** Asserting that code emits a warning, with a well-formed control case.
**Source:** 53.1-04-SUMMARY.md

---

### Run a hook byte copy in a scratch repo
A scratch repo with `core.hooksPath` pointing at a byte copy of the repo hook, with a hermetic env.

**When to use:** Testing git hooks without touching the real tree.
**Source:** 53.1-05-SUMMARY.md

---

### Publish by rename for files a poller reads
Write to a `.tmp` file, then `mv`.

**When to use:** Test hooks and markers read by a polling process (fixes the empty `""` marker read in 999.257).
**Source:** 53.1-05-SUMMARY.md

---

### Allow exactly one rendered sentence in a "leads with only" check
`leads_with_only_allowing(context, sentence, allowed)` admits one production-rendered sentence after the way-on and nothing else.

**When to use:** A gate that must name its own reject route without breaking the GATE-04/C2 rule.
**Source:** 53.1-06-SUMMARY.md

---

### Scripted GSD stub replies, with `!exit <code>`
`plant_gsd_run_stub` supports `!exit <code>` replies, and `GsdStub::script_reply` rewrites one reply.

**When to use:** Tests of finish-time GSD calls, including refusals.
**Source:** 53.1-07-SUMMARY.md

## Surprises

### The phase's own finish route did not run on its own run
The run finished on the build installed before the fixes, so 53.1-07's `phase.complete` route did not run. GSD's execute-phase completed the phase (54d2aec) and the Progress row was set by hand.

**Impact:** The finish route is still to be proven live on the next dogfooded run.
**Source:** 53.1-CONTEXT.md

---

### Finish-route verification is fixture-only
Every finish test drives a planted gsd-tools stub. No test or run drove the real `phase.complete` plus `query commit` pair, and a signing prompt under null stdin is not exercised.

**Impact:** VERIFICATION marks truth D-10 as coincidental reliance. A scratch-repo test against the installed gsd-tools would close it.
**Source:** 53.1-VERIFICATION.md, 53.1-07-SUMMARY.md

---

### Phase 53 could not be completed by GSD
`phase.complete 53` refused on stale verification (999.259). 53.1-07 exists to fix that.

**Impact:** Completion of a phase needed a hand digest refresh until the finish route is proven.
**Source:** 53.1-CONTEXT.md

---

### The installed GSD names its TDD-review override differently and calls it unimplemented
The installed GSD 1.22.0 names the override `--force-mvp-gate`, not `--n`, and still calls it "not-yet-implemented" (verify-phase-goal.md:109). It is logged as 999.252 and the incident log.

**Impact:** The end-of-phase TDD review can block a completed phase with no working override.
**Source:** 53.1-01-SUMMARY.md

---

### Several backlog entries were already fixed
999.189, 193, 202 and 219 were already fixed. Of 999.213's points, the stop-reason and merged-branch points already passed at RED. Only the contradiction line still reproduced, and `cleanup --force` no longer exists.

**Impact:** Closing a backlog entry needs evidence re-read on the current tree.
**Source:** 53.1-01-SUMMARY.md, 53.1-04-SUMMARY.md

---

### Token estimates far exceeded realized diffs
The 53.1-05 estimate was 65000 tokens and the realized diff was about 5400.

**Impact:** Plan estimates for remediation work run high.
**Source:** 53.1-05-SUMMARY.md

---

### Plan-time assumptions were wrong in the test rig
`Rig::with_reset` builds an auto-mode shape in which `resume --agent codex` is refused. Auto-mode only accepts claude and antigravity for `resume --agent`. In auto mode, `gaps_found` loops back to Plan without a gate.

**Impact:** The far-route e2e needed `Rig::with_reset_supervised`, and OPERATIONS.md states the auto-mode limit.
**Source:** 53.1-REVIEWS.md, 53.1-02-SUMMARY.md, 53.1-06-SUMMARY.md
