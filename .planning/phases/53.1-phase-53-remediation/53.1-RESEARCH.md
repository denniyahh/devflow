The rest are small, local changes in files already holding tests that use the same fixtures. `pipeline_outcomes.rs` (999.206/249/250/254) and `pipeline_gate.rs` (999.251/259) are the shared files that set the wave order.

## Project Constraints (from CLAUDE.md)

- Gate every check on one named test: `cargo nextest run -p <pkg> --lib --no-tests=fail -E 'test(=module::path::name)'`; `--bin devflow` for CLI unit tests; `--test <file>` for integration tests. The CLI package is `devflow`, not `devflow-cli`. `cargo test -p devflow --lib` verifies nothing.
- A filtered `cargo test` exits 0 on no match; `rg -c` prints nothing on zero. Never use either as a gate. `scripts/lint-plan-bashisms.sh` refuses them in `<automated>` blocks of staged `*PLAN.md`.
- Every literal `std::env::var("DEVFLOW_…"` / `var_os(` / `env_value(` read under `crates/` and every `Command` variant must be documented (README/ARCHITECTURE/CONTRIBUTING/OPERATIONS.md or `docs/guides/`) or allowlisted in `doc-check-allowlist.toml` in the same change. Nothing below adds either; keep the 999.250 threshold a constant, not an env var.
- `devflow-core` is published: changing or removing a `pub` item is semver. Additive changes are expected here (§Semver); run `cargo semver-checks check-release -p devflow-core --baseline-rev origin/develop --release-type minor` and require exit 0 with a non-zero `Checked N checks`.
- `build.rs` embeds commit and dirty flag; never compare a rebuilt binary's sha256 with a stored one.
- `core.fileMode=false`: set an executable bit with `git add <f> && git update-index --chmod=+x <f>`.
- Hook, CI, devcontainer or tooling change → update `.planning/user/DEV-SETUP-CHECKLIST.md` in the same commit.
- Dogfooding: the phase runs under `devflow start --phase 53.1 … --until plan`; any stage run by hand is recorded in phase notes. Defects found go to `999.x` at once.
- Global rules that bind plans: Conventional Commits, `rg` not `grep`, one scenario per test, negative control asserted on the intended failure text, no process-global env mutation in tests (set env on the spawned child), scrub `GIT_*` in fixtures touching temp repos.

## Common Pitfalls

1. **`gate abort` is not a way on.** It clears the state; resume then refuses. Use `devflow stop`.
2. **`.devflow/state-*.json` is a state file to DevFlow.** A marker named that way prints a WARN on every `status`/`cleanup`/`gate list` (seen in Phase 44 evidence).
3. **The idle-timeout budget has 23 characters of slack.** Text before the reason on stage-failure gates breaks `commands::tests::the_budgeted_idle_timeout_clause_closes_inside_the_gate_display_bound`.
4. **Existing pins that change:** `a_long_failure_reason_is_stored_whole` (ends_with), `every_gate_names_only_the_routes_its_answers_run` (rate-limit row: reset string and resume string), `a_rate_limit_without_a_fallback_does_not_count_as_an_infra_failure` (reset string), OPERATIONS.md:409, :484-486.
5. **Workspace-only hook, develop-bound test.** A test of `scripts/hooks/post-commit` under `crates/` must be declared `only` in `.workspace-divergence`, or it fails on develop.
6. **TDD review on regression tests.** A plan whose test passes on current code has no RED; GSD's review blocks it (999.252). Pair each passing pin with a RED test in the same plan (999.206's `gate show` pin rides with the suffix RED).
7. **`in_bounded_child` names.** Tests that open gates in `pipeline_outcomes.rs` re-run themselves in a child by full module path; a wrong string runs nothing and `assert_child_ran_exactly_one_passing_test` fails.
8. **`phase.complete` leaves uncommitted writes** in the worktree (ROADMAP/STATE/REQUIREMENTS). See Open Questions.
9. **GSD messages can carry file names/paths.** Keep them out of the event body beyond a bounded message, per `gsd_reader`'s property 3.
