<objective>
Complete unit **29b** by giving the remaining two recoverable steps real
implementations: the release pull request from `develop` into `main`, and the
sync-back that keeps `main` a real ancestor of `develop`.

Purpose: the sync-back is the step this repository has already got wrong twice
— once by skipping it entirely before v1.5.0, producing conflicts across
eleven files, and once by auto-merging it without a method on 2026-07-27,
squashing away the ancestry it exists to create and requiring a repair pull
request. Porting the proven script rather than redesigning it, and resolving
the method from intent rather than from the branch name, closes both.

Output: the `release_pr_to_main` and `sync_back_pr` actions wired into
`action_for`, and a CONTRIBUTING.md note recording that the manual procedure now
has an executable equivalent. After this plan, `devflow release cut` walks to
the signed-tag step and stops there.
</objective>

<design_notes>
RD-N decision references are defined in `29-01-PLAN.md` § design_notes.

**Port, do not redesign.** `scripts/sync-main-to-develop.sh` is production-proven
and every one of its checks earned its place: the clean-tree guard, the
correct-branch guard, the fetch-first, the already-an-ancestor short circuit,
the `-X ours` merge, and the tree-identity verification that refuses to proceed
if the merge changed develop's content. This phase's job is to move it from
"bash plus direct push" to "Rust plus pull request", not to rethink its logic.
The two guards that become unnecessary are the clean-tree and correct-branch
checks — the executor works in a scratch worktree it created, so both are true
by construction rather than by assertion. Every other check is carried over.

**Why the tree-identity check is load-bearing.** The script's own comment
records the reason: `-X ours` should make the merge a pure history link, and if
the resulting tree differs from develop's pre-merge tree, then `main` carried
content develop genuinely lacked and a human must look before anything is
pushed. That is a refusal, not a warning, and it stays a refusal here.

**After this plan, `devflow release cut` stops at step 4.** Steps 1, 2, 3, and 5
have actions; steps 4 and 6 do not, and the walk reports so, naming unit 29c.
This is the operator's locked unit split working as intended — unit 29b is
usable on its own, and a stall in 29c leaves 29a and 29b delivered. The
consequence is deliberate and worth stating plainly: because the walk never
routes around a step, the sync-back implementation built here is not reachable
by the walk until 29c lands. It is complete, tested, and correct; it simply
sits behind the step in front of it, which is exactly what "never route around
a gate" means when the gate is a capability boundary rather than a repository
rule.
</design_notes>

  <action>
Port `scripts/sync-main-to-develop.sh` into `release_execute.rs` as the step-5
action, preserving every check it performs.

`fn sync_branch_name(version: &str) -> String` — returns
`sync/main-to-develop-v<version>`, matching what `pr_refs` already returns for
`ReleaseStep::SyncMerged`; add a test asserting the two agree so they cannot
drift.

`fn sync_back_pr(project_root: &Path, version: &str) -> Result<String, String>`:

1. Fetch `main` and `develop` from `origin`.
2. Short-circuit: if `origin/main` is already an ancestor of `origin/develop`,
   return a detail saying so and create nothing. This is the script's own early
   exit at its ancestor check, and it is what makes a re-run free.
3. Create a scratch worktree on a new branch off `origin/develop`, using the
   same always-cleanup structure `prepare_bump_branch` established — removal on
   every exit path, including the refusal path below.
4. Record the pre-merge tree object id.
5. Merge `origin/main` with `-X ours` and no edit, using the script's own commit
   message including its explanation that develop's content is authoritative and
   the merge should be a pure history link.
6. Record the post-merge tree object id. **If the two differ, refuse:** return
   `Err` naming both ids and stating that `main` carried content develop
   genuinely lacked, so a human must inspect the merge before anything is
   pushed. Push nothing and open nothing. The script exits non-zero here and so
   must this — a warning that continues would defeat the check.
7. Push the sync branch and call `open_and_arm_pr` with head
   `sync_branch_name(version)`, base `develop`, and intent
   `MergeIntent::SyncBack`. That intent requires a real merge commit, so the
   armed method is `--merge`. CONTRIBUTING.md step 6's block quote records that
   an unspecified-method auto-merge on this exact pull request defaulted to
   squash on 2026-07-27, destroyed the ancestry link, and needed a second pull
   request to repair. Here the wrong method is not merely discouraged — it is
   unrepresentable, because resolution is keyed to the intent and
   `MergeMethod` has no unspecified variant.

Wire `action_for(ReleaseStep::SyncMerged)` to it.

Add `#[cfg(test)] mod tests` cases for every `<behavior>` bullet against real
git fixture repositories. The tree-identity refusal case is the one that must
not be skipped: build a fixture where `main` carries a file `develop` lacks,
run the action, and assert it returned `Err`, that no branch was pushed, and
that the scratch worktree is gone. A fixture-repo test is an assertion at git's
own object model, which is a real boundary, not a reimplementation of the
production algorithm.

Add a CLI-level test in `crates/devflow-cli/tests/release_cut.rs` named
`cut_walks_to_the_signed_tag_step_and_stops`, asserting that against a fixture
where steps 1, 2, 3, and 5 all observe as already done, the walk stops on the
signed-tag step with an outcome naming unit `29c`. This pins the unit boundary
as a tested fact rather than a claim, and it is the assertion that will need
updating — deliberately — when `29-07` lands.

Finally, add a short note to `CONTRIBUTING.md` § "Cutting a Release" recording

the executor implements, and that `scripts/sync-main-to-develop.sh` stays in
the repository as the reference the port was made from. Do not delete the
script and do not rewrite the manual procedure: a human must still be able to
cut a release by hand when the executor cannot run.

<threat_model>
ASVS level **1**; blocking threshold **high**.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> DevFlow CLI | the version string reaches branch names, commit messages, and pull-request titles |
| DevFlow -> `origin` | a sync branch is pushed; the push crosses `scripts/hooks/pre-push` |
| DevFlow -> GitHub REST API (via `gh`) | two pull requests created and armed against discovered rules |
| git's merge result -> DevFlow's decision to push | the tree-identity comparison is the gate; a wrong answer here corrupts `develop`'s content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-08 | Tampering | the sync pull request squashed, destroying the ancestry link | high | mitigate | `MergeIntent::SyncBack` resolves to `MergeMethod::Merge`; `MergeMethod` has no unspecified variant; `resolve_merge_method` refuses rather than substituting when merge is unavailable; unit-tested against an allowed set containing both methods |
| T-29-20 | Tampering | a `-X ours` merge silently changing develop's content | high | mitigate | the pre-merge and post-merge tree object ids are compared and a difference is a hard refusal that pushes nothing and opens nothing, exactly as the ported script does; a fixture test where `main` carries extra content asserts the refusal |
| T-29-01 | Tampering | version string reaching branch names, commit messages, and `gh` argv | high | mitigate | discrete `Command::args` elements throughout; pull-request bodies passed by file; no shell invoked on any release path |
