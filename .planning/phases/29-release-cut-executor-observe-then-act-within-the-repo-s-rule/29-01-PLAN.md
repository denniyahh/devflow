## The six questions and their oracles (fixed for the whole phase)

`ReleaseStep` is the phase's **fixed, enumerable action set** (RD-2's
"action set: fixed and enumerable" layer), in the exact order the ROADMAP
goal line states: version bump -> changelog -> release PR to `main` ->
signed tag -> sync back to `develop` -> publish core then cli.

| # | `ReleaseStep` | Question | Oracle |
|---|---------------|----------|--------|
| 1 | `VersionBumped` | does `origin/develop`'s root `Cargo.toml` declare version X? | `gh api` contents at ref `develop` |
| 2 | `ChangelogWritten` | does `origin/develop`'s `CHANGELOG.md` carry a `## X` heading? | `gh api` contents at ref `develop` |
| 3 | `ReleasePrMerged` | does `origin/main`'s root `Cargo.toml` declare version X? | `gh api` contents at ref `main` |
| 4 | `SignedTagPresent` | is `refs/tags/vX` on `origin`, annotated, and carrying a signature? | `git ls-remote --tags` + `gh api` git-tag object |
| 5 | `SyncMerged` | is `origin/main` an ancestor of `origin/develop`? | `gh api` compare `main...develop` |
| 6 | `CratesPublished` | is every `publish_order()` member live at X? | crates.io `/api/v1/crates/{name}/{version}` |

**This plan implements questions 4 and 6 only.** Questions 1, 2, 3, 5 land in
`29-02-PLAN.md`. Question 4 is the tracer because it is the exact defect the
motivating incident produced, and question 6 is the second task because the
crates.io HTTP call is the one piece of this phase with **no analog anywhere
in the codebase** (`29-PATTERNS.md` § No Analog Found) — proving it early is
what a tracer is for.

**Why observations 1/2/3/5 read content through `gh api` rather than through
a local `git fetch`:** the observer must not mutate the operator's
repository. A `git fetch` writes `FETCH_HEAD` and can opportunistically update
remote-tracking refs; `gh api` reads GitHub's copy and writes nothing locally.
A `gh` that is missing or unauthenticated therefore yields **Unreachable with
gh's own message**, never Absent — which is exactly the required discipline,
not a workaround for it.

Create `crates/devflow-core/src/release_observe.rs` and declare it in
`lib.rs` as `pub mod release_observe;`, placed in the existing alphabetical
module list between `recover` and `registry`.

Define in that module:

`Observation` — a public enum with exactly three variants:
`Present { detail: String }`, `Absent { detail: String }`,
`Unreachable { reason: String }`. Derive `Debug`, `Clone`, `PartialEq`, `Eq`.
Every arm carries a `String`; no bare unit variants. This mirrors
`SigningViability`'s `{ reason: String }` convention from `git.rs`. Two-valued
results are forbidden anywhere in this module (RD-8's `unreachable != absent`
rule) — a tool that fails to run, a non-zero exit, an unparseable response, or
an unexpected status code all produce `Unreachable`, carrying the real tool's
own message.

`ReleaseStep` — a public `Copy` enum with the six variants
`VersionBumped`, `ChangelogWritten`, `ReleasePrMerged`, `SignedTagPresent`,
`SyncMerged`, `CratesPublished`, in that declaration order (it is the release
sequence). Add `pub const ALL: [ReleaseStep; 6]` listing them in that same
order, and `pub fn label(self) -> &'static str` returning a short human label
per variant for the report ("version bumped on develop", "changelog written on
develop", "release PR merged to main", "signed tag on origin", "main synced
back into develop", "crates published"). Only `SignedTagPresent` is wired to a
real oracle in this task; the rest are wired in `29-02-PLAN.md`.

`TagRefs` — a public struct with `object: Option<String>` and
`peeled: Option<String>`, plus `pub fn is_annotated(&self) -> bool` (true when
`peeled` is `Some`) and `pub fn exists(&self) -> bool` (true when `object` is
`Some`). A peeled `^{}` entry proves annotated, not signed.

`TagSignature` — a public enum `Present`, `Missing`,
`Undetermined { reason: String }`. `Undetermined` is the arm for "the GitHub
API call did not answer", and it must propagate to `Observation::Unreachable`,
never collapse to `Missing`.

`pub fn classify_tag_refs(ls_remote_stdout: &str, tag: &str) -> TagRefs` —
pure. Parses `git ls-remote --tags` output: tab-separated `<sha>\t<ref>` lines,
matching `refs/tags/<tag>` for the object sha and `refs/tags/<tag>^{}` for the
peeled sha. Ignores every other line. No I/O, no `Command`, fully unit-testable.

`pub fn classify_signed_tag(refs: &TagRefs, signature: TagSignature) -> Observation` —
pure. Absent when the ref does not exist; Absent (with a detail naming
"lightweight") when it exists but is not annotated; then delegates to the
signature arm: Present -> `Observation::Present`, Missing -> `Observation::Absent`
with a detail naming "annotated but carries no signature",
Undetermined { reason } -> `Observation::Unreachable { reason }`.

`pub fn signed_tag_on_remote(project_root: &Path, version: &str) -> Observation` —
the I/O wrapper. Builds the tag name as `v` followed by the version string.
Runs `git ls-remote --tags origin` through `devflow_core::git::git_command(project_root)`
(never `Command::new("git")`), passing the tag refspec as an argument via
`Command::args`, never string-interpolated into a shell. A spawn error or a
non-zero exit becomes `Unreachable` carrying the trimmed stderr. On success,
calls `classify_tag_refs`; if the tag is annotated, resolves the signature by
calling `tag_signature_via_gh` and then `classify_signed_tag`.

`fn tag_signature_via_gh(project_root: &Path, tag_object_sha: &str) -> TagSignature` —
runs `gh api repos/{owner}/{repo}/git/tags/<sha> --jq .verification.verified`
with `Command::new("gh")` pinned to `.current_dir(project_root)` (git-scrubbing
is unnecessary for `gh` per 29-RESEARCH Open Question 2, but the pinned cwd is
what makes `{owner}`/`{repo}` resolve to this repository — leaving it ambient
is threat T-29-10). `gh` substitutes those two placeholders from the repo
context itself; do not parse the remote URL. Map stdout `true` -> `Present`,
`false` -> `Missing`, and anything else (spawn failure, non-zero exit, empty or
unexpected stdout) -> `Undetermined { reason }`. The reason must describe the
failure class and may quote `gh`'s exit status, but must **never** include
`gh`'s raw stdout or stderr — that is the T-17-13 discipline `preflight.rs`
already documents, and it is inherited here, not re-decided.

    - `classify_http_status("404")` is `Observation::Absent`.
    - `classify_http_status("000")` is `Observation::Unreachable` (curl's code for "could not connect").

  <action>
Extend `release_observe.rs` with the crates.io oracle.

`pub fn classify_http_status(code: &str) -> Observation` — pure, no I/O.
Exactly `"200"` is Present, exactly `"404"` is Absent, and every other value —
including empty, non-numeric, `"000"`, and any 3xx/4xx/5xx — is Unreachable
with a reason naming the code that was seen. This split (pure classification
separate from the invocation) is what makes the oracle unit-testable without a
network and without re-implementing the HTTP call inside the test body, which
`rules/test-signal-rejection.md` rejects.

`fn crate_version_http_status(project_root: &Path, name: &str, version: &str) -> Result<String, String>` —
runs `curl` with `Command::new("curl")`, `.current_dir(project_root)`, and the
argument list `-s`, `-o`, `/dev/null`, `-w`, `%{http_code}`, `--max-time`, `20`,
`-A`, a descriptive user agent, and the URL
`https://crates.io/api/v1/crates/<name>/<version>`. Build the URL with
`format!` and pass it as a single `Command::args` element — never through a
shell, never with any interpolation into a shell string (threat T-29-01). The
user agent must be descriptive and carry this repository's URL, because
crates.io's data-access policy expects one; do not ship RESEARCH.md's
placeholder agent string. Use the `/api/v1` JSON endpoint and nothing else:
the sparse index at `index.crates.io` is CDN-cached and lags a real publish by
seconds, which is the literal mechanism behind the "waiting for devflow-core
2.2.0 to be available" message this repo already observed — using it here would
manufacture the exact absent-versus-unreachable ambiguity this phase exists to
eliminate. A spawn error or a non-zero curl exit returns `Err` with the
failure text, which the caller converts to Unreachable.

`pub fn crates_published(project_root: &Path, version: &str) -> Observation` —
calls `devflow_core::git::publish_order(project_root)` for the member list.
Never hardcode the two crate names anywhere; `publish_order` already computes
them from the workspace manifest and is already tested. Query each member in
the returned order, classify each with `classify_http_status`, and fold with
`combine_crate_observations`.

`pub fn combine_crate_observations(per_crate: &[(String, Observation)]) -> Observation` —
pure. Unreachable dominates everything; then Absent dominates Present; all
Present is Present; an empty slice is Unreachable. The Present and Absent
details must name which crates were found at which state so the report is
