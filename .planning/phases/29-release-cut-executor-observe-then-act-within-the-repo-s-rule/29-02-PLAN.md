Extend `release_observe.rs` with a shared remote-content reader and three
oracles built on it.

`fn file_at_ref(project_root: &Path, path: &str, git_ref: &str) -> Result<String, String>` —
runs `gh api repos/{owner}/{repo}/contents/<path>` with the query parameter
`ref=<git_ref>` and the header `Accept: application/vnd.github.raw`, so GitHub
returns the file's raw bytes rather than a base64 envelope. Use
`Command::new("gh")` with `.current_dir(project_root)` pinned (T-29-10) and
every argument as a discrete `Command::args` element (T-29-01). On spawn
failure, non-zero exit, or empty stdout, return `Err` with a failure-class
description that does **not** embed `gh`'s raw stdout or stderr (T-29-03,
T-17-13). Callers convert every `Err` into `Observation::Unreachable`.

This reads GitHub's copy rather than fetching into the local object database
on purpose: a `git fetch` writes `FETCH_HEAD` and can opportunistically update
remote-tracking refs, which would make the observer a mutator. A `gh` that is
absent or unauthenticated therefore surfaces as Unreachable carrying gh's
failure class — which is the required behavior, not a workaround for it.

`pub fn classify_manifest_version(cargo_toml: &str, expected: &str) -> Observation` —
pure. Calls `devflow_core::version::read_workspace_self_pins(cargo_toml)`.
Unreachable when it yields no `[workspace.package]` version (unparseable or
empty input). Absent when that version differs from `expected`, with a detail
naming both. Absent when the workspace version matches but any local-path
self-pin does not, with a detail naming the drifted pin — CONTRIBUTING.md
step 1 makes the two-place bump a single fact, and "bumped only the first" is
the documented easy miss, so it must not read as done. Present only when the
workspace version and every self-pin equal `expected`.

`pub fn classify_changelog_heading(changelog: &str, version: &str) -> Observation` —
pure. Unreachable on empty input. Present when any line, after trimming
leading whitespace, begins with `## ` followed by the version string as its
first whitespace-delimited token (so `## 2.3.0` and `## 2.3.0 - 2026-08-01`
both count, and a bare inline mention does not). Absent otherwise. Document
and test the two edge inputs named in `<behavior>` rather than leaving them
implicit.

`pub fn version_bumped_on_develop(project_root: &Path, version: &str) -> Observation` —
`file_at_ref(project_root, "Cargo.toml", "develop")` then
`classify_manifest_version`.

`pub fn changelog_written_on_develop(project_root: &Path, version: &str) -> Observation` —
`file_at_ref(project_root, "CHANGELOG.md", "develop")` then
`classify_changelog_heading`.

`pub fn release_pr_merged_to_main(project_root: &Path, version: &str) -> Observation` —
`file_at_ref(project_root, "Cargo.toml", "main")` then
`classify_manifest_version`. The observable is the outcome — `main` carrying
version X — not the pull request object. Under RD-8 the outcome is the oracle;
a merged PR is only the means by which it became true, and querying the PR
list instead would make the answer depend on a mutable GitHub search index.

Wire all three into `commands.rs`'s `release_status` check list via the
existing `Observation`-to-`Check` helper, in `ReleaseStep::ALL` order.

Add `#[cfg(test)] mod tests` cases for every `<behavior>` bullet. Feed the
classifiers literal manifest and changelog strings; never reconstruct the
parse inside the test body.

`pub fn classify_compare_status(status: &str) -> Observation` — pure, mapping
GitHub's compare `status` field. `ahead` and `identical` are Present (base
`main` is an ancestor of head `develop`); `behind` and `diverged` are Absent;
anything else, including empty, is Unreachable naming the value seen.

`pub fn sync_merged(project_root: &Path) -> Observation` — runs
`gh api repos/{owner}/{repo}/compare/main...develop --jq .status` with the same
pinned-cwd, discrete-argv, never-log-raw-output discipline as the other `gh`
calls, then `classify_compare_status`. Note in the doc comment that this
answers remotely the same question `scripts/sync-main-to-develop.sh` asks
locally, and that it is deliberately a different function from
`git::origin_main_ancestor_status`, which reads already-fetched local refs and
must keep its existing no-fetch behavior for `release --check`. Two functions
here are correct: one answers "what is true on the remote", the other answers
"what does this checkout already know", and collapsing them would silently
change `release --check`'s documented no-network property.

`pub fn observe(project_root: &Path, step: ReleaseStep, version: &str) -> Observation` —
an exhaustive `match` over all six `ReleaseStep` variants, each arm calling its
own oracle. No wildcard arm: a future seventh variant must fail to compile
rather than silently return a default.

`pub fn observe_all(project_root: &Path, version: &str) -> Vec<(ReleaseStep, Observation)>` —
maps `ReleaseStep::ALL` through `observe`, preserving order.

In `commands.rs`, rewrite `release_status`'s body to call `observe_all` and
build its `Check` list from the result, replacing the per-question calls added
in earlier tasks so there is exactly one place that knows the question list.
Keep `release_check`'s printing loop shape unchanged. End with a summary line
naming the version and the count of Present rows out of six, and return
`CliError::Message` when any row is `"fail"`.

Add unit tests for every `<behavior>` bullet, including a test that asserts
`observe` handles all six `ReleaseStep::ALL` variants — for example by
iterating `ReleaseStep::ALL` against a fixture with no remote and asserting all
six come back Unreachable with distinct, non-empty reasons, which simultaneously
proves the dispatcher is wired and that no arm quietly reports Absent when the
oracle could not be reached.

<threat_model>
ASVS level **1**; blocking threshold **high**.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> DevFlow CLI | the `version` positional reaches `gh` argument vectors and the classifiers |
| DevFlow -> GitHub REST API (via `gh`) | remote file contents and compare status are untrusted external input parsed by pure classifiers |
| DevFlow -> local repository | the observer must read without writing; any write is a boundary violation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-01 | Tampering | version string and ref names reaching `gh` argv | high | mitigate | every argument a discrete `Command::args` element; no shell invocation anywhere in `release_observe.rs` |
| T-29-03 | Information Disclosure | `gh` stdout/stderr in `file_at_ref` and `sync_merged` | high | mitigate | failure-class descriptions only; raw `gh` output is never logged, printed, or embedded in an `Unreachable` reason (T-17-13) |
| T-29-11 | Tampering | a missing or unauthenticated `gh` classified as "not done" | high | mitigate | every `Err` from `file_at_ref` becomes `Unreachable`; `status_reports_unreachable_not_absent_without_a_remote` asserts zero absent-shaped rows when nothing is reachable |
| T-29-12 | Tampering | the observer mutating the operator's repository while "reading" it | high | mitigate | content is read through `gh api` rather than a local fetch; `status_leaves_the_repository_untouched` asserts HEAD, working tree, and the full ref listing are byte-identical after a run |
| T-29-13 | Elevation of Privilege | observation being treated as authorization | medium | mitigate | `release status` accepts no authorization flag; `status_rejects_an_authorization_flag` asserts argument parsing refuses `--yes-release` |
| T-29-05 | Tampering | inherited `GIT_DIR` redirecting the observer's git calls | medium | mitigate | every git call routes through `git_command`, which unconditionally scrubs all 18 redirecting variables (Phase 27, already delivered) |
| T-29-SC | Tampering | npm/pip/cargo installs | high | mitigate | this plan adds zero new dependencies; 29-RESEARCH.md § Package Legitimacy Audit records nothing to gate. Any added dependency requires the Package Legitimacy Gate and a blocking human checkpoint first |
</threat_model>
