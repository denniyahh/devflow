reports state-orphaned processes as their own class, and an opt-in reaping path that clears them
with verified death — and retarget the second flaky identity test.

Purpose: 999.44 / DEN-68 and 999.47 / DEN-72. Today both of Phase 23's primitives return success
while an orphan keeps running: `gate sweep` never lists it, because its root is absent from the
registry, and `devflow stop --phase N --root PATH` reports that no lock is held and exits 0. The
messages are *true* against recorded state, so this is not a false attestation — but an operator
reading exit codes concludes the machine is clean when it is not. This is the one remaining case
that requires `kill(1)`, and on 2026-07-27 it required `SIGKILL` specifically: 30 processes, none
responding to `SIGTERM`.

Output: a read-only `doctor` finding, an opt-in `gate sweep` reaping flag, an end-to-end test that
deletes a live process's root out from under it, and the retargeted `stop` identity test.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS process table → reaping decision | On a possibly-shared machine, every process is visible in `/proc`; a stray has no lock file it authored, so identity is inferred rather than attested |
| CLI flag → irreversible signal | `SIGKILL` cannot be undone; the flag is the authorisation boundary |
| reap event → `.devflow/events.jsonl` | `OPERATIONS.md` advertises the event log as safe to tail (WR-02) |
| `doctor` → the machine | `doctor` is contractually read-only; Phase 18-01 proved it so with a twice-run fixture |
