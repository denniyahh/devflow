  <action>
Rewrite CONTRIBUTING.md's release procedure step 5 to fix both drifts the 25f entry files,
verified against live file content:

**(a) The tag command produces the wrong signature.** Step 5 currently instructs a bare
`git tag -s vX.Y.Z <commit>`. On a machine where the agent works, `user.signingkey` is the
*agent's* key, so that command produces an agent-signed release tag — exactly what the
maintainer-key policy exists to prevent. The `pre-push` hook now refuses to push such a tag, so
the outcome is a blocked release rather than a mis-signed one, but the operator discovers it
*after* the squash-merge to `main` has already happened, which is the expensive moment. Change
step 5 to the explicit key-selection form CONTRIBUTING.md's own signing-keys section already
documents at lines 79-82 — `git -c user.signingkey="$(git config --get devflow.releaseSigningKey)"
tag -s …` — and cross-reference that section by name so the two can never drift apart again.
Use the `git config --get` indirection, never a literal key path: this file is public and a
literal path would embed a contributor's home directory and username.

**(b) The warning reasons about an inverted default.** Step 5's justification for preferring
`-s` over `-a` rests on a repo-local tag-signing default that the tracked `.gitconfig` added in
PR #38 has since set the other way. A reader following the stale warning reasons about the wrong
failure mode. Remove that justification and replace it with the actual current reason to use
`-s` with an explicit key: signing is already on by repository policy, so the risk is not an
unsigned tag but a tag signed with the wrong key, which looks correct in `git log` and on GitHub
because both keys carry the same `user.email` — the fingerprint is the only distinguishing
identity, which is why the hook compares fingerprints.

Keep the `git push origin vX.Y.Z` and `git tag -v vX.Y.Z` verification instructions. Do not touch
steps 1-4 or step 6. Do not modify `.gitconfig` — it is correct; the documentation is what drifted.
  </action>
