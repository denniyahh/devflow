<objective>
Stop `devflow start` from resolving its base branch out of a local ref that may be arbitrarily
behind the remote — the defect that forced a human to run `git fetch` by hand before two of
three acceptance attempts, on a goal whose entire definition is "unattended".

Purpose: 999.51 / DEN-76. On 2026-07-27 local `develop` was 0 ahead / 21 behind
`origin/develop`; Phase 24's heading existed on the remote and not locally, so
`ensure_phase_reachable_on_base` would have refused a phase that was plainly reachable. The
operator ran `git fetch origin develop:develop` by hand. `23-ACCEPTANCE-SETUP-2.md` records the
same class on 2026-07-26 at 120 behind. **The dangerous variant is the silent one**: when the
phase heading *does* exist on a stale local `develop` while the code does not, the guard passes
and the run forks from an outdated base, producing a green run against the wrong source — the
false-evidence shape D-18 exists to prevent, arriving through the base ref instead of the binary.

Output: a currency probe next to the existing reachability probe, and a one-line ordered call in
`start`. What a stale base *does* was adjudicated by the operator on 2026-07-27 — see
`<resolved_decision>`.
</objective>

## D-18a — what a stale base does (operator, 2026-07-27)

CONTEXT.md D-17 recorded 25a's three fix directions as **unchosen**, with the operator's tension
verbatim: *"refuse-loudly is the S-sized variant the entry sizes for, but a refusal still means an
unattended run does not start."* This plan originally opened with a `checkpoint:decision` for that
reason. **The operator resolved it during plan review on 2026-07-27; the checkpoint is removed and
this plan is autonomous.**

**Selected: fetch, compare, fast-forward the local base when it is safe, else refuse loudly**
(999.51 option 1+3 combined — the `<action>` below implements exactly this).

**Rationale as adjudicated.** The deciding fact is that local `develop` is behind `origin/develop`
in the **normal steady state** — every phase that ships via a PR merge on GitHub leaves the local
clone behind. That is precisely the condition that forced a manual `git fetch` before two of three
acceptance attempts. Refuse-loudly would therefore halt on the *common* path, not an edge case,
converting a silent wrong answer into a routine non-start on a goal whose entire definition is
"unattended".

The operator's stated tiebreaker was simplicity — *"I want simpler though as a principle"* — and it
was applied and found not to govern here: fast-forward costs one extra branch plus a safety
predicate, and simplicity is a tiebreaker between options that both work, not a reason to choose
one that does not. (The same test was applied to 25b in CONTEXT.md D-03, where the simpler option
*did* work and won.)

**Recorded acknowledgement, required by the original checkpoint's acceptance criteria:** the
"no `git fetch` in the start path" design property stated at `commands.rs:1877` and `:1980` **is
reversed for the start path**. Note this property is conceded by *both* candidate options — a
trustworthy comparison requires a fetch either way — so it was not a differentiator between them.
Update those two comments rather than leaving a future reader to read them as a contradiction.

**Safety envelope, unchanged from the option as offered:** the fast-forward is attempted only when
the local ref is a strict ancestor of the remote (lossless — no divergence, no local commits) AND
the base branch is not the currently checked-out branch. Every other case still refuses loudly, so
refuse-loudly's safety property is retained as the fallback. `Diverged` always refuses.
</resolved_decision>

Add to `crates/devflow-cli/src/preflight.rs`, immediately alongside the existing
phase-reachability triple so the two probes read as siblings:

1. `pub(crate) enum BaseRefCurrency { Current, Ahead, Behind { count: u32 }, Diverged, Undeterminable }`
   — the same shape as `PhaseReachability`, with `Undeterminable` carrying the same
   fail-open-where-blind meaning the module already documents.

2. `pub(crate) fn base_ref_currency(project_root: &Path, base: &str) -> BaseRefCurrency`
   — a pure probe with no side effects beyond the fetch described below. Follow
   `origin_main_ancestor_status`'s shape verbatim: `git rev-parse --verify --quiet
   origin/<base>` for ref existence, collapsing spawn failure and non-zero exit into the same
   `Undeterminable` branch, then `git merge-base --is-ancestor` in **both** directions to
   distinguish behind, ahead, equal and diverged. Get the behind-count with
   `git rev-list --count <base>..origin/<base>` so the message can state how far behind.

   Before comparing, issue `git fetch --quiet <remote> <base>`, which updates only the
   remote-tracking ref — it never touches the local branch or the working tree, so it cannot
   fail with the "branch is checked out" error that a refspec fetch into the local branch
   would. **The fetch must fail soft**: on spawn error or non-zero exit, print a warning naming
   the base and stating the comparison may be stale, then continue with whatever the
   remote-tracking ref currently holds. This is Phase 24's inherited D-06 precedent — a new
   code path must not introduce a false hard-block on correct work, and an offline machine is
   correct work. Do not let the fetch block indefinitely; if the codebase has no existing
   subprocess timeout idiom, note that in the summary rather than inventing one here.

3. `pub(crate) fn stale_base_message(base: &str, remote_ref: &str, count: u32) -> String`
   — modelled on `unreachable_message`: self-contained, actionable, naming the exact repair
   command, and containing **no absolute filesystem path** (WR-02 — on Linux a path embeds the
   operator's username, and this string reaches operator output). Name refs and commands only.

4. `pub(crate) fn ensure_base_ref_current(project_root: &Path, base: &str) -> Result<(), CliError>`
   — mirroring `ensure_phase_reachable_on_base` exactly: `Current`, `Ahead` and `Undeterminable`
   all return `Ok(())` (the last with a warning); `Diverged` returns
   `Err(CliError::Message(...))` — a divergent base is never silently forked from.

   **The `Behind` arm implements the operator's 2026-07-27 adjudication (see
   `<resolved_decision>`): fast-forward when safe, else refuse loudly.** Attempt the
   fast-forward only when BOTH hold: the local ref is a strict ancestor of the remote (already
   established by the probe returning `Behind`, which is lossless — no divergence, no local
   commits), AND the base branch is not the currently checked-out branch (check with
   `git symbolic-ref --quiet --short HEAD` and compare to `base`). Perform it with
   `git update-ref refs/heads/<base> refs/remotes/<remote>/<base>` — this advances the ref
   without touching the working tree, which is why the not-checked-out precondition is
   sufficient. On success print one line naming the base and the commit count advanced, then
   return `Ok(())`. On **any** failure — checked out, spawn error, non-zero exit — fall through
   to `Err(CliError::Message(stale_base_message(...)))`. The refusal is the fallback for every
   failure path; never proceed silently after a failed fast-forward.

   Update the doc comments at `crates/devflow-cli/src/commands.rs:1877` and `:1980`, which state
   that checks run "against ALREADY-FETCHED local refs, issuing NO `git fetch`". That property is
   now reversed for the start path. Record the reversal in those comments with a pointer to
   999.51 rather than deleting the sentence, so the original intent stays legible.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote repository → local base ref | `git fetch` brings remote-controlled refs into the local repository before any comparison is made |
| base ref → forked worktree | Whatever `develop` points at becomes the start point for the phase's worktree and therefore the source every stage runs against |
| refusal/warning message → operator output | Absolute paths on Linux embed the operator's username (WR-02) |
