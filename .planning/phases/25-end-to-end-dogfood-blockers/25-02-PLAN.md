<objective>
Give `devflow-core` the two process primitives a stalled run needs in order to be recovered
without `kill(1)`, and retire the dead predicate whose tests feed the 3-strike Validate gate.

Purpose: 999.44 / DEN-68 and 999.47 / DEN-72. On 2026-07-27 all 15 orphaned monitor wrappers
on the machine survived `SIGTERM`; only `SIGKILL` cleared them, and killing the wrappers then
orphaned their `devflow advance` children, which also required `SIGKILL` — 30 processes, none
responding to `SIGTERM`. `agent::terminate` sends exactly one `SIGTERM` with no escalation and
no verification of death, so **any reaping path built on it reports success and leaves the
process running** — strictly worse than the silence 999.44 already describes. Separately,
`looks_like_devflow_process` has no production callers left (D-02) but its two tests race
`execve` and fail roughly half the time under CI load, which inside an unattended loop is a
mechanism for halting a healthy run.

This plan is the library half. Plan 25-07 surfaces both primitives on the CLI and retargets
the second flaky test.

Output: `terminate_and_verify`, `discover_stray_devflow_processes` + `StrayProcess`, and a
`#[deprecated]` `looks_like_devflow_process` whose unit test asserts the identity guard
production actually uses.
</objective>

Add `pub fn terminate_and_verify(pid: u32, wait: std::time::Duration, poll: std::time::Duration) -> bool`
to `crates/devflow-core/src/agent.rs`, built from the primitives already in the file — do not

Sequence: call the existing `terminate` (one `SIGTERM`); if it returns `false`, the process
could not be signalled, so return `!agent_running(pid)` — already dead counts as success.

point of the function per D-17 ("must escalate `TERM` → `KILL` with a bounded wait and
*verify* death rather than assume it").

Add module-level constants for the default wait and poll intervals (a wait on the order of a
few seconds, a poll on the order of tens of milliseconds) so callers in plan 25-07 do not each
invent their own, and document that a caller which needs a different ceiling passes its own.

Note in a doc comment why `SIGKILL` escalation is not optional here: 999.44's 2026-07-27
measurement found 15 of 15 orphaned wrappers surviving `SIGTERM`, and the wrapper installs

shell blocked in `wait` on a child it can never reap. Per 25-RESEARCH.md Open Question 2 and
999.47's own recorded lesson, the fix deliberately does **not** depend on explaining that
mechanism; the escalation works regardless of why `SIGTERM` alone fails. Record that as
accepted unexplained behaviour the code defends against, not a root cause this plan must fix.

  <action>
Add `pub struct StrayProcess { pub pid: u32, pub start_time: u64, pub layer: StrayLayer }` and
`pub enum StrayLayer { MonitorWrapper, AdvanceChild }`, plus
`pub fn discover_stray_devflow_processes() -> Vec<StrayProcess>` to
`crates/devflow-core/src/agent.rs`.

Implementation: iterate `/proc`'s numeric entries, read each `/proc/<pid>/cmdline`, and split
it on NUL bytes exactly as `looks_like_devflow_process` already does. A process is a candidate
only when it matches one of two **narrow, structural** shapes:

- **Layer 1 — the monitor wrapper.** Its argv is a shell invoked with `-c` whose script
  argument contains the literal, DevFlow-specific marker string that `monitor::spawn_monitor`
  writes into its wrapper script (the trap-installation line — read `monitor.rs` and take the
  marker verbatim from the source rather than retyping it, so the two can never drift). Match
  on that multi-token literal, not on any single word.
- **Layer 2 — the trailing advance child.** `argv[0]`'s **basename** equals the binary name
  AND `argv[1]` equals the advance subcommand. Both conditions, on those two specific argv
  positions.

These matchers are deliberately narrower than the predicate 999.47 disproved, which matched
**any** argv element whose basename began with the binary name — so `sleep /tmp/devflow-scratch/x`
matched, as did any process merely mentioning a devflow path in its arguments. Do not
reintroduce that shape: never scan all argv elements, and never match on a prefix.

Two hard constraints on the census:

1. **Do not filter candidates by parent-process identity.** These orphans reparent to the
   user's per-user service manager, not to the init process — a filter on a parent identity of
   one was directly measured against this repository (`23-FINDINGS.md`) to report **zero**
   orphans while 14 genuinely existed. The census must be subreaper-aware, which here means
   simply not consulting parentage at all.
2. **Never return a process owned by another user.** Compare `/proc/<pid>`'s owning uid
   against the current effective uid (`libc::geteuid`) and skip anything that does not match.
   999.44 sizes this unit on exactly this requirement — "a PID-discovery mechanism that is
   safe on shared machines and does not misidentify unrelated processes" — and signalling a
   process belonging to someone else is the concrete hazard.

Record `process_start_time(pid)` for every candidate at discovery time and skip any pid whose
start time cannot be read (the process exited mid-scan). The recorded pair is what lets plan
25-07's reaper re-confirm identity with `is_same_process` immediately before it signals,
closing the check-then-act TOCTOU 999.47's own "Related TOCTOU" note names. Discovery itself
**never signals anything** — it is a pure read-only census; the decision to act is the
caller's.

Tolerate every read failure silently (a pid that vanishes between the directory listing and
the cmdline read is normal), and return an empty vector when `/proc` cannot be read at all
rather than propagating an error.
  </action>
