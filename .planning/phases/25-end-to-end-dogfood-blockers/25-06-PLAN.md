## 25-RESEARCH.md Open Question 1 is RESOLVED — no defence-in-depth second check is needed

25-RESEARCH.md flags a timing gap (Pitfall 1): `run_preflight` fires before the Ship-stage agent
spawns, so any commit the Ship agent itself makes would escape the classification. It could not
confirm whether the Ship agent commits, and recommended the planner verify before deciding whether
to add a second classification immediately before `Merge`.

**Verified since RESEARCH.md was written, and the answer is favourable.** The Ship-stage prompt
(`crates/devflow-core/src/prompt.rs`) runs the code-review workflow **without a fix flag**, so it
only writes a review report, committed as a `docs`-typed commit. It then runs the ship workflow,
whose only commit is a `docs`-typed state-file commit. Both are `docs` under D-08's classifier and
therefore contribute **no bump**. **No breaking-change commit can land between the D-09 preflight
gate and `hooks_after_ship`.**

**Therefore: implement the preflight check only.** Do not add a second late classification, and do
not carry Pitfall 1 as an open risk in the summary. Record the resolution instead, so a future
reader does not re-open a settled question.
</resolved_open_question>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| commit messages → version bump decision | Commit subjects and footers are attacker-influenceable through an untrusted contributor's PR, and they now determine whether a major version is cut |
| preflight verdict → `hooks_after_ship` | Everything after the Merge step is unrollable; the gate is the last point at which a human can intervene |
| `Err(reason)` string → gate file, notify hook, operator output | The reason is persisted into a gate file and surfaced to the operator; it carries attacker-influenced commit text |
