<why_the_production_window_is_reachable>
The full derivation is in `25-11-PLAN.md` §`<scope_decision>`. In short, and grounded in this
codebase's own documentation rather than inference:

`agent.rs:175-187` states the mechanism as settled fact: *"Between `Command::spawn()`
returning a pid and the child completing `execve`, the child is a copy of its parent:
`/proc/<pid>/cmdline` reports the PARENT's argv."* That rule is a property of `fork()`, not
of `std::process::Command` — it holds for the wrapper shell's own `&` background fork too.

`monitor::spawn_monitor_inner` spawns `sh -c <script>` where the script contains
`MONITOR_WRAPPER_MARKER` verbatim. That shell then forks twice more: once for the agent
(`"$@" ... &`) and once for the trailing `devflow advance`. Each of those children, inside its
own window, presents argv[0] basename `sh`, argv[1] `-c`, and an argv[2] containing the
marker — which is `classify_stray_layer`'s Layer 1 predicate exactly (`agent.rs:373-380`).
Symmetrically, a child forked by `devflow advance` presents argv[0] basename `devflow` and
argv[1] `advance` — Layer 2.

`reap_stray_candidates` re-confirms `is_same_process(pid, start_time)` before signalling. For
a mid-`execve` child that check **passes** — same process, same start time. It then calls
`terminate_and_verify`, which sends `SIGTERM` and escalates to `SIGKILL`.

The co-occurrence required is not hypothetical. `commands.rs:3663-3667` states it as the
operating condition: this command is expected to run while *"this machine's live process
table legitimately contains other, unrelated devflow activity (concurrent phases in sibling
worktrees)."* And `25-CI-OBSERVATION.md` demonstrated that the window is wide enough under
load to be hit routinely, not rarely.

**The opposite direction is deliberately NOT in scope.** A census *miss* during the window
(the shape that broke the tests) is harmless in production: a process created microseconds
ago is by construction not a stray, `doctor` only prints, and `gate_sweep` re-runs discovery
after each pass (`commands.rs:1211-1220`). Widening the census to catch it would be a
regression, not a fix.
</why_the_production_window_is_reachable>

<design_decision>
**Chosen: an age floor at the *signalling* decision, not at the census.**

`reap_stray_candidates` refuses to signal a candidate whose process age is below
`agent::STRAY_MIN_AGE`, reporting a new `StrayReapOutcome::TooYoung`. The census
(`discover_stray_devflow_processes`) is left **unchanged** and keeps its documented contract
as a pure read-only survey.

Why the reap point and not the census:
- The census has two consumers with wildly different consequences. `doctor` prints a finding
  and tells the operator to inspect manually; `gate sweep --reap-strays` sends `SIGKILL`.
  Gating the destructive one is proportionate; gating discovery would also suppress a
  legitimate `doctor` finding and would change a documented public contract.
- Gating the census would break the positive census tests by construction — they assert a
  freshly spawned fixture IS discovered. That is the correct assertion and it should keep
  holding.

Why an age floor and not the alternatives, both of which were considered:
- **Cmdline stability re-read** (read twice, require the same classification): still fooled
  if both reads land inside the window, and adds latency proportional to candidate count.
  Weaker for more cost.
- **Parent-cmdline-equality exclusion** (skip a candidate whose parent has a byte-identical
  cmdline): more precise, and timing-free. Rejected because `discover_stray_devflow_processes`'s
  doc comment records **"No parentage filter"** as constraint 1, load-bearing and *measured*
  against this repository (`23-FINDINGS.md`: a parent-identity filter reported zero orphans
  while 14 genuinely existed). Reopening that constraint to fix a different problem is a
  larger and riskier change than the defect warrants.

The age floor is legible against the mechanism: the window is sub-millisecond in the normal
case and, per `25-CI-OBSERVATION.md`, widened by compile pressure into the range where a
handful of test runs hit it. A genuine stray is an orphan of a *previous* run — a monitor
wrapper lives for the duration of an agent stage, minutes to hours. There is no value of the
floor that is both above any plausible `execve` window and below any plausible stray age
conflict; those two populations are separated by six orders of magnitude.

**`STRAY_MIN_AGE` = 2 seconds.** Well above any `execve` window even under the 2-core pinned
load, and far below the age of anything that has actually been orphaned. The cost of a false
refusal is bounded and already handled: `gate_sweep` re-runs discovery after the pass and
prints `re-run \`devflow gate sweep --reap-strays\` to clear them` (`commands.rs:1211-1220`),
so a candidate refused for youth is reported and cleared on the next invocation.
</design_decision>

**Step 2 — the primitive.**

In `crates/devflow-core/src/agent.rs`, next to `process_start_time`, add:

- A private helper resolving the kernel's clock tick rate via `libc::sysconf` with
  `libc::_SC_CLK_TCK`. Do NOT hardcode 100. `process_start_time`'s existing doc comment says
  `USER_HZ` is "conventionally 100" — conventionally is not a guarantee, and an age computed
  against the wrong divisor would silently scale the floor. Return `None` when `sysconf`
  yields a non-positive value, so the caller can fail closed.
- `pub fn process_age(pid: u32) -> Option<std::time::Duration>` — reads `/proc/uptime`
  (whitespace-separated; the first field is seconds since boot as a decimal), reads
  `process_start_time(pid)` (ticks since boot), converts the start time to seconds using the
  resolved tick rate, and returns the difference. Returns `None` if `/proc/uptime` cannot be
  read or parsed, if the tick rate cannot be resolved, or if `process_start_time` returns
  `None`. Clamp a negative difference to zero rather than returning `None` — a small negative
  is a rounding artefact between two clocks read microseconds apart, not an error, and
  treating it as zero keeps the fail-closed direction (age zero is below any floor).
  Document that `None` means "age could not be determined," which callers must treat as
  do-not-act, never as "old enough."
- `pub const STRAY_MIN_AGE: std::time::Duration` — 2 seconds. Its doc comment states the
  reasoning from `<design_decision>` in this codebase's own voice: the two populations it
  separates (an `execve` window, sub-millisecond even under 2-core CI load, versus a genuine
  orphan, minutes to hours old) are six orders of magnitude apart, so no value in between is
  contentious; and a candidate refused for youth is reported and cleared by the next
  invocation, because `gate_sweep` re-runs discovery after the pass.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kernel `/proc` -> `devflow-core` | `/proc/uptime` and `/proc/<pid>/stat` are parsed into a signalling decision; on a shared machine the pid space is populated by other users |
| census result -> `SIGKILL` | `gate_sweep --reap-strays` turns a structural argv match into an uncatchable signal; this is the only path in the codebase where a `/proc` inference is lethal |
| `devflow` monitor tree -> its own reaper | the wrapper shell forks children that transiently present the wrapper's argv, so devflow's own healthy processes are candidates for devflow's own reaper |
