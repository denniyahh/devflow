  <name>Task 1: Bind the guard from reloaded state and prove the spawn happened</name>
  <files>crates/devflow-cli/src/pipeline_launch.rs</files>
  <action>
In `crates/devflow-cli/src/pipeline_launch.rs`, in
`tests::resume_clears_stop_marker_and_advances_past_stop_point`:

The test currently runs `let result = resume(root, phase);` (`:480`), restores `PATH` in an
`unsafe` block, then calls `result.unwrap()` (`:489`) and asserts on a reloaded state.

Insert the guard AFTER the `PATH`-restore `unsafe` block and BEFORE `result.unwrap()`.

READ THIS BEFORE WRITING THE LINE — the obvious form is wrong here. The five existing guard
sites do:

    let _reap_guard = ReapMonitorOnDrop::after_launch(&state);

That is CORRECT at those sites because the launch there took `&mut state` and populated
`state.monitor_pid` in place. It is WRONG here: `resume(root, phase)` takes no state — it loads
its own `State` from the state file (`pipeline_launch.rs:215-230`) and never writes back into
this test's local `state` binding, which was last saved before the call. Binding from the local
`state` would capture `pid: None`, reap nothing, and look exactly like a correct fix.

Read the pid back from disk instead:

    // `resume()` loads its own `State` from the state file and never writes the
    // spawned pid back into this test's local `state`, so binding the guard from
    // that local binding would capture `None` and silently reap nothing. Read the
    // pid back from disk. `ReapMonitorOnDrop` captures `Option<u32>` by value, so
    // the guard does not borrow the temporary it is built from.
    //
    // Bound here, ahead of `result.unwrap()` below: a `resume()` that spawned the
    // monitor and then failed a later `?` leaves `result` as `Err` with the pid
    // nonetheless live.
    let reloaded_for_reap = workflow::load_state(root, phase).ok();
    let _reap_guard = reloaded_for_reap.as_ref().map(ReapMonitorOnDrop::after_launch);

Then, after the existing `let reloaded = workflow::load_state(root, phase).unwrap();`, append a
new assertion LAST (do not reorder the three existing ones):

    assert!(
        reloaded.monitor_pid.is_some(),
        "resume() must have spawned a monitor whose pid is recorded in state — if this \
         fails, the reap guard above is silently reaping nothing and this test has \
         stopped covering the launch path it was written to cover"
    );

`ReapMonitorOnDrop` and `workflow` are already in scope in this module (the file's other guarded
test at `:426` uses the former; the test body already calls `workflow::load_state`). Add no new
imports unless the compiler demands one.
