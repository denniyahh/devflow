`run_preflight_advance_gate_launches_agent_exactly_once` and
`run_preflight_loopback_gate_launches_agent_exactly_once` each drive a real `monitor::spawn_monitor`
and then let a `TempDir` delete the project root out from under the still-running wrapper. They were
missed by 25-16 for a structural reason, not carelessness: 25-16 enumerated launch-driving tests by
searching for direct `launch_stage`/`launch_stage_inner` calls, and these two reach the spawn
through `run_preflight`'s own `Advance`/`LoopBack` arms — a recursion no call-site search surfaces.

The leak is empirically hard to catch after the fact, which is why it survived a round: the stubbed
`claude` exits in well under a millisecond, and the wrapper's trailing `devflow advance` resolves
`current_exe()` to the test binary itself, which rejects the argument shape and exits immediately.
On an unloaded machine the wrapper is usually gone before anything looks. That is a timing accident,
not a structural guarantee — and this project has already measured the difference once
(`25-CI-OBSERVATION.md`: 0 failures across 17 warm runs of a related defect class, 2 failures in 2
attempts under a loaded, 2-core-pinned container shape).

Purpose: close G-25-1 / WINDOWS.md item 1, and close WINDOWS.md item 3 now that 25-17 has landed the
unwind-safe guard, so `/gsd-ship` is no longer blocked on defects that have been fixed.

Output: both preflight tests converted to `ReapMonitorOnDrop`, each additionally asserting that it
really did spawn a monitor, and a consistent `.planning/WINDOWS.md`. Test-only; no production
behaviour changes.
