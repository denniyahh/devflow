<objective>
Move the self-dogfood build-staleness adjudication out of the per-stage launch path and into
`devflow start`, so a phase that modifies DevFlow's own source can complete unattended — and
fix the flaky test that lives in the same module.

Purpose: 999.48 / DEN-73 and 999.38. Phase 24's run on 2026-07-27 reached Define→Plan→Code
fully unattended — a project first, no phase had previously passed Define — and then halted at
the Validate boundary with `self_dogfood_stale_blocked`. The Code stage itself had succeeded:
exit 0, 15 commits, both plans complete with SUMMARYs, review and UAT. The build-affecting diff
that tripped the guard was the phase's own deliverable. Such a phase can never complete
unattended while `enforce_build_staleness` is called from `launch_stage`.

Output: one call site moved (~7 lines), one call site deleted, one regression test proving the
check is not re-invoked mid-run, and one de-raced test.
</objective>

## The ROADMAP's proposed one-liner is WRONG — do not implement it (D-01)

`.planning/ROADMAP.md`'s Phase 25 entry and its 999.48 entry both state that `launch_stage`'s
third parameter `archived_stage: Option<Stage>` already distinguishes a fresh start from a
transition, so the fix is `if archived_stage.is_none() { enforce_build_staleness(…)?; }`.
**It does not.** `None` is passed by *three* callers, verified against live source:

| Call site | Situation |
|---|---|
| `crates/devflow-cli/src/commands.rs:236` | fresh `devflow start` |
| `crates/devflow-cli/src/pipeline_launch.rs:233` | `resume` after a rate-limit or infra pause — **mid-run** |
| `crates/devflow-cli/src/preflight.rs:435` | preflight `LoopBack` retry — **mid-run** |

Under that one-liner a rate-limited self-modifying phase still hard-blocks on resume — the exact
halt 25b exists to remove. D-03's hoist replaces it. Where the ROADMAP and CONTEXT.md disagree,
CONTEXT.md wins.
</scope_correction>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| driving binary → repository under test | The build-staleness guard is the control that stops a stale binary producing false evidence about the repository it drives (the Phase 16 incident) |
| refusal message → operator output and `.devflow/events.jsonl` | `OPERATIONS.md` advertises the event log as safe to tail; an absolute path on Linux embeds the operator's username (WR-02) |
| test process → its own process environment | Concurrent `std::env::set_var` reads/writes in a threaded test binary are unsound, which is why Rust 2024 marks them `unsafe` |
