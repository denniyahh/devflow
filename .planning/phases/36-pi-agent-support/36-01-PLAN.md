## Planner decision record

### P-01 — Model/provider surface (the gap the existing three adapters don't have)

`AgentAdapter::exec_command` has no model/provider parameter, and Pi *defaults* to provider
`google` with no model. The adapter reads two optional env vars — `DEVFLOW_PI_MODEL` and
`DEVFLOW_PI_PROVIDER` — and appends `--model`/`--provider` only when set. Unset means Pi's own
default (google). This avoids inventing config plumbing in a trait that never needed it, and it is
documented in the adapter's doc comment so Phase 37 (the real driver) knows where model selection
belongs.

### P-02 — `--approve` is unconditional, not a choice

Under DevFlow's fresh-worktree-per-phase model, `~/.pi/agent/trust.json` never has a matching
entry, so `defaultProjectTrust: "ask"` silently drops project resources and still exits 0.
`--approve` is always passed. This is a safety decision, not a knob.

### P-03 — What this plan does NOT establish

- It does not make `devflow start --agent pi` reach terminal completion (Phase 37: the Code-stage
  prompt still hardcodes `/gsd-execute-phase`, and non-Claude agents route to the legacy launch).
- It does not parse Pi's JSON-mode output (the `-p` transport used here terminates on process
  exit; `completion_signal_detected` mirrors Claude's `false`).
