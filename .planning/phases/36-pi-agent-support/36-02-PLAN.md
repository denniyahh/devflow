## Planner decision record

### P-01 — The guard goes where the tag is actually cut, not where it isn't

`release_finish` (git.rs:198) has one caller — its own unit test. The release tag is hand-cut by
`scripts/cut-release.sh:114`, which already runs
`git -c user.signingkey="$(git config --get devflow.releaseSigningKey)" tag -s …`. If the key is
unset, `git config --get` returns empty and the command silently signs with `-c user.signingkey=`
(whatever git defaults to). The guard is added there: fail loudly before the `tag -s` if the config
is unset or the file unreadable.

### P-02 — The pre-push hook is retained (reversing the earlier deletion)

The hook's fingerprint comparison is the only check that distinguishes the agent key from the
maintainer key on a hand-pushed tag — both keys share `user.email` and render identically everywhere
but the fingerprint. It is *not* tautological in the sense that matters: it compares a pushed tag's
fingerprint against the configured maintainer key. Deleting it would leave the hand-cut release path
unguarded. The plan's earlier "delete the hook" was wrong; it is kept, and `pre_push_signing_policy.rs`
/ `DEV-SETUP-CHECKLIST.md` need no change as a result.

### P-03 — Probe removal is by deletion of the whole private cluster, gated on clippy

Deleting only `check_signing_viability` orphans its private helpers, which produce `dead_code`
* warnings* — `cargo build` stays green. The removal deletes the full cluster (probe + SSH/GPG
helpers + fingerprint helper + inline-key classifier + `SSH_SIGN_PROBE_*` constants + their tests),
and the gate is `scripts/check.sh` (`cargo clippy --workspace --all-targets -- -D warnings`), not
`cargo build`.

### P-04 — SSH signing is the ambient config's job, not this plan's

`cut-release.sh` already signs SSH keys today (v2.5.0 was SSH-signed via the maintainer key), so
`gpg.format=ssh` is already in effect in the operator's config. The guard only fails loudly on a
missing/unreadable key; it does not change the sign invocation's gpg.format.
