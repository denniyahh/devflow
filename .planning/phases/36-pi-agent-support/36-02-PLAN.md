## Planner decision record

### P-01 — The release tag becomes signed; the VersionBump tag does not

`release_finish` (git.rs:197) creates the real `v{version}` release tag and currently passes
`-c tag.gpgSign=false`. `tag()` (git.rs:224) is a separate, deliberately-unsigned lightweight tag
for VersionBump's auto-bump. Only `release_finish` changes: `git -c
user.signingkey=<devflow.releaseSigningKey> tag -s -m "v<version>" v<version>` — the `-m` supplies
the annotated message headlessly, replacing the `$EDITOR` block the old code avoided. The message
is the version string; no new surface. `tag()` is left untouched.

### P-02 — Removal is by deletion, not by nulling

The probe is removed entirely — `check_signing_viability`, `check_ssh_signing_viability`,
`sign_probe_verdict`, `run_ssh_sign_probe`, the `SigningViability` enum, and their tests — plus the
`TagSigningViabilityCheck` row in commands.rs. The compiler is the completeness guarantee: a
dangling reference fails `cargo build`. The `release --check` output simply loses the tag-signing
row (there is no replacement row — that is the point).

### P-03 — Fail-loudly lives where the sign happens

`release_finish` and `tag` read `devflow.releaseSigningKey` (git config); if unset or the file is
unreadable, return an error naming the config key and the fix — never fall back to the agent's
`user.signingkey`, never sign unsigned silently.
