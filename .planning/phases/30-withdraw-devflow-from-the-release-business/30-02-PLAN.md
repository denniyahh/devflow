<objective>
Withdraw the release-acting class from the `GitFlow` library itself, and delete the
signing-viability predictor chain root and branch.

Plan 30-01 removed the callers. This plan removes the capability. Review finding C4
named the gap precisely: `release_start`, `release_finish`, `feature_finish` and `tag`
are public, compiled, and reachable — `release_finish` is a complete local release cut —
and a draft that deleted only the hooks would have "fixed the instance and left the
class open," which is exactly how this project arrived at Phase 30 twice.

Review finding H3 covers the other half: the signing predictor has no production
consumer, D-10 says this class of prediction must never exist, and it carries two
live-measured false negatives. A predictor is a second implementation of git's behaviour
that must stay in sync with it — the bug class that got 999.50 and 999.54 deleted rather
than fixed.

Purpose: an uncalled capability is an affordance for the next caller. Withdrawing means
the library cannot express release-acting, not merely that nothing currently asks it to.

Output: a `git.rs` reduced to branch and observation primitives, and a `release --check`
that has stopped predicting.
</objective>

an explicit key selection, documented in CONTRIBUTING.md's release-signing section, and
enforced at push time by `scripts/hooks/pre-push`, which compares key fingerprints rather

`crates/devflow-cli/tests/pre_push_signing_policy.rs`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `devflow-core` public API → any future caller | A public, compiled release-acting primitive is reachable by any code added later, inside or outside this workspace. |
| Signing predictor → operator's trust in a release | A prediction presented as a fact is trusted; when it is wrong, the operator is misled at exactly the moment a mistake is irreversible. |
