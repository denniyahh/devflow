<objective>
Delete the version-computing and version-writing layer, keep the commit-classification
layer that lets DevFlow *notice* a breaking change, and make `release --check` honest
about the limits of what it reports.

Review finding C1 killed the draft's original claim outright: the `semver` and
`git-conventional` dependencies cannot be dropped, because the D-09 major-bump gate is
built on the same helpers `compute_version` used. R5 resolved the question the draft had
never asked — D-09 SURVIVES, reworded as breaking-change awareness. DevFlow may still
notice release-significant facts; it may no longer act on them.

Purpose: the distinction R5 draws is the whole phase in miniature. Classifying commits is
a deterministic local fact. Computing "the next version" and writing it to disk is an act
with a consequence. One stays; the other goes.

Output: a `version.rs` that classifies and reports but never derives or writes a version;
a D-09 gate whose text says what it is; and a `release --check` that names its own
blind spots.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Classification output → operator judgement | A deterministic fact reported to a human who will act on it; the risk is the report implying more authority than a classification has. |
| `release --check` report → operator's belief about release readiness | A passing report is read as "ready"; silence about a limit is read as coverage. |
| `Cargo.toml` self-pin → crates.io | A stale pin is invisible locally and rejected only at publish, after the tag is cut. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30-08 | Spoofing | `release --check` report | high | mitigate | Add an explicit statement of undetermined facts on both the pass and fail paths, so a passing report cannot be read as a release-readiness attestation. Reintroducing an advisory version row is forbidden (R5's rejected alternative). |
| T-30-09 | Tampering | D-09 gate reason string | medium | mitigate | Retain `truncate_reason` on the gate message; commit subjects are attacker-influenced text that reaches a persisted gate file and operator output. |
| T-30-10 | Denial of Service | D-09 classification against the wrong root | medium | mitigate | Keep CR-02's worktree-targeting; with no merge step remaining, evaluating against the project root would miss a phase's breaking commits permanently rather than temporarily. |
| T-30-11 | Repudiation | workspace self-pin guard | medium | mitigate | Guard logic unchanged; framing rewritten so a reader is not sent looking for a hook that would fix it automatically. |
| T-30-SC | Tampering | npm/pip/cargo installs | low | accept | No packages installed. `semver` and `git-conventional` are retained per R5 and not re-resolved; a `cargo tree` assertion proves they are still reached. |
