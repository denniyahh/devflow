cover.

Purpose: criteria 1 and 5 are both explicit that a flag's value is not the evidence — a real GSD

<planner_findings>
**F-17 — criterion 6's observation lives in `35.1-DRILL.md` (CONTEXT.md Claude's Discretion, item 1).**
Not in a source doc comment (it would go stale silently while still reading as a contract), not in
ROADMAP.md (that is where the ask lives, not the answer), not in a SUMMARY (the observation belongs
with the run that produced it, and 35.2 is told to reuse this drill). `35.1-DRILL.md` is the run
record; the count goes there with the rest of the evidence, and the SUMMARY points at it.

**F-18 — how the fixture is made to enter the `--gaps-only` loop deterministically, without
pre-baking the plan.** D-11 forbids pre-writing the plans, so the failure has to be designed into the
inputs Plan reads. The construction uses GSD's own documented precedence: the fixture's ROADMAP phase
declares TWO success criteria, and the fixture's CONTEXT.md moves the second one to Deferred Ideas.
GSD's planner honours Deferred Ideas — they must not appear in plans — so the plan legitimately omits
it; the Validate stage checks against the ROADMAP criteria and legitimately reports it missing;
`select_loop_back_fix` sees a freshly-authored `{N}-VERIFICATION.md` and dispatches `GapsOnly`
(`pipeline_outcomes.rs:317-395`); the gaps-only Code pass builds the missing artifact and the run
converges. Nothing is faked and Plan still runs live.

**This mechanism can fail to fire, and the script must handle that honestly rather than silently.**
If the first Validate passes anyway, the script forces the loop by deleting an artifact the plan's
own `must_haves` require and re-running Validate — and it records WHICH path produced the loop.
"The loop was exercised" and "the loop was exercised by the designed-in construction" are different
claims, and the evidence file must not conflate them.

**F-19 — the checkpoint is a locked decision in the fixture's CONTEXT.md, not a hoped-for emergent
behaviour.** A phase goal phrased so a planner *might* emit a checkpoint is not a fixture, it is a
coin flip. The fixture's CONTEXT.md carries an explicit locked decision requiring the plan to include
a `checkpoint:human-verify` task with `gate="blocking"` — an ordinary blocking checkpoint, which is
exactly the class in scope, and never one of the human-only markers, which no mode auto-approves.
If the generated plan contains no such task, the drill has not set up its own measurement and must
fail loudly rather than report a clean run.

**F-20 — the negative-control arm is `--mode supervise`, which under F-1 (`35.1-01`) is precisely
"the flag mechanism not active" while every other variable is held fixed.** Same fixture, same agent,
same plan-generating inputs, one flag changed. The two arms must produce DIFFERENT observations at
the checkpoint: the auto arm's capture carries GSD's auto-approval log line and the run proceeds; the
supervise arm's does not, and the checkpoint surfaces — visible either as DevFlow's own
`checkpoint_auto_decided` recovery event (the phase-28 route) or as a pending gate, depending on
what DevFlow does with the surfaced checkpoint. Either observation is a valid negative; "the run
finished the same way" is not, and means the measurement is broken.

**F-21 — the drill runs outside this checkout, and outside any agent worktree.** The fixture goes
under `$TMPDIR`, guarded by `scratch-dogfood-repo.sh`'s existing refuse-to-scaffold-inside-this-
checkout check (T-23-01). The run outlives a single agent turn, so it is launched detached with its
log outside the worktree and polled — a worktree subagent cannot own a process that outlives its
turn; such a process is orphaned, not killed. Poll with a stated ceiling; on timeout, kill the
process tree and record the timeout as the result rather than reporting nothing.

**F-22 — build first, every time.** `devflow`'s own staleness gate and this project's recorded
dogfood lesson both point the same way: a drill run against a stale binary measures the previous
build. The script builds the binary from this checkout before scaffolding anything and records the
build commit in the evidence file.
