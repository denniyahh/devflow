### F-1 — CRITICAL — D-04 is unimplementable; auto-mode at Plan necessarily chains

**Raised by:** both lanes independently, and independently re-derived from source before either
returned. Three-way convergence.
**Status:** CONFIRMED. **D-04 revised** — Plan removed from the auto-mode stage set.

The flag that enables checkpoint auto-approval at Plan is the same flag that makes plan-phase
chain into execute-phase, which criterion 3 bans.

- `~/.claude/gsd-core/bin/lib/check-command-router.cjs:107` — `active: autoChainActive || autoAdvance`;
  no third key exists for bypass-without-chaining.
- `plan-phase.md:1564` — `OR AUTO_CHAIN is true` → *"GSD ► AUTO-ADVANCING TO EXECUTE"* → chains via
  `Skill(skill="gsd-execute-phase", args="${PHASE} --auto --no-transition ${GSD_WS}")`.
- `plan-phase.md:540`/`:555` — the same `AUTO_CHAIN` selects which branch handles blocking gates,
  so the flag really would fix the Plan stall; it just cannot do so without chaining.
- G-03 blocks clearing it afterwards (`:1564` reads the pre-clear INIT value); `plan-phase.md:1560`
  blocks passing `--auto` (that *sets* the flag).

### F-2 — HIGH — the leak is not confined to the kill path; the happy path leaks and dirties the tree

**Raised by:** agycli only. pi examined this area and **concluded the opposite** ("not a defect").
**Status:** CONFIRMED with a corrected mechanism. **D-01 amended.**

For the whole Code stage, DevFlow will hold a *tracked* file modified. A sweeping `git add -A`
commits the `true` — this repo has had that exact incident (see `CLAUDE.md`) — and a later
`git reset --hard` would restore it.

**Mechanism corrected on verification:** agycli claimed GSD commits `config.json` automatically
because `commit_docs` is true. It does not. Every `query commit` in `execute-phase.md` passes an
explicit `--files` list (`:945`, `:1304`, `:1449`, `:1528`, `:1585`, `:1610`) and none names
`config.json`. The real exposure is a sweeping `git add`, not an automatic GSD commit — narrower
than reported, still real.

### F-3 — HIGH — pi's clearance of D-01 rests on a false premise

**Raised by:** neither lane — found while verifying pi's Finding 2.
**Status:** pi's conclusion REJECTED. **D-01 amended.**

pi cleared D-01 by arguing a leak cannot propagate because *"(b) requires a successful Ship stage,
which is impossible after a SIGKILL — the run never completes."* `devflow resume` exists precisely
to continue a killed run. Live path: leak commits to the feature branch → kill → resume → run
completes → Ship merges → `develop` carries `true` → next phase chains. A force-clear that only
edits the working tree does not close it.

### F-4 — HIGH — the fixture would not exercise the fix loop, and has no negative control

**Raised by:** agycli (both halves); pi raised the related point that the fixture does not test
DevFlow's own flag management.
**Status:** CONFIRMED. **D-10 amended with three constraints.**

A single trivial plan succeeds at Code and passes Validate first try, so `--gaps-only` never runs —
while the run gets reported as covering it. After F-1 narrowed D-04, the fix loop is half the
remaining scope. And without a run of the same fixture with the flag unset, an agent that simply
never hits a checkpoint is indistinguishable from a successful auto-approval.

### F-5 — MEDIUM — no-override may be a denial-of-service if the preflight itself is buggy

**Raised by:** both lanes. pi judged the supervise fallback adequate; agycli called it a DoS
because supervise defeats the purpose of an overnight run.
**Status:** ACKNOWLEDGED, decision unchanged. Recorded against D-09 so a planner does not
silently add the override the operator declined.

### F-6 — MEDIUM/HIGH — the `STREAM_JSON_STAGES` precedent is not a clean analogy

**Raised by:** pi. agycli explicitly rated D-05 sound — **the two lanes disagree.**
**Status:** ACCEPTED in the narrow form. **D-05 amended with a required doc comment.**

`STREAM_JSON_STAGES` lists all five stages because the transport choice has no upstream side
effects. The auto-mode flag's effects differ per stage. The constant must carry a comment saying
so, or a future contributor "completes" it by adding `Stage::Plan` and reintroduces F-1.

**Raised by:** pi. **Status:** noted for the planner; not a defect.
