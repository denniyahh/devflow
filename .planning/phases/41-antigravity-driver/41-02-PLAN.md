<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test spawning → process reaping | Test spawns monitor subprocess; must clean up before exit to avoid leaked processes |
| Git environment (host vs. container) | Tests expect git config behavior consistent across uid 0 (root) and uid 1000 (user); divergence is environment-specific, not code |
| CI pipeline (uid 0) vs. local (uid 1000) | CI runs with root privileges; tests must not assume non-root git behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-41-HYG-01 | Denial | Orphaned monitor processes accumulate during test suite | medium | mitigate | Every `run_devflow()` test includes process-list assertion before exit; full suite cleaned up between test runs |
| T-41-HYG-02 | Denial | Git-env tests fail spuriously under root (uid 0) in CI, blocking CI pipeline | medium | mitigate | Identify three failing tests; scope git config to `--local` (`.git/config` only) or add root skip guard; verify in both uid 1000 and uid 0 environments |
| T-41-HYG-03 | Availability | Test infrastructure assumes non-root execution; CI environment diverges | low | accept | No code security risk — purely test infrastructure hygiene; skipping under root is acceptable |

**Disposition rationale:**
- **T-41-HYG-01:** Mitigated by explicit process-list assertions in cleanup phase — ensures no orphans survive test completion.
- **T-41-HYG-02:** Mitigated by (a) git config scoping to avoid permission issues, or (b) conditional skip under root — tests remain functionally valid while accommodating environment differences.
- **T-41-HYG-03:** Accepted — test infrastructure is not a security boundary; divergence between uid 0 and uid 1000 is expected OS behavior.

**Related ASVS controls:** None directly (these are test infrastructure and operational concerns, not code security).
