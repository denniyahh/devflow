## Decisions this plan locks (CONTEXT.md "Claude's Discretion")

CONTEXT.md left one item to Claude's discretion that this plan resolves. Recording it here so the
executor implements a decision rather than re-deriving one:

**Does `FixType` need a new variant, or can the mid-arc/gaps branch happen upstream of the
`loop_back_to_code` call using the existing two variants?** — **A new variant is required, and the
branch also happens upstream.** Neither existing variant can emit the needed string: `GapsOnly`
renders `/gsd-execute-phase {N} --gaps-only` and `AuditFix` renders `/gsd-audit-fix {N}`. Nothing
renders the unflagged `/gsd-execute-phase {N}`, so "keep the enum as-is" cannot satisfy ROADMAP
criterion 1. The enum therefore gains `FullExecute`, **and** the selection still happens upstream
in a single `pipeline_outcomes.rs` helper — which keeps `prompt::fix_prompt` a pure string builder
with no filesystem knowledge, matching 33-RESEARCH.md's Architectural Responsibility Map. Variant
naming follows the existing convention, which is command-shaped (`AuditFix` → `/gsd-audit-fix`),
not reason-shaped.

**Semver note (awareness, not a blocker):** `FixType` is a public enum in the published
`devflow-core` crate and is not `#[non_exhaustive]`, so adding a variant is technically a
breaking change for any external crate matching on it exhaustively. A workspace-wide
`rg -n "FixType::" crates/` confirms every construction and the single `match` are in-workspace,
so there is no in-repo breakage. Do **not** add `#[non_exhaustive]` as part of this plan — that is
a separate, speculative API decision this phase has no mandate for. Surface the variant addition
in the SUMMARY so the Ship stage's version bump can account for it.
