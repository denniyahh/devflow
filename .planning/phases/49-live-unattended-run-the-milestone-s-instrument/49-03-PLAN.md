## Evidence layout contract (copy this section verbatim into `tools/EVIDENCE-LAYOUT.md`)

`P49` is `$HOME/.cache/devflow-phase49` unless a tool is given `--home <dir>` (every selftest passes a temp `--home`;
there is no environment-variable override, and never a `DEVFLOW_`-prefixed one). `EV` is `$P49/attempt-<N>`, `N` one
digit 1-9. The payload phase is always `1`: events carry the JSON number `1`, paths use `01`, the worktree is
`<launch>/.worktrees/phase-01`, the feature branch is `feature/phase-01`.

- `$P49/current-attempt` — one line `N`; written only by `launch-attempt.sh prepare`, atomically (temp file + rename).
- `$P49/bin/devflow-<first 12 hex of its sha256>` — pinned binary, mode 0555, never overwritten.
- `$EV/attempt.json` — `{"attempt":N,"bin":"<abs>","bin_sha256":"<64 hex>","build_commit":"<40 hex>","launch":"<abs $EV/project>","base_branch":"integration","created_at":<epoch>}`.
- `$EV/identity.txt` — `key=value`: `bin_sha256`, `build_commit`, `build_dirty` (`true|false`, measured by `prepare` immediately before `cargo build` with the same whole-tree `git status --porcelain` that `crates/devflow-cli/build.rs:52-54` embeds as `DEVFLOW_BUILD_DIRTY`, non-empty → `true`; `prepare` requires only `crates/` and `Cargo.*` to be clean, so `true` is possible and is recorded, never asserted `false`; the binary's own value is `workflow_started.dirty`), `claude_version`, `gh_version`, `gsd_version`, `python3_version`, `git_version`.
- `$EV/project/` — the disposable project and launch checkout, from `scripts/scratch-dogfood-repo.sh --live-payload`.
- `$EV/prelaunch/` — `check.txt` (the scaffold `--check` output), `gh-auth.txt` (only the `Logged in to` and `Token scopes` lines of `gh auth status`, never a token), `repo.json` (`gh repo view --json nameWithOwner,visibility`), `agent-env-names.txt` (the exported variable NAMES inside the auth-probe unit, which is launched with the start unit's `--setenv` values; one name per line, never a value), `auth-probe.txt` (`key=value`: `unit`, `probe_exit`, `is_error` = `true|false|ABSENT`, `reply_ok` = `yes|no`, `auth_source` = the stream-json init event's `apiKeySource` or `ABSENT`, `probe_timeout_secs`, `measured_at`; only derived fields, never the probe's raw output), `fork-base.txt` (`base_sha=<40 hex>` = `integration` just before `start`, fork-point value 1 of D-16; `main_sha=<40 hex>`).
- `$EV/units.txt` — `start=p49-a<N>-start`, `surv=p49-a<N>-surv`, `negctl=p49-a<N>-negctl`.
- `$EV/start.stdout`, `$EV/start.stderr` — the positive arm's `start` process output (the only place the Define per-condition report and the base-source note appear).
- A snapshot root `R` is `$EV` for the positive arm and `$EV/negctl` for the negative arm. `snapshot-hook.sh <launch> <R>` writes `R/gates/<seq>-<stage>/` holding `devflow/` (copies of `.devflow/state-01.json`, `.devflow/gates/01-*.json`, `.devflow/events.jsonl`, `.devflow/phase-01-stdout`, `.devflow/history/phase-01/`), `git.txt` (`key=value`: `base_branch`, `base_head`, `main_head`, `worktree_head`, `feature_head`, `merge_base`, `worktree_status_lines`, `config_json_status`; an unreadable value is the literal `ABSENT`), `env.txt` (`phase`, `stage`, `non_silent`), `context.txt` (the gate context, stored as data), `MANIFEST.sha256`; and appends to `R/ledger.jsonl` one `jq -c` line per snapshot, `{"seq":n,"stage":"…","phase":"1","non_silent":"0|1","dir":"<abs>","manifest_sha256":"<hex>","t":<epoch>}`, under `flock -w 30 R/ledger.lock` with a single `printf '%s\n'`. `<seq>` is three digits, one more than the ledger's line count, taken under the same lock. Hook errors go to `R/hook-errors.log`. Consumers select snapshots through the ledger, never by directory-name order, and resolve an entry's snapshot as `R/gates/<basename of its dir>`, where `R` is the directory holding that ledger (`$EV/ledger.jsonl` → `$EV/gates/`, `$EV/negctl/ledger.jsonl` → `$EV/negctl/gates/`), never through the absolute `dir`, so a relocated copy still resolves; both arms number from `001`, so the same basename exists under both roots and a snapshot resolved under the wrong root reads the other arm's state.
- `$EV/negctl/` — also `start.stdout`, `start.stderr`, `develop.sha` (before start), `worktree-head.sha`, `bin_sha256`, `repo/` (the scratch repository).
- `$EV/surv/` — `watch.jsonl`, `analysis.txt` (from `surv-watch.py`).
- `$EV/collected/` — from `collect-attempt.sh`: `devflow/` (full copy of `<launch>/.devflow/`), `sessions/` (the Claude project directory for the worktree path, when found), `git.txt` (`integration_head`, `integration_merge_count`, `integration_merge`, `integration_merge_parents`, `main_head`, `feature_head`, `feature_is_ancestor_of_integration` = `yes|no|ABSENT`, `tags`; the merge is located in `integration`'s first-parent history since `prelaunch/fork-base.txt` `base_sha` — `git rev-list --first-parent --merges <base_sha>..integration` — never read from `integration`'s tip, because DevFlow's terminal batch tags and then commits `CHANGELOG.md` on `integration` after the merge, so a correct run's tip is a single-parent commit; `integration_merge` and `integration_merge_parents` are `ABSENT` unless exactly one such merge exists), `pr.json`, `evidence.json` (`<bin> evidence --phase 1 --json --root <launch>`), `absent.txt` (one line per expected item not found), `MANIFEST.sha256`, then `DONE` last.
- `$EV/verdict.json` — from `collect-attempt.sh`: `{"attempt":N,"outcome":"shipped"|"stopped","workflow_shipped":true|false,"stop_note":"<text>"|null,"state_present":true|false}`; `outcome` is derived from the collected events (a `workflow_shipped` event for phase 1), never from typed input.

Verbatim texts (the checker holds them as constants): positive note `note: base branch is \`integration\` (from
devflow.toml (base_branch))`; positive report line `  [holds] GSD config can hold the chain flag`; negative report line
`  [DOES NOT HOLD] GSD config can hold the chain flag — no \`.planning/config.json\` under the launch root — nowhere for
the chain flag to live`.

## Style (every Phase 49 tool)

`#!/usr/bin/env bash`, `set -euo pipefail`; header states WHAT THIS ESTABLISHES and WHAT THIS DOES NOT ESTABLISH
(`scripts/unattended-drill.sh:5-34`); `die`/`note` helpers (`:81-86`). Selftest: hermetic (unset
`git rev-parse --local-env-vars`, `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1`, fixture repos with
`core.hooksPath` pointed at an empty dir, `commit.gpgsign false`, a local identity), one `mktemp -d` with an EXIT trap;
case lines `  ok   <name>` / `  FAIL <name> — <why>`; last line `SELFTEST passed=<P> failed=<F>`; exit 0 only if F=0
and P>0; case names below are exact (the gate greps them). Absent vs false: `jq -r '(.x // "ABSENT") | tostring'`.
Counting: `rg --count-matches … || true` then `${c:-0}`. `--fake-cmds <dir>` prepends a shim directory to `PATH` for
the tool's own children, so no selftest calls the network or the real systemd user manager. Build every
secret-shaped test string at runtime (the global gitleaks pre-commit hook scans commits).
