<objective>
Prove at the operator boundary what plan 24-01 fixed in the library: a repository
configured with an inline `user.signingkey` value gets a truthful, non-blocking
`devflow release --check` result, and the configured blob never reaches stdout.

Purpose: D-08's redaction rule and D-10's negative assertion are only meaningful
where an operator can see them. `check_signing` maps `NotViable`→`"fail"` and
`release_check` turns any `"fail"` into a non-zero exit, so the integration
surface is where the original defect actually bit — a correct configuration
producing `release preflight failed`. These tests pin both halves: nothing leaks,
and nothing falsely fails.

This plan changes no production code. It adds two tests beside the existing
Phase 20 signing tests (D-11), leaves those tests byte-for-byte untouched as the
path-branch regression (D-12), and records the RED evidence that the new tests
fail against pre-Phase-24 behaviour.

Output: `crates/devflow-cli/tests/release_check.rs` with two new `#[test]`
functions, and a full three-job CI gate chain green.
</objective>
