## Planner decision record

### P-01 — Tracer scope is the Code stage only, across three adapters

The full `AgentDriver` trait (render_prompt + build_command + parse_completion + health + …) is plan
37-02/37-03. This tracer lands ONLY the `StageIntent` enum and the Code-stage `render_prompt`
migration, on Claude/Codex/OpenCode (Pi's `-p` migration is 37-03). Code stage is the one that
matters for the dogfood bug (`/gsd-execute-phase` reaching Codex) — it is the smallest slice that
proves the concept.

### P-02 — Byte-identity is the zero-regression bar

The current `stage_prompt(Stage::Code, phase)` output is snapshotted BEFORE the change and asserted
byte-identical for Claude/OpenCode AFTER. No "semantically equivalent" hand-waving for the existing
agents — D-01's "no regression" means the exact text.

### P-03 — The shared-prompt invariant test retires, not mutates

`every_adapter_receives_identical_prompt_text` encodes the false assumption. It is deleted and
replaced by (a) per-driver byte snapshots and (b) a `StageIntent`-level test that Claude/OpenCode
render the same text and Codex renders a non-slash text. A skipped test would leave the false
invariant silently in the tree.

### P-04 — StageIntent carries data, not syntax

`StageIntent::Code { phase, fix }` carries the `FixType` the loop-back needs (the `fix_prompt`
path), but the *rendering* of "how do I fix" is per-driver. No variant holds a slash-command string.
