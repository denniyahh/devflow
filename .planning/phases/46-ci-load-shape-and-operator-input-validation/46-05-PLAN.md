<task type="auto">
  <name>Task 2: Implement the block-parsing scanner with a containment allow rule</name>
  <files>scripts/lint-plan-bashisms.sh</files>
  <action>
Create `scripts/lint-plan-bashisms.sh` with `set -euo pipefail` and a usage block.

Interface:
- `scripts/lint-plan-bashisms.sh --staged` — take the file list from
  `git diff --cached --name-only -z --diff-filter=ACM`, consumed with `read -r -d ''`, filtered to
  names matching a trailing `PLAN.md` segment. The `-z`/`read -d ''` pair is what makes a path
  containing non-ASCII or a tab survive; `git diff --cached --name-only` without `-z` QUOTES such a
  path and the file is then skipped silently. Keep `--diff-filter=ACM`: a deleted plan has no
  content to scan and would reintroduce the silent skip from the other end.
- `scripts/lint-plan-bashisms.sh <path>...` — scan the named files. This is the mode the tests and
  any ad-hoc use drive.
- No arguments — exit 0 after printing a scanned count of 0. Print the count in both modes so an
  empty scan is visible rather than inferred.

A named path that is missing or unreadable is an error naming the path, not a skip.

Scanning, per file, in `awk` — not in bash string arithmetic. `awk` is already a hook dependency
(`scripts/hooks/pre-commit:30`) and is present in the pinned image; do not introduce `python3` into
the hook path.

1. Read the whole file into one string so blocks spanning lines are visible.
2. Find each opening tag and its matching closing tag. An opening tag with no closing tag anywhere
   after it is a MALFORMED BLOCK: report it and fail. Leaving it unhandled is a bypass by
   construction.
3. Within each block body, find every occurrence of the bash-only patterns:
   `${PIPESTATUS[` ... `]}`, `${BASH_REMATCH[` ... `]}`, any `${` name `[` digits `]}` array index,
   `${` name `,,}`, `${` name `^^}`, and `declare -A`.
4. Decide each occurrence by CONTAINMENT, not by order. Compute the set of single-quoted regions
   that a `bash -c '` opened: for each occurrence of `bash -c` followed by optional spaces and then
   a single quote, the region runs from just after that quote to the next single quote. An
   occurrence is ALLOWED only if its offset falls strictly inside such a region.
5. Any occurrence not inside such a region is a violation. Report it as `file:line: <text>`, where
   the line number is derived by counting newlines before the offset.

Write the reasoning for step 4 into the script as a comment, naming all four cases it decides:
containment accepts the legitimate single-quoted form; it rejects a trailing `# bash -c` because
that opens no region; it rejects a sequenced `bash -c ':'; …` because the region has already closed
before the bashism; and it rejects a double-quoted `bash -c "…"` because double quotes open no
single-quoted region and the outer shell expands first. Note that single quotes do not nest in
POSIX shell, which is what makes the region boundary unambiguous.

Where the rule cannot decide — nested quoting gymnastics such as an embedded `'"'"'` — it must fail
CLOSED and say so, telling the author to restructure the command. A conservative false positive
costs one edit; a false negative is the entire finding.

Exit non-zero on any violation, with the same guidance the old hook printed about wrapping the
command so it runs under bash.

Run the Task 1 suite. It must now be fully green.
