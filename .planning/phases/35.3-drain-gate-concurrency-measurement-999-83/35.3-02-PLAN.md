## Planner decision record

### P-01 — Dedicated minimal probe, not a dogfood ride-along (resolves D-01 discretion)

CONTEXT.md's discretion allows either riding an existing dogfood run or a dedicated minimal
`devflow start --no-worktree` probe. This plan chooses the **dedicated probe**, on the same
scaffolded single-file phase `scripts/scratch-dogfood-repo.sh` produces, because it is
deterministic and repeatable — a dogfood run may or may not dispatch a sub-agent in any given
stage, and this plan cannot depend on luck. The probe runs the same `devflow start --phase 1
--no-worktree --agent claude --mode auto` argv 34-evidence used, so the capture is comparable.

### P-02 — One real capture is sufficient, recorded with its limits

D-01 requires "at least one real capture." This plan produces one. It is a *validation*, not a
second measurement campaign: it confirms or refutes the synthetic mapping, and its limits (which
stages reached, which paths exercised) are recorded in the run.log and the comparison, so plan
35.3-03's analysis does not overstate it.

### P-03 — What this plan does NOT establish

- A real capture that reaches Code and dispatches sub-agents validates the sub-agent half of the
  mapping. If the run does NOT dispatch a sub-agent (or does not reach a concurrent stage), the
  capture validates less — and says so. It cannot manufacture concurrency.
- The backgrounded-shell half may remain unvalidated by the real capture (34's real run had 0
  backgrounded shells). If so, the record states "the backgrounded-shell mapping rests on the
  synthetic capture only," which feeds criterion 4's scope statement in plan 03.
