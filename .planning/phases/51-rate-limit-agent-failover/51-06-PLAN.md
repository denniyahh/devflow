Harden the hop 51-01 built: per-agent evidence does not cross it (D-04 canary), the event records what was handed over
(D-10, D-08), the boundaries hold at Code (D-06 at the ceiling, D-05 after the hop, the ordering edge), and a relaunch
that fails after the commit ends at the never-silent infra gate with an event (D-04 never silent; R2-D1: a gate, not the
cron arm) inside a real supervisor, where every write is fenced to the recorded launch (Phase 50 D-03).

Purpose: RESEARCH found that the hop's risks are in what is inherited across it — canary, counters, a half-done relaunch.
Plan check (iteration 2) found that a failed launch clears the supervisor record before the never-silent write, so inside
a supervisor that write is refused as `NotOwner` and the run ends silently; the fix keeps the record through the failover
relaunch only. Review round 2 (R2-D1) moved the never-silent end from the cron arm to the gate: after a post-commit
failure a scheduled resume either cannot succeed (a refused canary stays recorded) or is unsafe (a successor may still
run).
Output: changes inside `hand_off_agent`, `fail_over_on_rate_limit`, `refuse_launch` and `record_failed_launch`, eight
tests and one scan clause, all at the Code stage (R-2). No change to `pipeline_outcomes.rs` (R2-2 is narrowed, not
fenced; see the ledger).
</objective>
