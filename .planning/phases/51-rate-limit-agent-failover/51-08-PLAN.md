<objective>
D-09, Plan half: a fallback that takes over a Plan stage a rate limit interrupted mid-write finishes the plan instead of
accepting a partial `PLAN.md` as done. Today both Plan renderers short-circuit on the mere presence of any
`{padded}-*PLAN.md`, and `Stage::Plan` then transitions to Code with no artifact check. This plan fixes both for a Plan
stage a rate limit interrupted: the prompt (Tasks 1-2) and the transition (Task 3), so a fallback that reports success
over a still-incomplete plan set does not reach Code.

Scope (operator ruling at the 2026-11-05 plan check): both changes apply only when a rate limit interrupted the current
Plan stage, recorded by a persisted marker that the failover handoff and the cron arm each write in a commit they
already make. The cron arm is included because its later `devflow resume` relaunches through the same path, so it costs
one field write, and it is still a rate-limit interruption. Ordinary Plan launches and successes keep today's
behaviour, pinned by two negative-control tests. The general defect (on an ordinary run, uncommitted plans can reach
Code) is out of scope: the orchestrator files it as a backlog entry 999.184, and this plan does not edit ROADMAP.md.

Purpose: the mechanism is left to the planner (D-09); this plan decides "plan complete" from git (tracked and clean)
rather than presence, scopes that decision with the marker, and renders the continuation per driver.
Output: two prompt fns, one provided trait method (+2 overrides), one `State` field and its two writers, the
completeness predicate and its scoped wrapper, the prompt selection, the Plan-success refusal, seven tests.

Ordering: this plan depends on 51-09 only because both modify `crates/devflow-core/src/state.rs` (51-09 corrects a doc
comment there), and plans in the same wave may not share a file.
</objective>
