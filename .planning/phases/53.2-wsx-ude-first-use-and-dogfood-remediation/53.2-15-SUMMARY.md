# Phase 53.2 Plan 15: `devflow start --reviews` Summary

`devflow start --reviews` runs the Plan stage as `/gsd-plan-phase N --reviews`: the flag is persisted as `State::reviews_pass`, refused unless the phase's `NN-REVIEWS.md` is on the base the run forks from, shown in the dry run, kept across stop and resume, and spent when the run leaves Plan or halts there under `--until`.

## What changed

- **main.rs:** `Command::Start` gains `--reviews`; the dispatch passes it to `commands::start`.
- **state.rs:** `pub reviews_pass: bool` with `#[serde(default, skip_serializing_if = "std::ops::Not::not")]`, `false` in `State::new`, lifecycle doc.
- **commands.rs:** `start` sets `state.reviews_pass`; `start_reserved` refuses through `reviews_file_refusal(LaunchVerb::Start, phase, "on `{base}`")` when `!phase_artifact_on_base(.., "-REVIEWS.md", base)`, directly after the CONTEXT.md refusal; `dry_run_not_checked_line` takes `reviews` and appends `, and, with --reviews, the REVIEWS.md check on `{base}``, unchanged without it. The four test callers of `start` pass `false`.
- **pipeline_gate.rs:** `print_dry_run` appends ` --reviews` to the Plan line; `enter_stage` and `transition`'s `--until` halt commit clear `reviews_pass`.
- **pipeline_launch.rs:** `default_stage_prompt` gains `Stage::Plan if state.reviews_pass => StageIntent::PlanReviews` ahead of the gaps arm; doc extended with the precedence.
- **OPERATIONS.md:** `[--reviews]` on the `start` row with its refusal, dry-run note, resume and end.

## D-04 resume finding

Resume re-renders Plan from state through `default_stage_prompt` (the only stage-prompt renderer), so a reviews pass that is stopped and resumed renders `--reviews` with no resume flag (`a_reviews_pass_plan_renders_reviews_after_resume`). A run its `--until plan` cap halted after Plan has the flag spent by the halt commit, so D-04's resume clause for that case is 53.2-17's `resume --reviews`, which reuses this plan's field, prompt arm and `reviews_file_refusal`.
