# Phase 53.2 Plan 14: resume an --until halt at the halted transition's target Summary

`devflow resume` after an `--until plan` halt reached through a Plan gate's "validate again" now launches Validate: the halt records where its transition was going in `State::until_halt_target`, the resume advances there (falling back to `Stage::next`), and entering any stage clears it.

## What changed

- **state.rs:** `pub until_halt_target: Option<Stage>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`, `None` in `State::new`.
- **pipeline_gate.rs:** `transition`'s `--until` halt commit sets `s.until_halt_target = Some(to)`; `enter_stage` sets it to `None`; `until_cap_fired`'s doc rewritten.
- **pipeline_launch.rs:** `resume_advance` returns `state.until_halt_target.or_else(|| state.stage.next())`; its doc and `resume_loaded`'s doc rewritten. `resume_loaded`'s advance commit runs `enter_stage`, so the resume spends the target beside `stop_until`.
- **OPERATIONS.md:** the resume row now says a halt resumes at the stage the halted move was going to (Code for a plain `--until plan` halt, Validate for one reached through Plan→Validate); the 999.260 sentence is gone.
- **999.260 = #281:** `.planning/audits/2026-11-22-backlog-migration.md:261` maps 999.260 (53.1's filed residual Plan→Validate resume gap) to #281; this plan fixes that one defect.
