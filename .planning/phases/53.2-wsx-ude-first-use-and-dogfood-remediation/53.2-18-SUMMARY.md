# Phase 53.2 Plan 18: Fake systemd-run waits for the runner's READY=1 Summary

**The fake `systemd-run` now reads a start from the launched runner's real `READY=1` on a per-launch `NOTIFY_SOCKET` listener (the test binary re-run as `common::fake_notify_listener_entry`), so a runner that finishes between two 50 ms polls is no longer read as a failed start (#337).**

## Accomplishments

- The fake `systemd-run` starts a listener before each launch, sets `NOTIFY_SOCKET` on the launched command, and exits 0 on `ready`, prints `FAKE_START_FAILED` on `exited`, and prints systemd's timeout text on `timeout`. The `--phase` scan, the `held()` fdinfo probe and the 600-try poll are gone, and the fake calls no `flock`.
- The listener reports `exited` only after the launched pid is gone or a zombie and its socket has been drained, so a `READY=1` sent just before the exit still counts.
- A new direct-run test with a stand-in runner (`fast_ready_runner_entry`: take lock, send `READY=1`, exit) proves the #337 window is closed. The 53.2-06 negatives pass with their test bodies unchanged.
- The harness docs (module doc, `FAKE_START_FAILED`, `FAKE_SYSTEMD_RUN_CALLS`, `service_bin`) describe the listener protocol and the per-launch `U.notify-<pid>.{sock,listening,launched,result,log}` files. None of these files ends in `.pid`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Listener cleanup on the fake's early-exit paths**
- **Found during:** Task 1 GREEN
- **Issue:** As written, the plan left the listener running when it never created `.listening` or when `cd "$wd"` failed. It would then live until its 30 s deadline, which is the T-53.2-33 risk.
- **Fix:** `kill "$lpid" 2>/dev/null` on both paths.
- **Files modified:** crates/devflow-cli/tests/common/mod.rs
- **Commit:** d4fb5ad

**2. [Rule 1 - Bug guard] `.launched` is read only once its newline is written**
- **Found during:** Task 1 GREEN
- **Issue:** The listener could read `.launched` between the shell's truncating open and its write.
- **Fix:** `launched_pid` parses the file only when its content ends in `\n`. Any other read is retried on the next tick, as the plan specifies for empty files.
- **Files modified:** crates/devflow-cli/tests/common/mod.rs
- **Commit:** d4fb5ad

**Total deviations:** 2 auto-fixed (1 missing critical, 1 bug guard). **Impact:** neither changes the protocol or the verdicts. Both only harden failure paths.
