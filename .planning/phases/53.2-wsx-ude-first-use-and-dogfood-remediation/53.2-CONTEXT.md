## Implementation Decisions

### Scope
- **D-01 (auto):** Plans cover every OPEN row. #273 and #308 get no plan: #273 is closed citing `ask_e2e.rs:232-245` and
  `ask_e2e::the_marker_hook_publishes_the_marker_whole` (the delayed-write control, `ask_e2e.rs:1051`) once it passes by name; #308 is closed as moot (test and file
  removed in 52.2). The fd-inheritance concern #308 raised is carried by #277 and #310.

### Discuss route (#246) — the Phase 54 blocker
- **D-02 (auto):** The Plan stage owns the route; no new `Stage` variant. When the phase has no `*-CONTEXT.md`, the
  Plan prompt runs `/gsd-discuss-phase N` (interactive mode, not `--auto`) first, every question going through
  `devflow_ask` with `kind: discuss`, then `/gsd-plan-phase N` in the same launch. With a CONTEXT.md present the
  prompt is unchanged. Why not a Discuss stage: Phase 52 removed Define and the v4 direction is a pared-down runner;
  adding a `Stage` variant is a public `devflow-core` change (`Stage` is not `#[non_exhaustive]`) that also
  touches `next()`, `--until` and state. — **Reversibility:** reversible — a prompt branch; a Discuss stage can
  replace it later if D-03's proof fails.
- **D-03 (auto):** The phase must prove D-02 live on a scratch project with no CONTEXT.md: at least one real GSD discuss
  question reaches the operator as a `discuss` gate, its answer lands in the written CONTEXT.md, and Plan continues
  to plan-phase. Negative control: with a CONTEXT.md present, no discuss question is asked. If GSD's
  nested-AskUserQuestion behaviour (#1009) defeats the in-session route, stop and bring it to the operator with the
  Discuss-stage option; do not route around it.

### Reviews route (#250)
- **D-04 (auto):** An explicit opt-in, not detection: `devflow start --reviews` (and the same on `resume` if the
  planner finds resume re-renders Plan) makes the Plan stage run `/gsd-plan-phase N --reviews`. It is refused without
  a `NN-REVIEWS.md` in the phase directory, naming the expected path. Why explicit: the restrictive-verbs rule (one
  verb, one job, no hidden behaviour) and "never predict a gate". Test: dry-run pipeline shows `--reviews`; control
  without the flag shows the plain command. The flag is documented (doc_check).
- **D-05 (auto):** The plain `/gsd-plan-phase N` on a phase that already has plans (plan-phase step 6 "Add more /
  View / Replan") is not handled by this phase beyond what the question channel already does (it arrives as a
  `decision` question). The planner checks that it does arrive as a question and records the result.

### Status output (#247, #248, #249)
- **D-06 (auto):** #247: for a question gate the banner prints `devflow gate answer N --gate-id <id>` with the offered
  option ids and no approve/reject; approval gates keep approve/reject. Test: a live question gate's banner has no
  `gate approve`; control: an approval gate's banner still has it.
- **D-07 (auto):** #248: a branch that belongs to a run is compared against that run's recorded `base_branch`;
  config/env is the fallback only for branches with no run. Status names the base it compared against.
- **D-08 (auto):** #249: the start time prints as ISO-8601 local time with UTC offset, followed by the existing
  relative age.

### Resume and stop correctness (#281, #324, #258, #297)
- **D-09 (auto):** #281: the `--until` halt records the halted transition's target in a new persisted `State` field
  (additive: `State` is `#[non_exhaustive]`, `state.rs:34`, checked), and resume goes to it; `Stage::next` stays
  the fallback when the field is absent. Test reaches a Plan gate's validate-again under `--until plan` and asserts
  resume launches Validate; control: a plain Plan finish under `--until plan` resumes at Code.
  Run semver-checks against `origin/develop` per CLAUDE.md.
- **D-10 (auto):** #324: every stop reason and event `source` names the runner (or the unit stop), not the
  supervisor; the planner searches all stop paths for the stale label. Test on the printed text.
- **D-11 (auto):** #258: on the `NotLive` arm, clear only when the state is unchanged from what `start` wrote (no
  stage progress, no history); otherwise keep it and print `devflow status` and `devflow discard` as next steps.
- **D-12 (auto):** #297: hold the phase holder across `stop_unit` and the reload, as `discard` and `cleanup` do.

### Start preflight (#285)
- **D-13 (auto):** `start` and `start --dry-run` run `git check-ignore` for each GSD derived path
  (`.planning/state.json`, `.planning/milestone.lock`, and any others the planner confirms GSD writes) and warn,
  naming the exact `.gitignore` lines to add. Warn, not refuse: DevFlow respects repo rules and does not predict a
  gate; the operator may have reasons. — **Reversibility:** reversible — promoting the warning to a refusal later is one line.

### Test harness (#296) and flaky tests
- **D-14 (auto):** #296: the fake `systemctl` reports `active` while the recorded runner pid lives, and the fake
  `systemd-run` treats only the launched phase's runner lock, held, as readiness. At least one e2e test drives
  `runner_liveness`'s `active` arm through the binary.
- **D-15 (auto):** Known-shape flakes are fixed by construction, one plan or task each: #276 (every listed writer goes
  through `devflow_core::test_support::write_executable`), #277 (bounded poll on the shared read, as
  `wait_for_released_write_lock` does), #279 (wait for `inactive` or gone, assert `Result`/`ExecMainStatus` in the
  message), #301 (one configurable budget for all six `phase7_cli` helpers, longer under `CI`, the panic names the
  budget used; the env var is documented), #178 (a `Drop` teardown removing each scratch root; no process-hunting
  teardown, per the issue's warning).
- **D-16 (auto):** Not-root-caused flakes (#265, #310): first try to reproduce under load (oversubscribed
  `--test-threads`, repeated, run alongside a process-spawning test), record the counts. If it reproduces, fix the
  cause and show the failing direction before the fix. If it does not, apply the condition-wait fix the issue names,
  leave the issue open with the run counts, and do not claim it fixed: a green run is not evidence of a fix.
- **D-17 (auto):** Every fix has one named test that fails on the old code with its intended assertion text, checked
  once by reverting the fix. Gates follow the repo traps: `cargo nextest run --no-tests=fail -E 'test(=…)'`.

### Ordering
- **D-18 (auto):** #246 (D-02/D-03) is the first plan and its live proof the phase's headline success criterion, since
  it is what unblocks Phase 54. The test-harness work (#296, #276) lands before tests that depend on the fake service
  manager.

### Review tier
- **D-19 (auto, orchestrator's classification):** Tier B. Gate and status text, a Plan prompt branch, a start flag, an
  additive `State` field and test fixes. Nothing irreversible or on the release path; no public `devflow-core` item
  removed. One external review round on the plan set (codex and agy, adversarial lens), then execute.

### Claude's Discretion
- Exact wording of banners, warnings and stop reasons; the name of the new `State` field; the `phase7_cli` budget env
  var name and CI default; plan grouping beyond D-18.
