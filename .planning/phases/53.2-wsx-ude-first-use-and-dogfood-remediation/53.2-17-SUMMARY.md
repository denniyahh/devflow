# Phase 53.2 Plan 17: `devflow resume --reviews` Summary

`devflow resume --reviews --phase N` reruns a Plan that its `--until plan` cap halted as a reviews pass (`/gsd-plan-phase N --reviews`) instead of advancing to Code, keeps the cap so the run halts again after Plan, and refuses every other state and a missing `NN-REVIEWS.md` before writing anything.

## What changed

- **main.rs:** `Command::Resume` gains `--reviews` with its help line; the dispatch passes it to `resume_with_fallback`.
- **pipeline_launch.rs:**
  - `resume_advance(state, reviews)` returns `None` for a reviews resume, so Plan reruns.
  - `resume_loaded` refuses a wrong state through `reviews_resume_refusal`, then a missing file through `require_reviews_file_in_checkout`, both before its first write.
  - The final resume commit keeps `stop_until` and sets `reviews_pass` for a reviews resume, then prints the reviews-pass line.
  - `re_mark_stopped_after_failed_launch` takes `reviews`. For a reviews resume it writes back `until_halt_reason(Plan)` and clears `reviews_pass`, unless the runner already recorded its own stop.
  - Docs updated on `resume_with_fallback`, `resume_loaded`, `resume_advance` and `default_stage_prompt`. The precedence sentence was checked against the code: only `commands.rs:345` (`start`) sets `stop_until`, and `transition` halts the first Plan exit under it.
- **state.rs:** `reviews_pass` doc names `resume --reviews` as its second writer. Only the doc changed, so the public API is unchanged.
- **start_refusals_e2e.rs:** `resume_phase` takes `extra: &[&str]`. Adds the e2e test that the binary refuses `resume --reviews` on a run stopped in Code.
- **OPERATIONS.md:** `[--reviews]` on the `resume` row, with what it does and when it is refused.
