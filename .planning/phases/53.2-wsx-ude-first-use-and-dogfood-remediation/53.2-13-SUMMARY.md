# Phase 53.2 Plan 13: stop holds the phase holder; texts name the runner Summary

`devflow stop` now claims the phase holder right before the unit stop and keeps it through the state reload (no write-lock barrier), and every stop reason, event source, gate text and clap help line names the runner instead of the removed supervisor, with a lexer-based source scan guarding it.

## What changed

- **#297 / D-12:** `stop_report` keeps its liveness read and holder probe, returns "no live run; nothing to stop" with nothing created, and otherwise claims `liveness::claim_phase_holder` right before `stop_unit`. `HolderError::Held` maps to the existing "another DevFlow verb holds phase N (pid P) … run devflow stop --phase N again once it returns" text (`unknown` pid when unreadable), `HolderError::Io` to "stop: phase N: could not claim its holder file … nothing was stopped". The hold is dropped explicitly after `stop_outcome`'s reload. `stop_report` calls neither `claim_foreground_holder` nor `update_state_with_within`.
- **Pitfall 6 behaviour change:** a stop while another verb holds the phase now refuses even when the runner reads Live, including inside `start`'s launch window, where it used to stop the unit. OPERATIONS.md's stop row says so.
- **#324 / D-10 reworded sites:** `ADVANCE_STOP_REASON` = "stopped during advance: the runner was ended by its unit stop"; `advance_stopped` `source` = `runner`; pipeline_outcomes.rs rate-limit leads ("once this waiting runner has ended", both branches); commands.rs gate-route texts ("the runner decides when it picks this answer up", "the runner reads GSD's verification status again …"); main.rs help for `--fallback-agent` ("before the first runner launches"), resume's re-arm flag ("whose runner has ended") and `gate sweep` ("without a live runner"). The two tests asserting the old wording (commands.rs `PICKUP`, failover_e2e.rs) were updated with them.
