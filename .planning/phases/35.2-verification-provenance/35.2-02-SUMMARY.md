# Phase 35.2 Plan 02: Branch-Naming Convention Pin Summary

**The cross-repo branch-naming coincidence that keeps `{N}-VERIFICATION.md` from being routinely replaced is now pinned by two tests in `phase_id.rs` — and the pin revealed the assumption behind it was already safe: production code was using `padded()` all along.**

## Performance

- **Duration:** ~30min
- **Tasks:** 1
- **Files modified:** 1 (`phase_id.rs`)

## The RED that wasn't

The plan anticipated the format-string test would fail because `Display` for `PhaseId::new(7)` is `"7"`, producing `feature/phase-7` against GSD's `feature/phase-07`. **That RED never materialised.** The branch name is not built from `Display` — every construction site uses `PhaseId::padded()`:

- `crates/devflow-cli/src/parallel.rs:22` — `format!("{FEATURE_PREFIX}phase-{padded}", padded = phase.padded())`
- `crates/devflow-cli/src/commands.rs:330` — the worktree-created message
- `crates/devflow-cli/src/commands.rs:590` — the branch-match predicate

So `feature/phase-07` was already what production produces. The fix chosen was therefore **neither** of the plan's two options (Display zero-padding vs. `feature_branch` substitution) — it was *no production change at all*, with the test asserting the already-correct `padded()` output. The value delivered is the pin itself: drift on either side is now loud instead of silently turning a rare failure routine.

## GSD-verification test outcome

`gsd_computes_the_same_phase_branch_name_when_available` ran with `gsd-tools` present and matched for all three phase numbers (`7`, `35`, `35.2`). The NOTICE path (tool absent) was not exercised live on this host because `gsd-tools` is installed, but the branch is structurally the same early-return as the absent-tool probe, and the test is designed to print `NOTICE: gsd-tools absent — cross-repo branch-name parity NOT verified by this gate` and pass vacuously when the tool is missing.
