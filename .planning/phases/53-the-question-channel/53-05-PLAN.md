    - crates/devflow-core/src/question.rs (as 53-01 wrote it)

  </read_first>
  <behavior>
    - question::tests::each_malformed_payload_is_refused_naming_its_field: one case per refusal in must_haves; each returns the expected `QuestionError` variant and its Display text contains the field name (`question`, `options`, `options[1].id`, `recommended`, `kind`).

    - question::tests::option_ids_differing_only_by_case_are_distinct: `a` and `A` are accepted.

  <action>
    Add `QuestionError` (`thiserror`, one `#[error("…")]` per refusal, each naming the field, modelled on `GateError`). Add `pub const` bounds (planner values, counted with `chars().count()`): `QUESTION_MAX_CHARS = 4096`, `CONTEXT_MAX_CHARS = 16384`, `OPTION_ID_MAX_CHARS = 64`, `OPTION_LABEL_MAX_CHARS = 512`, `OPTION_DESCRIPTION_MAX_CHARS = 2048`, `MAX_OPTIONS = 32`; over-long text is refused, never truncated (D-16 stores the full text). An option id must be non-empty and contain no control characters (it is typed at a shell). Implement `QuestionSpec::from_arguments(args: &serde_json::Value) -> Result<QuestionSpec, QuestionError>` reading each field by name (no `unwrap_or` defaults for required fields), mapping an unknown `kind` string to `QuestionError::UnknownKind` naming the value and the three accepted ones, and assigning a fresh `question_id`. Ignore unknown keys.
  </action>
