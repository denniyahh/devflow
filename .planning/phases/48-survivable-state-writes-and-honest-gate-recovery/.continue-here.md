## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|----------------------|
| Instance-only fixing | Fixing the first instance of a defect class and closing the class. It recurred three times here: two false security closures, and the code-review fixes each exposed another instance. | blocking | State the class invariant first, then enumerate every site that could violate it (every response writer, every state deleter, every success message) before declaring it closed. |
| Wrong-regime measurement | Proving a flake gone with the cheap loop instead of the workload it failed under. | blocking | Reproduce in the same regime; say which regime a green result covers. |
| Loop counts as proof | Reading 0/N as "fixed" after a 2/30 baseline — 0/30 happens ~12% of the time with no change at all. | blocking | Deterministic fault injection plus revert-mutations are the proof; loop counts are supporting evidence only. |
| Success claimed on a no-op | Commands printing "cleaned up" after a refusal or an empty sweep (fixed here; three older instances filed as 999.133). | advisory | Report only what the code established, and exit non-zero when the requested action did not happen. |
| Silent parse failure in probes | A broken count reads as empty and then as zero. | advisory | Count a second, independent way, and keep a control that must produce the opposite result. |
