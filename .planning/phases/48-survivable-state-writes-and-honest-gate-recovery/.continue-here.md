## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|----------------------|
| A test that passes before the implementation | 48-15's rejection test asserted "some gate context names the plan file" — already true of 48-07's own gate — so it passed against the old code and measured nothing. | blocking | Run every new test BEFORE implementing. A test that does not go red is not a test yet; strengthen it until it does. |
| A guard the test cannot see | Deleting 48-15's `Unrecorded` guard did not fail the test meant to pin it: the pass path's outer `== Pending` already blocked that route, leaving the refusal-gate path untested. | blocking | For every guard, run the mutation that removes it. If the test still passes, the test is wrong, not the guard. |
| Trusting a gate's text pattern | A long `#[expect(...)]` reason was silently re-wrapped by `cargo fmt`, so the plan's single-line `expect\(clippy::disallowed_methods` pattern matched 0 of 16 real annotations. | blocking | Run the gate after formatting. rustfmt's `attr_fn_like_width` caps the attribute's INNER args at 70 chars — measured, not guessed. |
| Reading clippy results from a cached crate | A workspace clippy run after a `-p devflow` run emitted only CLI sites; `devflow-core`'s 12 sites were cached and re-emitted nothing. | blocking | `touch` the crate root to force a fresh lint before trusting a diagnostic count. |
| A test that hangs instead of failing | Any test reaching a real gate polls `gate_timeout_secs()` — the three-day production default. An unbounded hang cannot be told apart from a wedged harness. | blocking | Pre-write a gate response in every test that could reach a gate, including controls where it is inert. For a deliberate failing-direction probe, bound it with `DEVFLOW_GATE_TIMEOUT_SECS`. |
| Trusting GSD tracking writes | See the `advance-plan` constraint above. | blocking | Inspect every generated diff; repair and log before committing. |
