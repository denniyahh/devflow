### Discard refuses a phase branch held by any other checkout, and runs the live-run refusal first
Discard looks through `git worktree list` for any checkout other than the phase worktree holding the branch, and the live-run refusal runs before the items are read, so a possibly live run is refused before "nothing to discard". A `--delete-unmerged-branch` value that is not the phase branch is refused whatever its merge state.

**Rationale:** Otherwise git would refuse the branch deletion after the state was already removed, breaking "all refusals before the first removal"; a phase whose only trace is a swept socket must be sent to `devflow stop`.
**Source:** 52.1-07-SUMMARY.md

## Lessons

### A parked fork holds every descriptor of the process it is forked from
A test control that holds a fork-before-exec window open for a 2 s bound, inside the shared in-process `cargo test` runner, holds every sibling test's lock files, stub write descriptors and pipe ends for that time, which is the very flake this phase removes. Long holds must run in a child process via `run_test_in_child`.

**Context:** Found independently in plans 01 and 06; 01 wrote the rule into `ForkHeldBeforeExec`'s doc comment after 06 was planned.
**Source:** 52.1-01-SUMMARY.md, 52.1-06-SUMMARY.md

---

### Shell `chmod` is not found on a child test's stub-only PATH
The planned `printf ... && chmod 0755` helper exits 127 under `PATH=/nonexistent`; `std::fs::set_permissions` (chmod(2) by path) avoids the lookup and opens no descriptor.

**Context:** `test_support::write_executable` for child test halves.
**Source:** 52.1-01-SUMMARY.md

---

### Plan gate premises must be checked against the pre-plan code
Plans 03 and 04 required `shellcheck` to exit 0 on scripts that already exited 1 before the plan touched them (SC2016, SC2001). Fixed with disable directives, comments only.

**Context:** A gate written without running it on the base commit fails correct work.
**Source:** 52.1-03-SUMMARY.md, 52.1-04-SUMMARY.md

---

### `done < <(git ...)` reads nothing and passes when git fails
The fix captures each listing with `if ! X="$(git ...)"`, stops with the script's own message, then reads a here-string.

**Context:** The plan kept the shape and added another instance of it; avoiding a glob removed one cause, not the shape.
**Source:** 52.1-04-SUMMARY.md

**Context:** Recurring Rule 2 "missing check" deviations across plans 01, 02, 03, 04, 06, 07.

## Patterns

### `fork_held_before_exec` plus an on-ETXTBSY observer
Reproduce a fork-before-exec race deterministically by parking a fork and observing the ETXTBSY retry.

**When to use:** Later flake reproductions of exec races in this codebase.
**Source:** 52.1-01-SUMMARY.md

---

### `wait_until` for unit tests, `common::wait_for` for CLI integration tests, same failure text
Bounded polling helpers with identical failure wording at both layers; `wait_for_released_write_lock` before reading a released state write lock.

**When to use:** Any test that must observe an asynchronous state change.
**Source:** 52.1-01-SUMMARY.md, 52.1-06-SUMMARY.md

---

### Hermetic script e2e fixture
Bare origin plus work repo (or a scratch repo plus a hook-checkout copy) under one TempDir, every spawn through `Fixture::hermetic` (global and system git config nulled, repo-local `GIT_*` removed).

**When to use:** End-to-end tests of shell scripts and git hooks.
**Source:** 52.1-03-SUMMARY.md, 52.1-04-SUMMARY.md

---

### Mutated-script control for selftest wiring
Copy the script into a scratch git repo, change one heredoc line, run `--selftest` there and read the named FAIL line.

**When to use:** Proving a selftest case actually bites.
**Source:** 52.1-05-SUMMARY.md

---

### `phase_run_liveness` before any destructive removal, and `PhaseItems` equality to prove nothing was removed
A verb calls the live-run test before it removes a run's worktree or state; tests compare `PhaseItems` before and after to show a refusal removed nothing, or only its own phase.

**When to use:** Destructive verbs (`discard`, and later `start`/`cleanup` refusals).
**Source:** 52.1-07-SUMMARY.md

---

### Lower-bound duration assertion on a give-up control
Assert `waited_for >= BOUND` (a named constant) alongside the failure text, so a wait that quits early cannot pass; a lower bound cannot fail under load.

**When to use:** Any bounded retry or wait with a negative control.
**Source:** 52.1-01-SUMMARY.md, 52.1-06-SUMMARY.md

---

### Background the full test suite and write its exit code to a file
`scripts/check.sh test` outlived the tool's foreground limit in plans 03, 04 and 05; the same command wrote its exit code to a file that was read afterwards.

**When to use:** Long suites run from an agent session.
**Source:** 52.1-03-SUMMARY.md, 52.1-04-SUMMARY.md, 52.1-05-SUMMARY.md
