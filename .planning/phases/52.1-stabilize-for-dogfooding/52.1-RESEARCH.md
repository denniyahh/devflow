## Summary

Every scope item was located by symbol and its cause read from source this session. Three kernel facts that the flake decisions rest on were confirmed with small probes on this host (kernel 7.2.11), each with a negative control: a forked, not-yet-exec'd child holds a close-on-exec write descriptor and makes `exec` fail with `ETXTBSY`; the same child keeps a released `flock` held; `rename` does not help; `kill(SIGKILL)` returning does not mean the process is gone (263 of 300 reads showed state `R` immediately after the kill). A fourth probe confirmed that Rust's `Command::spawn` blocks for the whole time a `pre_exec` hook waits, which shapes the D-05 reproduction helper.

The code contradicts or under-specifies the CONTEXT in seven places (listed in "CONTEXT decisions the code contradicts" below). Two need an operator answer before planning: **D-09.3** asks for a test that `stop` ends a `ProbeFailed` run, but `stop` refuses a probe error by design and an existing test pins that refusal; and **D-09.1** does not say what `start` does with a state that only a killed `start`'s reservation wrote, or with a state file that does not load. Today `start` handles both.

The 999.223 cause is in production ordering, not the test's launcher wait: the stopped supervisor answers `stopped` to `stop` in `Supervisor::finish`, and only after that does `pipeline_launch::run_monitor` call `remove_liveness_file`. `stop` returns on the answer, so the liveness file can still exist and be locked when `stop` exits. No production reader misreports it (`status` and the launch guards already wait up to 2 s through `held_without_socket` / `STOP_LOCK_RELEASE_WAIT`), so per D-06 this is a test fix plus a note, not a defect to file.

For the proof run (D-15): GSD's `config-set` rewrites the whole config as `JSON.stringify(config, null, 2)` plus a newline, every time. A probe showed the fixture stays clean only when the committed config **already holds the key and is in that exact layout**. A compact layout with the key present still went dirty. The live-payload config in `scratch-dogfood-repo.sh` passes this probe.

**Primary recommendation:** Build one shared `test_support` fork-hold helper (raw `fork`, child blocks on a pipe `read`, then `_exit`) and one bounded `wait_until` poll with its own timeout message. Use them for the four flakes. Get the operator's answer on D-09.1's two leftover states and on D-09.3's `ProbeFailed` exit before writing the `--force` plans.

## CONTEXT decisions the code contradicts or under-specifies

These are findings for the planner and operator. Each one says where it came from.

1. **D-09.3 vs `stop`'s probe-error refusal (real conflict, needs the operator).** D-09.3 asks for a test that "`stop` ends ... a `ProbeFailed` run". `stop` refuses a probe error by design. `stop_via_socket` (commands.rs) has `Err(error) => return Err(probe_refusal(phase, &located.socket, &error))`, `probe_refusal` says "nothing was signalled, removed or recorded", and `crates/devflow-cli/tests/stop_e2e.rs` `stop_reports_a_probe_error_and_never_runs_the_backstop` pins it ("R-6: a probe error is reported and never reaches the backstop"). `ProbeError` includes `NoReply` (a wedged supervisor that accepts a connection but never answers), `NotASocket`, `ForeignOwner`, `Connect` and `Stat` [VERIFIED: crates/devflow-core/src/supervisor.rs:294-315]. With `cleanup --force` gone, a `ProbeFailed` run has no DevFlow exit. The `Stale` half is already covered: `stop_tears_down_a_stale_supervisor_through_the_backstop` exists (stop_e2e.rs). **Recommendation:** keep `stop`'s refusal. Have `stop`, `cleanup` and `discard` all name the probe error and the manual fix (end the wedged process, or remove the stray path), after which the run reads STALE or GONE and `stop` ends it. Make D-09.3's test "stop refuses `ProbeFailed`, naming the fix; after the fix, stop ends it". Do not write a test that `stop` ends a `ProbeFailed` run.
2. **D-09.1 leaves two existing states unassigned (needs the operator).**
   - (a) A state only a killed `start`'s reservation wrote. `run_never_prepared` checks `!state.verification_baseline_captured`, and `refuse_unprepared_run` today tells `resume`/`advance` to "run `devflow start ...`". So `start` is the documented recovery for it today.
   - (b) A state file that does not load. `reserve_launch` replaces it for `start` and keeps a copy at `.devflow/unloadable-state-NN-<launch>.json`.
   - Under "start works only on a phase with no run state", both would be refused, and both are left by a dead `start`, not by a run. **Recommendation:** count (a) as "no run" (nothing ran). Refuse (b) and name `discard`. `discard` must then also handle a state that does not load. `start` itself already refuses (a) when a worktree is left behind (`ensure_phase_worktree` → `WorktreeError::Exists`).
3. **D-09.1 side effects the CONTEXT does not mention (agent finding).** `fresh_state_carrying_phase_failures` and `replaced_state_notice` exist to replace a finished or stopped state on `start` and carry `phase_validate_failures` across it (999.78/A-11, operator decision 2026-11-11: "a `start` over a state recorded `finished` begins at zero ... A stopped run that did not finish still carries its total"). Once `start` refuses those states, the notice's finished and stopped arms are dead, and `discard` becomes what resets the failure budget, the same way `clear_state` does today. ### Pattern 1: Fork held before exec (D-05 reproduction helper)

**What:** a child process that holds duplicates of every descriptor the parent had open at fork time, for as long as the test wants.
**Why raw `fork`, not `Command::pre_exec`:** `Command::spawn` blocks in the parent until the child execs. Probe: `spawn() with pre_exec holding 800ms returned after 801.712482ms`; control without the hold `403.5µs` [VERIFIED: local rustc probe this session]. A `pre_exec` helper would need its own spawning thread and a "forked" signal pipe. A raw `fork` whose child blocks on `read` and then calls `_exit` is simpler. `_exit` closes the descriptors exactly as a successful exec closes the close-on-exec ones.
**Async-signal-safety:** in a multi-threaded test process, the child may call only `read`, `write`, `close` and `_exit`. No allocation, no `println!`, no locks.
**Pipe trap:** the child inherits **both** pipe ends. Closing the parent's write end does not give the child EOF while the child still holds its own copy. Release by **writing a byte**, or have the child close its write copy first.
**Example (shape; names are the planner's choice):**
```rust
// devflow-core/src/test_support.rs  (#[cfg(any(test, feature = "test-support"))] module)
/// A child forked from this process and parked before any exec, so it holds a
/// duplicate of every descriptor that was open at the fork (close-on-exec ones
/// too) until it is released. Drop releases and reaps it.
pub struct ForkHeldBeforeExec { pid: libc::pid_t, release_write: libc::c_int }

pub fn fork_held_before_exec() -> ForkHeldBeforeExec {
    let mut fds = [0 as libc::c_int; 2];
    // SAFETY: pipe2 writes two descriptors into `fds`.
    assert_eq!(unsafe { libc::pipe2(fds.as_mut_ptr(), libc::O_CLOEXEC) }, 0);
    let (read_end, write_end) = (fds[0], fds[1]);
    // SAFETY: the child calls only async-signal-safe read and _exit.
    let pid = unsafe { libc::fork() };
    assert!(pid >= 0, "fork failed");
    if pid == 0 {
        let mut byte = 0u8;
        unsafe {
            libc::read(read_end, (&mut byte as *mut u8).cast(), 1);
            libc::_exit(0);
        }
    }
    unsafe { libc::close(read_end) };
    ForkHeldBeforeExec { pid, release_write: write_end }
}
// release(): write one byte to release_write, then waitpid(pid). Drop does the same if not released.
```

// crates/devflow-core/src/gsd_reader.rs, in run_bounded (shape; constants named per repo style)
#[cfg(any(test, feature = "test-support"))]
const TEXT_BUSY_RETRY_FOR: Duration = Duration::from_secs(2);
#[cfg(any(test, feature = "test-support"))]
const TEXT_BUSY_RETRY_STEP: Duration = Duration::from_millis(10);

fn spawn_reader(cmd: &mut Command) -> Result<Child, ReaderFailure> {
    #[cfg(any(test, feature = "test-support"))]
    {
        let deadline = Instant::now() + TEXT_BUSY_RETRY_FOR;
        loop {
            match cmd.spawn() {
                Err(error) if error.raw_os_error() == Some(libc::ETXTBSY) && Instant::now() < deadline => {
                    std::thread::sleep(TEXT_BUSY_RETRY_STEP)
                }
                Err(error) if error.raw_os_error() == Some(libc::ETXTBSY) => {
                    return Err(ReaderFailure::Spawn { message: format!(
                        "{error}; still busy after retrying for {TEXT_BUSY_RETRY_FOR:?} (test builds only)") })
                }
                other => return other.map_err(|error| ReaderFailure::Spawn { message: error.to_string() }),
            }
        }
    }
    #[cfg(not(any(test, feature = "test-support")))]
    cmd.spawn().map_err(|error| ReaderFailure::Spawn { message: error.to_string() })
}
