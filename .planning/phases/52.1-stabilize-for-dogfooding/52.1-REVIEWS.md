## Codex Review

### CONFIRMED

Source inspection only; Rust tests and live concurrency scenarios were not executed. The shell failure-control described below ran entirely in memory. No files or temporary artifacts were created.

1. **Major — Plan 08 calls a backstop that explicitly rejects the required input.**

   `52.1-08-PLAN.md:98` instructs replacing the probe-error refusal with `stop_stale_socket(phase, &located)?`.

   That calls `run_backstop`, which calls `supervisor::backstop::teardown_stale` (`crates/devflow-cli/src/commands.rs:3814–3825,3873`). The latter re-probes and accepts **only** `Ok(Liveness::Stale)`; every probe error returns `BackstopError::NotStale` before identity classification or signalling (`crates/devflow-core/src/supervisor/backstop.rs:475–487`). Its existing test explicitly asserts that a regular file produces this refusal (`backstop.rs:1073–1084`).

   Consequently, the planned `NotASocket` tracer still refuses, and the `NoReply` case cannot end its agent group. Removing the CLI refusal does not implement D-21/D-25.

   **Fix:** Plan an explicit core backstop entry supporting unprobeable sockets while retaining identity validation and protection against a socket becoming responsive. Include `backstop.rs`, its tests, documentation, and public-API verification in Plan 08.

2. **Major — Discard copies only part of cleanup’s protection and can delete work belonging to a live run.**

   `52.1-07-PLAN.md:73` specifies the liveness predicate as agent-pid liveness plus `PhaseLiveness::{Alive, LaunchPending, HeldNoSocket}`. Line 154 says to copy that refusal and accept unloadable state.

   Two dangerous cases escape:

   - `Stale` and `ProbeFailed` are outside that predicate. Current cleanup has a **separate** preservation block precisely because these states may leave an agent group running (`crates/devflow-cli/src/commands.rs:1261–1278`). Plan 07 does not copy it.
   - Missing or corrupt state cannot supply `probe_phase(state)`. A supervisor may nevertheless remain live; the existing `possibly_live_sockets` explicitly sweeps for this case (`commands.rs:4728–4765`). Discard’s specified algorithm performs no such sweep.

   The phase foreground holder excludes another foreground command; it does not prove an already-detached supervisor is dead. The planned live-agent-only test misses both cases.

   **Fix:** Refuse deletion whenever supervisor/group liveness cannot be ruled out, including stateless socket sweeps and unpublished-launch locks. Add corrupt-state/live-supervisor and stale-socket/live-group preservation tests.

3. **Major — Cleanup can race resume and remove its worktree and newly written state.**

   `52.1-11-PLAN.md:69` specifies:

   > “live refusal … → merged? … → clean? … → remove the worktree … and the run state”

   No foreground holder surrounds that sequence. Current cleanup snapshots states once (`crates/devflow-cli/src/commands.rs:1199`) and later removes state through an unconditional `workflow::clear_state` (`commands.rs:1382–1392`).

   A valid interleaving is: cleanup passes its dead/merged/clean checks; resume reserves and launches that phase; cleanup removes the still-clean worktree and clears resume’s state. Resume takes the foreground holder (`crates/devflow-cli/src/pipeline_launch.rs:3200–3207`), but cleanup never participates in that exclusion. The state write lock serializes individual writes; it does not protect the earlier liveness decision.

   **Fix:** Acquire the phase foreground holder before reloading state and checking liveness; retain it through removal. Add a barrier-controlled cleanup/resume race test that verifies the loser preserves the worktree and state.

4. **Major — `--no-worktree` bypasses the locked leftover-worktree refusal.**

   CONTEXT D-09.1 requires `start` to find **“no run state, no phase worktree and no phase branch”** (`52.1-CONTEXT.md:88–93`).

   But `52.1-10-PLAN.md:159` explicitly makes `refuse_leftover_phase_work` check the worktree directory only:

   > “In worktree mode…”

   For `--no-worktree`, it checks only the derived branch. Thus an orphan `.worktrees/phase-12` directory with no state or `feature/phase-12` branch is refused by ordinary start but accepted by `start --no-worktree`. That branch-in-place path does not inspect the leftover directory; `GitFlow::feature_start` creates its branch from the base (`crates/devflow-core/src/git.rs:166`).

   **Fix:** Check the derived worktree path regardless of the requested mode. Test both real and dry-run `--no-worktree` starts against a leftover directory with no derived branch.

5. **Major — The proof checkpoint supplies an invalid approval command.**

   `52.1-14-PLAN.md:101` instructs:

   > `devflow gate approve <id>`

   The positional argument is `phase: PhaseId`; the gate ID is a separate `--gate-id` option (`crates/devflow-cli/src/main.rs:298–314`). `gate list` actually prints `devflow gate approve <phase> [--gate-id <id>]` (`crates/devflow-cli/src/commands.rs:2039`).

   Following the plan literally will not approve the UUID-like gate ID. The central human checkpoint stalls on its prescribed command.

   **Fix:** Use `devflow gate approve 1 --stage validate --gate-id <id>` and record that exact invocation.

6. **Major — The new shared commit classifier converts Git failures into “nothing to replay.”**

   `52.1-03-PLAN.md:114` prescribes:

   > `git diff-tree ... | grep -v ... | grep -v '^$' || true`

   This suppresses **every** pipeline failure, including failure to read the commit’s tree. Empty output then means both “forbidden paths only” and “Git could not inspect this commit.” The existing replay skips empty results (`scripts/cut-pr-branch.sh:189–195`); the planned listing also excludes them.

   An in-memory shell control confirmed the failure shape: a simulated `diff-tree` failure returned status **0** with empty output; the positive control returned `src/x.rs`. `pipefail` does not survive the trailing `|| true`.

   **Fix:** Capture and validate `git diff-tree` separately. Treat filtering’s no-match result separately from command failure, and require failed Git reads to abort with the SHA named. Add a failing-read control.

7. **Minor — Plan 03’s single skipped-commit fixture contradicts the preserved zero-selection refusal.**

   `52.1-03-PLAN.md:108` specifies an out-of-scope `fix(52-review): code` commit and expects:

   > “exit 0, not replayed … on a `skipped` line”

   Its harness creates one commit per subject under test (`:67`). With only that subject, selection is empty. The actual script explicitly exits **1** when `COMMIT_LIST` is empty (`scripts/cut-pr-branch.sh:141–143`). Task 2 does not instruct removing that refusal.

   **Fix:** Explicitly add an independent in-scope sentinel to this fixture, or specify that an all-skipped range prints the listing and then refuses. Test the all-skipped case separately.

### F-01: `devflow discard` crashes with `Err` on partial state (missing worktree or missing state file), breaking D-09.1 recovery
- **Severity**: Major
- **Citations**:
  - [52.1-07-PLAN.md](file:///.planning/phases/52.1-stabilize-for-dogfooding/52.1-07-PLAN.md#L96-L98):
    > "...then remove worktree (`worktree::remove(project_root, &path, true)`), state, branch (`delete_branch(&branch, true)`), printing `removed ...` per item and a `warning:` per failure, and return `Err` if any removal failed."
  - [52.1-CONTEXT.md](file:///.planning/phases/52.1-stabilize-for-dogfooding/52.1-CONTEXT.md#L92-L93) (D-09.1):
    > "- a leftover worktree or branch with no state: it names `discard`."
  - [52.1-09-PLAN.md](file:///.planning/phases/52.1-stabilize-for-dogfooding/52.1-09-PLAN.md#L21-L24):
    > "D-09.1: start over a leftover phase worktree or a leftover phase branch with no run state refuses and names `devflow discard`..."
  - [worktree.rs](file:///crates/devflow-core/src/worktree.rs#L81-L88):
    `worktree::remove(project_root, path, force)` executes `git worktree remove --force <path>` via `run()`. If `<path>` is not an active git worktree on disk, `git` exits non-zero (`fatal: '...' is not a working tree`) and returns `Err(WorktreeError::Command(...))`.
- **Breakdown**:
  `52.1-07-PLAN.md` implements `discard` by unconditionally calling `worktree::remove`, removing the state file, and deleting the branch. If any step fails, it prints a warning and returns `Err`.
  However, D-09.1 (`52.1-CONTEXT.md`) and `52.1-09-PLAN.md` specifically direct operators to run `devflow discard --phase N` when a phase has:
  1. A leftover branch but **no worktree** (e.g. after a `--no-worktree` run or manual directory cleanup).
  2. A leftover worktree or branch with **no state file** (`Existing::Missing`).
  Under `52.1-07-PLAN.md`, running `devflow discard` on a leftover branch without a worktree invokes `git worktree remove --force <path>`, which fails because the directory is not a worktree. Running it on a leftover worktree without a state file fails when removing the non-existent state file. Because the plan requires `discard` to "return `Err` if any removal failed", `discard` will exit non-zero and fail on the exact partial states it was created to clean up.
  None of the eleven `discard_*` tests in Plan 07 exercise discarding when only a branch or only a worktree exists.
- **Negative Control / Limit**:
  Proving that `discard` succeeds when all three exist does not establish that it succeeds when one is missing. A negative/partial test fixture lacking a worktree directory must be asserted to exit 0 and remove the branch.
- **Concrete Fix**:
  In `crates/devflow-cli/src/commands.rs`, make each removal step conditional on existence:
  - Only invoke `worktree::remove` if `path.is_dir()` and git recognises it as a worktree.
  - Only delete the state file if `existing` is not `Existing::Missing`.
  - Only delete the branch if `branch_exists` is true.
  Do not return `Err` when skipping a resource that never existed. Add an e2e test in `crates/devflow-cli/tests/phase7_cli.rs` asserting that `devflow discard --phase N` exits 0 and deletes the branch when no worktree and no state file exist.

### S-01: Spawning `/bin/sh` to write stubs in `test_support::write_executable` introduces child process contention
- **Severity**: Minor
- **Citations**:
  - [52.1-01-PLAN.md](file:///.planning/phases/52.1-stabilize-for-dogfooding/52.1-01-PLAN.md#L140-L145):
    > "Add `pub fn write_executable(path: &Path, contents: &str)` to test_support.rs: spawn `/bin/sh -c 'printf "%s" "$1" > "$2" && chmod 0755 "$2"' sh <contents> <path>` and assert success..."
- **Analysis**:
  Spawning `/bin/sh` from Rust test threads avoids holding an open write file descriptor in the Rust parent process, which successfully eliminates the `ETXTBSY` race. However, forking `/bin/sh` from a heavily multi-threaded test process (e.g., during `cargo test --workspace`) momentarily creates child processes that duplicate the process table. On resource-constrained test environments or kernels with low `pid_max` limits, spawning shells for every test stub increases fork latency and may trip intermittent `EAGAIN` (resource temporarily unavailable) fork errors.
- **Fix**:
  Ensure `write_executable` checks for spawn errors and retries on `EAGAIN`, or use `libc::open` with `O_CLOEXEC` followed by immediate close in Rust, or keep `/bin/sh` bounded with error diagnostics.

### S-02: `52.1-08-PLAN.md` byte offset check `resume_offset > kill_offset` is brittle against formatting
- **Severity**: Minor
- **Citations**:
  - [52.1-08-PLAN.md](file:///.planning/phases/52.1-stabilize-for-dogfooding/52.1-08-PLAN.md#L130-L138):
    > "...then contains `devflow resume --phase {phase}` after the `kill {pid}` text (D-25: `kill <pid>` followed by `devflow resume --phase N`; assert the resume text's byte offset is greater than the kill text's, not only that both are present)..."
- **Analysis**:
  Asserting byte offset ordering in string output can produce false failures if output is formatted differently across terminals (e.g. multi-line error blocks, tracing prefixes, or log prefixes). If `eprintln!` calls interleave on unbuffered stderr, the byte offset test could fail even when both instructions are present and clear to the user.
- **Fix**:
  Assert that `kill {pid}` appears before `devflow resume` by matching line-by-line in stderr rather than raw byte offsets.
