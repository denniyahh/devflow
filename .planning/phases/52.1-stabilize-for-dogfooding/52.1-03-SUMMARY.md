# Phase 52.1 Plan 03: Close-out Script Stops Dropping Phase Work Summary

**`scripts/cut-pr-branch.sh` replays a phase's `(N-review)` and `(N-fix)` commits, names every other code commit its
scope filter skips before it creates anything, and replays one of those on request with `--include <sha>` (999.230,
999.167).**

## Read this first

- **The tests prove the script on synthetic ranges only.** Each range is one to six single-file commits in a scratch
  repository. The first real use is this phase's own close-out (D-18). Nothing here ran the script against this
  repository, by rule.
- **The plan's `shellcheck scripts/cut-pr-branch.sh` gate could not pass on the untouched script.** It exited 1 before
  this plan changed a byte (three notes: SC2016 once, SC2001 twice, all in lines this plan does not own). I marked
  each with a `# shellcheck disable=` directive and its reason, comments only, in its own commit (`33a8316`).
  `shellcheck` now exits 0. See deviation 1.
- **An unreadable commit is stopped "before anything is created" only when it is out of scope.** An in-scope commit
  git cannot read is still caught, with the commit named, but in the replay loop, after the PR branch exists. That
  is today's timing for that case and it has no test. See "What this does not establish".
- **Two tests and one refusal go beyond the plan**: a test that the listing precedes the PR branch's creation, and a
  refusal (with its test) of `--include` given without a phase. See deviations 2 and 3.

## What this does not establish

- **Real history.** No merge commits inside a replayed range, no conflicts, no renames, no multi-file commits beyond
  one two-file case, no commit that an `--include` makes conflict with its neighbours. The fidelity report and the
  forbidden-file audit at the end of the script ran on every passing test but nothing asserts on them.
- **An in-scope commit git cannot read.** `non_forbidden_paths` is called for an in-scope commit only in the replay
  loop, so the script stops there with `error: cannot list the files commit <sha> touches`, after
  `git branch -f <pr-branch>`. The must-have says "before anything is created"; the test
  (`an_unreadable_commit_aborts_before_anything_is_replayed`) covers the out-of-scope case, which is the one that
  could be dropped silently. Closing the gap means reading every range commit in the selection pass.
- **Three `--include` refusals have no named test.** An empty value (`--include=`), a SHA git cannot resolve, and a
  merge commit in the range were each run once by hand in a throwaway repository: each exited 1 with
  `error: --include <value> is not in origin/develop..feature/phase-52.1 (or is a merge commit)` and created no
  branch. So was `--include` with no value: `error: --include needs a commit SHA`, exit 1.
- **Non-phase mode.** Its replay loop now also goes through `non_forbidden_paths`. Only the `--include` refusal is
  tested there; no test replays a `workspace/*` branch.
- **A third reading of the forbidden paths still exists.** The fidelity report builds `TOUCHED_SET` with its own
  `git diff-tree ... | grep -v -E "$FORBIDDEN_REGEX"` (cut-pr-branch.sh:333). It predates this plan, is not part of
  selection or the listing, and I left it. The listing and the replay share one function; the report does not.
- **The unreadable-commit fixture depends on git keeping a fresh commit's tree as a loose object.** The test asserts
  that premise and panics naming the object path if a git version packs it instead.
- **"Before the replay" on the normal path is one test over a merged stdout+stderr transcript**: the `skipped` line
  comes before `==> Initializing clean branch`. That the listing goes to stderr is asserted by the other listing
  tests, which capture the streams apart.
- **Each test passed in one targeted run, one whole-suite run and one workspace run.** Three passes are a weak bound
  on flakiness. The tests spawn `bash` and `git`.
- **`shellcheck` is not run by `scripts/check.sh` or CI.** Its exit 0 is a hand gate on this host
  (ShellCheck 0.11.0).
- Everything ran on this host only (git 2.56.1). Nothing ran in the pinned container or in GitHub CI.

- `SCOPE_RE` is `^[a-z]+\((phase-)?0*${PHASE_ESC}(-[0-9]+|-review|-fix)?\)!?: `, the bytes RESEARCH tested. Phase
  50's close-out dropped nine review commits under the old pattern.

  captures `git diff-tree` as its own statement, checks that status itself, and on failure prints
  `error: cannot list the files commit <sha> touches (git diff-tree exited <n>)` and returns 1.
- In the same ordered `git log --reverse --no-merges` pass that applies the scope filter, every commit that is not
  selected and has a non-forbidden path is collected, then printed to stderr before the empty-selection refusal:

  ```

    skipped 8e7d540 chore(ci): b
  ```

  (stderr of a hand run in a throwaway repository.) Nothing extra is printed when there is nothing to list.
- `--include <sha>` and `--include=<sha>` collect into `INCLUDES`. After the fetch and before any branch is created,
  each value is resolved with `git rev-parse --verify -q "<sha>^{commit}"` and must be in
  `git log --no-merges "$BASE_REF..$CURRENT_BRANCH"`. Selection is "scope matches or included", inside the existing
  ordered loop, so an included commit keeps its place and is not listed.
- `CONTRIBUTING.md`'s close-out step names the listing and `--include <sha>`; the script's usage header names both
  scopes and both option forms.
