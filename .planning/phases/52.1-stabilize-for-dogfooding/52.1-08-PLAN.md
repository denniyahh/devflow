<objective>
Give an unprobeable supervisor a DevFlow exit before `cleanup --force` goes away (D-21, operator decision; D-09.3), and fix the 999.223 flake in the same `stop` area.

Purpose: a supervisor whose socket cannot be probed cannot be recovered, so it is in effect gone (operator, 2026-11-11). The backstop already validates the group's identity, so the probe was never what stopped a wrong-process kill. And `stop` returns before the stopped supervisor unlinks its liveness file, which makes a one-shot test check flaky.
Output: `stop` ends a ProbeFailed run via the backstop; the residue refusal names the manual kill; `assert_stopped` waits for the unlink; docs and help say so.
</objective>

Why resume can continue after the stop (read in source while planning): resume's live-run guard (`refuse_launch_over_a_live_run` → `possibly_live_sockets` → `socket_live_socket`) counts any probe error on the recorded socket as live, so a resume over an unprobeable socket that is still on disk is refused. The backstop's teardown removes the socket path and its sidecar (`run_backstop`'s Killed and RemovedNothingSignalled arms say so), after which the socket probes Gone; `held_without_socket` then makes the run live only while a process still holds the launch's liveness file. So: a NotASocket or ForeignOwner path with no supervisor process behind it is resumable after stop; a NoReply supervisor (alive, holding its liveness file) is not, until it exits.
