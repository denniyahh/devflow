<objective>
Make `start` work only on a new phase (D-09.1, operator decision), settle the two leftover states the operator ruled on (D-20, refined by D-26), build all of `start`'s run-state refusals as one guard sequence that both the reservation and `start --dry-run` run (D-26), and make `resume`, `advance`, the start live-run refusal (D-26 Clarification) and every other refusal name only the verb that applies. D-27's two dry-run preflights and its not-checked line are 52.1-15's, split out of this plan for context size; it builds on this plan's dry run.

Purpose: the operator: "start should only be for new phases. resume should only work on an incomplete phase. nothing should restart a finished phase." Today `start` silently replaces a finished or stopped state with a notice, a hand-run `advance` over a finished run names `resume`, which refuses it, the start live-run refusal ends "run `devflow start` again" over a run that start would then refuse, and `start --dry-run` returns before every guard, so it previews a start that would be refused. D-26 (operator, 2026-11-12): one place for the rules, and a dry run that reports every refusal a real start would hit without writing anything.
Output: `launch_guards`, `existing_run` and `refuse_start_over_an_existing_run` under the state write lock, `refuse_leftover_phase_work`, the read-only dry-run path, D-20's two states, the deleted replace-notice and carry paths, rewritten refusal texts, and their tests.
</objective>
