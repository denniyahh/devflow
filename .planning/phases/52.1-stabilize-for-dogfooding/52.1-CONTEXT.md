## Phase Boundary

Make DevFlow stable enough to resume dogfooding at Phase 53: a supervised run drives a phase from Plan to a finished
Validate with no hand-run stage and no hand-edited `.devflow/` state. The phase fixes known defects and flakes that
block or erode that, and closes by proving it with one live supervised run.

Not dogfooded itself (operator, 2026-11-11, ROADMAP.md). It runs as GSD commands in an agent session, the same way
Phase 52 did (52-CONTEXT D-18).

Out of scope: new capabilities (the question channel is Phase 53), and anything that does not block or erode an
unattended Plan→Validate run or the by-hand close-out after it.

### Flake fixes (999.221, 999.222, 999.223, 999.232)
- **D-05 [auto]:** Test the shared hypothesis before fixing around it. Three of the four entries suspect one cause: a
  child forked by another test thread holds a duplicate of a lock or write fd until its `exec`. The research step
  checks it from source: which fds are opened without `O_CLOEXEC`, and which test helpers fork without exec. The
  result decides D-06's second half.
- **D-06 [auto]:** The fix shapes from the backlog entries:
  - 999.221, 999.223 and 999.232: replace the single read with a bounded poll (at most 2 s) for the expected state.
  - 999.222: write the stub to a temp name in the same directory, close it, then `rename` it into place.
  - If D-05 confirms the fd hypothesis for a production path, add a note beside `write_lock_status` and the liveness
    probe that `status`/`doctor`/`stop` can briefly read a released lock as held in a multi-threaded caller. The poll
    stays test-side only unless a production caller is shown to misreport.
- **D-07 [auto]:** Each poll gets a negative control: a variant where the state never arrives (the lock is still
  held, the descendant is still alive) must fail with the poll's own timeout message, not hang and not pass.
- **D-08 [auto]:** Evidence of the fix: run each fixed test 50 times under `scripts/check-in-container.sh` load (the
  999.232 fix shape). Report it as what it is: 50 passes is a weak bound on a flake whose rate was never measured, not
  proof the race is gone.

### `--force` redesign (999.224)
- **D-09 [auto]:** Adopt the entry's five-point fix shape:
  1. `start` over a finished or stopped phase continues on its worktree and branch instead of demanding `--force`;
     `resume`, `advance` and `status` name that verb.
  2. One explicit discard verb, `devflow discard --phase N`, that lists what it removes (worktree, uncommitted
     changes, state, branch) and refuses an unmerged branch unless the operator names the branch.
  3. A stale or unprobeable supervisor goes through `devflow stop`; `cleanup` no longer offers `--force` for it.
  4. The "base is >50 commits ahead" refusal gets an override named for what it overrides.
  5. Both `--force` flags are removed; `cleanup` removes only what is provably safe (merged, clean, no live run).
  — **Reversibility:** one-way — `--force` and the new verb are CLI surface, and `devflow-core` is published on
  crates.io. Removing a flag or verb after 4.0.0 ships needs a 5.0.0. The version is `4.0.0-alpha.1` and unpublished,
  so doing it now rides the same major bump (999.226 used the same reasoning).
- **D-10 [auto]:** The interim Phase 52 fix (3f0714f: no `--force` deletes an unmerged phase branch) is kept as an
  invariant. Every new path must refuse to delete an unmerged branch, with a test per path (worktree,
  `--no-worktree`, and a non-default base, which nothing tests today).
- **D-11 [auto]:** No migration and no deprecation period for `--force`: the project has no users (operator,
  2026-10-12). The flag is removed outright, and the refusal for the old spelling names the new verb.

### Close-out scripts (999.230, 999.231)
- **D-12 [auto]:** 999.230: add `--include <sha>` (repeatable) to `scripts/cut-pr-branch.sh`, and before replaying,
  list every non-planning commit in the range that the scope filter skips. Pair it with 999.167 as the entry says.
- **D-13 [auto]:** 999.231: `scripts/hooks/pre-push` runs the divergence check per pushed `local_sha` from the
  hook's stdin, only for `refs/heads/workspace/*` remote refs, and reads the manifest from that commit
  (`git show <sha>:.workspace-divergence`), not the working tree. Both directions get a test: a clean PR branch pushed
  from a workspace checkout passes, and a workspace branch pushed from a develop-based checkout is checked (the
  suspected fail-open case).
- **D-14 [auto]:** Neither script has tests today. The new tests are named Rust integration tests that drive the real
  script against a temp repo (the project prefers a named Rust test to a shell pipeline). Gate each with
  `cargo nextest run --no-tests=fail -E 'test(=…)'`.

### Proof run (the phase's exit criterion)
- **D-15 [auto]:** The phase closes on one live supervised run, not on green tests alone. A throwaway project from
  `scripts/scratch-dogfood-repo.sh`, with one trivial pre-written plan (the cheapest workload that crosses the seams).
  The run is `devflow start --mode supervise` with no `--until` cap, and it must reach Plan → Code → Validate → the
  Validate gate → `gate approve` → `workflow_finished`. Pass requires no hand-run stage, no edit under `.devflow/`, and
  no process killed by hand. Any defect it hits is filed as 999.x and reported (dogfood defect rule), not routed
  around.
- **D-16 [auto]:** Once 999.224 lands, the same proof run ends with the by-hand close-out path: `devflow cleanup` on
  the finished run keeps the unmerged branch and says why. This exercises D-10 live.
- **D-17 [auto]:** The proof run uses the installed binary built from this phase's head (`cargo install --path
  crates/devflow-cli --locked --force`). Before the run, check that `command -v devflow` resolves to that binary and
  that `devflow --version` prints `4.0.0-alpha.1` with this phase's commit. Found during this discuss (2026-11-11):
  the shell's `devflow` is `~/.local/bin/devflow`, a **1.8.0** build from 2026-07-24, which shadows
  `~/.cargo/bin/devflow` (3.0.0). No v4 binary is installed. The operator had the 1.8.0 copy deleted the same day;
  `devflow` now resolves to `~/.cargo/bin/devflow` (3.0.0) until this phase's build is installed.
