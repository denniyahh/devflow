# Phase 52.1 Plan 04: Push-time Divergence Check Judges the Pushed Commit Summary

**`scripts/hooks/pre-push` now runs `scripts/check-workspace-divergence.sh` once for each pushed commit that carries
`.workspace-divergence`, and the script reads the manifest, the diff, the script modes and the built-in path list
from that commit instead of from the pushing checkout (999.231).**

## Read this first

- **The hook this machine runs on a push has not changed.** `git config --get core.hooksPath` prints
  `/var/home/denniyahh/Github/devflow/scripts/hooks`, the main checkout's copy, and that file still holds the old
  `if [ -f .workspace-divergence ]` block (read, not run). A push from any worktree, this phase's close-out
  included, keeps the old behaviour until the branch checked out in the main checkout carries `11e48ad`. Until
  then the false refusal and the fail-open this plan fixes are both still live.
- **Nothing here ran the hook or the script against this repository.** Every run was in a scratch repository, by
  rule. No push was made.
- **Six tests, not the plan's five.** The five planned tests could not tell a script that reads the manifest or
  `FORBIDDEN_PATHS` from the checkout apart from one that reads them from the commit. I added a sixth that can. See
  deviation 2.
- **A pushed tag is checked too.** D-13 says "whatever the remote ref is called", so a tag whose commit carries a
  manifest is judged like a branch (one hand run, below). Before, what was pushed played no part: the checkout's
  manifest on disk decided whether anything was checked.
- **The plan's `shellcheck` gate could not pass on the untouched hook.** It exited 1 on one pre-existing note
  (SC2001). I marked it with a directive, a comment only, in its own commit. See deviation 1.

## What this does not establish

- **Behaviour on this repository's real history.** The first real run is the first push after the main checkout's
  branch carries the change. `workspace/denniyahh` and `feature/phase-52.1` both carry a manifest, so both will be
  checked against `origin/develop` from their own commits.
- **The all-zero skip on its own.** Two lines keep a delete away from the script: the all-zero `case` and the
  `git cat-file -e "$local_sha:.workspace-divergence"` guard, which also fails for an all-zero SHA. With either one
  removed `a_delete_push_is_skipped` still passes (measured, both). It fails only when both are removed.
- **A manifest probe that fails for another reason.** `git cat-file -e` failing is read as "no manifest" and the
  commit is skipped. That is the plan's shape. A corrupt object, or a `local_sha` that is not a commit, is skipped
  the same way. Not tested.
- **Cases run once by hand, with no named test** (throwaway repository, results under "Hand runs"): the script
  with no arguments from a subdirectory, an unknown SHA, a commit with no `scripts/cut-pr-branch.sh`, stale `only`
  and `modified` declarations, an unknown line kind, a nested `scripts/hooks/` file at `100644`, a `scripts/lib/`
  fragment at `100644` left alone, a two-ref push, an empty stdin, a lightweight tag, and the drop-in contract.
- **An annotated tag.** Only a lightweight tag was run. `git cat-file -e "<tag object>:path"` should peel it; not
  run.
- **Paths git quotes** (non-ASCII, tabs, quotes) in the `ls-tree` and `diff` listings. The parsing is as loose as it
  was before; untested.
- **Flakiness.** Each test passed in at least one targeted run, two whole-file runs and one workspace run. That is a
  weak bound. The tests spawn `bash` and `git`.
- **`shellcheck` is not run by `scripts/check.sh` or CI.** Its exit 0 is a hand gate on this host.
- Everything ran on this host only (git 2.56.1, ShellCheck 0.11.0). Nothing ran in the pinned container or in CI.
- **The mutants are spot checks, not a mutation score**: eleven test/mutant pairs failed as intended, two passed
  and are explained above.
