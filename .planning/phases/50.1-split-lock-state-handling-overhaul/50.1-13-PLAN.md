<objective>
Move the CLI's three answer writers onto observed-id binding (D-04, D-05): each publishes for the gate it saw, or not
at all, and the operator can see and pass the id.

Purpose: AR-48-04's check-to-write window — a writer that observed gate G1 could today publish into the single slot
that G2, opened at the same stage, then reads. With answers keyed and writers passing the observed id, that decision
cannot be relabelled. The waiter still reads through 50.1-08's bridge (keyed first), so this lands before the waiter
switch (50.1-14) with both suites green.
Output: writers on `Gates::answer`/`reap_answer`, `--gate-id`, gate ids in listings, V-19 tests, integration tests
updated.
</objective>
