| Option | Description | Selected |

**User's choice:** "Help me reason about this. Is rejecting the first gate really the same as rejecting the second gate?"
**Notes:** Claude traced both gates. The re-scan gate asks whether to approve a changed checkpoint set. The follow-on
gate asks whether to retry or abort the stage, and any answer other than abort relaunches it. So a carried "no, needs
review first" relaunches Code at once on the rejected plan. Claude reversed its recommendation. Second round:

| Option | Description | Selected |
|--------|-------------|----------|
| Ask again (Recommended) | Rejection recorded; follow-on gate has its own id and waits | ✓ |
| Keep the carry-over | Today's behaviour, made explicit | |

Correction after the choice: Claude had first said that the "Supervise preflight always returns Ok". That covers only
the unattended-launch check. The conclusion rests on reasoning about the other preflight gates, and CONTEXT.md labels
it Reasoned.
