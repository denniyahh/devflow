# Phase 50.1 Plan 14: Bound Gate Waits, Ship Claim and Close Summary

**Every CLI gate wait now accepts only its own gate id's answer and consumes it through one first-wins claim, `devflow ship` claims the same way, and every gate cleanup sets unused answers aside.**

## What this does not establish

- **The claim-error arms have no CLI test.** `run_gate_with_timeout`'s and `ship_override`'s `Err` arms were checked by reading the source. Core's `gates::tests::a_paused_consumer_cannot_claim_a_gate_that_closed_or_was_replaced` (50.1-06) pins the refusal itself; nothing here drives a claim error through a CLI consumer.
- **V-21 is a backstop, not a production race (R2-11).** Its waiter is an in-process thread. It passed 40 of 40 alone and its failing direction was run. That supports "the claim alone lets one consumer act" for this fixture, and says nothing about how often real timing would reach it.
- **`scripts/check.sh all` passed once, at `df4c973`.** The phase's earlier plans saw this command fail about one run in three on unrelated tests, so one green run is weak evidence for the suite's stability.
- **The plan's suite gate failed once, on a test this plan did not change, and passed on the rerun.** See Issues Encountered.
- **`gate_wedge_e2e`'s dry-run-sweep check was not mutation-tested.** The other two of the three changed checks were; the mutation used does not reach that one.

## Accomplishments

- `run_gate_with_timeout` opens through `Gates::open_registered`, holds the registration for the whole wait, and consumes through `Gates::claim`. `AlreadyConsumed` and any claim error finish the registration and return with no `commit(gate_pending = false)` and no `gate_resolved`.
- `wait_for_gate_response` takes the gate id and only reads. An unbound file is set aside for this gate alone, then the wait continues with the time left. A refused set-aside ends the wait and leaves the file in place.
- `ship_override` reads the live gate's keyed answer, refuses an unbound one and moves nothing, and claims before acting.
- All 13 production `Gates::cleanup` calls in the CLI became `Gates::close`. No `Gates::cleanup(` remains anywhere under `crates/devflow-cli/src`.
- `start` names each answer it set aside, on stderr.
- D-06 and D-07 now hold: a rerun's gate and a re-scan rejection's follow-on gate each get their own id and wait.
