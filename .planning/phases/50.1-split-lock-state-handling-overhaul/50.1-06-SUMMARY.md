# Phase 50.1 Plan 06: Gate Identity and Answer Binding Summary

**A gate answer now decides only the gate it names: fresh 16-hex gate ids, answers keyed and bound to them, wrong or id-less answers moved aside under names no other process can take, and a claim that can succeed only while its gate is open.**

## Accomplishments

- Gates have an identity, and an answer is stored under it and names it (D-04, D-05).
- `answer` checks the observed id under a new bounded gate lock, publishes outside it, then re-checks. A publish that lands after its gate closed is set aside by the writer itself.
- A wrong-gate, id-less, unparsable or hostile answer is moved aside, never consumed and never deleted, under a no-replace name unique across processes.
- No read moves a file. Only `open_gate` and `close` touch a whole stage.
- `close` reports every claimed answer it removes, and removes the gate file last, so a crash reports a pair twice at worst.

Its diagnostics give a likely cause: `polls: 0`, still running 237 µs later, `survivor after: GONE`. One `agent_running` call said not running and the next said running.

- Measured: reading an already-open `/proc/<pid>/status` after the reap fails with `ESRCH`. Opening it after the reap fails with `ENOENT`. A live process reads fine (control).
- Measured: Rust maps `ESRCH` to `Uncategorized` and `ENOENT` to `NotFound`.
- `running_per_status` treats only `NotFound` as gone, so that read means "cannot tell" and `kill(0)`'s answer stands.

The sequence itself is inferred, not traced. I did not fix it; it is out of scope and is logged in `deferred-items.md`. Whether it also explains 999.151 was not checked.

- **Found during:** Task 2
- **Issue:** The plan's text says the answer "was set aside". If the waiter claims it and the gate closes before the writer's re-check, the writer finds nothing to set aside: the answer was consumed.
- **Fix:** The message and doc say "set aside unless its waiter had already consumed it". No test drives that interleaving; the text alone is pinned.
- **Files modified:** `crates/devflow-core/src/gates.rs`
