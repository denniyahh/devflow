<objective>
Fix 999.166 item 2 and finish D-08 in `devflow-core`: `recover --clean` decides liveness from the supervisor socket, the
pending reservation and the gate registration instead of the per-phase lock, and the per-phase pid-lock API is deleted.

Purpose: OPERATIONS says `recover --clean` probes the supervisor socket; without `--phase` it does not, and today it can
delete a live supervisor's state between its agent's exit and its advance (999.166 item 2). With no long lock left
(50.1-16/-19/-20), the lock it relied on no longer means anything, so the probe must be explicit.
Output: `recover::phase_may_be_live` and its callers, the `.live` sweep, the lock API deletion, rewritten tests.

Review round 1 (`50.1-REVIEWS.md` @ c512ef3; see the Review Dispositions Ledger) reshapes three parts. R-07 (codex 2):
deciding liveness and then removing gate files and state as separate steps lets a `start` that reserves run B in
between get B deleted, so the decision moves under the write lock with the removals (`workflow::clear_state_if`, new
here — 50.1-04 has no decide-and-remove primitive). R-03 (pi 4): `recover` is a repair verb, so that acquisition is
bounded and names the holder. R-06 (codex 1, pi 5) from 50.1-05's no-replace take: the `.live` age bound protects
nothing any more and goes; abandoned `.waiter` files and orphan hold temps are swept too. pi S3: `recover` lists the
set-aside answers it keeps, so the docs (50.1-25) can say it reports them.
</objective>
