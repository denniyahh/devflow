<objective>
Finish the waiter side of the gate protocol in `devflow-core`: registration by a held lock, taken before the gate file
is published (D-04), a binding,
quarantining wait (D-05) with 999.166 items 4 and 7 fixed in its loop (D-13), a test-only pre-answer for tests that must
answer a gate before it opens, and a temporary bridge so the CLI's unkeyed flow keeps working while 50.1-12/-13/-14 move
it over.

Purpose: once no gate wait holds the per-phase lock (D-08), `gate respond`, `gate sweep` and `stop` need another way to
tell a live waiter (`lock::holder_status` today). Foreground waits have no supervisor socket, so the socket cannot be
the answer (D-04, agy lane). A writer reads that registration the moment it sees a gate file, so the registration
must exist first: publishing and then registering leaves a gap in which `devflow gate approve|reject`, `stop`'s gate
arm or `gate sweep` refuses a live waiter's gate with "no registered waiter" (an operator-facing race, not a test flake).
Output: registration, `open_registered`, `await_answer`, the shared loop, the pre-answer seam and helpers, the
answer-publish hook, the bridge — all in core.
</objective>
