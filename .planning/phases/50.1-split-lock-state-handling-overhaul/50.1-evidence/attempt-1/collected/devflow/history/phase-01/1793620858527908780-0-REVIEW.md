## Warnings

### WR-01: Constraint stated as fact in code is unenforced; tests accept 30 and 300

**File:** `probe/budget.py:3-5`, `tests/test_budget.py:5,10-12`
**Issue:** The comment says the budget must cover the 90-second failover and stay under the 240-second pager. The tests only assert membership in `(30, 120, 300)`. In a throwaway copy, constants of 30 and 300 both exit 0 with `OK`, while 45, 120.0, True, -120 and 0 fail. A change to 300, which the comment says is wrong, would ship green. The plan's must-haves only ask for membership, so this is a gap in the plan rather than an executor fault.
**Fix:** Assert the bounds in a test, with their source noted, and do not pin 120 until a human confirms it:
```python
FAILOVER_SECS, PAGER_SECS = 90, 240  # plan figures, unverified
self.assertGreaterEqual(DEFAULT_RETRY_BUDGET_SECS, FAILOVER_SECS)
self.assertLess(DEFAULT_RETRY_BUDGET_SECS, PAGER_SECS)
```
The plan forbids editing `tests/test_budget.py`, so this needs a follow-up plan or a new test file.

### WR-02: Unverified, agent-chosen value documented as settled

**File:** `probe/budget.py:3-5`; gate at `.planning/phases/01-retry-budget/01-01-PLAN.md:10,29`
**Issue:** Plan Task 1 is `gate="blocking-human"` with `autonomous: false`. No human answered it, and an agent chose 120. `01-UAT.md` shows `result: [pending]`, with 0 passed and 1 pending. The planning documents say this plainly, but the source comment does not: it states both figures as fact and gives no sign that the value is provisional, and it is the only record a later maintainer is likely to read. The reasoning holds on the plan's figures, since 30 is below 90, 300 is above 240, and only 120 fits. The figures themselves are unchecked.
**Fix:** A human who knows the real upstream and pager must answer UAT test 1 before merge. Until then, mark the comment provisional:
```python
# PROVISIONAL: agent-chosen, awaiting human confirmation (see 01-UAT.md).
# Plan figures, not independently verified: must cover a 90 s upstream failover
# and stay under the 240 s on-call pager escalation.
```

### WR-07: The deadline test leaves realistic mutants alive

**File:** `tests/test_budget.py:12`
**Issue:** The single sample `deadline_after(10.0)` does not catch `int(start_secs) + DEFAULT_RETRY_BUDGET_SECS`, `10.0 + DEFAULT_RETRY_BUDGET_SECS` or a hard-coded `130.0`. All three exit 0. The `int()` mutant is the most realistic, because it silently drops sub-second precision. Twelve of the 15 mutants tried were killed.
**Fix:** In a new test file, sample several non-integral starts, then confirm the three mutants fail:
```python
for start in (0.0, 0.25, 1234.5):
    self.assertEqual(deadline_after(start) - start, DEFAULT_RETRY_BUDGET_SECS)
```

### WR-08: A NaN start time removes the retry bound

**File:** `probe/budget.py:8-10`
**Issue:** `deadline_after(float('nan'))` returns `nan`, and both `nan < x` and `nan >= x` are False. A loop that stops on `now >= deadline` would therefore never stop. `deadline_after(True)` returns 121. No caller exists yet, so the impact is latent. A clock source does not normally return NaN, so this matters only if the value comes from external data.
**Fix:** Reject non-finite input with `math.isfinite`, or state the requirement in the docstring when the first caller is written.

### WR-09: Runtime state is not reliably kept out of git

**File:** `.gitignore:1-4`, `.planning/state.json`, `.planning/milestone.lock`
**Issue:** `.planning/state.json` is untracked and matches no ignore rule, and `git add -n .planning` would stage it. Its content is harmless today: a command hint and a timestamp. `.planning/milestone.lock` holds a Claude Code session id and a PID, and is hidden only by `.git/info/exclude`, which a fresh clone does not have. Neither file is in any branch commit.
**Fix:** Add `.planning/state.json` and `.planning/milestone.lock` to the tracked `.gitignore`, or track `state.json` on purpose after reviewing what it holds.

### WR-10: Zero discovered tests only fail on Python 3.12 or newer, and no interpreter is pinned

**File:** repository as a whole; verify command at `01-01-PLAN.md:67`
**Issue:** With an empty `tests/`, a misnamed file or a class that is not a `TestCase`, the command exited 5 on Python 3.15.2. That exit status was added in 3.12, so older interpreters would exit 0, and nothing pins the version. An all-skipped suite exits 0 on every version, though no test skips today. The repository has no CI, so these runs are manual.
**Fix:** Pin the interpreter (for example `.python-version`) to 3.12 or newer, and assert the test count if the command is ever scripted.

## Info

### IN-01: `deadline_after` does not say which clock `start_secs` is on

**File:** `probe/budget.py:8-10`
**Issue:** The result is only meaningful against the same clock as the input. Mixing `time.monotonic()` and `time.time()` gives a silently wrong deadline, and wall-clock time can step.
**Fix:** State in the docstring that both values must come from one clock, and recommend `time.monotonic()`.
