## Warnings

### WR-01: Plan's blocking human decision gate was resolved without a human

**File:** `probe/budget.py:5`
**Issue:** Task 1 in `01-01-PLAN.md` is `checkpoint:decision gate="blocking-human"` and the plan has `autonomous: false`. The SUMMARY (key-decisions, Decisions Made, Deviations) says no human chose 120. The orchestrator did, under authority DevFlow granted it. The SUMMARY also says the `gsd-executor` refused to accept the choice from another agent. The constant therefore ships as a decision record that bypassed the plan's explicit human gate. I could not verify the claimed authorization: no record of it exists in `.planning/config.json`, and `.planning/state.json` has no matching entry. The value is valid, since it satisfies both stated constraints (above 90 s, below 240 s), but it is an unratified product choice (worker-slot cost of up to 2 min per stalled call).
**Fix:** A human should confirm or override 120 before the phase is treated as verified. Until then, record the phase as "decision pending human confirmation", not "complete". If 120 is overridden, change only `probe/budget.py:5` to 30 or 300. If it is confirmed, add the confirmation to the SUMMARY `key-decisions`.

### WR-02: Nothing pins the chosen value or the constraints that justify it

**File:** `probe/budget.py:3-5` (with `tests/test_budget.py:9-11`, context only)
**Issue:** The only guard on the constant is `assertIn(value, (30, 120, 300))`. The plan's constraints (budget above the 90 s failover and below the 240 s pager threshold) exist only in a prose comment and in the SUMMARY. The SUMMARY records that 30 and 300 pass the suite. Both violate the stated constraints, so a one-character edit to the wrong option ships green. The suite cannot distinguish a correct constant from an incorrect one.
**Fix:** Encode the constraints so a regression fails. For example, add to the tests (or as module constants):
```python
UPSTREAM_FAILOVER_SECS = 90
PAGER_ESCALATION_SECS = 240

def test_budget_covers_failover_and_precedes_pager(self) -> None:
    self.assertGreater(DEFAULT_RETRY_BUDGET_SECS, UPSTREAM_FAILOVER_SECS)
    self.assertLess(DEFAULT_RETRY_BUDGET_SECS, PAGER_ESCALATION_SECS)
```
The plan forbids editing `tests/test_budget.py` in this plan, so this belongs in a follow-up plan. Note that the 90 s and 240 s figures are unverified plan inputs.

## Info

### IN-01: Comment hardcodes unverified external figures

**File:** `probe/budget.py:3-4`
**Issue:** The comment states the upstream failover is 90 s and the pager escalates at 240 s. These are copied from the plan, and the SUMMARY admits they were not independently checked. If either external value changes, the comment goes stale silently. "Reports before the pager" is also true only if the retry loop reports at the deadline, and `deadline_after` does not account for an in-flight call that outlasts the deadline.
**Fix:** Name the source of each figure in the comment (the upstream doc or pager policy). Alternatively, move both to named constants (see WR-02) so the relationship is checked.

### IN-02: `deadline_after` does not state its clock domain or reject non-finite input

**File:** `probe/budget.py:8-10`
**Issue:** The docstring does not say whether `start_secs` comes from `time.monotonic()` or `time.time()`. Mixing the two produces a deadline in the wrong time base. I ran it: `deadline_after(float('nan'))` returns `nan`, `deadline_after(float('inf'))` returns `inf`, and `deadline_after(True)` returns `121`. A NaN deadline makes any `now >= deadline` check always false, so a retry loop would never stop. No callers exist yet, so this is latent, not live.
**Fix:** Document the clock (prefer "monotonic seconds") in the docstring. Optionally guard with `math.isfinite(start_secs)` and raise `ValueError`.
