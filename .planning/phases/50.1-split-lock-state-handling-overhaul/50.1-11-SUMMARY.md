## What this does not establish

Read this before relying on the plan.

- **`cargo semver-checks` run the plan's way does not show the R-10 break.** The plain command enables `test-support` by default, so `save_state` still looks present and is not in its list. It only appears with `--default-features`. 50.1-28 should use that flag for its semver list, or it will miss this removal. See the Semver section.
- **`stop` can still block without limit on a stopped write-lock holder.** `persist_stopped_state` uses the blocking `update_state_with`, as this plan specifies. The doc on `update_state_with_within` says `stop` must not hang this way. 50.1-20 (R-03) closes it, and until then this is a new way for `stop` to wait. Its long-lock contention handling is unchanged.
- **Two decisions still read the caller's copy.** `run_preflight`'s retry ceiling is checked before its commit, and `handle_validate_outcome`'s `baseline_absent` is read before the counter commit. Each could see an older value than the file for the first read after a load. I left both: the plan names only the infra ceiling, and a search of production assignments finds these fields written only by these same two functions. That search does not show that two such calls can never overlap. No test covers either case.
- **The scans are text scans.** They cut each file at its first line that is exactly `mod tests {`. A test module with any other name would be scanned as production and fail loudly, which is the safe direction. A `save_state` reached through a `use … as` rename is the name still on the `use` line, so it is caught there; a macro that assembles the name is not.
- **`start`'s create still replaces whatever is on disk**, under the lock. The race between `start`'s check and that write stays open until 50.1-16.
- **The two lock-ordering tests can pass falsely on a slow machine, never fail falsely.** The `stop` and `start` tests give the blocked writer 200 ms before releasing the holder. If a regressed, unlocked form took longer than that to reach its write, it would run after the holder and the test would pass. With the lock in place they pass at any speed. Each RED was seen once, so this is a sample, not a proof of every interleaving.
- **`scripts/check-in-container.sh` was not run.** The plan does not ask for it.
