### `crates/devflow-core/src/durable.rs` (NEW; utility, file-I/O) — D-09

**Analog 1, exclusive publish with an fsynced temp:** `crates/devflow-core/src/lock.rs::publish_lock` (L149-185).
This is the only existing writer that already fsyncs its temp before `hard_link`; copy its shape and add the
directory fsync after a successful link.
```rust
fn publish_lock(path: &Path, before_publish: impl FnOnce()) -> io::Result<LockPublication> {
    let (tmp, mut file) =
        crate::workflow::create_unique_temp(path, std::process::id(), &LOCK_TEMP_SEQ)?;
    if let Err(error) = file
        .write_all(lock_contents().as_bytes())
        .and_then(|()| file.sync_all())
    {
        drop(file);
        let _ = fs::remove_file(&tmp);
        return Err(error);
    }
    drop(file);

    before_publish();
    let publish = fs::hard_link(&tmp, path);
    let cleanup = fs::remove_file(&tmp);
    match publish {
        Ok(()) => { /* warn if cleanup failed */ Ok(LockPublication::Published) }
        Err(error) if error.kind() == io::ErrorKind::AlreadyExists => {
            let _ = cleanup;
            Ok(LockPublication::AlreadyExists)
        }
        Err(error) => { let _ = cleanup; Err(error) }
    }
}
```
Note the `before_publish: impl FnOnce()` seam: reuse it as the test hook for "crash between temp fsync and link".

**Analog 2, replace (rename):** `crates/devflow-core/src/workflow.rs::write_state_atomic` (L239-255) and the
identical `gates.rs::write_atomic` (L573-589). Both lack `sync_all` and the directory fsync; `replace_durably` is this
body with `file.sync_all()` before `drop(file)` and `File::open(dir)?.sync_all()` after the rename.
```rust
fn write_state_atomic(path: &Path, contents: &str) -> Result<(), WorkflowError> {
    if let Some(parent) = path.parent() {
        ensure_devflow_dir(parent)?;
    }
    let (tmp, mut file) = create_unique_temp_for_current_process(path)?;
    if let Err(error) = file.write_all(contents.as_bytes()) {
        drop(file);
        let _ = std::fs::remove_file(&tmp);
        return Err(error.into());
    }
    drop(file);
    if let Err(error) = std::fs::rename(&tmp, path) {
        let _ = std::fs::remove_file(&tmp);
        return Err(error.into());
    }
    Ok(())
}
```

**Temp naming to reuse (do not invent a new shape):** `workflow.rs::create_unique_temp(target, pid, &AtomicU64)`
(`pub(crate)`, L222-235), shape `.{name}.{pid}.{sequence}.tmp` (`unique_temp_path_with`, L205-208). Every cleanup
sweep (`clear_state_with_partial_result_impl` L385-395, `Gates::cleanup_with_partial_result` L396-418) matches on that
prefix/suffix, so `durable.rs` must keep it.

**Remove analog:** `workflow.rs::clear_state_with_partial_result_impl` (L359-410) and
`gates.rs::cleanup_with_partial_result` (L373-420) — the `(removed: bool, Result)` partial-result pairing is the
convention; `remove_durably` keeps returning enough for callers to report partial removal, then fsyncs the directory.

**Error type:** return `std::io::Result<_>`, as `ensure_devflow_dir` does (L104-109 doc comment): every module error
enum (`WorkflowError`, `GateError`, `LockError`, `MonitorError`) has `Io(#[from] std::io::Error)`, so `?` converts
with no signature churn. The exclusive publish should return a tri-state (published / already-exists / error), like
`LockPublication` (L143-146), so `gates.rs` can still map `AlreadyExists` to `GateError::AlreadyResponded`.

**Directory creation (Pitfall 11):** `ensure_devflow_dir` (L117-137) uses `create_dir_all` and writes `.gitignore`
`create_new`; when it creates a directory, fsync the parent too.

**Source-scan test (criterion 3, D-09):** copy `pipeline_launch.rs` test helpers `non_test_code_lines` (L9106-9112),
`item_lines` (L9117-9127) and the violation-vector shape of `launch_record_clear_violations` (L9142-9166) with its
planted-source test `the_supervisor_record_is_cleared_only_on_launch_failure_paths` (L9172-9237):

### `crates/devflow-core/src/workflow.rs` (storage, CRUD under lock) — D-08, D-11

**Write-flock analog:** `crates/devflow-core/src/lock.rs::coordination_path` / `acquire_coordination` (L194-213). A
never-replaced, never-removed sidecar inode, `create(true).truncate(false)`, std `File::try_lock`:
```rust
/// The advisory coordination inode is never replaced or removed by DevFlow.
fn coordination_path(path: &Path) -> PathBuf {
    let name = path.file_name().unwrap_or_default().to_string_lossy();
    path.with_file_name(format!(".{name}.coord"))
}

fn acquire_coordination(path: &Path) -> Result<File, LockError> {
    let coordination = OpenOptions::new()
        .read(true).write(true).create(true).truncate(false)
        .open(coordination_path(path))?;
    match coordination.try_lock() {
        Ok(()) => Ok(coordination),
        Err(TryLockError::WouldBlock) => Err(contended(path.to_path_buf())),
        Err(TryLockError::Error(error)) => Err(error.into()),
    }
}
```
For `update_state` use the blocking `File::lock()` (not `try_lock`) on a distinct name such as `.state-NN.lock`
`[ASSUMED]`; never lock `state-NN.json` itself (it is replaced by rename). The name must not start with `lock-`
(`LOCK_FILE_PREFIX`, `lock.rs` L477) or `recover`'s stale-lock sweep deletes it. Never call `unlock()` on any
handle; dropping the `File` releases it. The fork-inheritance hazard is documented at `lock.rs` L215-225
(`acquire_coordination_settling`): no spawn inside the closure.

**Re-read-under-lock analog:** `crates/devflow-cli/src/pipeline_launch.rs::record_supervisor_stop` (L1428-1471). It is
the one existing writer that checks, takes the lock, re-loads, re-checks, then writes only two fields:
```rust
let names_this_launch = |state: &State| {
    state.supervisor.as_ref().is_some_and(|record| record.launch_id == launch_id)
};
// ... pre-check outside the lock ...
let _lock = match lock::acquire_blocking(project_root, phase, SUPERVISOR_STOP_WAIT) { ... };
let mut state = match workflow::load_state(project_root, phase) {
    Ok(state) if names_this_launch(&state) => state,
    Ok(_) => { info!("phase {phase}: launch {launch_id} was superseded before its stop was recorded"); return; }
    Err(err) => return not_recorded(&format!("the state does not load ({err})")),
};
state.stopped = true;
state.stop_reason = Some(SUPERVISOR_STOP_REASON.to_string());
if let Err(err) = workflow::save_state(&state) { ... }
```
`update_state`/`update_owned_state` `[ASSUMED]` generalise this: lock → `load_state` → closure sets only its delta →
`replace_durably` → drop lock → return the committed `State`. `names_this_launch` becomes the owner-fence check
(D-03), extended to accept "my id is `pending`" only during the bounded promotion wait (D-15, Pitfall 5).

**Error enum:** `WorkflowError` is `#[non_exhaustive]` (L18-39), so adding a `NotOwner { recorded, ours }` variant
`[ASSUMED]` is additive.

**Create-if-absent (Pitfall 8):** `start` currently saves fresh state blindly (`commands.rs` `start`, ~L700). The new
create path refuses an existing live run inside the same lock; `load_state`'s `MissingState(path)` (L262-264) is the

**D-11 deletion set:** `migrate_legacy_state` (L156-185), `legacy_state_path` (L148-150), its calls in `load_state`
(L259) and `list_states` (L275), the legacy branch of `clear_state_with_partial_result_impl` (L373-384),
