<objective>
Finish D-08 in the CLI: no command takes the per-phase lock, and every "is a waiter live" question is answered by the
gate registration (D-04) instead of `lock::holder_status`.

Purpose: since 50.1-19 no gate wait holds the long lock, so the five `holder_status` readers would report no waiter for a
live one (`gate respond` refusing a legitimate answer, `gate sweep` never reaping, `stop` never answering). This plan
moves them to the registration, removes the last lock takers and rewrites the lock-premised integration tests.
`stop`'s third arm is not retired here: 50.1-29 already retargeted it to D-17's per-phase holder file (CONTEXT D-17,
operator 2026-10-24), and this plan keeps it. The lock API itself is deleted in 50.1-21.
Output: registration-based writers and doctor fact, lock-free `ship_override`/`persist_stopped_state`, the new stray
safety set, and rewritten `stop_e2e`/`gate_sweep_e2e`/`gate_wedge_e2e` and `commands.rs` lock-premised tests.

Review round 1 (`50.1-REVIEWS.md` @ c512ef3) and the planners' hand-offs add four things to `stop` here (see the Review
Dispositions Ledger): R-03's bounded state write with a SIGSTOPped-holder fixture; Planner C1's MUST-DO that the gate
arm declines a gate whose answer is already claimed, so a finalizing `devflow ship` is reached through the D-17 holder
arm (50.1-22's D-18 fixture fails otherwise); B's `GateLockTimeout` mapping in every CLI gate writer; and a fix for the
pre-existing window C1 flagged, in which a signalled holder that published a supervisor before releasing let `stop`
mark the run `stopped` beside that live supervisor.
</objective>
