## Accomplishments

- A pending supervisor can now be probed before its socket exists. No caller uses this yet; the launch path arrives in 50.1-07.

## Readings the Plan Asked For

- **Negative control, fd 3:** the dup2-only variant reads `Abandoned` right after the parent's drop (asserted, and the test passes). With the `raw == 3` branch removed from the real `pass_to_child`, the main half fails: `the child at fd 3 must hold the lock`, `left: Abandoned, right: Live`.
- **Harness at fd 3:** under nextest fd 3 was free (`fd 3 was free`, measured with a temporary print), so the fixture moved nothing. Run directly with `3</dev/null`, both tests printed `fd 3 was open; moved aside to 64` and passed, so the moved-aside path works too.
- **Exclusive probe:** with `probe` switched to `try_lock`, part (a) fails: `a probe must not read another probe as live`, `left: Live, right: Abandoned`.
- **R-01 cursor rewrite:** with `adopt_inherited` rewriting by `set_len(0)` plus a cursor `write_all`, the main half fails with 15 leading NUL bytes, and `live_holder` reads `Err(InvalidData)`, `unreadable record: "\0\0...\01452817 756953\n"`.
- **`.write_all(` check:** `liveness::tests::no_code_writes_a_hold_record_through_the_cursor` scans the non-test, non-comment lines and finds none. It is a test rather than a shell count, per CLAUDE.md. A planted production line fails it, naming that line.
- **Create-then-lock control:** ends `probe == Missing` with its lock still held, because the sweep unlinked the name. Asserted in `a_hold_is_published_only_once_it_is_held`.
- **Orphan sweep's returned list:** exactly `[.a.live.<gone>.0.hold-tmp]`.
- **`PROBE_RACE_WAIT` residual (REVIEWS.md):** 50 ms under load can make a take report `WouldBlock` while only a probe holds the lock. A spurious refusal fails safe, and a temp is never probed, so `Hold::take` itself does not meet this. Its first real exposure is 50.1-29's `claim_phase_holder`. The test's part (b) retries up to five times for the same reason; an implementation that does not wait fails every attempt.

### Notes

**2. `hold_at_fd_3` keeps a hold already at fd 3.** The plan says `fcntl(raw, F_DUPFD_CLOEXEC, 3)` returns 3 because 3 is free. But with 3 free, the take's own temp open lands there, and that call would return another number. The established state the plan asserts (`as_raw_fd() == 3`, close-on-exec set) is unchanged and still asserted.

**3. More tests run in their own process than the plan names.** Any test reading a lock right after its release does, because under `cargo test` another thread's fork holds a duplicate until its exec. These children get the real `PATH` through `run_test_in_child`'s `extra_env`, so `sleep` resolves.

**4. Tests beyond the plan's list.** `no_code_writes_a_hold_record_through_the_cursor` (the `.write_all(` acceptance check as a test), `a_take_never_replaces_an_existing_name`, `a_take_whose_temp_vanished_publishes_nothing` and `a_hold_file_is_owner_only` cover behaviour the plan specifies without naming a test. `b1a5d4c` adds `a_take_skips_a_temp_name_already_taken`, `a_take_in_a_missing_directory_is_an_error`, `a_probe_reports_an_error_other_than_absence`, `live_holder_reports_a_record_it_cannot_read`, `a_handoff_that_cannot_place_the_descriptor_fails_the_spawn`, `adopting_a_close_on_exec_descriptor_keeps_it_close_on_exec` and `an_unreadable_directory_is_an_error_not_an_empty_sweep`, plus five planted names in the orphan test beyond the plan's six: four in `e5feef8` and a fifth in `b1a5d4c`.
