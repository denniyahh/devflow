<objective>
Give gates an identity and bind answers to it in `devflow-core` (D-04, D-05): fresh gate ids, keyed answer storage,
observed-id writers with a publish re-check, quarantine instead of consumption or deletion, an exclusive consumption
claim, and a close that never deletes an unconsumed answer.

Purpose: today there is one response path per phase and stage (`gates.rs` `response_path` ~L131), `poll_response` takes
any file on its first read, and `respond` has no re-check after its hard-link publish — the AR-48-04 stale-answer
hazard. This plan adds the identity-bound API alongside the unkeyed one; the waiter half (registration, `await_answer`)
is 50.1-08, the CLI moves onto both in 50.1-13/-14, and 50.1-15 deletes the unkeyed API. No CLI file changes here.
Output: the new `Gates` API and its tests in `gates.rs`.
</objective>
