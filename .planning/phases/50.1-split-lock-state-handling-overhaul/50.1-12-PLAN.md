<objective>
Move the CLI's unit tests off the legacy unkeyed answer slot before the waiter stops reading it, so 50.1-14's
production switch is not also a mass test edit.

Purpose: dozens of tests in `pipeline_outcomes.rs`, `pipeline_gate.rs`, `preflight.rs`, `pipeline_launch.rs` and
`commands.rs` write `NN-{stage}.response.json` before the code under test opens its gate, relying on exactly the
"a leftover answer decides the next gate" behaviour that D-05 and D-06 remove. They test what an answer leads to; the
pre-answer seam (50.1-08) gives them that without the hazard. This is test-only and mechanical; the classification
rule below decides each usage.
Output: the five test modules migrated; a SUMMARY list of the stale-answer tests 50.1-14 rewrites.
</objective>

Classification rule for each test usage of `Gates::response_path(`, `Gates::ack_path(`, `Gates::respond(`, a raw
`std::fs::write` of response JSON, or `poll_response`:
1. **Pre-answer** — written before the code under test opens the gate it is meant to answer (e.g. `pipeline_outcomes.rs`
   ~L1397, ~L1700, ~L1753, ~L2070, ~L2119, ~L2163): replace with `test_support::preanswer_gate(root, phase, stage,
   &response)`, parsing the existing JSON literal into a `GateResponse` with `serde_json::from_str` so the bytes the test
   meant are unchanged.
2. **Answer an open gate** — written after the gate file exists (often from a thread that waits for `gate_path`): use
   `test_support::answer_open_gate(root, phase, stage, &response)`.
3. **After-the-fact existence check** — `!Gates::response_path(..).exists()` or `.exists()`: use
   `test_support::gate_answer_files(root, phase, stage).is_empty()` (or its negation); an ack check becomes a check that
   no claim/ack of either layout remains, through a listing of `Gates::dir` filtered by the stage prefix.
4. **Stale-answer subject** — the test's point is how a leftover answer behaves: leave it, list it in the SUMMARY.
Count the usages per file before and after (from `rg -n` output, not memory) and put both counts in the SUMMARY.
</context>
