The held reservation asserts the launch id, `devflow stop --phase N`, the bytes and no mark. That text differs from the plan's. I changed no production path to match it. VALIDATION V-88's wording may need the same note.

**2. `stop_marks_stopped_after_...`'s control holds C's liveness file.** Unheld, the pending branch clears C and the run is correctly marked. Held, it waits 15 s, then the write refuses as the plan expects.
