# Phase 50.1 Plan 13: Bind the CLI's Gate Writers to the Observed Gate Id Summary

**`gate approve`, `gate reject`, `gate sweep` and `stop` now publish through `Gates::answer` / `Gates::reap_answer` for the gate id they saw, so a decision about one gate can no longer land on the next; the operator can see the id in `gate list` and `gate show` and pass it back with `--gate-id`.**

## Needs Attention First

**`devflow ship` cannot read a Ship approval from `gate approve` until 50.1-14.** This plan moved the writer to the keyed answer and `ship_override` still reads the unkeyed one. I probed it with a temporary test, since removed: approve, then `ship_override`, refuses with "no Ship gate response written yet". It fails closed and nothing is finalized, but the wording is wrong for that one wave. 50.1-14 already rewrites that read. No suite catches this, so a green suite here says nothing about it. It is logged in `deferred-items.md`.

- **Found during:** Task 1
- **Issue:** The plan prints the id from the gate file, which `list_open` does not validate, so a crafted file could put control characters on the terminal. `context` is already sanitized for this reason.
- **Fix:** `printable_gate_id` prints `-` for anything `is_gate_id` refuses.
- **Files modified:** `crates/devflow-cli/src/commands.rs`

**3. [Rule 1 - Bug] The sweep no longer says "already answered" for errors that are not that**
- **Found during:** Task 2
- **Issue:** Every reap error printed "already answered". With `reap_answer` that would describe a set-aside or a lock timeout falsely.
- **Fix:** That wording stays for `AlreadyResponded` and `NoOpenGate`; other errors print the error itself.
- **Files modified:** `crates/devflow-cli/src/commands.rs`
- **Verification:** The `AlreadyResponded` arm through `gate_sweep_skips_already_responded_gate_without_clobbering`. The other arm is not exercised.
- **Committed in:** `32eae35`

**Small wording changes, not asked for:** `stop`'s abort message says "awaiting a live waiter", since a registered waiter holds no lock. `gate list`'s footer names `--gate-id`.
