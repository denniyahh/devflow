## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust built-in test harness (rustc 1.97.1) run through cargo-nextest 0.9.148; TDD mode on |
| **Config file** | `scripts/check.sh`, `rust-toolchain.toml`, workspace `Cargo.toml` |
| **Quick run command** | `cargo nextest run -p devflow-core --lib --no-tests=fail` then `cargo nextest run -p devflow --bin devflow --no-tests=fail` |
| **Full suite command** | `scripts/check.sh all` (then `scripts/check-in-container.sh` before push) |
| **Estimated runtime** | quick: tens of seconds; full: several minutes (container 2–9 min cold) |

**Exact-name rule:** run each named test as its own command, chained with `&&`:
`cargo nextest run -p <pkg> <--lib | --bin devflow | --test T> --no-tests=fail -E 'test(=<exact name>)'`.
With `--no-tests=fail` a name that matches nothing exits 4; under `cargo test`, or with two names in one filter
(`-E 'test(=a) | test(=b)'`), a wrong name exits 0. Lib and bin unit tests take the full module path
(`durable::tests::…`); integration tests (`--test T`) take the bare fn name. The CLI package is `devflow`
(binary-only: `--bin devflow`, never `--lib`). A structural check ("no X left") is a Rust source-scan test run by
name, never an `rg -c` count. A map row's command follows from its test path: `commands::`, `pipeline_gate::`,
`pipeline_launch::` and `pipeline_outcomes::` run under `-p devflow --bin devflow`; `durable::`, `gates::`,
`liveness::`, `monitor::`, `recover::`, `supervisor::` and `workflow::` under `-p devflow-core --lib`; `stop_e2e::name`,
`supervisor_e2e::name`, `doctor_json_e2e::name`, `pending_supervisor_e2e::name`, `gate_sweep_e2e::name` and
`start_lock_e2e::name` are `-p devflow --test stop_e2e` (or that target) with the bare `name`. V-78 is a build
gate and is written out in full.

## Sampling Rate

- **After every task commit:** the task's named test(s), one `cargo nextest … -E 'test(=…)'` per test, chained with `&&`
- **After every plan wave:** `cargo nextest run -p devflow-core --lib --no-tests=fail && cargo nextest run -p devflow --bin devflow --no-tests=fail`, plus the integration tests the wave touched
- **Before `/gsd-verify-work`:** `scripts/check.sh all` and `scripts/check-in-container.sh` green; `cargo semver-checks check-release -p devflow-core` run with every break listed
- **Max feedback latency:** one named test, seconds (up to about 12 s for the long-by-design rows below); a wave suite, minutes
- **Long by design** (the duration measures a timeout constant, not the work, so a slow run of one of these is its bound,
  not a regression): V-59 and V-66 take 10–12 s (`WRITE_LOCK_REPAIR_WAIT`, 10 s, plus at most 2 s); V-47 takes 5–7 s
  and V-60 at least 5 s (`GATE_LOCK_WAIT`); V-27 at least `PROMOTION_WAIT` (5 s under `cfg(test)`, 15 s in a release
  build) and V-58 at least `PROMOTION_WAIT` + 2 s; V-50 and V-56 at least 3.5 s (they wait out the waiter's backoff reads); V-85, V-87 and V-91's timeout case at least 5 s (`GATE_LOCK_WAIT`, round 2); V-117 about 6 s (`GATE_LOCK_WAIT` + 1 s)
