### Round 4 findings

Real, introduced by this phase:
- `recover --clean` over an unloadable state does not check held launch liveness files (`recover.rs:717-719`), and `start` over a missing state skips its liveness scan (`commands.rs:950`). So a supervisor that is stuck before publishing (launcher dead, state unloadable) can be cleaned away and a second one launched beside it. The refusal at `commands.rs:1046-1051` itself suggests `recover --clean`. Needs three faults at once; Codex said High, the check says Low to Medium. Fixed in `60b8278`: both refuse while a held launch lock is recorded by no other phase's state, naming its holder pid.
- `stop` against an unpublished pending supervisor whose launcher is dead fails the same way every time (`commands.rs:3060-3068` probes the foreground holder, which a supervisor never holds), and its "run stop again" advice never works. Only a stuck child (SIGSTOP or D-state) reaches it. Fixed in `60b8278`: `stop` still never signals an unpublished launch, but now names the holder pid and the manual route.
- A failed directory fsync after the ack hard link succeeds (`durable.rs:103-108`) returns an error, and the caller reports "nothing was consumed" (`pipeline_gate.rs:657-663`, `:926-928`) while the ack stays on disk; a later `ship` gets `AlreadyConsumed`. Fixed in `3fec65f`: under the gate lock the ack is withdrawn on that failure, so the claim can be retried.
- `logs --follow` (`5ec18d4`, `commands.rs:4409-4435`) never ends if the state is already gone at its first poll and no exit file exists: `saw_state` starts false and is set only after the first 500 ms sleep. Both lanes found it. Fixed in `8e815f5`: no state at any poll ends the follow. Still follows until Ctrl-C while an orphaned pending supervisor's state stays on disk, as OPERATIONS.md documents.

Real, already in `ee6ec79` (backlog, not fixed here):
- A `yes_ship` revoke written between the advance's state load and the Ship gate answer is ignored (`pipeline_outcomes.rs:852` builds the approval from the in-memory copy; `pipeline_gate.rs:602-604` writes it unchecked). A revoke while the Ship agent runs is still honoured. 999.178.
- `SuccessorAlreadyEnded` falls through to a `stage_launched` event and a "launched" line for a supervisor already gone (`pipeline_launch.rs:2195-2248`). Output only; the state is right. 999.179.
- A Validate gate approved to Ship is not closed (`pipeline_outcomes.rs:556`, `:742-745`), unlike the failure gate at `:927-929`. Its files stay until finalization. Whether `status` shows it as open was not checked. 999.180.

Not defects:
- A pending spawn failure leaving `pending_supervisor` set: `record_failed_launch` clears it (`pipeline_launch.rs:2166`), and every reader treats an unheld record as abandoned.
- An orphaned pending agent that exits before the promotion deadline leaves its group's leftovers running: accepted on purpose by plan 19's rule R-13 (`50.1-19-PLAN.md:37`), as for every completed agent.

`5ec18d4` itself had no outside review before round 4. Each round found something, so a clean later round would not show none remain.
