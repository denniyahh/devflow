# Phase 50.1 — One Live Attempt and its Fault Arm (D-12)

This runbook extends `50-addressable-monitor-liveness/50-RUNBOOK.md`; where a section below says "as Phase 50", follow
that section with the names in "Before every attempt". Where Phase 49 or Phase 50 text says a waiter holds the per-phase
lock, or reads a monitor pid, that is history: 50.1 removed both. A waiter is the holder of a gate's registration, and
`devflow doctor --json`'s `reconciliation[].gate_waiter` reports it.

## What an attempt is

One attempt is the fault arm, then one launch to Ship, both on one binary built from `feature/phase-50.1` HEAD. It is
the 50.1-27 checkpoint. The run uses Phase 49's rig (`scripts/scratch-dogfood-repo.sh --live-payload` through
`launch-attempt.sh`), `--agent claude`, the payload's seeded `blocking-human` checkpoint and `--yes-ship`. The rig's unit
names stay `p49-a<N>-*`.

The operator performs the attempt. The orchestrating session performs it only under a written delegation recorded in
this section before the attempt starts, and then from its main session, never from a subagent: the run is owned by
systemd user units, and a subagent's turn would end while the attempt is live, leaving its gates unanswered.

**Delegation:** none recorded.

While the run is live, perform no manual git operation against its project tree. Capture, do not narrate: the tools keep
the original outputs. A stall or failure is a result; preserve each attempt's record and never replace it with a retry.

The live run uses the operator's real DevFlow cache (`~/.cache/devflow`). Only the fault arm uses a private cache.

## Failure handling (49 D-10, 49 D-11, 50 D-18, carried unchanged)

- Full attempts are capped at 3. Only an attempt that ends without reaching Ship counts against the cap. The fault arm
  never counts.
- The attempt is judged afterwards by `check-supervisor-evidence.sh --attempt-gate "$P501" --current-source`. Only
  `verdict=shipped` or `verdict=cap_reached` closes the checkpoint.
- A blocking defect is fixed in-phase and the attempt repeated on a rebuilt binary. A non-blocking defect goes to the
  backlog as a ROADMAP.md `999.x` entry.
- Every attempt rebuilds the binary and records its identity; the fault arm runs on that pinned binary, never on another
  build.
- Evidence enters the repository only through `sanitize-evidence.py`.
- A gate other than Define and Code, a departure from this runbook, or a credential, auth or `gh` scope problem goes back
  to the operator before going on.
- Work stays within GSD's confines: no hand-made SUMMARY, no edited state.

## Before every attempt

Open a plain terminal in this phase's worktree. The private API-key file and configured Claude apiKeyHelper must remain
available; never paste the key into the project, evidence or terminal history.

```bash
cd "$HOME/Github/devflow/.worktrees/phase-50.1"
W=$(git rev-parse --show-toplevel)
T49="$W/.planning/phases/49-live-unattended-run-the-milestone-s-instrument/tools"
T50="$W/.planning/phases/50-addressable-monitor-liveness/tools"
P501="$HOME/.cache/devflow-phase50.1"
N=1
EV="$P501/attempt-$N"
gh auth status
```

Use the next attempt number, not necessarily 1 (`prepare` refuses a wrong one). The Token scopes line must include
`repo`; otherwise run `gh auth refresh -s repo`.

## 1. Prepare (rebuild and pin the binary)

Commit every crate change first: the binary embeds its commit, and the fault arm records the crate source it ran.

```bash
git -C "$W" status --porcelain -- crates Cargo.toml Cargo.lock rust-toolchain.toml
bash "$T49/launch-attempt.sh" prepare --attempt "$N" --home "$P501"
BIN=$(jq -er '.bin | select(type == "string" and length > 0)' "$EV/attempt.json")
```

The first command must print nothing. The destination must not already exist; never delete an old attempt to make
preparation pass.

Never compare this binary's sha256 with a stored one: `crates/devflow-cli/build.rs` embeds the commit and dirty flag, so
a rebuild's hash changes after every commit. The only hash this procedure relies on is the one `prepare` and the fault
arm each record from the same pinned file, which the attempt gate pairs.

## 2. Fault arm

Right after `prepare`, run the full case set on `$BIN` and judge it with `--require-all`:

```bash
M=1; while [ -e "$P501/fault-$M" ]; do M=$((M + 1)); done
bash "$T50"/fault-arm.sh run --bin "$BIN" --out "$P501/fault-$M" --cases all
bash "$T50/check-supervisor-evidence.sh" --fault "$P501/fault-$M" --require-all >"$P501/fault-$M/verdict-require-all.txt"
echo "fault verdict exit=$?"
cat "$P501/fault-$M/verdict-require-all.txt"
```

Expected: five `FAULT case=<name> ok live` lines (`alive-stop-stream`, `alive-stop-capture`, `kill9-stale-stop`,
`kill9-at-gate`, `stop-races-completion`), `FAULT case=publish-unlink-window ok pointer`, `FAULT complete=yes`,
`FAULT verdict=pass` and exit 0. It took about 30 s in the one timed run. It uses a private `DEVFLOW_CACHE_DIR` under
`/tmp/df50f.*`, never touches `~/.cache/devflow`, and removes its scratch on exit.

`kill9-at-gate` reads the Define gate's waiter from `doctor --json`: `waiter_before` must be `live`; `waiter_after` must
be `absent` or `no_phase`; a `FAILED <why>` reading is unmet, never a gone waiter.

A failing case is blocking: do not launch. Fix it (see "Fix vehicle"), prepare a new attempt number and run the fault arm
again with a new `M`. Never edit a fault record. `--attempt-gate` refuses `shipped` unless a fault directory that passes
`--fault --require-all` records this attempt's `bin_sha256`, so skipping this step makes the attempt unjudgeable.

## 3. Repository

These commands create external GitHub state. Run them after checking the account reported above.

```bash
ACCOUNT=$(gh api user --jq .login)
REPO="$ACCOUNT/p501-live-attempt-$N"
gh repo create "$REPO" --private
git -C "$EV/project" remote add origin "https://github.com/$REPO.git"
git -C "$EV/project" push -u origin main
git -C "$EV/project" push origin integration
(cd "$EV/project" && gh repo view --json nameWithOwner,visibility)
```

Confirm `PRIVATE` and the intended owner and name. Keep both pushed branches: `main` is the PR target; `integration` is
DevFlow's local merge base and target.

## 4. Launch

```bash
bash "$T49/launch-attempt.sh" start --attempt "$N" --home "$P501"
bash "$T49/launch-attempt.sh" status --attempt "$N" --home "$P501"
```

`start` runs the bounded Claude authentication probe first and launches only when it succeeds; it then runs
`"$BIN" start --phase 1 --agent claude --mode auto --yes-ship "$EV/project"` in unit `p49-a$N-start` and the watcher in
`p49-a$N-surv`. On `auth probe failed` nothing launched and the attempt is unused; read `49-RUNBOOK.md` section 4 for the
credential checks (names only, never values).

Liveness is the supervisor socket, not a pid: `"$BIN" status "$EV/project"` prints
`supervisor: <socket> — ALIVE (owner: …, launch: stream|capture)` for a live stage.

## 5. Answer the Define and Code gates

Every answer goes through `devflow gate approve` or `devflow gate reject`, which fill the gate id. A gate answered by
hand, by writing a response file, is out of procedure and makes the attempt a deviation.

```bash
"$BIN" gate list "$EV/project"
"$BIN" gate show 1 --stage define "$EV/project"
"$BIN" gate approve 1 --stage define --note "attempt $N: seeded blocking-human checkpoint is intentional" --project "$EV/project"
```

Wait for Code and inspect its own context before approving:

```bash
"$BIN" gate list "$EV/project"
"$BIN" gate show 1 --stage code "$EV/project"
"$BIN" gate approve 1 --stage code --note "attempt $N: this approval records the checkpoint set" --project "$EV/project"
```

The Code approval records the auto-decide set; the resume that follows runs under the capture-shape supervisor. An
approval needs a live waiter on that gate's registration. Do not answer any other gate as though it were expected.

## 6. Wait for the end

As Phase 50 section 6, with `$EV` above. Completion is a `workflow_shipped` event.

## 7. Collect and judge

After the run ended, stop the observer and release the start unit exactly as `49-RUNBOOK.md` section 7 describes, with
`p49-a$N-*` unit names. Then collect, add the leftover sidecars, record the seam checks and judge:

```bash
bash "$T49/collect-attempt.sh" --attempt "$N" --home "$P501"
bash "$T50/check-supervisor-evidence.sh" collect-sidecars "$EV" --project "$EV/project" --bin "$BIN"
E="$EV/collected/devflow/events.jsonl"
{
    if [ -s "$E" ]; then
        for name in gate_answer_quarantined supervisor_superseded workflow_shipped; do
            printf '%s=%s\n' "$name" "$(jq -s --arg e "$name" '[.[] | select(.event == $e)] | length' "$E")"
        done
    else
        echo "events=ABSENT $E"
    fi
    rg -x -e 'integration_merge_count=.*' -e 'integration_merge=.*' "$EV/collected/git.txt"
} | tee "$EV/seam-checks.txt"
bash "$T50/check-supervisor-evidence.sh" --attempt "$EV"
bash "$T50/check-supervisor-evidence.sh" --attempt-gate "$P501" --current-source
```

The collector records these checks, because no judge line above reads them; 50.1-28 quotes them from the published
evidence. `events=ABSENT`, an empty value or a missing line means the read failed, not zero.

| Check | Expected | If not |
|-------|----------|--------|
| `gate_answer_quarantined` | `0`, unless an answer was really set aside | Write each set-aside answer and its `reason` in `$EV/deviations.txt`; an event with no answer really set aside is a defect |
| `supervisor_superseded` | `0` | A supervisor stood down in a one-supervisor run: triage it as a defect |
| `workflow_shipped` | `1` | The run did not ship: see "If the run dies without reaching Ship" |
| `integration_merge_count`, `integration_merge` | `1` and a commit: the Ship merge on the throwaway repository's base, `integration` | Triage as a defect, whatever the verdict says |

`--current-source` refuses an attempt whose paired fault record was not taken from this checkout's committed crate tree,
such as a binary built before a later fix (`reason=… from the current crate source`). `collect-sidecars` finding no
sidecar is the normal result after a run to Ship.

For an intentionally aborted stopped run, pass the actual reason to the collector:
`--stop-note "aborted: describe the observed failure"`. If the attempt shipped but the gate says `not_ready` for a
collection reason, follow `49-RUNBOOK.md` section 7's archive-and-recollect procedure (with `--home "$P501"`); never
rewrite collected files.

Before any attempt exists the closing line exits 1 with `verdict=not_ready`, not 2: measured for 50.1-26 on an empty home
and on the absent `$P501` itself (`reason=ABSENT … current-attempt`).

## 8. Close the checkpoint or stop the attempt

Reply `done` to the 50.1-27 checkpoint only after this line printed `verdict=shipped` or `verdict=cap_reached`:

```bash
bash "$T50/check-supervisor-evidence.sh" --attempt-gate "$P501" --current-source
```

On `verdict=not_ready`, do not reply. If the attempt stopped below the cap, record it with `--stop-note`, end the
execute-phase session, confirm the fix vehicle, fix, and resume with `/gsd-execute-phase 50.1` for the next attempt.

## If a gate you did not expect opens

Every gate beyond Define and Code is a deviation to record in `$EV/deviations.txt` before answering it, exactly as in
`49-RUNBOOK.md` ("If a gate you did not expect opens"), and it goes back to the operator. Never fabricate a response file.

## If the run dies without reaching Ship

As Phase 50's section of the same name, with `$EV` above: `status`, then `doctor --json` into `$EV/death-doctor.json`,
then the ALIVE, STALE and GONE handling, signalling nothing by pid alone or by name. Read the waiter from that file; a
gate file left on disk is not proof of one:

```bash
jq '[.reconciliation[] | select(.phase == 1) | .gate_waiter] | unique' "$EV/death-doctor.json"
```

`status: "live"` means the run is not dead. Do not delete or answer a stale gate to make collection work.

Only after confirming every run process is gone, no waiter remains and no shipped event exists, collect the dead run with
the Phase 49 collector's `--allow-state --stop-note "died: …"`, then run section 7's remaining lines. A failure here
cannot be attributed to 50.1 rather than Phase 50 without triage: name the seam that broke before choosing a fix.

## Fix vehicle for a blocking defect

As Phase 50's section of the same name, with `feature/phase-50.1` for `feature/phase-50`, `--home "$P501"`, and
`/gsd-phase --insert 50.1` for a cross-crate fix or a design decision. Run the fault arm on the binary `prepare` pinned.

As Phase 50's section of the same name, with `$EV` above. Do not delete local or GitHub records until Phase 50.1

## What this attempt does not establish

- One run is a seam smoke check. It shows the seams worked end to end once, on this binary; it is one sample, a weak
  bound on reliability, not a guarantee.
- It proves nothing about durability, ownership races or stale answers. The named tests and kill-point fixtures carry
  those (D-12), and a clean run neither replaces nor strengthens them.
- A failure cannot be attributed to 50.1 rather than Phase 50 without triage: no live run has exercised the Phase 50
  supervisor at this HEAD, so a defect may predate this phase.
- `gate_answer_quarantined=0` and `supervisor_superseded=0` say those paths did not fire in this run, not that they work.
  Their behavior rests on their tests.
- The fault arm's `kill9-at-gate` proves the waiter ends with its supervisor on Linux under `kill -9`; it does not show
  that a waiter survives anything, and it reads the waiter only through `doctor --json`, so it trusts that reading
  (`doctor_json_e2e::doctor_json_names_the_open_gates_waiter` carries it).
- Phase 50's limits still hold: `50-RUNBOOK.md`, "What an attempt does not establish".
