### 60b8278 against the decisions

- **D-01 (record before spawn; criterion 1's control "with no such supervisor the launch proceeds").** The new check refuses only on a held lock that no other phase's loadable state records. An unheld lock is skipped, which is the "abandoned" case D-01 requires. Liveness is decided by `liveness::probe`; the pid read from the lock's record is only printed. So D-01's "without a pid read" still holds for the decision. Controls pass: a released lock, and a lock another phase records.
- **D-02 (the repair is `stop`).** D-02 covers a supervisor the state records, recorded or pending. The new refusal covers one no state can name: no pending record, no socket yet. `stop` cannot reach that supervisor, so naming `stop` would be wrong. The sweep still runs first (`refuse_launch_over_a_live_run` precedes the new check), so a published supervisor is still refused with its `devflow stop --phase N --launch <id>` line. `start_lock_e2e` pins that for unloadable states, on the same code path a missing state takes. Neither refusal names `resume`.
- **D-17 (holder arm, no state-file pid signalled).** The holder arm is unchanged. The new `stop` text signals nothing and reads the pid from the liveness lock's own record, not the state file.
- **D-19 (name an orphaned agent honestly).** The orphaned-agent branch of `stop_via_holder` is unchanged. The new text replaces "run `stop` again", which could never succeed here, with the holder pid and the manual route. That is the same honesty rule applied to a new case.

### The two changed tests

- **`a_second_start_launches_when_the_sweep_has_nothing_to_find` → `a_second_start_refuses_through_the_held_lock_when_the_sweep_has_nothing_to_find`.** The old test asserted the unsafe behaviour (a second supervisor launched beside a live one) as a control. This tightens the behaviour; nothing was weakened. **One side effect:** its sibling `a_second_start_refuses_beside_a_failed_starts_stopped_supervisor` asserts only the launch id, which both refusals contain. That pair no longer shows which arm refused for a missing state. The sweep's own wording is still pinned by `start_lock_e2e` (`start_refuses_over_a_live_supervisor_when_the_state_will_not_load` and siblings). `possibly_live_sockets` receives `None` for both a missing and an unloadable state. So no path lost coverage. Info only.
- **`two_launchers_cannot_both_reserve` now saves a state first.** Without it, the no-lock control's second launcher would also be refused by the new stateless check, and the control could not show that the write lock is what excludes it. The lock case still asserts 1 arrival at the hold, exactly one reservation, a refusal naming `devflow stop --phase N`, the state naming the winner, and one liveness file. In a real first start the second launcher reads the first's saved pending record, so it meets the same guard the test now exercises. Not weakened; it passes.
