# Phase 50.1 Plan 04: State Write Lock and Owner Fence Summary

**`devflow-core` now has one state write path: a short `flock` on the never-replaced `.devflow/.state-NN.lock`, a re-read, the caller's closure and a durable replace, with a create-capable form, an owner-fenced form and a bounded form that returned in at most 500.6 ms against a 500 ms deadline, naming a stopped holder.**

## Read this first

**No production code calls this API yet, so the lost update is still live.** The CLI still saves the copy it loaded before a gate wait (`pipeline_gate.rs`). Plans 50.1-10 and 50.1-11 route the callers here. The bounded forms have no caller either, so `stop` can still wait on what it waits on today until later plans wire `stop`, `recover`, `status` and `doctor`. This plan delivers and tests the library only.

**`clear_state` is the one production path that changed.** It now takes the write lock and blocks while it is held. No caller holds that lock yet, so nothing can wait on it today.

**The three requirement IDs are not ready to mark complete.** `requirements.ready-ids` reports `SURV-03`, `SUPV-03` and `SUPV-04` as blocked, because sibling plans that declare them have no SUMMARY yet. The frontmatter copies them as the plan requires. `REQUIREMENTS.md` was not edited. This plan supplies only the core half of each: `SURV-03` ("every state change") is not true until the CLI routes through this API, and `SUPV-03` and `SUPV-04` need the launcher and CLI plans.

## Accomplishments

- `update_state` re-reads under the write lock. The test's stale-copy control shows the lost update it removes.
- `update_state_with` hands the closure `Existing::{Missing, Unloadable, Loaded}` under the lock, so a launcher can check and create in one step. Returning `None` writes nothing.
- `update_state_with_within` and `clear_state_within` try every 10 ms until the deadline, then return `WriteLockTimeout` without running the closure or removing anything.
- Every acquisition records `"{pid} {start}\n"` with one positional write and clears it while still holding the lock. A pid is reported only when `agent::is_same_process` confirms it. Nothing signals or waits on the record.
- `write_lock_status` reads the lock without waiting and creates no file.
- `update_owned_state` refuses under the lock, before the closure, unless the state records the launch.
- `State.pending_supervisor` is a separate field beside `State.supervisor`. An older file with no key parses as `None`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `flock` retries EINTR**
- **Found during:** Task 1, then proved by the mutation run
- **Issue:** The plan says a blocking `File::lock()`. std does not retry it, so a signal handler without `SA_RESTART` turns a stalled peer into a failed state write. That is the failed stage transition the plan's reasoning rules out for this form.
- **Fix:** Retry on `Interrupted`. DevFlow's own stop handler sets `SA_RESTART`, so only a library host's handler reaches this today.
- **Files modified:** `crates/devflow-core/src/workflow.rs`
- **Verification:** `a_signal_does_not_fail_a_blocked_write`, with the temporary edit above
- **Committed in:** `15959ff`, test in `af20785`

**2. [Rule 1 - Bug] `clear_state` created `.devflow` in an untouched project**
- **Found during:** Task 1
- **Issue:** Taking the lock first creates the directory, its `.gitignore` and the lock file, where `clear_state` used to touch nothing.
- **Fix:** With no `.devflow` directory there is nothing to remove, so it returns before the lock.
- **Files modified:** `crates/devflow-core/src/workflow.rs`
- **Verification:** `clear_state_in_a_project_without_a_devflow_dir_creates_nothing`
- **Committed in:** `15959ff`

**3. [Rule 3 - Blocking] `#[allow(clippy::large_enum_variant)]` on `Existing`**
- **Found during:** Task 1's RED commit
- **Issue:** Clippy refuses the plan's `Loaded(State)`, at 408 bytes against 32.
- **Fix:** Kept the plan's shape, with the reason beside the allow, because later plans match on `Existing::Loaded(state)`.
- **Files modified:** `crates/devflow-core/src/workflow.rs`
- **Verification:** clippy exit 0
- **Committed in:** `a176c94`
