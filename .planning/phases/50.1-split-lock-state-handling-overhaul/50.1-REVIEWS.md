### 1. Missing file rewind after `ftruncate`/`set_len(0)` causes NUL-byte corruption in all adopted liveness and phase holder records
* **Severity:** BLOCKER
* **Citations:**
  * [.planning/phases/50.1-split-lock-state-handling-overhaul/50.1-05-PLAN.md:167-168](.planning/phases/50.1-split-lock-state-handling-overhaul/50.1-05-PLAN.md#L167-L168): `truncate and rewrite the identity line for this process; set_len(0) then one write_all`
  * [.planning/phases/50.1-split-lock-state-handling-overhaul/50.1-29-PLAN.md:165, 195](.planning/phases/50.1-split-lock-state-handling-overhaul/50.1-29-PLAN.md#L165-L195): `rewritten in place under the held lock (set_len(0), then one write_all)` and `Ok -> set_len(0) and one write_all of this process's "{pid} {start}\n" record`
* **Concrete Failure Scenario:**
  1. The launcher process takes a reservation: `Hold::take` opens `supervisor-<id>.live`, locks it, and calls `file.write_all(b"{launcher_pid} {launcher_start}\n")`. This advances the underlying open file description's offset to ~18 bytes.
  2. The supervisor child inherits descriptor `fd 3` (which shares the same open file description and offset 18).
  3. In `adopt_inherited(3, path)`, the child wraps `fd 3` and executes the plan specification: `file.set_len(0)` followed by `file.write_all(b"{supervisor_pid} {supervisor_start}\n")`.
  4. **POSIX standard behavior (`man 2 ftruncate`):** `ftruncate` changes file length but does **not** alter the file offset. The subsequent `write_all` writes starting at byte offset 18. The operating system pads bytes 0..17 with ASCII NUL (`0x00`) bytes!
  5. Any observer (e.g. `devflow stop`, `devflow status`, `registry_reachable_pids`) calling `live_holder(path)` opens the file and reads from offset 0. It encounters 18 leading NUL bytes before the supervisor's PID string.
  6. Parsing byte 0 as an ASCII integer PID fails, returning `Err(io::Error::from(ErrorKind::InvalidData))`.
  7. Consequently, `stop_via_holder` ([50.1-29-PLAN.md:206-208](.planning/phases/50.1-split-lock-state-handling-overhaul/50.1-29-PLAN.md#L206-L208)) and `stop_in` fail closed, refusing to signal live supervisors and foreground holders.
  8. *Why the plan's test passed in design:* Test `adopting_the_inherited_descriptor_marks_it_close_on_exec_and_records_the_adopter` ([50.1-05-PLAN.md:153](.planning/phases/50.1-split-lock-state-handling-overhaul/50.1-05-PLAN.md#L153)) creates a synthetic descriptor via `open` at offset 0 rather than inheriting a descriptor pre-populated by `Hold::take`.
* **Fix:** In `adopt_inherited` and `claim_phase_holder`, explicitly rewind the file offset: `file.seek(std::io::SeekFrom::Start(0))?;` immediately before or after `file.set_len(0)?;`.

* **Fix:** When `try_lock_past_probes` hits `WouldBlock` after 50ms, before returning `Held`, read the file's contents via `live_holder`. If `live_holder` finds no holder record or an empty file, wait an additional exponential backoff interval before failing.
