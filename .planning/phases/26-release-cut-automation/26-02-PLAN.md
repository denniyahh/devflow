<objective>
Replace DevFlow's hardcoded one-line CHANGELOG bullet with real, grouped content
derived from the conventional-commit classification the version-bump step
already computes over the same range (**D-12**, backlog `999.5`).

Purpose: `999.5` was deferred three times (plans 17-10, 17-12, and Phase 21's
optional 21e) for want of a content source. Phase 25's conventional-commit
classifier supplies one for free — the range-resolution and per-commit-parsing
machinery already exists and is already correct. This plan reuses that machinery
and adds only the aggregation step it lacks.

Output: a `ChangelogHeading`-grouped body generated from `baseline..HEAD`, wired
through the existing Ship-time hook chain into `CHANGELOG.md`.

**Resolved open question (RESEARCH.md § "Open Questions" #2).** RESEARCH.md
recommended narrowing the changelog to only version-affecting types
(feat/fix/perf/breaking) and omitting `docs`/`chore`/`test`/`ci`/`refactor`/
`style`. That recommendation is **not adopted**. This plan includes **every**
type the Phase 25 classifier recognizes, grouped under Keep-a-Changelog
headings, because this repository's own hand-written entries already place
`docs:`-typed work under `### Changed` (see `CHANGELOG.md`'s 2.1.0 entry) and
narrowing arbitrarily would silently drop content a maintainer expects to see.
The mapping table in Task 2 is the locked answer.
</objective>
