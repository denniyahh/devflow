    --yes-release`. Confirm this capability should be built.

  <context>
    CONTEXT.md rates D-04 **one-way**: "a crates.io publish can never be
    un-published or reused at that version." Every release to date has been
    published by hand; no DevFlow code has ever invoked `cargo publish`.

    D-04's mitigation is a pre-publish existence query (`cargo info
    <name>@<version>`), which lets a re-run distinguish "already live at this
    version, skip" from a genuine failure — this is also the anchor for D-06's
    idempotent resume on the publish step specifically, since cargo itself has
    no "already done" signal beyond its own duplicate-version rejection.

    D-05 applies: there is no automatic rollback. If `devflow-core` publishes and
    `devflow` then fails, the `devflow-core` publish stays; the fix is forward.

    The environment precondition (`cargo login` credentials or
    `CARGO_REGISTRY_TOKEN`) is the operator's, not this phase's — RESEARCH.md's
    Environment Availability table records it as unverified in the research
    sandbox.
  </context>
