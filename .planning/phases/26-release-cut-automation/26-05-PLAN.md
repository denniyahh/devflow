**Resolved: the hermeticity question `26-VALIDATION.md` § "Wave 0 Requirements"
left open.** Its third bullet asked for either a fake `cargo` shim on `PATH` or
tests against a known-immutable registry version, and recorded that neither was
ever chosen. **Neither is adopted.** The boundary moves instead: the decision
logic lives in a pure function, `classify_cargo_info_result`, which takes an
already-captured exit code and stderr and returns a typed verdict, and the argv
it is fed is pinned by its own assertion. Rationale, in order of weight:

1. A `PATH` shim mutates process-global state in a threaded test binary,
   requiring a serializing mutex like this repository's existing `ENV_MUTEX`,
   and buys coverage of `Command::spawn` alone.
2. A live-registry test makes the unit suite network-dependent, which breaks
   `scripts/check-in-container.sh` and every offline run, against this
   project's hermetic-fixture discipline throughout.
3. A shim would assert this plan's own assumption about cargo's output back at
   itself — rejected test shape #2 in
   `.claude/skills/ai-change-acceptance/rules/test-signal-rejection.md`
   ("tests that reproduce the production algorithm inside the test body").
   It cannot close RESEARCH.md Assumption A4 (cargo's wording could change);
   only a live run can, and A4's failure direction is already safe: an
   unrecognized message classifies ambiguous, which refuses to publish rather
   than double-publishing.
4. What a shim would add and this design does not cover is `Command::spawn`
   itself, which is `std`. Task 1's live oracle probe checks the real tool's
   real behavior once, at implementation time, outside the test suite.

`26-VALIDATION.md` § "Manual-Only Verifications" row 2 (a real `cargo publish`
of both crates in order, observed by the operator) stays **manual-pending** and
is recorded as a `backstop` truth above — this plan does not and cannot close
it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crates.io registry -> DevFlow's skip decision | `cargo info`'s output is remote, attacker-influenceable-in-principle text that decides whether an irreversible publish runs. |
| DevFlow process -> crates.io | `cargo_publish` is the first production code that can write to a public registry under the operator's credentials. |
| cargo subprocess stderr -> operator log | Untrusted, unbounded text crosses into `PublishError` and then into terminal output. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
