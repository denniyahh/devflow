**Both operator authorizations are already on record — cited, not re-asked.**
Direct push to `origin/develop` (D-01/D-08): `direct-push`,
`26-01-SUMMARY.md` Decision 1 / coverage id `D1`. Unattended `cargo publish`
(D-04, one-way): `automate-publish`, `26-01-SUMMARY.md` Decision 2 / coverage
id `D2`. No checkpoint is emitted for either. What `--yes-release` adds is not a
new authorization decision — it is the per-invocation typing that keeps the
already-authorized capability from becoming a standing default.

**Resolved: the executor's pre-gate omits the signing check (D-10).**
RESEARCH.md's architecture diagram proposes reusing all four of `release_check`'s
checks as a hard pre-gate. Three are kept; the tag-signing viability check is
**not**, because running it on the executor path would be exactly "the
signing-viability predictor reused by the executor", which D-10 forbids in those
words. The tag step answers the signing question by running the real command and
reading git's real result. Divergence is also demoted from blocking to
informational: `origin/main` failing to be an ancestor of `HEAD` is the *normal*
state of an in-flight release between the human's merge and the sync step, so a
blocking divergence gate would make resuming a release impossible. Self-pin and
publish-order stay blocking.

**Surfaced, not silently absorbed: `Cargo.lock` is not synced by the automated
bump.** CONTRIBUTING.md step 1 says to run `cargo build` after bumping so
`Cargo.lock` records the new workspace member versions. Neither
`version::write_version` nor `hooks::version_bump` has ever done this, and
26-06's bump step inherits that shape. This plan does not add it — it is outside
the five verification gaps and belongs to whoever owns the version-bump
machinery next. It is instead documented in CONTRIBUTING.md's step mapping as a
remaining manual sub-step so an operator is not surprised by a stale lock.

**Manual-only verifications become actionable but stay operator-pending.**
`26-VALIDATION.md` § "Manual-Only Verifications" rows 1 (a tag created with the
operator's real signing key) and 3 (`devflow sync` landing a direct push against
the real `origin`) now have code paths to exercise, so they stop being moot.
This plan does **not** claim them: both are recorded above as `backstop` truths,
which a verifier should abstain on rather than pass. Row 2 (a real
`cargo publish`) is backstopped in 26-05 for the same reason.
