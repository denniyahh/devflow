<design_decisions>
Three items CONTEXT.md left to Claude's discretion are settled here, because later plans build
on them.

**The monitor's outer process shape: re-exec the `devflow` binary as a hidden subcommand.**
`spawn_monitor`'s caller (`devflow start` / `devflow advance`) must return quickly while the
monitor outlives it, so the monitor has to be a distinct OS process. Re-exec needs no
daemonization primitives beyond `Command::spawn()`-without-`wait()`, which is exactly what
today's `sh` monitor already relies on, and it preserves the existing "advance runs as its own
process" boundary. `Command::Advance` in `crates/devflow-cli/src/main.rs:95-105` is the
established precedent for a hidden internal subcommand.

**Prompt transport from `spawn_monitor` to the monitor process: a file, not argv.** DevFlow
stage prompts are large and argv has a length ceiling. `spawn_monitor` writes the prompt to
`.devflow/phase-NN-prompt` and passes the path.

**The D-09/D-10 sequencing gate is a named predicate, not a behaviour prediction.**
`ClaudeAgent::exec_command` returns the stream-json shape unconditionally — the adapter switch
is always-on and stage-blind, satisfying constraint 1 literally. The pre-31 shape survives only
as an explicitly named separate builder, selected by one predicate whose doc comment states
that it is a sequencing choice per D-09/D-10 and names the evidence that widens it.
</design_decisions>

Add `pub fn run_pipe_owning_monitor(project_root, phase, workdir, prompt, idle_timeout,
program, args, envs) -> Result<i32, MonitorError>` implementing the supervisor:

  - Spawn `program`/`args` with `hermetic_command(program, workdir)`, `.envs(envs)`,
    `.stdin(Stdio::piped())`, `.stdout(Stdio::piped())`, `.stderr(Stdio::from(stderr file))`,
    and `.process_group(0)` via `std::os::unix::process::CommandExt` so the child leads its own
    group. `process_group` is stable since Rust 1.64 and this workspace is on 1.97.1 / edition
    2024. Today's `spawn_monitor` has no `setsid`, `process_group`, or `pre_exec` call anywhere
    — detachment comes only from the parent not waiting. Adding group leadership here closes
    the group-signal ambiguity that plan 31-02's termination step depends on.
  - Record `child.id()` to `agent_pid_path(...)` immediately, preserving the existing contract
    `wait_for_agent_pid` relies on.
  - `take()` the child's stdin and stdout. Move stdin into a writer thread that writes
    `user_turn_line(prompt)` followed by a newline, flushes, and then **blocks on an
    `mpsc::Receiver`** rather than returning; it drops stdin only when it receives the close
    signal or the channel disconnects. Do not let the writer thread close stdin after the write:
    constraint 4's `AND` can never be honoured if stdin is already gone, and a large prompt
    written on the same thread that must also drain stdout is the textbook two-pipe deadlock
    (the Linux pipe buffer is commonly 64KiB and a stage prompt can exceed it).
  - Move stdout into a reader thread wrapping it in `BufReader::lines()`. For each `Ok(line)`:
    append the line verbatim plus a newline to `stdout_path(...)` (open once, append mode — this
    preserves the existing capture-file contract the whole Layer 1 cascade reads), then
    `tx.send(line)`. On `Err`, break — a read error is EOF for supervision purposes. Dropping
    `tx` at thread end is what surfaces `Disconnected` to the supervisor.
  - Supervisor loop on the main thread: `rx.recv_timeout(idle_timeout)`. `Ok(line)` inspects the
    line for the close rule (below) and continues. `Disconnected` means the child's stdout
    closed — leave the loop and fall through to reaping. `Timeout` is the idle-timeout firing;
    for this task, leave the loop and fall through to reaping, and mark the arm with a comment
    naming plan 31-02 as the owner of what it must do instead. Do not invent a partial
    idle-timeout behaviour here.
  - Close rule (constraint 4, an `AND` of two arms, neither sufficient alone). Track
    `marker_seen: bool` and `pending_background_tasks: Option<usize>`. Parse each line with
    `serde_json::from_str::<serde_json::Value>`; a line that does not parse is noise and is
    ignored for the close rule but is still teed to the capture. Set `marker_seen` when a line is
    a `type` of `result`, satisfies `is_top_level`, and whose `result` string field carries a
    DEVFLOW_RESULT marker — reuse the existing marker parse rather than writing a second one,
    and reuse `is_top_level`'s exact predicate rather than a new notion of trustworthiness. Set
    `pending_background_tasks = Some(tasks.len())` on any line whose `type` is `system` and
    `subtype` is `background_tasks_changed`. The drain arm is satisfied when
    `pending_background_tasks` is `None` (no background task was ever announced — vacuous, and
    the common single-plan case) or `Some(0)`. When both arms hold, signal the writer thread to
    drop stdin. Do NOT treat the drain alone as a stop signal: 30d measured the
    drain-to-final-`result` lag at 4.54-11.51s across 14 trials, and closing at the drain would
    have truncated the final orchestrator turn in all seven 30d trials.
  - After the loop, `child.wait()`, write the resulting code to `exit_code_path(...)`, join the
    threads, and return the code. Where the child must be terminated rather than waited on, call
    `crate::agent::terminate_and_verify` against the child's process group rather than writing
    new escalation logic.
