<objective>
Close the two remaining wiring obligations: a stream-derived `Success` must not short-circuit a
contradicting exit code, and an operator must be able to fall back to the pre-31 launch path
without a release — loudly, and only on purpose.

Purpose: constraint 9's items 1 and 2 were closed in Phase 30 by the `a557805` root-cause
refactor. What survives is that a capture cut at an exact line boundary is byte-identical to a
healthy shorter run, so **no parser assertion can exist for it** — the defense has to live one
layer up, in the wiring. A writer that died between flushing turn N and turn N+1 also died
non-zero, and that non-zero code is the only signal left. Today Layer 1 always wins over Layer 2
by construction, so a truncated success stands unchallenged.

Output: exit-code arbitration on Layer 1's success verdict, a loudly-logged opt-out flag, and the
D-12 isolation-test contract re-verified with its inverse assertion for the new argv.
</objective>

Add `fn reconcile_stream_success_against_exit_code(project_root: &Path, phase: u32, result:
AgentResult) -> AgentResult` beside `reconcile_layer0_verdict`, and apply it to `evaluate_layer1`'s
result inside `evaluate_agent_result_inner` before that result is returned.

It arbitrates only when `result.status == AgentStatus::Success`. Read `exit_code_path`; on a
missing or unreadable file, return the result unchanged. On a parsed code of zero, return the
result unchanged. On a non-zero code, return a result with `status: AgentStatus::Failed`,
`exit_code: Some(code)`, `decided_by_layer` preserved at 1, **`verdict: None`**, other fields
carried over, and a `reason` stating plainly that the stream reported success while the agent
exited with that code, and that a capture cut at an exact line boundary is byte-identical to a
healthy shorter run — so the exit code is the only remaining signal. Do not touch `RateLimited`,
`IdleTimeout`, `ResourceKilled`, `AgentUnavailable`, `Failed`, or `Unknown`.

**`verdict: None` is load-bearing — do not "carry it over" for symmetry (adversarial review of
this plan, 2026-08-03).** `classify_validate_outcome` (`crates/devflow-cli/src/pipeline_outcomes.rs:206`)
matches `(_, Some(Verdict::Pass)) => ValidateOutcome::Passed` **first**, with `_` discarding the
status entirely. A Layer 1 success carrying `verdict: Pass` plus a non-zero exit would therefore
set status `Failed`, keep verdict `Pass`, and still classify Validate as **Passed** — making this
task's own success criterion false at the one stage that matters most. Neither
`parse_devflow_result` nor `parse_claude_event_result` normalises `verdict`; both normalise only
`decided_by_layer`. 31-02 hit this and dodged it the same way: `idle_timeout_result`
(`crates/devflow-core/src/agent_result.rs`) sets `verdict: None` with a doc comment naming this
exact reason. A downgraded result has no verdict to offer and must not invent one.

The underlying defect — that an agent's self-reported verdict outranks the status the cascade
derived — is **999.74 / DEN-95**, filed 2026-08-03 and deliberately not fixed here: changing that
match arm silently re-routes `Failed`, `Unknown` and `ResourceKilled`, whose current behaviour
nothing has audited. `verdict: None` is the correct local defence, not a workaround for a defect
this plan owns.

**Exit-code fidelity (adversarial review, W1).** Returning a blanket `Failed` for any non-zero code
flattens two codes the cascade treats specially: `evaluate_layer2` maps **137 → `ResourceKilled`**
and **127 → `AgentUnavailable`**, which `outcome_policy::decide_action` routes to `GateInfra`
rather than `GateReview`. Preserve that mapping here rather than collapsing it — the same exit code
must not reach two different operator gates depending on whether a stale Layer 1 success happened
to be present. Note also that on the `PipeOwning` arm `run_pipe_owning_monitor` writes
`status.code().unwrap_or(-1)`, so a SIGKILLed child records `-1`, not `137`; record that the
`ResourceKilled` arm is currently unreachable on that path rather than silently relabelling a real
OOM as `Failed`.

The doc comment must state why this cannot be a parser assertion: constraint 9's items 1 and 2
were closed by the root-cause refactor, and what survives is precisely the case no parser can
detect. It must also state why the fix is narrow rather than a cascade reordering — Layer 1 is
authoritative by design in the ordinary case, and making Layer 2 run first would replace a rare
wrong answer with a slow one on every stage.

(999.64, unfixed on this path)."* Name `legacy_launch_skips_the_delivery_canary` in its doc comment
as testing *scoping*, not a permitted bypass.
