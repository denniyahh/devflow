## Recorded decision — Claude's Discretion item #3: in-flight phases across the D-08 upgrade

**DECIDED: `#[serde(default)]` semantics plus a dedicated, named `doctor`
finding. Not a refusal, and not folded into the generic Unknown bucket.**

CONTEXT.md left open whether a phase whose `state.json` predates the
`supervisor` field should be *refused with guidance* or handled otherwise.

Refusing is wrong. `state.rs` has one consistent, well-tested precedent for
every field added since 17-01: `#[serde(default)]`, defaulting to a value that
downstream consumers already treat as "unknown, never assume Stuck or Healthy".
`liveness()`'s `None` arm resolves `Unknown`, and that is directly guarded by
the existing `liveness_unknown_when_no_monitor_recorded` test. A hard refusal
would make an old `state.json` un-inspectable by the very commands an operator
would reach for to understand it.

But "absent field defaults to None" does not cover the genuinely new risk. A
phase whose monitor was spawned by the **old** mechanism carries a *populated*
`monitor_pid` and no `supervisor`. The new binary correctly reports Unknown —
while the old shell monitor may still be alive and is now unreachable by any
new-binary command. That is not data corruption; it is a **silent loss of
control**, and DevFlow self-dogfoods, so it is plausible rather than
theoretical.

So: a dedicated `doctor` finding for exactly `monitor_pid: Some(_) &&
supervisor: None`, named and worded so the operator is told what to do — locate
and signal the process by hand, or let it complete naturally — rather than being
handed a generic Unknown. It is a one-time transition concern (D-08's big-bang
carries no long-term dual-path cost) and costs one more finding alongside the
existing `check_dead_agent` / `check_dead_monitor` pair.

## Recorded decision — `Liveness::Stale` representation and `cleanup`'s fail-closed rule

**Reviewers diverged and the plan previously delegated this to the implementer.
It is decided here instead (review finding — Hermes / OpenCode / Codex,
divergent view).** Hermes argued for a fifth `Liveness` variant so
`recovery_hints` can differentiate the remedy; OpenCode worried only about
`cleanup`'s refusal wording; Codex added that `cleanup` must be **fail-closed**
on `Stale`/`Unknown` because a false "not live" is destructive. All three are
addressed below.

**DECISION 1: add `Stale` as a fifth `Liveness` variant.** Not a rendering
special case on `Stuck`. A stale socket and a dead-and-gone supervisor call for
**different verbs** — `devflow stop` reaps a stale group, `devflow resume`
restarts a phase nothing is watching — and `recovery_hints` (`commands.rs:536`)
dispatches on the variant, so a rendering-only distinction would leave the two
sharing one hint. Making it structural also converts the phase's core
observability property from a string-comparison guard into a type-level fact:
`Stale` and `Stuck` cannot collapse into each other by accident.

The full mapping, so no arm is left to interpretation:

| `Option<SocketState>` | agent | `Liveness` | `recovery_hints` |
|---|---|---|---|
| `None` — no handle recorded | — | `Unknown` | none |
| `Some(Unknown)` — probe inconclusive | — | `Unknown` | none |
| `Some(Alive)` | running | `Healthy` | none |
| `Some(Alive)` | exited | `BetweenStages` | none |
| `Some(Stale)` | — | **`Stale`** | `devflow stop --phase N` |
| `Some(Gone)` | — | `Stuck` | `devflow resume --phase N` (plus `devflow advance` when `gate_pending`, preserving 21a/D-03 exactly) |

`Liveness::Unknown` therefore widens from "no monitor recorded" to "liveness
could not be determined", and its `describe()` is reworded to match. That keeps
`liveness_unknown_when_no_monitor_recorded` passing unchanged in intent, and the
distinguishability requirement is carried by `Stale` versus `Stuck` rather than
by the `Unknown` bucket. The `Some(Gone) → Stuck` arm deliberately reproduces
today's behaviour (a recorded handle whose process is gone renders `Stuck`), so
this plan adds a state rather than re-classifying existing ones.

**DECISION 2: `cleanup` is fail-closed, via its own pure predicate.** `liveness`
stays the single shared answer to "is this phase live" — that is what stops
`status`, `doctor` and `cleanup` disagreeing — but the *destructive* decision
gets its own auditable pure function,
`cleanup_is_safe(liveness, socket, pre_supervisor_pid) -> CleanupSafety`, with
`CleanupSafety::{Safe, Refuse(String)}`. Its arms:

- `Healthy`, `BetweenStages`, `Stale` → **Refuse.** For `Stale` the refusal
  message names `devflow stop --phase N` as the resolving verb, since a stale
  socket may still have a running orphan group behind it.
- `Some(SocketState::Unknown)` → **Refuse.** The probe did not answer; a
  non-answer is not a negative answer, and the cost of being wrong is a deleted
  worktree of a running phase.
- no handle recorded **and** `monitor_pid` populated → **Refuse.** This is
  `check_pre_supervisor_monitor`'s exact shape: an old `sh -c` monitor may still
  be alive and is unreachable by this binary. The message repeats the finding's
  guidance.
- no handle recorded **and** no `monitor_pid` → **Safe.** Nothing was ever
  registered for this phase; this is the never-started and cleared-after-early-
  failure case, and refusing here would make `cleanup` useless for its most
  common target.
- `Some(Gone)` → **Safe.** The supervisor exited and removed its own socket:
  a definite negative answer, not an absent one.

Only the last two arms permit deletion, and both rest on a positive statement
that no process exists — never on the absence of evidence.
